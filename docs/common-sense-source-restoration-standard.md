# 常识判断源文完整还原与阅读优化标准

> 状态：已确认。现有摘要仍不视为已校对原文；后续内容按本标准逐小节重建。

## 目标

1. 教材内容信息完整还原：正文、列表、表格单元格、插图图注、粗体重点、数字、条件与例外均不可无故遗漏。
2. 填空可用知识库补全，但补全不替代原始文档证据。
3. 小程序保留易读、易背的卡片与速记体验；阅读优化不得删减、截断或隐藏教材内容。
4. 内容层级严格遵循原书“篇—章—节—小节—知识点—知识点内分项”；前四级构成目录，小节是目录的最小颗粒度，知识点及其内部层级只在所属小节内部展示。

## 目录层级与术语

1. `篇`：最高层内容分篇，如“第一篇 文史常识”。
2. `章`：篇内正式章节，如“第一章 历史常识”。
3. `节`：章内正式分节，如“一、中国古代史”。
4. `小节`：节内带括号序号的最小目录项，如“（一）史前时代”“（二）先秦时期”。小节对应一个独立详情入口，也是源文还原与验收的最小批次。
5. `知识点`：小节正文内部的数字序号、主题标题、段落、表格或插图，如“1.夏”“2.商”。知识点可拆成页签或内容卡，但不得提升为目录小节或独立目录入口。
6. `知识点内分项`：知识点内部的事件、制度、分类或主题项。若某一条是后续若干条的统领标题，如“秦朝加强统治→政治、军事、思想、经济”“农具→曲辕犁、筒车”“制瓷业→南青、北白、唐三彩、补充”，必须建立明确父子关系，不得把父标题与子项渲染为同级连续编号。
7. 知识点内分项允许继续保留源文顺序，但展示编号必须体现层级，例如父项为 `3`，其子项为 `3.1、3.2……`；父项结束后的下一个同级项续接为 `4`，不得沿用源文扁平数组位置形成伪同级编号。
8. 页码、内容长度和阅读卡拆分都不得改变上述层级。目录归属不明确时，先对照原书前后同级标题确认，再开始内容重建。
9. 若原书某一“节”下直接出现正文、表格或知识点，未设置独立小节标题，则必须建立一个与该节同名的无编号单一小节容器；审计路径须标注“源文无独立小节标题，沿用节名”，不得擅自补造括号序号或主题名称。该容器只用于保持目录层级，不改变源文标题，也不得把内部知识点提升为小节。

层级示例：`第一篇 文史常识（篇） → 第一章 历史常识（章） → 一、中国古代史（节） → （三）秦汉（小节） → 1.秦（知识点） → 秦朝加强统治（知识点内父项） → 政治、军事、思想、经济（子项）`。因此“秦”不能单独出现在小节目录中，“秦朝加强统治”也不能与其下属四项显示为并列内容。

## 双层数据

### 源文完整层（唯一事实底稿）

每个内容单元建立稳定 ID，并记录：PDF 文件与页码、阅读顺序、区域类型、原始文字、粗体片段、表格行列单元格、插图及图注。

填空额外记录：原句、空位位置、补全答案、知识库依据和置信状态。前台只显示补全后的完整陈述。

源文中所有被填空的内容一律视为重点，不因答案长短、是否为数字或是否与其他重点重复而降级。每个补全答案必须在展示层进入重点高亮；该规则写入处理与审计标准，不在学习页面额外展示过程说明。只写入审计记录而未在正文标为重点，视为未完成映射。

### 现行法校对层（法律模块硬性门槛）

法律模块不得只以 PDF 为最终事实依据。每个知识点都必须对照国家法律法规数据库、全国人大或国务院及其部门公布的现行有效文本逐项校对；未经逐知识点覆盖的整页概括或抽样检查，不算完成现行法审计。

源文与现行法不一致时，审计文件必须同时保存原图文字与正式展示文字，并记录校对日期、效力版本、官方链接、变化原因和知识点映射。正式页面采用现行法文字；不得直接覆盖或删除源文底稿，也不得以“教材原文如此”为由继续展示已失效内容。学理分类、教材口诀和法条规则必须明确区分，不得为学理概念伪造法条依据。

法律模块重新识别或重新生成后，必须再次应用现行法展示覆盖并执行双层一致性验证；若任一知识点缺少现行法状态、引用非官方来源、显示内容回退为旧法或源文记录被覆盖，均阻断发布。

法律模块的固定发布门槛依次为：运行 `node scripts/apply-common-sense-current-law-audits.js` 同步全部源文/现行法双层记录，运行 `node scripts/validate-common-sense-current-law-audit.js` 检查各批知识卡与知识点全覆盖，再运行 `node scripts/validate-common-sense-source-audit.js --problems-only` 检查正式展示与审计文字一致。任一命令未通过，不得发布。

所有法律模块的校对更新必须汇总到唯一统一台账 `docs/common-sense-current-law-audit/law-correction-log.md`，不得另建彼此割裂的人工说明。台账逐项展示“PDF旧表述—现行法新表述—变更说明—官方依据—审计状态”，并明确区分真正的旧法、教材过度概括、学理分类和原书错误。每次增加、重识别或修改法律模块后，必须运行 `node scripts/generate-common-sense-law-correction-log.js` 重新生成台账；台账未同步视为发布未完成。

目录与展示结构还必须运行 `node scripts/validate-common-sense-knowledge-point-tabs.js --part=law`：每个源文知识点 ID 必须且只能映射一个独立页签，每个页签只能承载一个源文知识点，页签标题必须与知识点标题一致。把多个知识点合并进“六项原则”“四类效力”等总括页签，即使正文没有遗漏，也属于层级还原失败并阻断发布。

### 阅读记忆层（小程序展示）

速记、思维导图、页内导航、卡片和表格移动端布局均从源文完整层生成。每个页面内容块必须反向关联一个或多个源文单元 ID；速记只能导读，不能替代完整内容。

### 学习导读与总结要求

“学习导读”必须是帮助记忆的有效归纳，不得只把原文标题、对象或字段换一种说法再陈述。

1. 先从完整源文中抽出可复用的记忆结构，例如时间线、因果链、分类框架、对照关系、递进顺序或口诀线索。
2. `一句结论` 要说明“怎样串联和回忆本页”，而非罗列“本页包含什么”。
3. 必须按知识点逐项生成学习导读总结。原书小节内每个知识点都必须有一条独立、明确、可回忆的总结，不得只为整个小节提供一段总括性导读。
4. 每条知识点总结必须直接对应其源文知识点 ID，并说明该知识点的核心结论、记忆关系、判断线索或易混边界；仅复述知识点标题视为不合格。
5. `重点卡` 必须覆盖本小节全部知识点，知识点数量与已生成的有效导读总结数量必须一致。跨知识点的时间线、分类框架或总口诀只能作为补充，不能替代任何一个知识点的独立总结。
6. `阅读路线` 按最适合记忆的顺序组织完整内容；不得改变源文事实、制造原文没有的因果，或以导读替代任何一段原文。
7. 导读是独立的阅读记忆层：可归纳、可重排，但必须能追溯至已映射的源文内容；完整内容始终在导读之后可直接查看。
8. `30秒回顾` 是整个小节的全局回顾，必须覆盖该小节全部知识点，并在每个页签下保持同一内容可见；不得绑定第一个页签，也不得拆成互不完整的页签局部回顾。

## 证据与识别规则

1. PDF 原生文本正常时，以原生文本为主，并用页面图像核验标题、粗体、表格与插图。
2. 原生文本乱码或顺序异常时，使用 OCR；OCR 结果须与页面图像及另一份识别证据交叉比对。
3. 识别结果有分歧、表格边界不清或无法确认的文字，一律标为待处理，不以知识库猜测后发布。
4. 知识库仅可用于填空补全、现行规则纠错；不得用于替代缺失的原文段落、案例、表格或图注。

## 硬性校验

每个小节必须满足以下规则，任一失败即阻断发布：

- 每个教材内容单元均有“小程序内容块”去向，或有明确、可审计的非内容排除理由。
- 表格原始行数、列数、逻辑单元格数与展示字段数完全一致；原表存在跨行或跨列合并时，必须记录合并起点及跨度，移动端即使展开为重复字段，也不得丢失原始合并关系。
- 粗体、数字、期限、否定词、条件和例外均保留。
- 源文所有填空补全答案均须进入展示层重点标记；任一补全答案未被重点化即阻断发布，但学习页面不得额外展示处理过程说明。
- 页面正文禁止省略号截断、单行截断、固定高度裁切和不可展开的隐藏内容。
- 拆分、合并或覆盖数据时，源文单元总数与映射关系不得减少；未映射内容禁止静默丢弃。
- OCR 或文本层差异必须清零，或明确标为待处理并不进入正式内容。
- 学习导读须通过“记忆结构有效性”检查：存在明确的串联方式与可回忆线索，且不只是对标题、字段或原文内容的简单改写。
- 学习导读须通过“知识点逐项覆盖”检查：每个源文知识点均有且至少有一条独立导读总结，并保留知识点 ID 映射；任一知识点缺少总结、只有标题复述或被整页总括替代，均阻断发布。
- 知识点内分项须通过“父子层级”检查：凡源文中存在统领后续条目的标题，审计层和展示层都必须记录其子项范围；父标题与子项同级编号、子项范围为空、交叉或越界均阻断发布。
- `30秒回顾` 须通过“全局一致性”检查：内容覆盖整个小节，且切换任一页签时显示内容一致；仅在首个页签显示或随页签变化均阻断发布。

## 执行节奏

每批只处理一个原书小节，批次边界由正式目录层级决定，不由页数、知识点数量或现有卡片划分决定。

小节较长时，可以分页面完成识别和内部复核，但必须等整个小节全部映射并通过验收后再标记完成；不得把“夏”“商”等小节内部知识点作为独立批次或目录入口发布。

批次步骤：

1. 先确认本批在“篇—章—节—小节”中的完整正式路径，再建立该小节的源文完整层与页码清单。
2. 逐段、逐表、逐图映射到阅读记忆层。
3. 运行覆盖率、表格单元格、重点词、截断、学习导读有效性和知识点逐项覆盖校验。
4. 生成验收单；通过后才开始下一小节。

## 每批验收单

仅输出以下简表：PDF 页码与正式目录位置；段落、列表项、表格单元格、粗体、插图的“源数量 / 已映射数量”；OCR 分歧数量；知识库补全项；知识点数量 / 有效学习导读总结数量；每个知识点的导读映射；待处理项。

通过门槛：内容单元覆盖率 100%、表格单元格覆盖率 100%、知识点导读覆盖率 100%、无标题复述型无效导读、无未解释差异、无内容截断。

## 用户验收范围

用户无需逐段校对全文。每批只抽看 1 个普通段落和 1 个复杂表格或插图；仅在验收单出现待处理项时查看对应原页证据。其余完整性责任由映射、计数和差异校验承担。

## 迁移约束

现有内容作为参考版本，不视为源文底稿。重建完成前不得用后续摘要、浅合并覆盖或拆分页签过滤取代已建立的源文映射。
