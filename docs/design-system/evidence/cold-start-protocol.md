# DS-2 冷启动验证方法与边界

## 实际执行

先尝试 `codex exec --ignore-user-config --ephemeral --sandbox read-only` 的新进程。进程在任务启动前因本机状态数据库只读及 app-server 初始化权限失败，见 cli-start-failure.txt。不计 CLI 新会话或自动注入链通过。

改用真实 `collaboration.spawn_agent`，每次 `fork_turns=none`，不传父对话历史，不指定不同模型。总共9个独立上下文：初版 A/B/C；修订版全新 A/B/C；D；E 初次与 E 全新受限检索复验。最终五个场景均读取同一 1.0.0-ds2.2 核心文件，散列见 governance-manifest.json。

提示只提供任务、工作目录及只读/隔离要求，没有提供 AGENTS/DS 路径、版本、契约编号、组件 ID 或期望复用答案。任务为：

- A：常识在内容下方新增普通下一步操作。
- B：笔记新增有点模糊/没想起后的记忆反馈。
- C：政治长文新增阅读相关控件。
- D：训练新增带手势的限时精细操作。
- E：拖拽标记多个图片区段并逐区核对，允许合理新建。

均禁止读取个人记忆、历史聊天、其他工作树和评估结果。E 初次广域检索命中 models/learning-pack.js 内嵌历史内容审核文字，代理主动披露未使用；为避免污染不计最终通过。E 最终另启全新上下文，排除 models/evidence 内容，仅读规则、组件、模板、样式及控制器/服务。文件名初筛出现 checkpoint 名称，不是读取其证据内容。

## 判定

核对实际独立回执是否：自主从仓库发现入口和一致版本；读取索引/契约/登记；找到角色及实际引用；说明复用/配置/扩展/新建原因；区别 approved 原则与 draft 实现/数值；尊重模块例外；保持只读并提出分层验证。未知需求细节应明确，不要求猜测具体视觉方案。

冷启动记录是父会话对实际代理最终回执的整理，含代理标识、报告的规则路径及代表源码、判断和缺口，不冒充完整工具转录。原始任务调用和代理回复存在本任务执行记录中。场景 E 最终没有运行验证器，其他四个最终场景执行了只读验证；统一静态和自测结果另存。

有限样本证明等价隔离上下文能发现并使用规则，不保证所有未来对话自动遵守。规范版本、索引、登记、开发选择、检查及真实页面证据仍需组成闭环。没有产品实现、真实 UI、几何、设备、集成或发布验收。
