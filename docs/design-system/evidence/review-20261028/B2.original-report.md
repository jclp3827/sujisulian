## 源码事实、角色与真实消费者

PAT-MEMORY 是 Pattern，不是可以直接引用的统一组件。其 directConsumers 为空是正确关系，不能解释为“没有该角色”。其 rolePages 与候选 applicablePages 是以下五页：笔记 memory、常识 learning、政治 practice、route、detail。消费者查询仅核验已登记角色证据，不证明动态可达、全部状态或同一实现。

笔记实际自评：

- `miniprogram/subpackages/note/memory/index.wxml:36`：答案可见且非列表时显示四项评价；记住/模糊/没想起受 imagesReady 控制，跳过不受该禁用控制；揭晓前有退出、揭晓、跳过（37）。
- `memory/index.js:23`：非跳过且图片未就绪时拒绝评价并提示；正常路径先保存位置，再 engine.assess，随即 show 当前会话。
- `services/memory-session.js:35`：评价校验当前卡片版本及回忆模式是否揭晓，记录 event、responses、非跳过 ratings，然后 `v.index++`。没有独立的“已自评后停留在本卡”状态。`weak`（11）将 fuzzy/missed 作为弱项并排序；report（39）计算四种计数。新增展示不能改写这些业务事实。
- `memory/index.js:20`：show 根据当前会话重新投影卡片、揭晓、结果和进度；图片异步采用 token/卡片身份保护（21、49–53）；`onShow`（15）重新读取引擎，来源跳转（48）、滚动保存（28–29）由页面负责。当前模板完成态仍显示四种评价统计（wxml:27）。
- `memory/index.json` 只引用 math-formula 与 note-example，没有 knowledge-card-surface。页面依赖 note blocks 与 learning-ui，反馈四按钮仍是页内结构。CSS 的既有白底、中性文字、尺寸、圆角和安全区是当前事实，不是已批准的数值标准。

常识导读：`learning/index.js:314–318` 将结果交给 guideEngine.assess 后渲染；`services/guide-session.js:228–241` 写 assessments、seen、非跳过 records，并 session.index += 1。它与笔记均为自评后自动前进的角色实例，但存储结构/引擎不同，不能合并业务状态。

政治每日练习：`practice/index.wxml:52` 使用 knowledge-card-surface 并设置 skin=politics、reveal-managed、assess-dock、allow-skip、show-reading-return=false；`practice/index.js:211` 分发 assessRecall 或跳过。`politics-practice-engine.js:349–355` 只保存本题 outcome，不推进 index；`advance`（362–384）才管理持久记录、到期与 index。页面 assessed 状态提供下一题，模糊/没想起另提供查看原文（wxml:73–80）。这是停留核对模式，不能从相同评价词推断笔记也应该这样做。

政治 route 的实际角色线索在导入的 guided-route.wxml:105、122 与 guided-route.js:499–500，包含自评事件和不同结果后续动作；detail 的 `index.js:390–405` 更新 recall snapshot 后渲染，并非笔记引擎。只把这些视为角色与实现差异，不补推全部政治运行态。

CMP-KNOWLEDGE-CARD 是真实组件：登记与工程消费者查询均列出政治 detail、route、practice 三页，已读取三页 usingComponents 与模板引用。笔记、常识不是它的直接消费者。该组件接受 card/recallView/displayPreferences/skin/管理开关，管理局部展开并发出 reveal、recallresult、原文和返回等事件；不直接评分、排队或写记忆记录。其 wxml:60–73 有揭晓、评价和“有不确定的地方，可以核对…原文”的展示，但提示受 showReadingReturn 等条件控制；每日练习将该值置 false，因此不能把组件存在提示误报为每日练习当前显示了该文案。

## 选择与影响面

1. 选择复用 PAT-MEMORY 角色语义和 approved 边界，保留笔记当前自动前进、资源门禁、来源与恢复责任。
2. 选择对笔记现有局部展示做最小扩展：若只是已记录评价的短提示，应绑定被评价卡片/会话身份，确认保存成功后展示，不把上一卡结果附到下一卡，也不假装仍停留在原卡。具体文案、颜色、时间和交互尚待对应产品方案；本只读回执不批准或实施它们。
3. 不选择直接配置政治 knowledge-card-surface：其 card/recallView 投影、阅读正文和政治页面管理接口与笔记 blocks/图片/引擎不同；替换会扩大正文、资源、工具栏与恢复影响，超出“新增记忆反馈表现”。现有两类前进模式并存合规。
4. 当前无必要新建全产品公共组件。若后续明确多个真实消费者共享同一展示协议，可扩展公共展示能力，并先核对上述三名直接消费者与五页角色范围；不得把五页全部当作同组件引用。合理笔记专用适配允许按 C 存在，登记与例外须随真正实施更新；本次未新建登记。
5. PAT-FEEDBACK 是收藏筹备/本机内容反馈专用 Pattern，角色不匹配，不因“反馈”词相同复用。
