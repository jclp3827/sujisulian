# 01 试点章程

> 状态：已确认

## 试点目标

以一个全新的政治模块证明以下闭环能够稳定运行：

1. 批量接收 PDF 或图片资料。
2. 在本地生成可追溯、可复核的证据单元。
3. 将审核通过的内容转换为可由 Obsidian 管理的 Markdown。
4. 从 Markdown 自动生成小程序知识包。
5. 在小程序中提供知识地图、体系浏览、知识卡、进度和复习。
6. 内容更新后能够重新审计、重新构建并安全回滚。

## 隔离约束

- 政治模块使用独立的内容目录、模块 ID、运行时数据和页面入口。
- 试点期间不批量转换资料分析、数量关系、判断推理、言语、图形或现有常识内容。
- 不以“顺便统一格式”为理由修改现有知识数据。
- 可以复用稳定的通用组件和工具，但不得让政治试点破坏现有模块行为。
- 若必须修改通用渲染器，应保证旧数据协议继续可用，并执行现有校验。

## 本阶段交付物

### 内容侧

- 原始资料清单和文件哈希。
- 页级证据、内容单元、差异和风险清单。
- 审核记录与未解决问题清单。
- 审核通过的政治 Markdown 知识源。
- 政治模块目录、关系、卡片和来源映射。

### 工程侧

- 可重复运行的本地提取命令。
- 内容协议校验和发布门禁。
- Markdown 到小程序数据的确定性构建。
- 政治模块页面及必要的通用展示组件。
- 本地进度和卡片复习数据。
- 构建报告、版本信息和回滚产物。

## 明确不做

- 不做全库迁移。
- 不做自适应学习算法。
- 不用浏览次数伪造掌握度。
- 不建设完整题库或模拟考试。
- 不建设在线多人 CMS、权限系统和审批后台。
- 不依赖社区插件完成发布。
- 不追求任意 Markdown 或任意 Obsidian 语法兼容。
- 不把全局自由力知识图作为主要移动端入口。

## 成功标准

### 内容可信

- 每个正式内容块均有有效 `source_units`。
- 高风险内容已经人工确认。
- 未解决 OCR 差异为 0，或对应内容明确处于阻断状态且未发布。
- 表格、公式、数字、否定词、条件和例外通过专项检查。
- 相同输入和工具版本重复构建，正式输出一致。

### 内容运营

- 新增一个知识点不需要修改小程序页面代码。
- Obsidian 关闭或未安装时仍能完成校验和构建。
- 能从运营视图找到草稿、待审、缺来源、缺卡片和待发布内容。
- 修改原始资料后，受影响的审核状态能够失效并重新进入队列。

### 用户展示

- 用户能从全局层进入政治模块并逐级浏览。
- 用户能在模块地图、目录和搜索之间找到同一知识点。
- 知识卡是可主动回忆的小单元，不是截短的详情页。
- 阅读、收藏和复习状态互不混淆。
- 手机窄屏下地图、表格和长内容均可使用。

### 发布安全

- 所有硬门禁通过后才生成可发布版本。
- 每次发布都有知识包版本、来源版本和构建报告。
- 能恢复到上一个通过验收的政治知识包。
- 发布和回滚不要求修改现有知识模块。

## 迁移决策门槛

只有政治模块完整上线并完成一次内容更新演练后，才评估现有模块迁移。评估至少回答：

1. 每页和每个知识点需要多少人工审核。
2. 哪些错误能自动发现，哪些仍需人工。
3. Markdown 编辑是否比现有 JSON/JS 录入更稳定。
4. 构建和回滚是否足够简单。
5. 地图、卡片和复习是否产生真实使用价值。
6. 迁移旧模块是否能减少长期维护成本，而不只是统一形式。
