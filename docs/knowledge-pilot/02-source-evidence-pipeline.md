# 02 源文证据流水线

> 状态：通用规则已确认；具体工具参数待政治资料到位后用样本校准

## 目标

把 PDF 或图片转换为可追溯的证据单元，而不是直接生成看似流畅的 Markdown。任何正式文字、表格、公式和插图都能返回原始文件、页码和页面区域。

## 数据阶段

建议的逻辑目录如下，实际路径在试点初始化时确定：

```text
sources/      不可修改的原始 PDF、图片和来源清单
evidence/     页面图、文本层、OCR、版面、裁图和差异
drafts/       自动生成但未审核的 Markdown
knowledge/    审核通过的正式 Markdown，作为 Obsidian Vault
dist/         自动生成的小程序运行时数据
```

规则：

- `sources` 只增不改；文件内容变化必须成为新版本。
- `evidence` 和 `dist` 由工具生成，不人工直接编辑。
- `drafts` 永远不可发布。
- `knowledge` 只接收完成来源映射和审核的内容。

## 步骤 1：资料接收

每份资料建立清单：

```json
{
  "sourceId": "politics-source-001",
  "file": "政治资料.pdf",
  "sha256": "...",
  "sourceUrl": "",
  "acquiredAt": "2026-08-27",
  "pageCount": 0,
  "hasNativeText": false,
  "status": "received"
}
```

必须确认：

- 文件是否完整、是否缺页、是否重复。
- 页面方向、清晰度和分辨率是否异常。
- 是否存在文本层、扫描页、混合页或密码保护。
- 是否有不同版本、答案版、勘误版或配套图片。
- 来源是否允许内部加工和面向用户展示。

## 步骤 2：页级提取

每页统一生成：

- 高清页面图。
- PDF 原生文本和字符坐标（若存在）。
- 版面区域：标题、段落、列表、表格、公式、图片、页眉页脚。
- 第一 OCR 结果及逐行坐标和置信度。
- 必要时的第二 OCR/结构模型结果。
- 页面风险标签。

不得只在“完全没有文字”时运行 OCR。建议策略：

- 正常文本 PDF：原生文本与一套 OCR 全页比对。
- 图片扫描件：两套独立 OCR 全页比对。
- 表格、公式、多栏、低清晰度页面：强制结构识别并进入专项审核。
- OCR 只提供证据候选，不自动覆盖原生文本。

工具和模型必须锁定版本；升级后先对固定样本回归，不直接重建正式内容。

## 步骤 3：证据单元切分

按语义和版面切成标题、段落、列表项、表格单元格、公式、图片和图注。推荐字段：

```json
{
  "id": "politics-s001-p003-u012",
  "sourceId": "politics-source-001",
  "page": 3,
  "order": 12,
  "type": "paragraph",
  "bbox": [0, 0, 0, 0],
  "nativeText": "",
  "ocrTextA": "",
  "ocrTextB": "",
  "resolvedText": "",
  "riskFlags": [],
  "reviewStatus": "pending",
  "crop": ""
}
```

表格还必须保存：

- 行数、列数和逻辑单元格数。
- 单元格坐标、阅读顺序和合并关系。
- 每个单元格对应的文字证据。

公式还必须保留原图裁片，不能只保存 OCR 或模型生成的表达式。

## 步骤 4：差异检测

至少检测：

- 文本层与 OCR 字符差异。
- 两套 OCR 之间的差异。
- 阅读顺序、段落边界和跨栏串行。
- 数字、百分比、年份、序号和单位。
- “不、未、除外、仅、应当、可以”等规则性词语。
- 人名、地名、机构名、会议名、文件名和政治术语。
- 表格行列缺失、串格和合并关系变化。
- 标题层级跳跃、页间段落断裂和重复。
- 图片或图注未归属、误把水印当正文。

页面平均置信度只能作为参考，不能代替单元级差异和风险判断。

## 步骤 5：草稿生成

草稿 Markdown 从证据单元生成，并保留来源引用。草稿可以进行：

- 标题层级恢复。
- 段落和列表组合。
- 表格重建。
- 填空候选和明显断行建议。
- 知识点边界建议。

草稿不得进行：

- 无记录地改写原文。
- 用常识补足缺失段落。
- 自动把 OCR 猜测升级为已审核事实。
- 自动删除重复或疑似无关内容。
- 直接进入小程序运行时。

## 本地审核视图

第一阶段不建设在线审核后台，生成一个可在本地打开的最小审核视图即可。每个待审核单元同时显示：

- 原始页面局部裁图及页码。
- 原生文本、第一 OCR 和第二 OCR。
- 字符差异和风险标签。
- 上下相邻内容，避免脱离语境判断。
- 采用候选、手动修正、排除和待处理操作。

审核决定写入独立记录，不直接覆盖页面证据。审核视图必须支持只查看：

- 未解决差异。
- 高风险单元。
- 表格、公式和图片。
- 抽样单元。

这样人工工作集中在风险区域，而不是逐页重新抄录全文。

## AI 使用边界

AI可以：

- 推荐阅读顺序、目录层级和内容单元类型。
- 解释差异并提出采用哪份证据的建议。
- 标记疑似错字、重复、过期或逻辑冲突。
- 为审核通过的原文生成卡片和关系候选。

AI不可以：

- 覆盖原始证据。
- 自行确认高风险事实。
- 在无来源单元时补造正式正文。
- 以语言更流畅为由静默改变事实。

## 完成条件

源文证据阶段完成需要同时满足：

- 每页均有页面图和提取记录。
- 每个正文区域均成为证据单元或有明确排除理由。
- 所有差异均已分类。
- 高风险内容已进入审核队列。
- 草稿中的每段内容均能追溯到证据单元。
