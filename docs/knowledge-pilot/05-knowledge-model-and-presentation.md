# 05 知识模型与展现

> 状态：第一阶段产品形态已确认

## 产品定位

政治试点首先建设“用户主动探索的结构化知识平台”，而不是强任务学习课程。知识卡是记忆组件，知识地图和体系浏览是主要承载方式。

## 知识层级

实际名称和深度以政治资料正式目录为准，通用模型为：

```text
模块 → 目录层级 → 知识点 → 内容块 / 速记卡
```

原则：

- 目录表达正式知识体系。
- 关系表达跨目录联系。
- 运营标签表达内容状态。
- 三者不能互相替代。

“高频、待审核、缺卡片”属于运营标签，不应成为正式目录节点。

## 三层知识地图

### 全局地图

展示小程序已有模块和新政治模块的聚合入口，不展开全部知识点。

目标：让用户知道整个知识体系有哪些部分，并能进入目标模块。

### 政治模块地图

展示政治模块的正式目录和学习分支。节点可显示知识点数量和阅读进度。

目标：支持用户主动选择主题、理解模块结构和继续上次位置。

### 局部关系图

围绕当前知识点只展示一层或受控深度：

- 前置知识。
- 易混知识。
- 明确相关知识。

目标：解释“这个知识点与什么有关”，不是展示所有链接。

## 移动端地图原则

- 默认采用可展开树、分层分支或横向路径，不照搬桌面自由力图。
- 首屏节点数量受控，用户下钻后再加载细节。
- 每种连线含义明确，并有图例。
- 点击节点必须进入内容或下一层，不能只有缩放观看。
- 长标题可换行，不能依靠悬浮提示。
- 地图不可用时，目录列表提供等价导航。

## 三种内容入口

### 知识地图

回答“整个体系是什么、这个知识在哪里”。

### 知识体系

回答“我想完整、连续地查看这个主题”。复用统一详情渲染，支持段落、列表、表格、图片、时间线、对比、提示和局部导图。

### 速记卡

回答“我能不能从提示中回忆起一个小知识”。支持按模块浏览、收藏和到期复习，并能返回完整知识点。

## 知识点详情结构

建议顺序：

1. 标题、所属路径和一句话理解。
2. 当前知识点的局部关系。
3. 完整内容。
4. 易混与边界。
5. 速记卡入口。
6. 前置、相关和下一知识导航。
7. 来源版本与更新时间（需要时展示）。

内容较长时使用页内导航或合理分段，但不得为了卡片化截断事实条件。

## 通用展示类型

第一阶段优先复用或补齐这些通用形态：

- 概念说明。
- 层级列表。
- 时间线。
- 对比卡。
- 表格及移动端卡片化表格。
- 规则与例外。
- 人物、会议、文件映射。
- 思维导图。
- 图片与图注。
- 速记问答卡。

遇到新内容时，先判断能否使用已有形态；只有多个知识点确实共享同一种新语义，才增加新的通用 block 类型。

## 完整性与记忆层分离

- 完整内容忠实承载事实和条件。
- 一句话理解、导图和卡片可以重组信息以帮助理解和记忆。
- 记忆层必须引用完整内容对应的来源单元。
- 记忆层不能取代完整内容，也不能制造来源中不存在的因果或结论。

## 关系生成

关系处理顺序：

1. 从目录和显式链接生成候选。
2. 根据标题、术语和正文相似度提出补充候选。
3. 人工确认关系类型和必要性。
4. 构建正向与反向索引。
5. 生成模块地图和局部关系图。

不能因为两个知识点共享标签就自动建立正式关系。

## 第一阶段验收

- 全局地图不会因知识点增加变成不可读的节点团。
- 模块地图和目录能到达同一知识点。
- 局部图关系数量受控且含义明确。
- 完整内容和速记卡均能追溯来源。
- 卡片不是详情页的机械截断。
- 新增知识点后无需修改专用页面代码。
