# 06 轻量学习流

> 状态：第一阶段已确认；题目验证与自适应学习明确后置

## 目标

在尊重用户主动选择的前提下，提供轻量的连续性和复习辅助：用户知道看过什么、可以继续上次内容、可以收藏并复习知识卡。

## 第一阶段能力

- 最近浏览。
- 继续学习。
- 已读标记。
- 收藏。
- 模块阅读进度。
- 速记卡自评复习。
- 今日待复习卡片。

不做：

- 强制每日任务。
- AI 个性化路径。
- 基于浏览行为推断掌握度。
- 排行、连续打卡和复杂激励体系。
- 没有题目依据的能力评分。

## 状态分离

### 阅读状态

```text
unread → reading → read
```

只表达用户是否浏览和主动确认完成，不表达会不会。

### 个人状态

```text
favorite: true / false
```

收藏与已读无关。

### 复习状态

```text
new → due → reviewed → due
```

只表达卡片是否进入复习和何时再次出现。

在没有题目验证前，界面使用“已读、待复习、记得程度”，不使用“已掌握、掌握率”。

## 卡片复习交互

1. 显示提示，不显示答案。
2. 用户先主动回忆。
3. 用户点击显示答案和易错边界。
4. 用户选择自评：

   - 没想起来。
   - 有点模糊。
   - 基本记得。
   - 很熟悉。

5. 根据自评安排下次复习。

第一版规则保持简单：

| 自评 | 建议下次出现 |
|---|---|
| 没想起来 | 当天稍后 |
| 有点模糊 | 1 天后 |
| 基本记得 | 3 天后 |
| 很熟悉 | 7 天后 |

后续可以根据真实使用调整，但试点不实现复杂间隔算法。

## 首页轻量入口

政治模块上线后可提供：

- 继续上次浏览。
- 今日待复习卡片数量。
- 最近浏览。
- 我的收藏。
- 政治知识地图入口。
- 最近新增或更新的政治知识。

这些入口帮助继续，不替用户规定必须学习的路线。

## 模块进度

模块页可以显示：

- 已读知识点数 / 总知识点数。
- 各目录已读数量。
- 上次浏览位置。
- 已加入复习的卡片数。

不得把页面停留时间、滚动到底或打开次数直接换算成掌握百分比。`read` 建议由用户主动标记，或在完成明确阅读动作后由用户确认。

## 本地数据建议

第一阶段用户量少，进度优先保存在本地，数据按稳定知识 ID 记录：

```js
{
  pointId: "politics-example-point",
  readStatus: "read",
  favorite: true,
  lastViewedAt: 0,
  review: {
    dueAt: 0,
    count: 2,
    selfRating: "fuzzy"
  }
}
```

约束：

- 内容改名不影响进度。
- 删除或合并知识点时提供 ID 迁移。
- 本地数据损坏不能阻止知识内容打开。
- 尚未提供账号同步时，应接受清理小程序数据可能丢失进度的限制。

## 未来加入题目后的升级

题目准备好后，另行增加：

```text
已阅读 → 能回忆 → 基础题正确 → 变式题正确 → 延迟验证 → 稳定掌握
```

届时自评只作为参考，掌握状态由实际答题和延迟复习共同决定。该升级不应改变知识源和卡片协议，只扩展用户学习记录。

## 验收指标

试点优先观察：

- 地图到知识详情的到达率。
- 用户主动标记已读的比例。
- 收藏和加入复习的比例。
- 到期卡片复习完成率。
- 卡片返回完整知识详情的比例。
- 次日继续浏览或复习的比例。

用户量少时这些指标用于发现明显障碍，不据此训练自适应模型或做伪精确结论。
