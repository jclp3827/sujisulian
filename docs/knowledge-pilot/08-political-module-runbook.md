# 08 政治模块执行手册

## 启动前不做的假设

资料已提供（政治理论 / 政治理论.pdf），因此以下项从首批样本中补决：

- 政治模块正式目录层级。
- 原始资料的权威性和时效范围。
- 总页数、扫描质量和表格比例。
- 一个详情页对应章、节、小节还是知识点。
- 首批上线覆盖范围。
- 是否需要现行政策或官方文件校对层。
- 最适合政治内容的地图和卡片类型。

这些决定必须根据真实资料样本产生。

## P0：资料接收与范围冻结

输入：用户提供的政治 PDF、图片、补充来源或说明。

执行：

- 建立来源清单、哈希和页数。
- 识别资料版本、目录、答案版和勘误版。
- 检查授权、时效和官方校对需要。
- 选择能代表普通段落、表格、图片、复杂版面和高风险表述的样本页。
- 确定首个可完整验收的正式目录单元。

产物：

- 政治来源清单。
- 资料质量报告：见 [09-political-intake-log](./09-political-intake-log.md)。
- 样本页清单。
- 首批边界和排除项。

退出条件：资料完整，试点范围明确且没有依赖现有模块内容。

## P2A：首批完整审计

依据：[03-审计与质量门禁](./03-audit-quality-gates.md)。

退出条件：首批内容通过来源、OCR、版面和事实校对门禁。

## P3：知识展现

依据：[05-知识模型与展现](./05-knowledge-model-and-presentation.md)。

执行：

- 建立政治模块入口和分层地图。
- 建立目录浏览和知识详情。
- 建立局部关系和速记卡。
- 对表格、时间线、人物/会议/文件关系选择通用展示形态。
- 在手机窄屏完成视觉走查。

当前进展（2026-08-27）：已使用 6 篇审核通过的正式知识建立“政治理论”第四主导航 Tab，并按 [11-政治知识展现 Demo 契约](./11-political-presentation-demo-contract.md) 串联体系理解、完整阅读、关系探索和主动回忆。政治首页提供目录、地图和速记入口；地图节点先显示摘要预览，再进入阅读、一层局部关系或速记；详情支持阅读/速记切换、上一篇/下一篇及地图定位。构建器根据正式 Markdown 和前置关系生成运行时包，页面不保存内容副本，也不记录掌握状态。搜索、代表性复杂内容块、其他窄屏规格走查与最终 UI 验收仍待后续批次完成。

退出条件：地图、目录、搜索和卡片可到达同一正式知识点，完整内容无截断。

## P4：轻量学习流

依据：[06-轻量学习流](./06-learning-experience-v1.md)。

执行：

- 保存最近浏览、阅读状态和收藏。
- 显示政治模块阅读进度。
- 建立卡片正反面和自评复习。

- 验证内容版本变化后的进度兼容。

退出条件：阅读、收藏和复习状态清晰分离；不展示无依据的掌握度。

## P5：端到端发布演练

依据：[07-构建发布与维护](./07-build-release-operations.md)。

执行：

- 从原始来源重新运行整条链路。
- 执行全部自动门禁和人工验收。
- 生成政治知识包、构建报告和版本说明。
- 在微信开发者工具完成核心路径走查。
- 演练回滚到上一预览版本。

退出条件：正式发布包可重复生成，回滚有效，现有模块校验和行为未受影响。

## P6：更新演练与复盘

至少模拟一次资料更正或新增：

- 加入一个新来源版本或修改样本页。
- 验证来源哈希使相关审核失效。
- 重新审核受影响单元。
- 生成内容差异和新知识包。
- 验证未受影响内容保持稳定。

复盘记录：

- 自动处理比例和人工审核负担。
- OCR 漏错类型和规则补充。
- Markdown 编辑效率。
- 地图、详情和卡片使用问题。
- 本地进度与版本兼容问题。
- 是否具备迁移现有模块的收益。

## 试点结束后的决定

只允许三种结论：

1. **通过**：流程可靠，开始制定现有模块迁移顺序。
2. **有限通过**：政治模块继续使用，但暂不迁移旧模块，并修复明确瓶颈。
3. **不通过**：保留有效工具和内容，停止扩大范围，不为统一形式继续投入。
