# 10 Obsidian 与构建器接入时序

> 状态：已确认；Obsidian 1.13.7 已安装，正式 Vault 与 Bases 已完成首次打开验证

## 目的

明确 Obsidian 在哪一阶段介入、正式知识怎样进入 Vault，以及独立构建器何时从协议校验扩展到小程序知识包生成。

Obsidian 是正式知识的本地编辑与运营界面；构建器是从正式 Markdown 到小程序运行时数据的唯一转换入口。两者互不依赖。

## 阶段划分

| 阶段 | 内容 | 状态或退出条件 |
|---|---|---|
| P2B-1 源稿生成与清洗 | 从审核文本生成知识点源稿，清除广告和结构噪声 | 25 篇源稿已完成 |
| P2B-2 加工、审核与结构化 | 全量生成成形候选；核对证据，确定知识粒度、边界、卡片和关系 | 候选进入 `review`；单篇通过后进入 `approved` |
| P2B-3 Obsidian 试运营 | 将成形候选和审核通过的 Markdown 放入 `knowledge/` Vault | Bases 可按状态运营，关闭 Obsidian 仍可读取 |
| P2B-4 校验与预览构建 | 校验协议、链接和状态，生成最小预览知识包 | 真实样本可重复构建且无错误 |
| P3 知识展现 | 使用预览知识包开发目录、地图、详情和卡片 | 数据契约经真实页面验证 |
| P5 前完整构建 | 增加搜索、反向关系、版本、发布报告和回滚产物 | 满足完整发布门禁 |

P2B-2、P2B-3 和 P2B-4 采用小批量流水方式推进，不等待 25 篇全部完成后才验证工具链。首批以 3–5 篇低风险且能验证关系的知识点为宜；复杂版面样本在专项人工核验后加入。

## 正式知识准入

文件从 `review` 升为 `approved` 前必须同时满足：

- 来源页已对照页面图或更高等级证据核验。
- 不命中尚未关闭的表格、插图、阅读顺序或 OCR 风险。
- 知识点粒度可独立进入详情页。
- `一句话理解`、`易混与边界` 和至少一张首批验证卡片不含占位内容。
- 关系只指向已进入 Vault 的正式知识；候选关系不写成正式链接。
- 状态、版本、审核日期、来源单元和来源哈希完整。

已经完成摘要、正文清洗、边界和卡片加工但尚未满足准入条件的文件可以 `status: review` 进入知识目录；必须保留来源页、风险页和审核状态。它们只进入隔离校对包，不进入默认运行包。

## Obsidian 最小配置

第一阶段只使用：

- Markdown 与 YAML Properties。
- 内部链接和反向链接。
- 官方 Bases 核心功能。

不安装社区插件，不开发 Obsidian 插件，不把 `.base` 文件作为正式数据源。Obsidian 自动修改文件后仍须运行独立校验器。

## 构建器演进

### 第一步：协议校验器

首批正式文件产生时立即建立，检查：

- 必填属性、合法状态和唯一 ID。
- 标题与固定正文结构。
- 来源单元和来源哈希。
- 已批准内容中的占位文字。
- 前置、易混和相关链接是否能解析。

### 第二步：预览构建器

首批 3–5 篇通过校验后生成最小预览包：模块信息、目录、知识点正文、关系、卡片和内容版本。该产物用于 P3 页面开发，不代表正式发布包。

当前命令：

```text
node scripts/build-politics-knowledge.js --check-only
node scripts/build-politics-knowledge.js --scope review
node scripts/build-politics-knowledge.js
```

### 第三步：完整构建器

P3 用真实页面验证数据契约后，再加入反向关系、地图、搜索、卡片索引、发布版本、构建报告和回滚信息。没有真实消费方的字段不提前加入。

## 单向写入规则

```text
正式 Markdown → 校验 → 预览/发布知识包 → 小程序
```

- 构建器不得依赖正在运行的 Obsidian。
- 构建器不得反向改写正式 Markdown。
- 不直接编辑 `dist` 修复内容。
- 构建失败时回到 Markdown 或更上游证据修复。
