# 11 政治知识展现 Demo 契约

> 状态：已确认；P3 Demo 的执行、维护和验收基线

## 产品判断

政治模块采用“Obsidian 的知识骨架 + 移动端学习交互”：不复制无限画布，也不把知识机械切成背诵条目。所有入口围绕同一个稳定知识点 ID，串联四种活动：

```text
体系理解 → 完整阅读 → 关系探索 → 主动回忆
    ↑________________________________↓
```

目录、地图、搜索和卡片只能改变进入方式，不得产生不同版本的知识正文。

## 两类地图

- **体系地图**只表达“模块 → 正式目录 → 知识点”和前置深度，支持分级展开、节点摘要及返回原位置。
- **局部关系图**只展示当前知识点一层内的前置、易混、相关和后续知识。
- 目录、关系、运营标签和学习状态不得混成同一种节点或连线。
- 手机端以受控节点、文字关系和渐进展开为主；拖动、缩放不能成为唯一操作方式。

## Demo 页面契约

### 政治首页

- 提供目录浏览、知识地图和速记卡三个真实入口。
- 目录按正式层级列出知识点，摘要只用于识别，不替代正文。

### 体系地图

- 首屏展示目录节点和受控数量的知识节点。
- 点击节点先显示摘要预览，不立即离开地图。
- 摘要预览提供“阅读全文、查看关系、开始速记”。
- 关系视图可继续选择相邻节点，并能返回体系视图。

### 知识详情

- 阅读模式依次展示路径与位置、一句话理解、局部关系、完整内容、易混边界和来源版本。
- 速记模式展示提示、答案和易错边界，不通过随机遮挡正文制造卡片。
- 固定提供上一篇、地图定位、下一篇；阅读与速记共享同一知识点。

## 展示语义

第一批通用内容块为标题、段落、列表、摘要、关系、易混和速记卡。后续只有在审核通过的真实知识出现共同需要时，才增加表格、时间线、对比、规则与例外、人物/会议/文件映射、图片与图注。

Obsidian 的 Outline、Callout、Local Graph、Backlinks、Canvas、Page Preview 和 Bases 只作为结构与交互参考。社区插件可以辅助编辑或验证，但插件输出、`.base`、`.canvas` 和运行中的 Obsidian 均不得成为小程序依赖。

## 数据、维护与更新

```text
正式 Markdown → 独立校验/构建器 → 政治运行时包 → 通用页面
```

- 正文、摘要、关系、卡片、来源和版本只在正式 Markdown 修正。
- 构建器负责解析、校验链接、生成正反关系及导航顺序；页面不得保存内容副本。
- 新知识通过协议后重新构建即可出现，不能为单篇知识修改专用页面。
- 内容变更保持知识点 ID 稳定；拆分或合并时另行提供 ID 迁移。

## 实时纠错

发现问题时记录知识点 ID、页面位置、问题类型和建议；先回到来源证据核验，再修改正式 Markdown、提升版本并重建。不得直接编辑生成包或在页面代码中覆盖错误内容。高风险或证据未闭环内容维持阻断状态，不进入正式包。

## Demo 验收

- 6 篇审核知识均能从目录和体系地图到达同一详情页。
- 地图节点可预览，并能进入阅读、关系和速记模式。
- 详情可前后连续导航，也能返回地图定位当前知识。
- 局部关系类型明确且只展示一层；不存在的关系不造假。
- 速记卡可揭晓答案并返回完整内容。
- 关闭 Obsidian 后仍可构建和运行；现有知识模块行为不变。

## 后续边界

P3 后续补搜索、代表性复杂内容块和更多窄屏走查。最近浏览、收藏、已读、进度、自评和到期复习属于 P4，不在本 Demo 中伪造状态。
