## 一句话结论

V2 不再把目录、导图、详情和卡片做成互相割裂的页面，而是建立一个“知识焦点工作台”：用户始终围绕同一个知识点，在**体系理解、完整阅读、关系探索、主动回忆**四种活动间可逆切换，位置、上下文和来源不丢失。

- **V2-1**：详情升级为统一知识焦点；体系、阅读、关系、回忆四种活动原地切换，前后导航、深链、来源与探索返回路径共享同一 `pointId`。
- **V2-2**：体系地图完成总览、目录分支和节点焦点三级展开，提供节点预览、总览和回到当前控制，不要求用户依赖拖动缩放。
- **V2-3**：关系视图展示类型、理由、反向关系和一层探索；阅读视图提供速览、页内提纲、语义块、辨析及可展开证据层，未知块保持正文降级。

- **联调结果**：微信开发者工具 Stable 2.02.2608040 在 iPhone 12/13 与 320px iPhone 5 模拟器走通首页、搜索、阅读、纠错面板、地图遮蔽和揭晓；运行错误为 0。警告仅为开发者工具基础库、预加载、热重载和不支持的实时上报提示。

```text
目录 / 搜索 / 体系地图 / 速记卡
                ↓
           当前知识焦点
      ┌────────┼────────┐

      └────────┴────────┘
                ↓
        下一知识点或返回原路径
```

## 1. 不可破坏的边界

1. 一个稳定知识点 ID 对应一份正式 Markdown；所有形态只是同一内容的不同视图，页面不得保存正文副本。
2. 运行时继续是“正式 Markdown → 独立构建器 → 小程序数据包”；不依赖 Obsidian、社区插件、`.base` 或 `.canvas`。
3. Obsidian 只提供可借鉴的知识组织思想：Outline、Callout、Backlinks、Local Graph、Canvas、Page Preview 和 Bases；小程序按移动端重构交互。
4. 体系地图表达目录与前置深度，局部关系图表达一层语义关系，两者不得混成自由力图。
5. 完整阅读承载事实，摘要、图谱和卡片帮助理解与记忆，不能替代或改写来源事实。
6. P3 不用“已掌握”制造虚假进度；收藏、已读、复习计划、自评和到期复习仍属于 P4。
7. 新政治模块保持路由、数据和样式隔离，不修改现有两个知识模块的行为。

## 2. V2 的统一体验

### 2.1 当前知识焦点

任何入口先确定 `pointId`，再携带入口、目录路径、地图展开状态和相邻顺序进入焦点工作台。工作台顶部固定显示标题、路径和当前位置，主体在四种活动间切换：

| 活动 | 回答的问题 | 核心形态 | 切换后保留 |
|---|---|---|---|
| 体系理解 | 它在整个体系哪里 | 语义缩放的分层地图、上级路径、相邻节点 | 展开层级、当前节点、视窗位置 |
| 完整阅读 | 它到底讲了什么 | 提要、语义内容块、完整证据、页内提纲 | 阅读位置、当前内容锚点 |
| 关系探索 | 它为什么与其他知识有关 | 一层局部关系、关系类型、关系理由 | 中心节点、探索路径 |
| 主动回忆 | 我能否从提示恢复关键内容 | 问答、易混辨析；后续按证据增加其他题型 | 当前卡、揭晓状态、返回位置 |

入口改变发现方式，不改变内容本体。用户从地图进入阅读、从阅读查看关系、从关系切到相邻知识或从卡片回看原文时，都能返回原来的上下文。

### 2.2 页面链路

- **政治首页**：继续作为模块入口，提供目录、体系地图、搜索和速记；首屏说明“从哪里开始”和当前样本范围。
- **知识焦点页**：V2 的主要容器，统一四种活动、上一篇/下一篇和返回原入口。
- **节点预览层**：地图点击节点后先显示摘要、路径和可用关系，再由用户选择阅读、关系或回忆。
- **搜索结果页**：结果不仅显示命中位置，还显示所属路径和一层关系数量，可直接进入体系、阅读或关系。

## 3. 可借鉴但需移动化重构的展示形态

### 3.1 体系地图：从长截图变成语义缩放

竞品的整张思维导图“笨拙但实用”，价值在于完整结构可见；问题是手机上文字过小、只能拖放缩放、节点不可操作。V2 采用渐进式语义缩放：

1. **总览层**：只显示模块、目录分支和知识点数量。
2. **分支层**：点击目录展开一层知识点，其他分支收束但保留位置感。
3. **焦点层**：选中知识点后显示摘要、前置/后续提示和三种行动。
4. **定位控制**：提供“适应屏幕、回到当前、返回上级”，双指缩放是增强操作而非唯一操作。

节点使用可读的自适应卡片，不依赖悬浮；长标题允许换行。地图不可用或用户不愿操作时，目录列表提供完全等价的路径。

### 3.2 局部关系图：解释关系，不展示线团

- 以当前知识点为中心，只显示一层、受控数量的前置、后续、相关和易混节点。
- 每条关系同时显示类型和简短理由，例如“先理解 A，才能判断 B 的适用条件”。
- 点击相邻节点先预览；确认切换中心后记入探索路径，可逐步返回。
- 正向关系由 Markdown 明确表达，反向关系由构建器派生；不能因标签相同就自动确认为正式关系。

### 3.3 阅读工作台：同页三层信息密度

阅读不是把 Markdown 原样堆在卡片中，而是在同一页提供三层：

1. **速览层**：一句话理解、核心结论、当前位置。
2. **理解层**：按语义渲染定义、条件、层级、对比、易混、例外、时间线等内容块。
3. **证据层**：完整正文、来源单元、版本和更新时间，默认不抢占阅读注意力但随时可核对。

长内容提供页内提纲、内容锚点和专注阅读；字号与密度可调，但不改变知识结构。内容块的推荐语义和颜色如下：

| 语义 | 推荐形态 | 颜色含义 |
|---|---|---|
| 定义、核心结论 | 定义块、重点句 | 蓝：理解与阅读 |
| 层级、组成、步骤 | 分层列表、路径图 | 绿：体系与前置 |
| 易混、边界、例外 | 对比块、警示块 | 橙：辨析与风险 |
| 提示、问答、回忆 | 速记卡、遮蔽块 | 紫：主动回忆 |
| 来源、版本、证据 | 来源折叠块 | 灰：证据与维护 |

正式知识出现共同需要后，再逐步启用表格的移动卡片化、时间线、人物/会议/文件映射、图片与图注；未知内容块必须降级为可读正文，不能整页失败。

### 3.4 主动回忆：按知识语义出题

- V2 第一批保留已审核的问答卡和易混辨析，不用随机挖空正文。
- 当 Markdown 有明确结构与证据时，可增加顺序恢复、成组对比和“地图节点遮蔽”。
- 地图遮蔽只隐藏节点标签或关键关系，让用户在原体系位置回忆；揭晓后可立即回到完整阅读核对。
- 每张卡必须关联 `pointId`、内容锚点和来源单元；无法追溯的卡片不进入运行包。

## 4. 构建与数据契约增量

V2 不建立第二套内容源，只扩展构建产物。建议将运行时包升级为显式 `schemaVersion`，并保持 V1 字段兼容。

| 增量 | 来源或生成方式 | 用途 |
|---|---|---|
| `blocks[].id/type` | Markdown 标题与语义标记 | 阅读锚点、纠错定位和通用渲染 |
| `relationItems[].type/targetId/why` | Markdown 显式关系；说明可显式维护，缺失时由构建器生成不扩展事实的类型说明并标记 `derived` | 局部图和关系解释；保留 V1 `relations` 字段兼容 |
| `reverseRelations` | 构建器派生 | 反向链接，不重复维护 |
| `outline/navigationOrder` | 目录与正文结构派生 | 地图层级、提纲、前后导航 |
| `entities/aliases` | 审核后的显式字段 | 人物/会议/文件映射与搜索 |
| `viewHints` | 可选、审核后的展示提示 | 对比、时间线等语义渲染；缺失时正常降级 |
| `searchIndex/cardIndex` | 构建器派生 | 搜索定位和主动回忆入口 |
| `sourceUnits/version` | 现有证据字段延伸 | 证据核对、变更影响和纠错 |

构建门禁必须验证：ID 唯一、内部链接存在、关系类型合法、显式关系说明格式合法、卡片可追溯、锚点稳定、正式状态合格、生成结果可重复。页面只消费构建包，不自行确认新的知识关系；派生说明只能复述已审核的关系类型，后续可回到 Markdown 补充更具体的人工说明。

## 5. 实时纠错与持续更新

纠错入口记录 `pointId + version + blockId + 来源入口 + 问题类型 + 用户描述`，形成可定位的问题单。处理链路固定为：

```text
发现问题 → 回查来源证据 → 修正正式 Markdown → 提升版本
        → 重新校验和构建 → 查看结构化差异 → 回归受影响视图 → 发布
```

- 不直接修生成 JSON、运行时模型或页面文案。
- 内容事实、关系理由和卡片答案都回到 Markdown 修正；构建逻辑问题修构建器；纯表现问题修通用组件。
- 构建报告列出新增、删除、版本变化、断链、受影响关系、卡片和搜索索引。
- 高风险或证据不完整的知识继续被发布门禁阻断；修正后仍沿用稳定 ID，拆分/合并才登记迁移映射。

当前 Demo 使用存储键 `politics-correction-queue-v1`，状态固定为 `local-pending`。记录只保存在当前设备，不自动上传、不直接修改 Markdown，也不宣称已经提交；“复制记录”导出 JSON 后才进入人工维护流程。维护者处理时必须先回查 `sourceFile/sourceUnits`，再修改正式 Markdown，禁止反向编辑生成 JSON。

固定维护命令：

```bash
node scripts/build-politics-knowledge.js --check-only
node scripts/diff-politics-knowledge.js
node scripts/validate-politics-presentation.js
```

第一条校验正式知识，第二条默认比较 `HEAD` 中的上一构建包和当前构建包，第三条回归 schema、搜索、四活动、地图遮蔽与本地纠错协议。需要生成新运行包时执行 `node scripts/build-politics-knowledge.js`，随后重复三项门禁。

## 7. 回归矩阵

每阶段至少检查以下场景：

- 目录、体系地图、搜索和卡片进入的是同一 `pointId` 与同一正文。
- 首篇、末篇、无关系、单向关系、长标题、长正文、缺少可选块均能正常展示。
- 地图分支展开、节点预览、关系跳转、阅读滚动和返回路径均可恢复。
- 直接链接打开焦点页时有合理默认上下文，不依赖上一页内存。
- 旧 `schemaVersion` 和未知 block 有明确降级；生成两次结果一致。
- 断链、非法关系、无来源卡片、未审核内容会让构建失败。
- 关闭 Obsidian、删除本地 `.base/.canvas` 后，小程序构建和运行不受影响。
- 政治模块的样式、存储键、路由和数据不污染现有两个知识模块。
- 320px 级窄屏、常见微信字体缩放和长文本下，控件可点、文字可读、页面不横向溢出。

## 8. 明确延期

以下内容不混入本轮 V2 Demo：P2A 未审核知识上线；P4 的阅读进度、收藏、复习计划和掌握度；无限自由画布；全库无边界关系图；自动确认 AI 关系；复杂间隔重复算法；为单篇内容写专用页面；装饰性重动画。

## 9. 下一门禁

1. 在至少一台真实微信设备复核键盘、滚动、底部安全区、剪贴板和返回栈。
2. 用一篇代表性复杂知识验证表格、时间线或人物/文件映射前，先扩充 Markdown 契约与测试夹具，不写单篇特例。
3. P2A 的 11 个风险页仍需专项复核；风险内容可以继续结构化加工和进入隔离校对包，复核通过前不得因为 V2 展示能力完成而进入运行包。
4. V1 回归点 `72e0d76` 继续保留；V2 变更未形成新提交前不得覆盖该基线。
