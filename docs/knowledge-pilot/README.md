# 新知识模块端到端试点方案

> 状态：已确认，等待政治模块原始资料后开始执行
>
> 更新日期：2026-08-27

## 目的

本目录沉淀新知识模块从原始 PDF 或图片到小程序学习内容的完整指导方案。首个试点模块为后续提供的政治模块。

试点遵循一条最高优先级约束：

> 从零建设政治模块并走通全链路；试点验收前，不迁移、不重构、不批量改写现有知识模块。

试点要同时验证两条链路：

1. **内容可信链路**：原始资料 → 本地证据提取 → OCR 差异与人工审计 → 审核通过的 Markdown。
2. **用户学习链路**：Markdown 知识源 → 知识关系与学习卡 → 小程序知识地图、体系浏览、进度与复习。

两条链路可以并行开发，但只有内容通过证据审计后，才能进入正式发布数据。

## 已确认的总体决定

- Obsidian 是可替换的本地编辑与运营界面，不是运行时依赖。
- Markdown、YAML、JSON、图片和稳定 ID 是长期知识资产。
- 未经审核的 OCR 结果只能进入草稿区，不能成为正式知识源。
- 每个正式知识内容块必须能追溯到原始资料的页码和内容单元。
- 面向用户采用主动探索模式，不在试点阶段建设强任务驱动或自适应学习系统。
- 第一阶段的学习形态是分层知识地图、完整知识体系、速记卡、阅读进度和轻量复习。
- “已阅读”“复习状态”和“掌握”严格区分；没有题目验证时不宣称掌握。
- 全局知识图只展示聚合层级，知识点关系在模块图和局部图中展开。
- 试点阶段不依赖 Obsidian 社区插件，不建设自研 CMS，不建设在线多人审核系统。
- 政治模块成功验收后，再决定是否以及如何迁移现有模块。

## 端到端主干

```text
0. 接收政治资料并冻结试点范围
                    ↓
1. 建立原始文件清单与版本哈希
                    ↓
2. 本地提取文本层、页面图、版面和多路 OCR
                    ↓
3. 切分证据单元并标记差异与风险
                    ↓
4. 人工审核高风险内容和未解决差异
                    ↓
5. 生成审核通过的 Markdown 知识源
                    ↓
6. 在 Obsidian 中组织目录、关系、卡片和运营状态
                    ↓
7. 编译小程序知识包、地图、搜索和卡片索引
                    ↓
8. 上线知识浏览、进度记录和卡片复习
                    ↓
9. 完成验收、复盘并决定现有模块迁移策略
```

任何阶段失败，只退回上一个有可信产物的阶段，不直接在后续生成文件中修补。

实际推进不是等整批内容处理完再开始产品开发。收到首批审核通过的样本后分成两轨：

```text
                 ┌─ A 轨：继续扩展证据、OCR、审计和正式 Markdown
审核通过的样本 ─┤
                 └─ B 轨：验证地图、详情、卡片、进度和复习

A、B 两轨都通过 ─→ 共同进入正式构建与发布演练
```

B 轨只能使用已审核样本；界面占位数据和未审核草稿不能混入正式知识包。

## 权威边界

- 本目录描述新的通用试点协议。
- 现有常识模块的审计规则仍由 `docs/common-sense-source-restoration-standard.md` 管理，本试点不修改它。
- 现有笔记运行时仍由 `docs/note-architecture.md` 和当前校验脚本约束，本试点先通过新政治模块验证扩展方案。
- 同一规则只在一个分文档中详细定义，其他文档通过链接引用，避免多处维护后互相矛盾。

## 变更原则

1. 先修改负责该规则的分文档，再更新本页导航或总体决定。
2. 已确认决定若发生变化，必须在 01 的决定记录中说明原因和影响。
3. 政治资料尚未提供前，不预设其目录层级、页数、时效来源和首批知识点。
4. 试点中发现的问题优先修复共享工作流，不在单张知识卡中做不可复用的特例。
