## 1. 决策摘要

V2 建设的不是若干知识页面，而是一个以“当前知识焦点”为中心、能够改变观察尺度、学习视角和认知状态的通用移动知识平台。

推荐冻结以下主模型：

```text
认知活动：体系｜关系｜阅读｜回忆
用户目标：快速了解｜系统学习｜易混突破｜考前速记
```

默认发现链路不是要求所有用户依次经过全部能力，而是按意图分流：

```text
自由探索：知识全景 → 原地展开分支 → 完整知识卡 / 按需关系 / 回忆
目标任务：选择目标 → 系统推荐计划 → 一键开始 → GoalGuide持续引导 → 目标特有完成反馈
```

四种认知活动是内部状态和可恢复能力，不是默认暴露给用户的四个并列标签；四种用户目标是由系统先编排并持续引导的路线，不是四套内容副本，也不是四种范围选择器。

## 2. 产品北极星

用户在任意知识模块中都应能够回答：

1. 这个知识领域由什么构成。
2. 当前知识位于哪里。
3. 它与什么有关，为什么有关。
4. 它完整讲了什么，条件和边界是什么。
5. 自己能否在缺少答案时恢复关键内容。
6. 发现问题时怎样追溯来源并提交可定位纠错。

产品成功不是“拥有目录、地图、文章和卡片”，而是用户在这些认知状态之间切换时，焦点、路径、来源和空间上下文保持连续。

## 3. 通用对象模型

平台不得写死政治模块的篇、章、节。所有模块统一为：

```text
Module 模块
└─ NavigationNode 导航节点
   └─ KnowledgeUnit 知识单元
      ├─ SemanticBlock 语义内容块
      ├─ Relation 可解释关系
      └─ RecallItem 回忆单元
```

- `Module`：一个可独立进入的知识领域。
- `NavigationNode`：模块提供的正式组织节点，可表现为科目、篇、章、节、主题、分类或文件夹。
- `KnowledgeUnit`：稳定 ID 对应的最小完整阅读焦点。
- `SemanticBlock`：知识单元内部可定位、可追溯、可降级的内容结构。
- `Relation`：知识单元之间带类型、方向和理由的语义联系。
- `RecallItem`：引用知识单元及内容锚点的主动回忆材料。

目录父子关系、知识语义关系、运营状态和用户学习状态是四类不同数据，不得互相替代。

## 4. 双轴产品模型

### 4.1 认知活动轴

| 活动 | 回答的问题 | 必须保持的上下文 |
|---|---|---|
| 体系 | 它在整个知识领域哪里 | 焦点、展开节点、视窗位置、目录路径 |
| 关系 | 它与什么有关，为什么 | 中心焦点、关系类型、探索轨迹 |
| 阅读 | 它完整讲了什么 | 焦点、内容锚点、阅读位置、来源版本 |
| 回忆 | 我能否恢复关键内容 | 焦点、范围、回忆项、揭晓状态、原文锚点 |

活动切换不得产生新的知识正文或改变 `KnowledgeUnit` 身份。

### 4.2 用户目标轴

| 目标 | 推荐路线 | 完成条件 |
|---|---|---|
| 快速了解 | 系统提供内容先行的连续导读 → 用两条主线、正式连接点和代表例形成第一张认知图 → 结构持续定位并可选深入完整卡或知识空间 | 到达导读收束，完成或明确暂缓一次轻量自我解释，并显式结束；只报告行为，不声称掌握 |
| 系统学习 | 系统推荐正式范围 → 定位与提示 → 完整理解 → 主动回忆 | 完成明确范围内规定动作并记录跳过 |
| 易混突破 | 系统推荐正式对照 → 先判断 → 核对边界与依据 → 再辨 | 完成正式ContrastPair规定的核对/辨析动作 |
| 考前速记 | 系统推荐或恢复冻结卡组 → 提示 → 揭晓 → 自评与补救 | 完成该卡组一轮可解释回忆 |

目标路线只能引用正式目录、关系、内容块和回忆项，不复制知识内容，也不得伪装成掌握预测。

## 5. 焦点状态

平台存在两个顶层状态：

### 无焦点状态

允许：

- 浏览领域地形。
- 选择模块、区域或目标。
- 搜索和问题定位。
- 恢复上次焦点。
- 选择目标后先获得系统推荐；范围调整只是次级控制。

禁止：

- 默认取第一篇知识直接开始回忆。
- 展示依赖特定知识点的关系工作台。
- 将全量知识列表当作首页主体。

### 已聚焦状态

必须保留：

- 当前知识单元。
- 当前活动和用户目标。
- 入口、导航节点和内容锚点。
- 目录/地图快照。
- 探索轨迹和返回目标。

体系、关系、阅读和回忆从此状态派生。

## 6. 首页职责

模块首页只负责：

1. 提供用户熟悉的搜索或问题入口。
2. 按有效路线、最近焦点和首次快速了解三选一给出唯一状态主任务。
3. 以紧凑入口表达用户目标，并由系统生成推荐路线。
4. 提供一个低权重“浏览全部知识”入口，进入独立KnowledgeSpace全览/目录；首页不重复渲染区域卡。

首页不负责：

- 平铺所有知识单元。
- 同时承载完整目录、完整关系图、正文和卡片。
- 在没有范围时启动回忆。
- 以多个功能卡片代替清晰的认知起点。

## 7. 知识地形

知识地形是目录与关系的受控空间投影，不是自由力图或无限 Canvas。

推荐语义：

- 主干：正式导航结构。
- 路径：前置和后续。
- 桥梁：跨分支相关知识。
- 警戒：易混和边界。
- 锚点：核心知识。
- 岔路：同层可并列学习内容。

目录列表与地形图必须由同一份导航数据生成，并可逆切换；切换时保留焦点、展开状态和当前位置。

## 8. 完整内容与派生形态

完整内容是事实母体。摘要、关系说明、地形、对比和回忆项都是帮助理解或记忆的派生形态，必须能追溯到知识单元及内容锚点。

通用语义块至少包括：

- 普通正文降级块。
- 定义和核心结论。
- 层级、组成和步骤。
- 条件、范围和例外。
- 易混、边界和对比。
- 时间变化。
- 人物、会议、文件或其他实体。
- 来源和证据。

是否启用某种增强展示由模块能力和真实内容共同决定；未知块必须降级为可读正文。

## 9. 通用能力与模块差异

### 所有模块必须具备

- 稳定知识 ID 和导航路径。
- 焦点状态及返回恢复。
- 完整阅读和来源版本。
- 目录/列表定位及安全降级。
- 语义块的普通正文降级。
- 搜索定位。
- 构建与模块隔离。

### 模块按能力启用

- 局部关系图。
- 易混对照。
- 时间、人物、会议、文件镜头。
- 地图消隐和其他结构化回忆。
- 目标路线生成。
- 版本时间机和误区地图。

模块缺少某项能力时应隐藏、替换或降级，不得显示空壳入口。

## 10. 不可破坏的技术边界

1. 正式内容只能由模块认可的源内容经独立构建器单向生成运行包。
2. 页面不得保存知识正文副本或确认新关系。
3. 小程序不得运行依赖 Obsidian、社区插件、`.base` 或 `.canvas`。
4. 新模块通过数据、模块配置和通用组件接入，不得要求为每篇知识改页面代码。
5. 当前模块的升级不得改变其他模块既有行为；共享能力必须通过显式迁移和回归启用。
6. 关系必须带类型和理由；自动候选未经确认不能成为正式关系。
7. 回忆项必须能追溯内容锚点；不能随机截断正文制造卡片。
8. 不得用“已掌握”或伪精确进度制造无依据判断。

## 11. 文档和实施依赖

```text
总纲与设计追踪
  → 产品模型与信息架构
    → 焦点状态 + 内容运行时契约
      → 知识地形 + 焦点工作台
        → 目标路线、搜索与回忆
          → 空间 UI 与可访问性
            → 跨模块验收与推广
```

不能因首页最直观而跳过状态和数据契约直接编码。

## 12. 当前基线不是目标完成态

政治 P3 已具备37篇知识、42个目录节点、39条关系及体系/阅读/关系/回忆组件，可作为真实数据验证基线；但首页、语义缩放、知识地形、空间连续性、语义内容块和目标路线仍未达到本总纲定义。

现有笔记与常识模块不得直接套用政治 UI；在迁移前先完成模块能力清点和回归基线。

## 13. 完成定义

V2 只有同时满足以下条件才可称为完成：

- 通用规格全部达到 `Ready`。
- 至少政治、常识、笔记三个模块配置能够解释其差异。
- 新知识只改数据即可进入相应通用视图。
- 活动切换、知识切换和返回恢复不丢焦点。
- 目录与地形可逆，关系可解释，正文可追溯，回忆有范围。
- 自动回归覆盖数据、状态、路由和降级。
- 规定的 UI 场景由用户手测通过。
- 实现差距为0，或明确登记为下一版本而未被错误标记完成。
