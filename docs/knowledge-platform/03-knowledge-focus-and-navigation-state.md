## 1. 本文要解决什么

本文冻结跨页面、跨认知活动、沿关系探索、深链进入和应用恢复时的统一知识上下文。它回答：用户“正在理解什么、从哪里来、下一步切到哪里、怎样返回原位置”。

本文不决定地图长什么样、关系节点怎样排布、正文卡片怎样着色，也不保存知识正文。视觉文档可以使用本状态，但不能自行发明第二套焦点、返回或恢复规则。

## 2. 核心原则

### 2.1 焦点是知识身份，不是页面身份

同一个 `KnowledgeUnit` 在体系、关系、阅读和回忆中保持同一 `pointId`。切换活动只改变观察方式，不创建知识副本，也不把当前页面地址当作知识身份。

### 2.2 认知上下文与界面瞬态分离

必须区分：

- **认知上下文**：焦点、活动、目标、入口、内容锚点、探索轨迹。
- **可恢复快照**：目录展开、关系镜头、阅读锚点、当前回忆项。
- **界面瞬态**：像素坐标、手势中间值、弹层动画、按钮按压状态。

前两类使用稳定语义 ID；界面瞬态只存在于当前页面内存，不进入深链和持久化。

### 2.3 页面返回与认知来源分工

微信页面栈负责所有物理页面返回，平台不得拦截或要求先完成另一层“认知返回”。KnowledgeContext仍维护来源、探索轨迹和语义快照，用于上一物理页重新出现时恢复焦点、关系来路和viewport，而不是替代微信返回按钮。

### 2.4 恢复宁可降级，不得伪造历史

恢复失败时可退回知识顶部、目录路径或模块首页；不得默认选第一篇、猜测已删除知识的替代项，或伪造用户上次位置。

## 3. 三层状态模型

### 3.1 第一层：稳定认知上下文

```text
KnowledgeContext
├─ schemaVersion
├─ moduleId
├─ focus
│  ├─ pointId
│  ├─ navigationNodeId
│  └─ contentVersion
├─ activity: system | relations | reading | recall
├─ relationMode: orientation | exploration | null
├─ goalContext
│  ├─ type: quick | systematic | confusion | exam | null
│  ├─ routeId
│  └─ scopeId
├─ lens
├─ origin
│  ├─ type
│  └─ refId
├─ anchor
│  ├─ blockId
│  ├─ relationId
│  └─ recallItemId
├─ explorationTrail[]
├─ snapshots
├─ returnTarget
└─ updatedAt
```

字段含义：

| 字段 | 必须性 | 含义与约束 |
|---|---|---|
| `schemaVersion` | 必须 | 状态契约版本，不等同内容版本 |
| `moduleId` | 必须 | 模块边界；所有引用对象必须属于此模块 |
| `focus.pointId` | 已聚焦时必须 | 当前唯一知识单元；无焦点时为 `null` |
| `focus.navigationNodeId` | 可选 | 当前焦点的正式导航节点；可由运行包重建 |
| `focus.contentVersion` | 已聚焦时必须 | 保存上下文时的知识内容版本，用于失效判断 |
| `activity` | 必须 | 当前认知活动；无焦点时只能为 `system` |
| `relationMode` | 关系活动时必须 | 阅读前定向或深度探索 |
| `goalContext` | 可选 | 当前目标路线及范围；没有目标路线时为 `null` |
| `lens` | 可选 | 当前投影镜头，如目录、前置、易混；必须受模块能力约束 |
| `origin` | 必须 | 地形、目录、搜索、问题、路线、深链、恢复等进入来源 |
| `anchor` | 可选 | 内容块、关系或回忆项的稳定语义锚点 |
| `explorationTrail` | 可选 | 沿知识关系切换形成的会话轨迹 |
| `snapshots` | 可选 | 各活动的最小可恢复语义状态 |
| `returnTarget` | 可选 | 明确覆盖默认返回时使用；只能指向可验证目标 |
| `updatedAt` | 必须 | 最近一次有效状态变化时间，仅用于恢复排序，不代表学习进度 |

### 3.2 第二层：活动快照

```text
snapshots
├─ system
│  ├─ projection: terrain | directory | list
│  ├─ expandedNodeIds[]
│  ├─ focusNodeId
│  ├─ scrollAnchorId
│  └─ viewportToken
├─ relations
│  ├─ centerPointId
│  ├─ lens
│  ├─ selectedRelationId
│  └─ viewportToken
├─ reading
│  ├─ blockId
│  ├─ scrollAnchorId
│  └─ readingMode
└─ recall
   ├─ scopeId
   ├─ itemId
   ├─ revealed
   └─ remedyStep
```

快照只保存足以重建位置的语义信息：

- `scrollAnchorId` 指向导航节点或内容块，不保存 `scrollTop=1372` 这类脆弱像素。
- `viewportToken` 是投影组件自己生成的有限状态，如 L1 区域、中心节点、缩放层级；不得包含任意画布矩阵。
- `expandedNodeIds` 只保留仍存在且属于当前模块的节点。
- 回忆揭晓状态只属于当前会话；不得据此推断“已掌握”。

### 3.3 第三层：界面瞬态

下列状态只保存在当前组件或页面内存：

- 手势开始、移动、结束中的缩放和平移值。
- 抽屉、弹层、提示条和键盘开关。
- 动画进度、骨架屏、按钮按压态。
- 未提交搜索词、临时筛选和滚动惯性。
- 节点碰撞、布局缓存和渲染测量结果。

页面销毁后丢失这些信息是允许的；不得为恢复它们扩大持久化契约。

## 4. 状态所有权

| 载体 | 保存内容 | 明确不保存 |
|---|---|---|
| 页面路由/深链 | `moduleId`、`pointId`、`activity`，按需附 `routeId`、`blockId`、`lens` | 完整轨迹、像素位置、揭晓状态、正文 |
| 当前会话内存 | 完整 `KnowledgeContext`、活动快照、探索轨迹、界面瞬态 | 跨版本长期历史 |
| 本地持久化 | 每模块最近焦点、最近有效路线/范围、用户显示偏好、状态 schema 版本 | 正文、完整页面对象、全量探索轨迹、弹层与手势状态 |
| 运行时知识包 | 正式导航、知识单元、语义块、关系、回忆项、来源和版本 | 用户会话状态 |

### 4.1 深链最小原则

深链必须在没有上一页面内存时独立工作。推荐参数：

```text
moduleId + pointId + activity
+ routeId? + blockId? + lens?
```

所有参数都视为请求，不视为事实。进入时必须用当前运行包验证并规范化；不能把序列化的页面对象放入路由。

### 4.2 本地持久化原则

推荐按 `moduleId` 分桶保存最近上下文摘要：

```text
RecentModuleContext
├─ moduleId
├─ pointId
├─ contentVersion
├─ lastActivity
├─ goalType
├─ routeId
├─ scopeId
├─ blockId
└─ updatedAt
```

完整 `explorationTrail` 仅在当前会话内保留；本地只保留最近焦点摘要。这样既支持“继续探索”，又避免把无期限的浏览历史误当成学习档案。

## 5. 合法状态与能力规范化

### 5.1 顶层状态约束

| 状态 | 合法活动 | 约束 |
|---|---|---|
| 无焦点 | `system` | 可浏览、搜索、选目标和恢复；不可进入关系、阅读或具体回忆 |
| 已聚焦 | `system`、`relations`、`reading`、`recall` | 所有活动必须引用同一 `pointId`，除非发生显式焦点切换 |

### 5.2 建立焦点后的默认知识表面

从地形、目录或路线选择知识单元时：

1. 建立焦点后通过微信原生页面栈进入独立`KnowledgeCard`页，并保留体系来源快照；所有入口复用同一Card渲染器。
2. 有已确认关系时，将轻量关系上下文投影进完整卡的按需入口；需要深入时才进入`relations`活动。
3. 无关系时不展示空关系图；`reading`仍直接可达。

搜索和问题入口在结果列表说明命中类型；用户点击结果时直接提交到精确正文块、关系或回忆，不增加知识预览状态。

### 5.3 能力缺失时的规范化

| 请求状态 | 当前数据不支持 | 规范化结果 |
|---|---|---|
| `relations` | 模块无关系能力 | `reading`，保留焦点并给出一次性说明 |
| `relations` | 模块有能力但当前焦点无关系 | 关系定向降级为路径、同级和来源上下文；不造关系 |
| `recall` | 当前焦点无回忆项 | `reading` 并定位可回看内容；隐藏下一张空卡 |
| 无焦点 `recall` | 没有范围 | 恢复有效卡组或由系统生成可解释推荐范围；调整为次级，不得选第一条知识 |
| `system/terrain` | 模块无地图能力 | `system/directory` 或 `system/list` |
| 未知 `lens` | 模块未声明或无数据 | 回到模块默认镜头 |
| 无效 `routeId` | 路线不存在或范围失效 | 退出路线，保留仍有效焦点；无焦点则回模块首页 |

## 6. 状态事件与转换

事件名称用于规格和自动测试，不要求页面代码采用同名框架。

| 事件 | 前置状态 | 结果 | 必须保留 |
|---|---|---|---|
| `OPEN_MODULE` | 任意 | 进入该模块无焦点 `system`，可显示恢复入口 | 其他模块最近上下文不删除 |
| `RESTORE_MODULE` | 模块首页 | 验证最近焦点后恢复；失败则停留首页 | 恢复失败原因，不伪造替代点 |
| `SELECT_POINT` | 体系节点或搜索结果 | 建立焦点并用原生页面栈打开独立KnowledgeCard；默认activity为reading | 来源、体系快照、内容版本 |
| `SWITCH_ACTIVITY` | 已聚焦 | 切换活动并保存离开活动的快照 | `pointId`、目标、来源、轨迹 |
| `FOLLOW_RELATION` | 关系活动 | 新焦点入栈，中心切到目标知识 | 来源关系、上一焦点与关系视窗 |
| `BACK_TRAIL` | 探索轨迹非空 | 恢复上一焦点和对应关系快照 | 当前点不写入正式知识历史 |
| `BACK_TO_SYSTEM` | 已聚焦 | 返回原体系投影或安全目录路径 | 原导航节点、展开状态、语义视窗 |
| `OPEN_SEARCH_RESULT` | 搜索结果 | 按命中类型一次提交pointId、activity及block/relation/recall锚点并进入KnowledgeCard | 查询、意图、结果序号、滚动锚点和入口 |
| `START_ROUTE` | 目标已选且范围有效 | 建立 `goalContext`，进入路线定义的第一活动 | 路线、范围、原首页状态 |
| `OPEN_RECALL_WITHOUT_SCOPE` | 无焦点 | 恢复有效卡组或生成推荐范围并展示依据 | 不创建假焦点；调整范围只更新待冻结计划 |
| `OPEN_SOURCE_BLOCK` | 回忆/关系 | 切到阅读并定位 `blockId` | 原活动快照和返回目标 |
| `OPEN_DEEP_LINK` | 冷启动或任意 | 验证参数并构造最小上下文 | 不依赖旧页面内存 |
| `CONTENT_UPDATED` | 已有保存状态 | 执行版本协调并降级失效字段 | 仍存在的焦点与来源 |
| `CLEAR_CONTEXT` | 任意 | 只清除指定模块最近上下文 | 其他模块、正式内容和用户偏好 |

## 7. 探索轨迹

### 7.1 轨迹条目

```text
ExplorationTrailEntry
├─ fromPointId
├─ toPointId
├─ viaRelationId
├─ relationType
├─ originActivity
├─ sourceSnapshot
└─ enteredAt
```

规则：

1. 只有用户在卡内关系情境中选择目标时入栈；展开或关闭关系理由不入栈。
2. 轨迹记录的是经过的知识关系，不复制关系正文。
3. 从 A→B→C 后逐次返回必须得到 C→B→A，并恢复当时关系中心和镜头。
4. 用户从体系重新选择 D 时开始新的探索分支；旧分支不自动拼接。
5. 会话轨迹建议最多20步，超出时丢弃最早步骤并保留起点摘要，避免状态无界增长。
6. 轨迹不是学习进度、浏览统计或掌握证明。

### 7.2 与微信页面栈分工

- 微信页面栈负责搜索→卡、空间→卡、A卡→B卡等全部物理返回。
- explorationTrail负责说明A→B的语义来路，并让来源页面`onShow`时恢复正确焦点/关系快照；它不在原生返回之前增加一次用户操作。
- reading/relations/recall在同一KnowledgeCard内切换时，可提供“返回正文”等页内语义动作；微信左上角始终直接退出当前物理页。

## 8. 统一返回优先级

页面内语义动作按以下顺序处理；**不适用于微信原生物理返回**：

```text
1. 关闭当前阻塞弹层或关系情境展开
2. 处理当前活动内部返回
3. 恢复当前卡内reading活动与锚点
4. 恢复origin对应的页内活动快照

微信原生返回单独执行：关闭当前物理页 → 上一页`onShow`读取既有来源/Trail/viewport完成语义恢复。不得先要求用户点“返回上一知识”或“返回全景”。
```

典型行为：

- 回忆“查看原文”后返回：回到原回忆项及揭晓状态，而不是退出模块。
- 卡内关系理由展开后关闭：只关闭情境槽，不改变焦点。
- 关系目标B页原生返回A页：A页按Trail恢复原焦点和关系位置，不增加第二次返回。
- 阅读直接来自体系时返回：恢复体系节点和视窗。
- 深链冷启动且没有来源时返回：回当前模块首页，再由系统处理退出。

## 9. 内容版本变化与状态协调

恢复顺序：先验证模块，再验证焦点，再验证活动能力，最后验证锚点和快照。

| 失效对象 | 处理规则 |
|---|---|
| 模块不存在 | 清除该模块上下文并回平台可用入口 |
| `pointId` 已迁移 | 使用构建包显式 `idMigrations` 映射；禁止按标题猜测 |
| `pointId` 已删除 | 回模块首页并提示最近内容已更新 |
| `navigationNodeId` 已变 | 从当前知识反向重建正式路径 |
| `blockId` 已删除 | 回知识顶部，并标记原定位已失效 |
| `relationId` 已删除 | 保留有效焦点，关闭相关情境槽；不得显示旧理由 |
| `recallItemId` 已删除 | 回当前知识回忆入口；无其他卡片则降级阅读 |
| `routeId/scopeId` 已失效 | 退出路线，保留有效焦点；无焦点则回目标选择 |
| 状态 schema 不兼容 | 丢弃活动快照和轨迹；若焦点仍有效只恢复焦点 |
| `contentVersion` 改变但 ID 均有效 | 恢复语义锚点并显示当前版本，不保留旧正文快照 |

知识拆分、合并和重命名必须由构建产物提供显式迁移表。一个旧 ID 映射多个新 ID 时不能自动替用户选择，只能回到新父级导航位置让用户重新建立焦点。

## 10. 多模块隔离

状态必须以 `moduleId` 为一级命名空间：

```text
knowledgeContext:politics
knowledgeContext:common-sense
knowledgeContext:notes
```

规则：

- 切换主导航 Tab 不覆盖其他模块最近焦点。
- 一个模块的 `pointId`、`blockId`、镜头和目标不能被另一模块解释。
- 共享组件只接受当前模块运行包和上下文，不读取全局“当前第一篇知识”。
- 清除某模块记录不得清除其他模块、收藏或正式内容。
- 未来若支持跨模块关系，必须作为新的显式能力和来源对象设计，不能先复用同模块轨迹暗中实现。

## 11. 纠错上下文

纠错是基于当前上下文创建的独立记录，不修改知识内容和浏览状态：

```text
CorrectionContext
├─ moduleId
├─ pointId
├─ contentVersion
├─ blockId?
├─ sourceRefId?
├─ activity
├─ origin
└─ submittedAt
```

提交纠错后用户仍回到原活动与位置。纠错记录不得携带完整正文副本；必要摘录由独立纠错系统按来源策略处理。关系理由、回忆答案和正文都必须能绑定到各自稳定锚点。

## 12. 跨模块验收场景

### STATE-AC-001：活动切换保持焦点

给定政治知识 P，用户从关系切到阅读再切到回忆，`moduleId`、`pointId`、内容版本和来源保持一致，各活动分别恢复自己的锚点。

### STATE-AC-002：体系位置恢复

给定用户从常识分类节点进入知识 C，返回体系时恢复原投影、展开路径和语义滚动锚点；内容增高后仍定位到该节点而非旧像素。

### STATE-AC-003：关系探索回退

给定用户沿A→B→C通过关系打开三张KnowledgeCard，连续两次微信原生返回依次显示B和A，并由Trail恢复各自关系位置；仅展开关系理由不新增轨迹。

### STATE-AC-004：无能力降级

给定笔记模块没有正式关系，深链请求 `activity=relations` 时保留目标知识并进入阅读，且不会出现空关系工作台。

### STATE-AC-005：无焦点回忆

给定模块没有最近范围，冷启动回忆入口必须由profile或正式顺序生成可解释推荐范围并等待用户开始；不得以数据数组第一项建立焦点，范围调整只作为次级控制。

### STATE-AC-006：内容锚点失效

给定保存状态中的内容块已在新版本删除，恢复时仍进入同一知识顶部并说明定位失效，不显示旧块或跳到相似标题。

### STATE-AC-007：冷启动深链

给定小程序没有任何页面内存，有效深链仍能从当前运行包恢复知识及指定活动；无效镜头按模块能力降级。

### STATE-AC-008：模块隔离

给定用户分别在政治和常识建立焦点，切换 Tab 后两个模块各自恢复自己的最近焦点，互不覆盖。

### STATE-AC-009：纠错返回

给定用户在阅读块提交纠错，完成后返回同一知识、同一块和同一阅读位置，正式内容状态不被页面改变。

## 13. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 只使用微信页面返回栈 | 无法表达沿关系切换的知识路径，也无法可靠恢复活动快照 |
| 所有模块共享一个全局 `currentPoint` | Tab 切换互相覆盖，ID 可能碰撞，无法独立恢复 |
| 持久化整页 `data` | 混入正文、布局和临时状态，升级后极易失效 |
| 保存像素坐标作为唯一位置 | 字号、内容和屏幕变化后不可恢复 |
| 建立焦点后直接抛入长正文 | 丢失知识身份、体系位置和必要上下文 |
| 建立焦点后一律进入关系图 | 对无关系模块或无关系知识形成空壳 |
| 按标题猜测已删除 ID 的替代知识 | 可能把用户带到语义不同内容，形成错误恢复 |
| 永久保存完整探索轨迹 | 无界增长，并容易被误解为学习档案 |
