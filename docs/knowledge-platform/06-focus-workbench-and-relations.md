## 1. 本文要解决什么

本文冻结建立知识焦点后的统一知识表面：体系、关系、阅读和回忆怎样共享同一焦点并按上下文投影，卡内关系提示与按需深度探索怎样分工，完整正文怎样从纯文字升级为同源知识卡，以及关系、回忆和正文怎样双向定位。

本文定义逻辑容器、信息顺序、数量、行为和降级，不决定最终导航条位于顶部还是底部、卡片圆角和动效参数。08负责视觉实现，但不能拆散焦点状态或改变关系切换与原文定位规则。

## 2. 单一知识表面，不是四个功能页面

已确认采用一个逻辑 `KnowledgeSurface`；既有`FocusWorkbench`可作为兼容名和实施容器，但不是用户需要理解的产品层：

```text
KnowledgeCardSurface
├─ ContextBar：正式路径和当前知识
├─ GoalGuideBand：有路线时回答为什么、现在做什么、怎样完成
├─ SemanticFlow：按正式顺序连续渲染正文；显式语义块原位形成小卡语法
├─ RelationSlot：正文锚点后的必要关系与文末完整入口
├─ RecallFace：同一pointId的提示、揭晓、自评和原文回看
└─ ContextTools：显示、来源与反馈等低优先工具
```

KnowledgeCard使用独立微信物理页，但自由探索、搜索和路线必须复用同一个原生组件/WXML渲染器。reading/relations/recall是该页内部活动，不是三份正文；微信原生返回退出物理页，语义快照只负责上一页恢复。

## 3. 工作台顶层状态

### 3.1 必须有焦点

工作台只接受已验证的 `moduleId + pointId`。无焦点、知识失效或跨模块 ID 不匹配时：

- 不默认打开数组第一项。
- 不保留旧知识标题或正文。
- 回到当前模块体系入口或有效父范围。
- 按03显示恢复失败原因。

### 3.2 ContextBar

上下文栏必须提供：

- 当前知识完整标题。
- 正式路径，窄屏可折叠但可完整查看。
- 返回体系或明确来源的入口。
- review/版本状态，仅在当前构建目标需要用户感知时显示。
- 当前路线信息，仅在存在 `goalContext` 时显示。

上下文栏不展示未经源内容明确提供的“为什么重要”，也不把风险标记当知识重要程度。字号和固定方式由08决定。

### 3.3 ActivityStage与上下文动作

`system → relations → reading → recall`保留为内部状态、深链和恢复语义，不再规定为默认可见的四个并列标签：

- `system`通过路径、全局缩略位置和返回知识空间持续提供。
- `relations`默认作为卡内上下文；只在用户主动深入时打开一层关系视图。
- `reading`是完整知识卡的主体。
- `recall`由合卡、文末或GoalGuide触发，仅在存在正式RecallItem时出现。
- 上下文动作仍只能触发明确状态事件，不更换未明示选择的焦点，不复制正式内容。

## 4. 从地形建立焦点

### 4.1 进入顺序

```text
知识空间选中具体KnowledgeUnit
→ 保存空间上下文并直接打开完整知识卡
→ 按需进入关系/回忆
→ 返回时恢复原分支、节点与viewport
```

关系能力是卡内上下文和可选深入，不是完整阅读前置。模块完全不支持关系时，知识卡仍按相同主链成立。

### 4.2 焦点入场信息

完整知识卡的首屏信息顺序：

1. 正式路径与知识标题。
2. 显式“一句话理解”；不存在时不随机截断正文。
3. 连续正文的开始。
4. 有正式关系或回忆时提供按需上下文动作。

这是同一知识卡的完整态，不再增加详情摘要页或关系过门页。用户无需先理解整张关系图。

## 5. 体系活动

工作台内的“体系”不是返回模块首页，也不是重新打开全量目录。它显示05定义的 L2/L3局部地形：

- 当前焦点在正式路径中的位置。
- 父分支、同级知识和必要的上下级上下文。
- 当前镜头和焦点高亮。
- “返回完整地形”操作，用03快照恢复原 L0–L2范围。

用户从体系活动切回关系或阅读时焦点不变。需要换知识时必须执行显式 `SELECT_POINT` 或关系 `FOLLOW_RELATION`，不能因滚动经过节点自动换焦点。

## 6. 卡内关系上下文

### 6.1 目标

完整知识卡中的关系上下文只回答三类问题：

- 理解当前知识前最需要先知道什么。
- 最容易与什么混淆。
- 它与哪个邻近知识存在明确联系。

它不展示两跳关系、全库网络或复杂筛选。

### 6.2 数量与选择

最多展示3条，每种类型最多1条：

```text
1. 当前路线明确要求的前置/下一步关系
2. prerequisite：直接前置
3. contrast：最需要辨析的易混项
4. related：明确相关项
```

总数达到3后停止。没有人工策展优先级时，按关系类型、方向、目标知识正式导航顺序和关系 ID确定，不能使用黑箱“相关度”或关系度数猜测重要性。

每条提示必须展示：

- 关系类型与方向。
- 目标知识标题。
- “为什么有关”的简短理由；可截断视觉行数，但必须可展开完整理由。
- 目标知识所在路径，跨分支时必须显示。

如果当前点无正式关系，卡片仍显示路径和完整内容入口；不生成“可能相关”，也不显示“深入探索”。关系上下文不存在时不得留下一个空的中间步骤。

## 7. 深度关系探索

### 7.1 一层局部图

深度探索始终以当前焦点为中心，只展示受控一层：

```text
当前焦点
├─ 前置 / 派生后续
├─ 易混
└─ 相关
```

- 图形视窗最多同时显示6个关系邻居。
- 超出部分按类型进入“查看全部 N 条”的列表等价视图。
- 切换镜头只过滤当前一层，不展开邻居的邻居。
- 每条边或列表项都显示类型、方向和理由。
- 反向关系由04构建器派生并明确标识，页面不写回关系。

### 7.2 确定性排序

关系展示优先级：

1. 当前目标路线直接使用的关系。
2. 当前选择的关系镜头类型。
3. `prerequisite`、`contrast`、`related` 的稳定类型顺序。
4. 方向、目标知识正式导航顺序、关系 ID。

排序只决定可见顺序，不改变关系事实和路线顺序。

### 7.3 先理解关系，再提交目标

点击关系入口先在当前卡的RelationSlot展开：

```text
目标知识标题与路径
关系类型、方向和完整理由
显式一句话理解（若有）
来源/正文锚点（若有）

操作：打开目标知识｜在体系中定位
```

- 展开或关闭关系理由不改变焦点、不写探索轨迹。
- “打开目标知识”执行`FOLLOW_RELATION`并通过原生页面栈打开目标KnowledgeCard，记录来源关系。
- “在体系中定位”更新system快照并进入KnowledgeSpace；不创建知识预览卡。

### 7.4 探索回返

沿A→B→C打开知识卡后，Card显示可理解的来源提示；微信原生页面栈逐页返回C→B→A，explorationTrail只用于恢复语义焦点和关系位置，不增加第二个“返回上一个知识”操作。

## 8. 阅读：一个完整语义内容流

### 8.1 不建立正文副本

阅读直接渲染04的 `KnowledgeUnit.blocks`，按源顺序完整覆盖内容。速览、结构理解、重点和证据都是对同一块集合的引用或增强，不保存另一份摘要正文。

### 8.2 推荐阅读结构

```text
一句话理解（显式存在时）
内容结构/本页目录
完整语义内容流
├─ definition / conclusion
├─ hierarchy / sequence
├─ condition / exception
├─ contrast
├─ 普通标题、段落、列表、表格
└─ evidence / 来源
```

- 一句话理解用于进入，不替代完整内容。
- 内容结构由 heading 与块顺序派生，可跳转但不重排正文。
- 增强块使用稳定语法，未知语义按原结构显示。
- 条件、例外和否定边界不能因“只看重点”被隐藏。
- 证据可以折叠，但必须与对应内容块或知识单元保持引用。

### 8.3 重点透镜

`keyPoints` 只改变强调程度，不删减完整内容。它可以突出 definition、conclusion、condition、exception 和 contrast；未显式标记的正文保持普通显示。第一轮不使用关键词扫描自动标红。

### 8.4 专注阅读

专注阅读只隐藏关系提示、辅助工具和非必要控制器外观；必须保留：

- 当前知识身份和退出方式。
- 阅读位置和内容锚点。
- 返回来源。
- 来源/纠错的可访问路径。

退出专注阅读恢复原工作台状态，不重新加载到知识顶部。

## 9. 回忆与失败补救接口

06只定义回忆怎样接入当前焦点，具体路线、题型和补救编排由07冻结。

- 无目标路线时，回忆范围默认为当前知识的正式 `RecallItem`。
- 有目标路线时，可使用当前路线 `scopeId`，但控制器必须显示范围。
- 当前知识和范围都没有回忆项时，回忆活动不可用，不随机生成。
- 揭晓、正确/错误和补救步骤属于03会话状态，不写入内容包。

最低失败补救链：

```text
一句提示（仅在 RecallItem 显式提供时）
→ 在体系中的位置
→ 易混对照（有正式数据时）
→ 对应原文块
```

回看原文后必须能回到同一回忆项及揭晓状态；没有对应增强数据时跳过该补救层，不生成内容。

## 10. 正文、关系和回忆双向定位

### 10.1 统一锚点

| 来源 | 目标 | 使用字段 | 返回 |
|---|---|---|---|
| 关系情境槽 | 正文理由依据 | `sourceBlockIds/targetBlockIds` | 原关系展开和正文锚点 |
| 正文块 | 相关关系 | 引用该 `blockId` 的 relation | 原阅读块和滚动锚点 |
| 回忆项 | 答案依据 | `sourceBlockIds` | 原回忆项和揭晓状态 |
| 正文块 | 回忆练习 | 引用该 `blockId` 的 recall item | 原阅读块 |
| 体系焦点 | 正文 | `pointId + blockId?` | 原地形范围和视窗 |

### 10.2 定位行为

- 进入阅读后定位并短暂强调目标块，同时显示“来自关系/回忆/体系”的来源说明。
- 返回优先使用03的 `returnTarget` 和活动快照。
- 块 ID失效时回知识顶部并说明原定位失效，不能跳到标题相似段落。
- 一个关系引用多个块时先展示块列表或定位第一块并允许逐项查看，不能暗中选择唯一依据。

## 11. 能力与空状态

| 情况 | 工作台行为 |
|---|---|
| 模块无关系能力 | 不显示关系动作；完整知识卡仍可直接阅读 |
| 模块有关系能力、当前点无关系 | 不显示关系上下文与深度探索入口；保留路径和完整内容 |
| 当前点无回忆，路线也无有效回忆 | 不显示回忆动作 |
| 缺少一句话理解 | 省略，不从正文随机截断 |
| 缺少精确内容锚点 | 关系/回忆仍可知识级追溯，并在 review 构建报告警告 |
| 关系超过图形预算 | 图形显示6个，完整列表显示全部 |
| 未知语义块 | 按04结构和 `fallbackText` 完整显示 |
| review 内容 | 显示明确状态；不能由工作台批准或发布 |
| 焦点内容更新 | 按03协调版本、锚点、轨迹和路线 |

“无数据”不是一个需要漂亮占位的大页面；可选活动应隐藏或退回仍有真实内容的活动。

## 12. FocusWorkbenchViewModel

以下为既有baseline ViewModel；S5.5B达到Ready后应按04及S5.5B第13节收敛为KnowledgeSurface/KnowledgeCard纯派生投影，不得继续用`controller`字段强制生成四项可见导航：

```text
FocusWorkbenchViewModel
├─ focus
│  ├─ pointId / title / path
│  ├─ summary
│  └─ status / source
├─ currentActivity
├─ availableActivities[]
├─ systemStage
├─ orientationStage
├─ relationStage
├─ readingStage
├─ recallStage
├─ controller
├─ returnModel
└─ diagnostics
```

输入为：

```text
KnowledgePackage
+ ModuleProfile
+ KnowledgeContext
+ viewport class
= FocusWorkbenchViewModel
```

相同输入必须产生相同关系选择、顺序、活动可用性和内容块引用。页面只渲染并发送03定义的事件，不复制正文、不自行排序知识事实、不推断关系。

### 12.1 渐进迁移

- 政治可先由现有详情/地图页面包裹共享控制器，逐步替换为统一工作台。
- 常识和笔记在 SourceAdapter 与行为回归建立前继续使用旧页面。
- 通用组件默认关闭；模块 profile 和适配器达到门禁后逐模块启用。
- 共享组件升级不得静默改变未启用模块的路由、数据和本地状态。

## 13. 三模块代表性场景

### 政治：完整能力

进入知识后直接打开同一完整知识卡，显示路径、一句话、显式小卡和连续正文；可按需打开关系上下文或进入最多6邻居的一层关系图。语义正文保留固定表述、条件和易混边界，回忆可定位原文。全部仍是review时只进入隔离入口。

### 常识：能力按分类启用

法律知识可以有易混、条件、例外、表格和回忆；没有正式关系的分类只显示体系路径与完整阅读。工作台不能因为其他分类有关系就给全模块所有知识显示关系图。

### 笔记：弱关系与训练增强

默认知识表面提供路径和完整内容；只有存在正式关系或回忆数据时增加对应上下文动作。“练对应题型”由笔记profile作为增强操作展示，不冒充`related`关系，也不改变内部ActivityStage。

## 14. 验收场景

### WORK-AC-001：建立焦点后的完整知识卡

给定政治知识存在正式关系，从知识空间选择具体KnowledgeUnit后直接打开同一完整知识卡，显示路径、一句话和连续正文，关系通过按需入口提供且不是独立过门页。

### WORK-AC-002：内部活动共享焦点

体系、关系、阅读和回忆被KnowledgeSurface或GoalGuide按上下文投影时，`moduleId`、`pointId`、内容版本、目标和返回来源保持不变，各内部活动恢复自己的快照；默认界面不要求四标签切换。

### WORK-AC-003：关系上下文确定性

相同运行包和上下文连续生成两次定向，关系选择和顺序一致；不会因关系图布局或访问次数改变。

### WORK-AC-004：展开关系理由不改焦点

点击关系入口只展开当前卡的理由；关闭后焦点和轨迹不变。选择目标后才新增轨迹并用原生页面栈打开目标知识卡。

### WORK-AC-005：受控一层与完整列表

当前知识有9条关系时，图形最多展示6个邻居，列表可访问全部9条及其类型、方向和理由。

### WORK-AC-006：完整阅读不丢内容

关闭重点透镜和所有增强组件后，正文标题、段落、列表、表格、条件、例外和来源仍按正式顺序完整可读。

### WORK-AC-007：关系定位原文

从关系理由打开正文时定位对应块；页内返回恢复原关系展开，原生返回恢复来源卡和焦点。

### WORK-AC-008：回忆失败回看

从回忆项打开原文后定位 `sourceBlockId`；返回恢复同一回忆项和揭晓状态，不跳到下一张。

### WORK-AC-009：无关系/无回忆降级

笔记知识没有关系和回忆时，知识表面只提供路径和完整内容，页面无空关系图、空活动或空卡片入口。

### WORK-AC-010：专注阅读恢复

在长文中部进入并退出专注阅读，焦点、块锚点、滚动语义位置和返回来源不变。

### WORK-AC-011：无焦点防护

冷启动工作台但没有有效 `pointId` 时回模块体系入口，不打开第一篇知识或旧缓存正文。

### WORK-AC-012：模块隔离

政治启用新工作台时，常识和笔记未启用模块继续使用原页面、路由和本地状态；共享代码不读取其源模型。

## 15. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 目录、地图、文章、卡片四个独立功能页 | 用户必须自己重建焦点和认知链路 |
| 工作台把四活动内容同时展开 | 移动端过载，快照和专注阅读难以成立 |
| 关系定向先展示完整关系图 | 阅读前负担过重，阻碍进入正文 |
| 一次展示两跳或全库关系 | 快速形成线团，关系理由无法阅读 |
| 点击邻居立即换知识 | 容易误触，无法判断切换依据，也污染轨迹 |
| 用“智能相关度”选择定向关系 | 缺少可解释数据，结果不稳定且无法审核 |
| 为速览、结构和完整内容维护三份正文 | 形成内容副本，纠错和版本必然漂移 |
| 重点模式隐藏普通正文或条件 | 用户看到的内容不完整，可能改变事实含义 |
| 没有回忆项时随机生成卡片 | 违反来源和内容锚点契约 |
| 可选活动保留可点击空页面 | 形成空壳功能，违背能力诚实性 |
| 为政治单独实现焦点状态和关系控制器 | 无法迁移常识、笔记及后续模块 |
