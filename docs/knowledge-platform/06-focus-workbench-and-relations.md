# 焦点工作台与关系探索

> 状态：Ready — WORK-001 至 WORK-013 已于 2026-08-28 全部接受
>
> 上游：[03 知识焦点与导航状态](./03-knowledge-focus-and-navigation-state.md)、[04 内容与运行时契约](./04-content-and-runtime-contract.md)、[05 知识地形与语义缩放](./05-knowledge-terrain-and-semantic-zoom.md)
>
> 下游：07 目标路线/回忆、08 空间 UI、首轮政治工作台重构

## 1. 本文要解决什么

本文冻结建立知识焦点后的统一工作台：体系、关系、阅读和回忆怎样共享同一焦点，阅读前关系定向与阅读后深度探索怎样分工，完整正文怎样从纯文字升级为语义内容流，以及关系、回忆和正文怎样双向定位。

本文定义逻辑容器、信息顺序、数量、行为和降级，不决定最终导航条位于顶部还是底部、卡片圆角和动效参数。08负责视觉实现，但不能拆散焦点状态或改变关系切换与原文定位规则。

## 2. 工作台不是四个功能页面

推荐采用一个逻辑 `FocusWorkbench`：

```text
FocusWorkbench
├─ ContextBar：当前路径、焦点、状态和返回来源
├─ ActivityStage
│  ├─ system：当前焦点在体系中的局部位置
│  ├─ relations：阅读前定向 / 深度关系探索
│  ├─ reading：完整语义内容流
│  └─ recall：当前焦点或路线范围内的主动回忆
├─ ActivityController：切换观察方式
└─ ReturnModel：来源快照、探索轨迹和原文回返
```

“一个逻辑工作台”不强制所有内容一次渲染在一个微信页面：活动表面可以按性能懒加载，也可以在迁移期由多个物理页面承载，但必须共享03的 `KnowledgeContext`、相同控制器语义和可序列化深链。物理页面数量不能成为产品状态。

## 3. 工作台顶层状态

### 3.1 必须有焦点

工作台只接受已验证的 `moduleId + pointId`。无焦点、知识失效或跨模块 ID 不匹配时：

- 不默认打开数组第一项。
- 不保留旧知识标题或正文。
- 回到当前模块体系入口或有效父范围。
- 按03显示恢复失败原因。

### 3.2 ContextBar

上下文栏必须提供：

- 当前知识完整标题。
- 正式路径，窄屏可折叠但可完整查看。
- 返回体系或明确来源的入口。
- review/版本状态，仅在当前构建目标需要用户感知时显示。
- 当前路线信息，仅在存在 `goalContext` 时显示。

上下文栏不展示未经源内容明确提供的“为什么重要”，也不把风险标记当知识重要程度。字号和固定方式由08决定。

### 3.3 ActivityController

控制器顺序固定为：

```text
体系 → 关系 → 阅读 → 回忆
```

- `system` 与 `reading` 是所有模块核心活动。
- `relations` 仅在模块支持关系认知时出现；当前点无正式关系时可以显示路径定向，但不出现深度探索入口。
- `recall` 仅在当前知识或有效路线范围内存在正式回忆项时出现。
- 不可用活动从交互控制器移除，不保留可点击空壳；可通过说明告知能力缺失。
- 切换活动只触发 `SWITCH_ACTIVITY`，不更换焦点或复制内容。

## 4. 从地形建立焦点

### 4.1 进入顺序

```text
L2 选择知识单元
→ L3 焦点及局部关系定向
→ 用户选择完整阅读或深度关系探索
→ 阅读后进入回忆或继续沿关系探索
```

若模块完全不支持关系，L2建立焦点后直接进入阅读；仍保留体系来源快照和上下文栏。

### 4.2 焦点入场信息

关系定向的首屏信息顺序：

1. 正式路径与知识标题。
2. 显式“一句话理解”；不存在时不随机截断正文。
3. 最多3条关键关系提示。
4. 主操作“完整阅读”。
5. 有更多关系时提供“深入探索”。

这是一段短定向，不是新的详情摘要页。用户应能在不理解整张关系图的情况下快速进入完整内容。

## 5. 体系活动

工作台内的“体系”不是返回模块首页，也不是重新打开全量目录。它显示05定义的 L2/L3局部地形：

- 当前焦点在正式路径中的位置。
- 父分支、同级知识和必要的上下级上下文。
- 当前镜头和焦点高亮。
- “返回完整地形”操作，用03快照恢复原 L0–L2范围。

用户从体系活动切回关系或阅读时焦点不变。需要换知识时必须执行显式 `SELECT_POINT` 或关系 `FOLLOW_RELATION`，不能因滚动经过节点自动换焦点。

## 6. 阅读前关系定向

### 6.1 目标

关系定向只回答三类问题：

- 阅读前需要先知道什么。
- 最容易与什么混淆。
- 它与哪个邻近知识存在明确联系。

它不展示两跳关系、全库网络或复杂筛选。

### 6.2 数量与选择

最多展示3条，每种类型最多1条：

```text
1. 当前路线明确要求的前置/下一步关系
2. prerequisite：直接前置
3. contrast：最需要辨析的易混项
4. related：明确相关项
```

总数达到3后停止。没有人工策展优先级时，按关系类型、方向、目标知识正式导航顺序和关系 ID确定，不能使用黑箱“相关度”或关系度数猜测重要性。

每条提示必须展示：

- 关系类型与方向。
- 目标知识标题。
- “为什么有关”的简短理由；可截断视觉行数，但必须可展开完整理由。
- 目标知识所在路径，跨分支时必须显示。

如果当前点无正式关系，定向区域显示路径、同级位置和完整阅读入口；不生成“可能相关”，也不显示“深入探索”。

## 7. 深度关系探索

### 7.1 一层局部图

深度探索始终以当前焦点为中心，只展示受控一层：

```text
当前焦点
├─ 前置 / 派生后续
├─ 易混
└─ 相关
```

- 图形视窗最多同时显示6个关系邻居。
- 超出部分按类型进入“查看全部 N 条”的列表等价视图。
- 切换镜头只过滤当前一层，不展开邻居的邻居。
- 每条边或列表项都显示类型、方向和理由。
- 反向关系由04构建器派生并明确标识，页面不写回关系。

### 7.2 确定性排序

关系展示优先级：

1. 当前目标路线直接使用的关系。
2. 当前选择的关系镜头类型。
3. `prerequisite`、`contrast`、`related` 的稳定类型顺序。
4. 方向、目标知识正式导航顺序、关系 ID。

排序只决定可见顺序，不改变关系事实和路线顺序。

### 7.3 先预览再切换焦点

点击相邻节点先打开关系预览：

```text
目标知识标题与路径
关系类型、方向和完整理由
显式一句话理解（若有）
来源/正文锚点（若有）

操作：切换焦点｜阅读全文｜在体系中定位
```

- 打开预览不改变焦点、不写探索轨迹。
- “切换焦点”执行 `FOLLOW_RELATION`，记录来源关系并以目标知识重新居中。
- “阅读全文”先通过该关系切换焦点，再进入目标知识阅读，轨迹仍可返回来源知识。
- “在体系中定位”使用临时 system 快照；返回后仍是原焦点和预览。

### 7.4 探索回返

沿 A→B→C切换后，工作台显示可理解的来源提示，并按03逐步返回 C→B→A。不能依赖微信页面栈，也不能把“返回上一个知识”与“退出工作台”混成同一操作。

## 8. 阅读：一个完整语义内容流

### 8.1 不建立正文副本

阅读直接渲染04的 `KnowledgeUnit.blocks`，按源顺序完整覆盖内容。速览、结构理解、重点和证据都是对同一块集合的引用或增强，不保存另一份摘要正文。

### 8.2 推荐阅读结构

```text
一句话理解（显式存在时）
内容结构/本页目录
完整语义内容流
├─ definition / conclusion
├─ hierarchy / sequence
├─ condition / exception
├─ contrast
├─ 普通标题、段落、列表、表格
└─ evidence / 来源
```

- 一句话理解用于进入，不替代完整内容。
- 内容结构由 heading 与块顺序派生，可跳转但不重排正文。
- 增强块使用稳定语法，未知语义按原结构显示。
- 条件、例外和否定边界不能因“只看重点”被隐藏。
- 证据可以折叠，但必须与对应内容块或知识单元保持引用。

### 8.3 重点透镜

`keyPoints` 只改变强调程度，不删减完整内容。它可以突出 definition、conclusion、condition、exception 和 contrast；未显式标记的正文保持普通显示。第一轮不使用关键词扫描自动标红。

### 8.4 专注阅读

专注阅读只隐藏关系提示、辅助工具和非必要控制器外观；必须保留：

- 当前知识身份和退出方式。
- 阅读位置和内容锚点。
- 返回来源。
- 来源/纠错的可访问路径。

退出专注阅读恢复原工作台状态，不重新加载到知识顶部。

## 9. 回忆与失败补救接口

06只定义回忆怎样接入当前焦点，具体路线、题型和补救编排由07冻结。

- 无目标路线时，回忆范围默认为当前知识的正式 `RecallItem`。
- 有目标路线时，可使用当前路线 `scopeId`，但控制器必须显示范围。
- 当前知识和范围都没有回忆项时，回忆活动不可用，不随机生成。
- 揭晓、正确/错误和补救步骤属于03会话状态，不写入内容包。

最低失败补救链：

```text
一句提示（仅在 RecallItem 显式提供时）
→ 在体系中的位置
→ 易混对照（有正式数据时）
→ 对应原文块
```

回看原文后必须能回到同一回忆项及揭晓状态；没有对应增强数据时跳过该补救层，不生成内容。

## 10. 正文、关系和回忆双向定位

### 10.1 统一锚点

| 来源 | 目标 | 使用字段 | 返回 |
|---|---|---|---|
| 关系预览 | 正文理由依据 | `sourceBlockIds/targetBlockIds` | 原关系预览和镜头 |
| 正文块 | 相关关系 | 引用该 `blockId` 的 relation | 原阅读块和滚动锚点 |
| 回忆项 | 答案依据 | `sourceBlockIds` | 原回忆项和揭晓状态 |
| 正文块 | 回忆练习 | 引用该 `blockId` 的 recall item | 原阅读块 |
| 体系焦点 | 正文 | `pointId + blockId?` | 原地形范围和视窗 |

### 10.2 定位行为

- 进入阅读后定位并短暂强调目标块，同时显示“来自关系/回忆/体系”的来源说明。
- 返回优先使用03的 `returnTarget` 和活动快照。
- 块 ID失效时回知识顶部并说明原定位失效，不能跳到标题相似段落。
- 一个关系引用多个块时先展示块列表或定位第一块并允许逐项查看，不能暗中选择唯一依据。

## 11. 能力与空状态

| 情况 | 工作台行为 |
|---|---|
| 模块无关系能力 | 控制器不显示关系；从体系建立焦点后直接阅读 |
| 模块有关系能力、当前点无关系 | 关系定向显示路径上下文；无深度探索入口 |
| 当前点无回忆，路线也无有效回忆 | 控制器不显示回忆 |
| 缺少一句话理解 | 省略，不从正文随机截断 |
| 缺少精确内容锚点 | 关系/回忆仍可知识级追溯，并在 review 构建报告警告 |
| 关系超过图形预算 | 图形显示6个，完整列表显示全部 |
| 未知语义块 | 按04结构和 `fallbackText` 完整显示 |
| review 内容 | 显示明确状态；不能由工作台批准或发布 |
| 焦点内容更新 | 按03协调版本、锚点、轨迹和路线 |

“无数据”不是一个需要漂亮占位的大页面；可选活动应隐藏或退回仍有真实内容的活动。

## 12. FocusWorkbenchViewModel

推荐由纯控制器从运行包和上下文生成：

```text
FocusWorkbenchViewModel
├─ focus
│  ├─ pointId / title / path
│  ├─ summary
│  └─ status / source
├─ currentActivity
├─ availableActivities[]
├─ systemStage
├─ orientationStage
├─ relationStage
├─ readingStage
├─ recallStage
├─ controller
├─ returnModel
└─ diagnostics
```

输入为：

```text
KnowledgePackage
+ ModuleProfile
+ KnowledgeContext
+ viewport class
= FocusWorkbenchViewModel
```

相同输入必须产生相同关系选择、顺序、活动可用性和内容块引用。页面只渲染并发送03定义的事件，不复制正文、不自行排序知识事实、不推断关系。

### 12.1 渐进迁移

- 政治可先由现有详情/地图页面包裹共享控制器，逐步替换为统一工作台。
- 常识和笔记在 SourceAdapter 与行为回归建立前继续使用旧页面。
- 通用组件默认关闭；模块 profile 和适配器达到门禁后逐模块启用。
- 共享组件升级不得静默改变未启用模块的路由、数据和本地状态。

## 13. 三模块代表性场景

### 政治：完整能力

进入知识后先显示路径、一句话和最多3条关系定向；可阅读全文或进入最多6邻居的一层关系图。语义正文保留固定表述、条件和易混边界，回忆可定位原文。全部仍是 review 时只进入隔离入口。

### 常识：能力按分类启用

法律知识可以有易混、条件、例外、表格和回忆；没有正式关系的分类只显示体系路径与完整阅读。工作台不能因为其他分类有关系就给全模块所有知识显示关系图。

### 笔记：弱关系与训练增强

默认工作台提供体系和阅读；只有存在正式关系或回忆数据时增加对应活动。“练对应题型”由笔记 profile作为增强操作展示，不冒充 `related` 关系，也不改变通用活动顺序。

## 14. 验收场景

### WORK-AC-001：建立焦点后的定向

给定政治知识存在正式关系，从地形建立焦点后先显示路径、一句话和不超过3条关系提示，并以完整阅读为主操作。

### WORK-AC-002：四活动共享焦点

在体系、关系、阅读和回忆之间切换时，`moduleId`、`pointId`、内容版本、目标和返回来源保持不变，各活动恢复自己的快照。

### WORK-AC-003：关系定向确定性

相同运行包和上下文连续生成两次定向，关系选择和顺序一致；不会因关系图布局或访问次数改变。

### WORK-AC-004：预览不改焦点

点击相邻节点只打开预览；取消后焦点和轨迹不变。确认切换后才新增轨迹并以目标知识居中。

### WORK-AC-005：受控一层与完整列表

当前知识有9条关系时，图形最多展示6个邻居，列表可访问全部9条及其类型、方向和理由。

### WORK-AC-006：完整阅读不丢内容

关闭重点透镜和所有增强组件后，正文标题、段落、列表、表格、条件、例外和来源仍按正式顺序完整可读。

### WORK-AC-007：关系定位原文

从关系理由打开正文时定位对应块；返回恢复原关系预览、镜头和焦点。

### WORK-AC-008：回忆失败回看

从回忆项打开原文后定位 `sourceBlockId`；返回恢复同一回忆项和揭晓状态，不跳到下一张。

### WORK-AC-009：无关系/无回忆降级

笔记知识没有关系和回忆时，工作台只提供体系和阅读，页面无空关系图和空卡片入口。

### WORK-AC-010：专注阅读恢复

在长文中部进入并退出专注阅读，焦点、块锚点、滚动语义位置和返回来源不变。

### WORK-AC-011：无焦点防护

冷启动工作台但没有有效 `pointId` 时回模块体系入口，不打开第一篇知识或旧缓存正文。

### WORK-AC-012：模块隔离

政治启用新工作台时，常识和笔记未启用模块继续使用原页面、路由和本地状态；共享代码不读取其源模型。

## 15. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 目录、地图、文章、卡片四个独立功能页 | 用户必须自己重建焦点和认知链路 |
| 工作台把四活动内容同时展开 | 移动端过载，快照和专注阅读难以成立 |
| 关系定向先展示完整关系图 | 阅读前负担过重，阻碍进入正文 |
| 一次展示两跳或全库关系 | 快速形成线团，关系理由无法阅读 |
| 点击邻居立即换知识 | 容易误触，无法判断切换依据，也污染轨迹 |
| 用“智能相关度”选择定向关系 | 缺少可解释数据，结果不稳定且无法审核 |
| 为速览、结构和完整内容维护三份正文 | 形成内容副本，纠错和版本必然漂移 |
| 重点模式隐藏普通正文或条件 | 用户看到的内容不完整，可能改变事实含义 |
| 没有回忆项时随机生成卡片 | 违反来源和内容锚点契约 |
| 可选活动保留可点击空页面 | 形成空壳功能，违背能力诚实性 |
| 为政治单独实现焦点状态和关系控制器 | 无法迁移常识、笔记及后续模块 |
| 由页面保存关系排序和正文副本 | 页面成为第二事实源，更新和纠错无法维护 |

## 16. 已接受的工作台决策

| 决策 ID | 推荐决定 | 主要影响 | 状态 |
|---|---|---|---|
| WORK-001 | 采用一个逻辑 FocusWorkbench共享焦点、上下文栏、活动控制器和返回模型 | 物理页面可渐进迁移，但产品状态保持统一 | Accepted |
| WORK-002 | 控制器固定“体系—关系—阅读—回忆”语义顺序，活动按有效能力出现 | 保持认知链路且不显示空壳入口 | Accepted |
