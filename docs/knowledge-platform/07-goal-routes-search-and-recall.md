## 1. 本文要解决什么

本文冻结快速了解、系统学习、易混突破和考前速记怎样编排体系、关系、阅读和回忆；同时定义搜索结果、结构化问题入口、回忆类型、失败补救、路线恢复和完成条件。

本文不建立掌握度模型、遗忘曲线、会员进度或自由生成式问答。路线完成只说明用户完成了本次明确步骤，不能宣称“已经掌握”。

## 2. 三层路线模型

路线不能既当正式知识又当用户状态。推荐分三层：

```text
LearningRouteDefinition：模块声明的路线类型、范围政策和步骤模板
        ↓ 系统按有效会话、上下文、profile与正式顺序确定性推荐；用户可次级调整
LearningRoutePlan：本次冻结的知识/活动顺序和依据
        ↓ 用户执行
RouteSession：当前位置、完成步骤、补救状态和返回目标
```

### 2.1 LearningRouteDefinition

```text
LearningRouteDefinition
├─ id
├─ moduleId
├─ type: quick | systematic | confusion | exam
├─ label
├─ scopePolicy
├─ requiredCapabilities[]
├─ stepTemplate[]
├─ orderingPolicy
├─ completionRule
└─ fallbacks[]
```

定义只说明路线规则，不列出正文、答案或固定知识副本。

模块可在profile提供`routeDefaults`作为无会话、无当前焦点时的确定性推荐输入：

```text
routeDefaults
├─ quick: scopeId, anchorNodeIds[], reason
├─ systematic: scopeId, allowedScopeIds[]/allowedScopeTypes[], reason
├─ confusion: priorityRelationIds[], reason
└─ exam: scopeId, order, reason
```

字段只保存稳定ID、允许范围、顺序和用户可解释理由，不复制正文、关系理由或答案。缺少显式默认时只能按正式目录顺序诚实生成，并说明依据；页面不得使用数组第一项、浏览热度、关系度数或标题相似度代替profile。

### 2.2 LearningRoutePlan

```text
LearningRoutePlan
├─ id
├─ definitionId
├─ moduleId
├─ type
├─ scopeId
├─ packageVersion
├─ seed?
├─ basis[]
├─ steps[]
│  ├─ stepId
│  ├─ activity
│  ├─ pointId / navigationNodeId
│  ├─ relationId / blockId / recallItemId?
│  ├─ required
│  └─ reason
├─ completionRule
└─ frozenOrder[]
```

计划必须说明“为什么选这些知识、为什么按此顺序”。相同 package、profile、路线定义、范围和随机种子必须生成相同计划。

### 2.3 RouteSession

```text
RouteSession
├─ planId
├─ packageVersion
├─ currentStepId
├─ completedStepIds[]
├─ skippedStepIds[]
├─ currentRecallState?
├─ remedyState?
├─ status: active | completed | abandoned | expired
├─ startedAt
└─ updatedAt
```

`RouteSession` 属于03用户状态，不进入知识包。它可以记录本次是否揭晓、回看或跳过，用于恢复路线；这些记录不自动转成长期掌握度。

## 3. 路线建立、恢复与失效

### 3.1 冻结路线前必须有明确范围

范围只能来自可解释来源：

- 整个模块或模块 profile明确推荐的总览范围。
- 正式导航节点及其后代。
- 当前知识焦点。
- 已确认易混关系集合。
- 最近有效路线范围。
- 用户明确选择的多个知识，后续能力启用时。

不得以知识数组第一项、页面当前排序或未说明的全库随机建立范围。

### 3.2 可恢复状态

本地只保存最近活动路线摘要和 `RouteSession` 必要字段；计划本身可以由 `definitionId + scopeId + packageVersion + seed` 重建。恢复时先验证 package、范围、步骤和能力，再定位当前步骤。

### 3.3 内容版本变化

路线计划绑定 `packageVersion`：

1. 计划涉及的知识、关系、块和回忆版本均未变化：继续。
2. 仅无关内容变化：重新计算计划相关哈希，一致则继续。
3. 某步骤内容或答案变化：旧会话标记 `expired`，提示重建路线。
4. 重建时仅对内容版本未变的知识保留“已访问”参考；不把它当新计划已完成。
5. 范围已删除或一对多拆分：计划失效并重新生成推荐范围；用户可次级调整，不按标题猜测。

不能在用户不知情时用新答案继续旧回忆会话。

## 4. 快速了解路线

### 4.1 适用目标

让从未系统学习、只有零星印象或时间有限的用户先回答“这个领域主要在解释什么、两条主线怎样相连、代表性方法和现实回答位于哪里、下一步可深入什么”，不要求阅读全文、遍历目录或完成知识卡。

### 4.2 推荐范围

- 默认由系统按`profile ∩ data ∩ target`选择一份经审核、可构建、可失效的有限导读制品，并在入口说明覆盖边界和依据；用户不先进入篇章或范围选择器。
- 导读中的事实判断、连接点、代表例和参考表达必须逐项引用04定义的正式unit/block/atom或已确认关系；页面、profile和路线不得复制第二份政治事实。
- L0/L1结构只作为“当前内容位于整体哪里”的轻量定位层，不能取代解释正文，也不能要求用户逐站点击。完整KnowledgeSpace和KnowledgeCard只作为可选深入出口。
- 导读制品缺失、审核状态不合格或任一必需引用失效时，快速了解能力应诚实显示为内容暂不可用；可以提供“浏览知识空间”，但不得把目录游降级后仍称快速了解完成。

### 4.3 路线步骤

```text
从首页一键进入真实导读内容
→ 连续理解两条主线、正式连接点、代表方法与现实例子
→ 结构定位随内容逐段高亮；完整知识详情始终可选、不构成关卡
→ 一次可提交或明确暂缓的轻量自我解释
→ 合拢整体、显式结束，并选择知识空间、完整知识或后续目标
```

导读正文采用单列连续流，段落之间不设置“下一站”通行按钮；滚动、打开详情、查看来源或进入viewport都不能自动完成。模块可以使用有限策展锚点取材，但锚点不是必须逐个打开的正文入口，正式目录顺序也不强制等于导读的理解顺序。

### 4.4 完成条件

用户到达导读收束段，自我解释已提交或明确暂缓，并显式结束本次导读，才记录本次路线完成。快速滚到底、遍历结构、打开锚点或停留达到某个时长都不能自动完成。结果只报告到达段落、实际打开的可选详情、自我解释状态和保存事实，不显示“已理解”“已掌握”、正确率或由停留时间推断的学习效果。

详细v2规格和首版政治内容已于2026-08-31确认，但仍处于`not implemented`；规格确认不等于OUT-J2通过，也不授权进入J3。

## 5. 系统学习路线

政治下一版候选以[小单元产品方案](./implementations/politics-systematic-understanding-v2-product-plan-20261020.md)和[实施规格](./implementations/politics-systematic-understanding-v2-implementation-spec-20261020.md)为已授权目标：每次围绕小目标连续阅读，明确结束后才记录单元已读；参考自我解释可选，不必逐篇回忆；已读与掌握不混同。多个主题的恢复由同一系统学习存储所有者持有。以下 5.1 至 5.4 保留为当前旧 J3 运行合同，不能直接拿旧门禁通过授予新候选通过。

### 5.1 推荐范围

系统必须先按profile默认、当前有效上下文或最近兼容范围推荐一个正式导航范围，并展示知识数量、预计步骤数、首尾知识、依据和范围外前置要求；用户可次级调整。当前版本不承诺准确学习时长。

### 5.2 排序算法

```text
范围内 KnowledgeUnit
→ 按 prerequisite 建立约束
→ 在约束内拓扑排序
→ 同一可选层按正式导航 order，再按稳定 ID
```

- 范围外前置知识不静默加入路线；开始前单独列为“建议先了解”，系统给出默认处理，用户可选择加入或只做提示。
- 模块声明 prerequisite 必须无环时，存在环则构建/计划失败，不能退化成随机顺序。
- 没有前置关系时使用正式目录顺序。

### 5.3 每个知识的步骤模板

```text
定位、前置与关系提示（KnowledgeCard顶部元数据，不是独立完成步骤）
→ 完整理解（reading）
→ 当前知识回忆（有正式卡片时）
→ 下一知识
```

到达正式导航边界时，可插入“阶段回看”：显示已经访问的结构和现有回忆项；没有回忆数据时只做体系回顾，不生成题目。

### 5.4 完成条件

完成范围内所有 `required` 步骤。跳过项保留在本次报告中；路线可以结束，但明确标记“有跳过”，不折算掌握率。

## 6. 易混突破路线

### 6.1 启用条件与范围

只使用已确认 `contrast` 关系或显式 `contrast` 内容块。没有正式易混数据时隐藏入口，不能从相似标题自动生成。

系统推荐范围可以来自：

- 一对明确易混知识。
- 某正式导航区域中的全部易混对。
- 当前焦点直接关联的易混项。

进入目标时必须先推荐一组正式ContrastPair并说明依据；换组或限定区域属于次级控制，不能先展示全部对照供用户编排。

### 6.2 每对步骤

```text
系统推荐正式A/B及理由
→ 在同一维度先判断，记录answered/unsure/skipped
→ 揭示并核对正式边界
→ 分别回看两侧Atom/Block证据
→ 在同一维度再辨，记录clear/fuzzy/missed
```

对照不能只显示两个标题；必须有理由或正式对照块。一个易混对没有回忆项时仍可完成“对照阅读”，但不能显示“辨析通过”。

### 6.3 完成条件

完成初答、正式边界、双方证据和复答四阶段。完成页只报告本次初答/复答与核对事实，不显示正确率或掌握度；任何正式pair、维度、边界或双侧锚点缺失都不能进入完整四阶段。

## 7. 考前速记或快速回顾路线

### 7.1 无焦点入口

入口顺序固定：

```text
恢复最近有效卡组（存在时）
或 按profile/当前上下文生成推荐范围
→ 用户可次级调整范围或明确开启随机
→ 显示可用回忆项数量
→ 用户开始
```

绝不默认第一篇知识，也不在未说明范围时全库随机。

### 7.2 计划冻结

- 只包含推荐或调整范围内正式、版本有效的 `RecallItem`。
- 默认按profile/目录顺序；用户可明确切换随机顺序。
- 随机模式在开始时冻结 seed 和 item ID 列表，恢复时不重新洗牌。
- 没有卡片的知识明确计入“无回忆项”，不从正文临时挖空。
- 有效回忆项为0时不允许开始，转到完整阅读或其他范围。

### 7.3 单项步骤

```text
只显示提示
→ 用户主动回忆
→ 揭晓答案
→ 记得 / 模糊 / 未记得 / 跳过（仅本次会话）
→ 需要时逐层补救
→ 下一项
```

这些选择只用于本次路线汇总和补救，不写成长期掌握度；P4学习状态另行设计。

### 7.4 完成条件

冻结列表中的每项均被揭晓并自评或明确跳过。报告分别显示remembered/fuzzy/missed/skipped/reviewed；fuzzy和missed都进入待回看队列，不输出百分制掌握度。

## 8. 搜索索引与结果模型

### 8.1 索引范围

搜索索引由04运行包派生，可包含：

- 知识标题与别名。
- 正式导航路径和标题块。
- 显式一句话理解。
- 完整正文块及 semantic 类型。
- 关系理由和目标标题。
- 回忆提示，不默认索引隐藏答案文本作为直接摘要。
- 来源标题/定位的可读部分。

review/release 搜索只能索引各自运行包中的对象，不能因共用索引泄漏 review 内容。

### 8.2 可解释排序

第一轮排序优先级：

```text
1. 标题/别名精确命中
2. 标题前缀或完整词命中
3. 正式路径/正文标题命中
4. 显式语义块命中
5. 普通正文命中
6. 关系理由或回忆提示命中
同级：正式导航顺序 → 稳定 ID
```

排序可以有内部匹配分数，但用户可见结果必须说明命中位置，不能只展示不可解释的“相关度”。访问次数、收藏和运营热度不改变正式搜索排序，除非未来作为明确可切换排序。

### 8.3 SearchResult

```text
SearchResult
├─ pointId
├─ title
├─ path
├─ matchKinds[]
├─ snippets[]
│  ├─ blockId?
│  ├─ semantic
│  └─ safeText
├─ targetActivity
├─ targetAnchor
└─ status
```

结果行必须回答“命中了什么、位于哪里”，并明确一次点击会进入正文块、关系、回忆或体系位置中的哪一个目标；不再列出三种同权去向。

### 8.4 点击结果直接提交精确目标

- 正文、关系和回忆命中在点击时一次建立焦点，并携带blockId、relationId或recallItemId进入独立KnowledgeCard。
- 体系位置命中直接进入KnowledgeSpace并高亮，不建立伪知识焦点。
- 不存在`search-preview`或“体系/关系/全文”三个并列动作。
- 返回恢复查询词、筛选、结果序号和滚动锚点。

空查询显示模块主要区域、最近搜索或结构化问题入口；不默认加载全量知识平铺。

## 9. 结构化问题入口

第一轮不做生成式自由问答，而是把用户意图映射到已有结构和来源：

| 问题类型 | 依据 | 结果形式 |
|---|---|---|
| 是什么 | definition/conclusion、标题和摘要 | 直接进入命中正文块 |
| 为什么/什么关系 | Relation.reason、evidence | 直接进入卡内关系情境和原文锚点 |
| 有什么区别/易混 | contrast关系与内容块 | 对照 + 易混路线 |
| 条件/范围/例外 | condition/exception块 | 命中块 + 上下文 |
| 在哪里/属于什么 | NavigationNode | 地形定位 |
| 怎么回忆/考什么 | RecallItem.prompt | 展示系统推荐/恢复的卡组后开始回忆 |

用户可显式选择问题类型并输入关键词。若系统不能唯一定位，只返回候选及依据；不能拼接多个片段生成一个貌似确定的新答案。单一显式语义块可展示为“来源内容”，但必须带路径、版本和阅读全文入口。

## 10. 主动回忆类型

### 10.1 第一轮正式能力

- `qa`：正式提示、答案、易错及原文块。
- `contrast-qa`：显式编写的易混辨析问答，本质仍是可追溯 RecallItem。
- `terrain-hide`：从正式导航投影生成的结构恢复练习。

`terrain-hide` 是 `NavigationNode` 的确定性视图练习，不是内容卡片：它引用节点 ID、父路径和 packageVersion，答案只是被隐藏的正式节点标签。它不能生成新的事实问题，也不进入正文 RecallItem 数量。

### 10.2 延期能力

填空、顺序、连线、层级重建和时间线排序只有在对应显式结构数据、来源、校验和无手势替代均成熟后才能启用。不能从标点、列表序号或关键词自动推断正式题目。

## 11. 失败补救

补救由用户主动逐层展开，每层最多出现一次，不设置强制等待：

```text
1. 显式提示（RecallItem提供时）
2. 体系位置和路径
3. 易混对照（有正式数据时）
4. 对应原文块
5. 完整内容
```

- 缺少某层数据时跳过，不生成。
- 打开原文使用 WORK-010，返回同一回忆项和揭晓状态。
- 看过原文后本次状态标记“已回看”，不能再记为一次独立正确回忆。
- 用户可以继续下一项或稍后重做，但当前版本不自动安排间隔复习。

## 12. 路线能力与模块文案

| 模块 | quick | systematic | confusion | exam |
|---|---|---|---|---|
| 政治 | 快速了解 | 系统学习 | 易混突破 | 考前速记 |
| 常识 | 快速了解 | 系统学习 | 易混突破（有数据时） | 考前速记 |
| 笔记 | 快速了解 | 系统学习 | 易混突破（有数据时） | 快速回顾 |

启用条件仍取 profile、有效数据和构建目标的交集：

- quick至少需要正式导航和可读标题。
- systematic需要正式范围和稳定顺序。
- confusion需要正式 contrast。
- exam需要推荐或调整范围内至少1个有效 RecallItem。

模块可以修改文案和推荐入口顺序，但不能改变路线类型含义或删除范围说明。

## 13. P4边界

本期只预留接口，不实现：

- 收藏范围提供器。
- 错题/未记得集合。
- 间隔复习和日历计划。
- 跨设备学习历史。
- 掌握度、预测和个性化推荐。
- 会员进度和激励体系。

未来能力只能消费本期明确的 `RouteSession` 事件和内容版本，不能反向改变正式知识、关系或当前路线完成含义。

## 14. 纯派生模型

```text
RoutePlanner
  (KnowledgePackage + ModuleProfile + routeType + scope + seed?)
  → LearningRoutePlan

SearchProjector
  (KnowledgePackage + query + filters)
  → SearchResult[]

RecallProjector
  (KnowledgePackage + RouteSession + KnowledgeContext)
  → RecallViewModel
```

相同输入必须生成相同顺序、范围、依据和可用操作。页面只更新03会话事件，不复制计划正文、答案或搜索索引。

## 15. 验收场景

### LEARN-AC-001：无焦点速记

首次进入政治点击考前速记时必须恢复有效卡组或展示profile生成的推荐范围；没有可解释范围不能开始，也不能打开第一篇。调整和随机只作为次级控制。

### LEARN-AC-002：系统学习排序

给定范围内存在前置关系，计划满足所有前置约束；同层按正式顺序稳定排列，并解释范围外前置知识。

### LEARN-AC-003：无关系系统学习

笔记范围没有前置关系时按正式目录顺序生成路线，仍可完成体系与阅读，不伪造学习路径。

### LEARN-AC-004：易混门禁

某常识分类没有正式 contrast 时不显示易混突破；有正式易混对时每一步都能查看关系理由和对照依据。

### LEARN-AC-005：随机路线恢复

在明确范围内随机生成10张速记卡，退出并恢复后 item ID和顺序不变，不重新洗牌。

### LEARN-AC-006：完成不等于掌握

路线结束只显示 required完成、揭晓、回看和跳过数量；任何页面都不输出无依据掌握百分比。

### LEARN-AC-007：版本失效

回忆答案对应内容版本变化后，旧会话标记过期并要求重建，不能继续显示旧答案。

### LEARN-AC-008：搜索可解释

标题精确命中排在普通正文命中之前，每条结果显示路径、命中类型和安全片段；相同输入排序一致。

### LEARN-AC-009：搜索回返

从搜索定位体系、再进入关系或阅读后返回，恢复查询、结果序号和列表位置。

### LEARN-AC-010：问题入口不编答案

条件类问题只有多个候选块时显示候选和来源，不拼接成新的确定答案。

### LEARN-AC-011：回忆补救回返

从卡片逐层查看体系、易混和原文后，返回同一回忆项；本次记录显示已回看而非独立正确。

### LEARN-AC-012：review/release隔离

政治 review路线只能引用 review运行包；release搜索和路线不能发现未发布知识或卡片。

## 16. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 四类目标只是首页四个跳转按钮 | 没有范围、依据、步骤和完成条件，不构成产品路线 |
| 路线复制摘要、正文或答案 | 形成第二事实源，内容更新后必然漂移 |
| 系统学习只按目录或只按关系 | 前者忽略前置，后者破坏正式体系；应使用约束内正式顺序 |
| 静默加入范围外所有前置 | 推荐或调整后的范围失控，步骤数不可解释 |
| 标题相似自动生成易混对 | 相似不等于易混，可能制造错误关系 |
| 无范围全库随机卡片 | 用户不知道正在复习什么，也无法恢复计划 |
| 每次恢复重新随机 | 路线无法继续，完成状态失真 |
| 看完或答完直接记为掌握 | 没有证据，制造虚假进度 |
| 自由问答拼接搜索片段 | 容易产生来源未支持的新结论 |
| 从正文自动挖空生成题目 | 破坏条件与事实完整性，且无法审核 |
| 低分自动安排复习 | P4学习状态尚未定义，当前事件不足以支撑 |
| 搜索结果先进入知识预览再决定去向 | 增加无信息增益的一层并恢复同权动作冲突 |
