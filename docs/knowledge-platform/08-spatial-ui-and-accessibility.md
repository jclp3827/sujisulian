## 1. 本文要解决什么

本文冻结跨模块共享的页面层级、空间连续性、视觉语义、动效、阅读密度、字号、触控、安全区、性能和无地图/低动画降级。目标是让体系、关系、阅读和回忆在移动端看起来属于同一认知空间，而不是四套相邻页面。

本文不修改03的状态、不改变05的层级、不重新选择06的关系，也不为摘要创建内容副本。视觉只能表达已确认的知识语义，不能替数据作判断。

## 2. 当前主题基线与演进方式

项目已有 `styles/theme.wxss` 和 `styles/ui.wxss`，包含全局背景、卡片、蓝/绿/橙/紫、文字、间距、圆角和阴影变量。V2采用“增加知识语义别名、逐步迁移组件”的方式，不在政治页面重新硬编码一套颜色和尺寸。

推荐知识语义别名：

```text
--knowledge-system-text      → 深绿色
--knowledge-system-soft      → 浅绿色
--knowledge-reading-text     → 深蓝色
--knowledge-reading-soft     → 浅蓝色
--knowledge-boundary-text    → 深橙色
--knowledge-boundary-soft    → 浅橙色
--knowledge-recall-text      → 深紫色
--knowledge-recall-soft      → 浅紫色
--knowledge-evidence-text    → 次级灰
--knowledge-evidence-soft    → 中性灰底
```

首轮可复用现有 `--color-green-700`、`--color-primary-600`、`--color-orange-700`、`--text-secondary` 和 soft背景；紫色正文需要使用达到对比度的更深语义别名，不能直接假设现有装饰紫适合小字号文字。

## 3. 页面层级

### 3.1 模块首页

第一屏信息顺序：

```text
模块标题 + 一句话说明
L0知识地形（第一视觉主体）
继续探索（有最近焦点时）
四类目标的紧凑入口
搜索/结构化问题入口
内容状态说明（需要时）
```

- L0地形必须是第一屏最大信息区域，不能再由四张功能卡抢占主视觉。
- 四类目标采用紧凑路线入口，显示范围要求或能力状态，不重复内容。
- 没有最近焦点时隐藏继续探索，不用第一条知识占位。
- 首页只到建立焦点或开始路线，不平铺全量知识。

### 3.2 焦点工作台

```text
ContextBar：路径 / 焦点 / 返回
GoalStrip：当前路线和步骤（存在时）
ActivityStage：当前活动主内容
ActivityDock：体系 / 关系 / 阅读 / 回忆
```

上下文栏滚动前显示完整信息，滚动后可压缩为当前知识短标题和返回来源，但完整路径必须可展开。活动舞台是唯一主滚动区域，不能在一屏同时滚动四个活动。

### 3.3 活动控制器

- 工作台子页面默认使用底部 `ActivityDock`，位于 `safe-area-inset-bottom` 上方。
- 每个可用活动同时显示图形和短文字，触控高度至少44逻辑像素。
- 不可用活动按 WORK-002/011移除，不出现可点击空页。
- 若物理实现仍位于主 Tab 页面，不能叠加两条完整底栏；活动控制器改为内容内粘性分段，但语义和顺序不变。
- 专注阅读可以收起 Dock，但保留清晰的退出专注入口。

## 4. 视觉语义

### 4.1 固定认知色

| 语义 | 主色 | 必须同时使用的非颜色信号 |
|---|---|---|
| 体系、正式路径、前置 | 绿色 | 主干/方向箭头/“体系、前置”文字 |
| 阅读、定义、结论 | 蓝色 | 左侧阅读标记/“定义、结论”标签 |
| 易混、条件、例外、边界 | 橙色 | 双栏、分界线、警戒形/明确标签 |
| 回忆、提示、揭晓 | 紫色 | 问号/卡片正反状态/“回忆”标签 |
| 来源、版本、证据 | 灰色 | 文档形、来源标题、版本文字 |

状态色与知识语义分离：成功、错误、网络异常、review风险使用明确图标和文字。即使同样借用橙色，也不得只靠颜色让用户区分“知识边界”和“待校对风险”。

### 4.2 对比度

- 普通文字与背景至少达到4.5:1。
- 大号文字和关键非文字图形至少达到3:1。
- `--text-tertiary` 只能用于非关键辅助信息；来源操作、路径和状态不得使用低对比灰。
- soft背景上的正文使用对应深色文本，不使用装饰色原值。
- 每个语义标签必须在浅色、灰阶和色觉差异场景下仍可通过文字/形状识别。

### 4.3 模块品牌边界

模块品牌色只用于模块标题、插图、轻量背景或入口标识。政治、常识、笔记都必须使用同一认知色含义；政治不能用品牌红覆盖“阅读蓝/关系橙”，新模块也不能重新定义紫色为体系。

## 5. 内容块视觉语法

完整阅读不是“每段一个白色卡片”。推荐以连续文章流为基础，只对显式语义增强：

| SemanticBlock | 推荐形态 | 禁止 |
|---|---|---|
| `plain` | 连续正文、标题、列表、表格 | 每段套重阴影卡片 |
| `definition` | 蓝色细边/标题标签 + 完整定义 | 只突出关键词而隐藏定义条件 |
| `conclusion` | 蓝色重点块，视觉权重高于普通段落 | 自动把粗体都当结论 |
| `hierarchy` | 绿色层级线、缩进或树形列表 | 画成不可访问的小节点图 |
| `sequence` | 有序路径、步骤编号和连接线 | 只用颜色表达顺序 |
| `condition` | 橙色条件标签和适用范围 | 与错误提示使用相同无文字图标 |
| `exception` | 橙色边界块、明确“例外/不适用” | 折叠到默认不可见 |
| `contrast` | 双栏/上下对照，窄屏改纵向配对 | 只放两个标题不显示差异 |
| `evidence` | 灰色来源栏，可折叠但可定位 | 用低对比文字隐藏版本 |

表格在窄屏优先转为“字段—值”卡行或可辨识纵向对照；只有列语义必须横向比较时才允许容器内横向滚动，并提供列标题固定或重复。

## 6. 字体、间距与触控基线

### 6.1 字体

以750rpx设计宽度为例，推荐首轮基线：

| 用途 | 基线 | 最低要求 |
|---|---|---|
| 长文正文 | 34rpx / 17px等价 | 不低于32rpx，行高1.65–1.8 |
| 普通界面正文 | 32rpx | 行高不低于1.5 |
| 次级说明 | 26–28rpx | 关键信息不低于26rpx |
| 非关键标签 | 24rpx | 不承载唯一状态或操作 |
| 知识标题 | 44–50rpx | 长标题允许换行，不强制单行 |
| 分区标题 | 36–40rpx | 与正文层级明确 |

字体放大到130%时，正文、按钮和控制器不得裁切；行高随字号变化，不用固定像素高度包裹文字。

### 6.2 间距和内容宽度

- 常规手机水平页面边距16px等价，宽度≤360px时可降到12px。
- 长文单行以约18–24个常见汉字为舒适目标，不强制固定字符截断。
- 卡片/语义块间距12–16px，正文段落间距随行高计算。
- 宽屏内容正文设最大可读宽度并居中，地形可使用更宽的独立容器。

### 6.3 触控

- 主要和次要交互目标至少44×44逻辑像素。
- 相邻高频操作间至少8px间隔。
- 不依赖悬浮、双击或长按完成核心任务。
- 节点小于触控目标时扩大透明点击区，但不能让相邻节点区域重叠。

## 7. 空间转换语法

所有方向来自03状态和05位置，不由页面临时选择。

| 转换 | 空间含义 | 标准动效 | 无动画等价 |
|---|---|---|---|
| L0→L1→L2 | 进入所选区域 | 所选节点保持锚点，内容向内展开 | 更新面包屑、范围标题和选中态 |
| L2→L3 | 建立焦点 | 节点成为中心，周围出现受控邻域 | 明确“当前焦点”标题和路径 |
| L3→L4阅读 | 进入知识内部 | 焦点标题保留，内容从其下展开 | 同一标题、路径和返回目标连续显示 |
| 地形↔目录 | 同一范围换投影 | 短交叉淡化，焦点位置保持高亮 | 直接切换并保持选中 |
| 关系A→B | 沿关系换焦点 | B沿关系方向进入中心，A进入轨迹 | 更新“来自A/关系类型”提示 |
| 回忆/关系→原文块 | 深入证据 | 定位滚动 + 块高亮 | 直接定位并显示来源说明 |
| 返回 | 逆向恢复来源 | 与进入方向相反 | 恢复面包屑、选中和来源文字 |

动画不可替代状态；如果共享元素能力不可用，使用源节点短暂选中、目标标题一致和方向性淡化即可，不为动画引入第二状态模型。

## 8. 动效与低动画

### 8.1 标准动效预算

- 普通活动切换：120–180ms。
- 层级进入、关系换焦点、预览弹层：180–240ms。
- 单段转换上限300ms，不串联多段装饰动画阻塞操作。
- 优先使用 `transform` 和 `opacity`，避免大范围布局重排。
- 用户操作后100ms内必须出现按压、选中或加载反馈。

### 8.2 低动画模式

`motion=reduced` 时：

- 取消缩放、抛物线、视差和大距离平移。
- 使用0–80ms淡化或直接切换。
- 保留焦点环、面包屑、关系来源和块高亮。
- 自动滚动改为立即定位或短距离滚动。
- 不影响地图、目录、关系、阅读和回忆的任何完成路径。

低动画是用户显示偏好，不以设备性能差自动替用户永久设置；设备降级可以临时使用并提示。

## 9. DisplayPreferences

显示设置将不同问题分开，不能只提供一个“简洁模式”：

```text
DisplayPreferences
├─ fontScale: default | large | extraLarge
├─ lineSpacing: normal | relaxed
├─ density: comfortable | compact
├─ emphasis: normal | keyPoints
├─ motion: full | reduced
└─ systemProjection: terrain | directory
```

- 字号、行距、密度、重点程度和动画相互独立。
- `fontScale/lineSpacing/motion` 默认跨模块共享。
- `systemProjection` 按模块保存；某模块无地图能力时自动规范化为目录。
- compact只压缩地形、列表和辅助卡片间距，不把长文正文降到不可读字号/行高。
- keyPoints只增强04显式语义，不隐藏普通正文、条件和例外。

## 10. 响应式与安全区

### 10.1 宽度类别

| 宽度 | 规则 |
|---|---|
| ≤360px | 12px边距；地形采用纵向局部结构；对照改上下排列；活动标签保留 |
| 361–430px | 16px边距；标准移动布局 |
| >430px | 正文限制最大可读宽度；地形/关系可使用更宽容器但不增加数据密度 |

宽度变化只改变布局，不改变 MAP节点预算、关系顺序和路线步骤。

### 10.2 安全区与固定元素

- 底部 Dock、操作栏和弹层加 `safe-area-inset-bottom`。
- 顶部自定义栏读取实际 safe area，不能使用固定机型高度。
- 固定底栏必须为主滚动内容预留等高底部空间，最后一块内容可完全滚出遮挡。
- 键盘弹出时搜索、纠错和范围选择的主操作仍可见或可滚动到。
- 底部弹层最高不超过可用视窗约80%，内部滚动且保留关闭操作。

## 11. 地形与关系可访问性

- 图形节点按正式阅读顺序提供文本名称、角色、层级、数量和当前状态。
- 每张地形和关系图都必须有共享数据生成的列表等价视图。
- 若使用 Canvas，Canvas不能成为唯一交互层；屏幕阅读器使用同步语义列表。
- 连接线同时有类型标签、箭头或形态；不能只靠颜色。
- 当前焦点有明确焦点环和“当前知识”文字。
- 缩放有“上一级/下一级/查看全部”按钮。
- 关系预览的关闭、切换焦点和阅读全文拥有明确可读名称。

## 12. 阅读与表单可访问性

- 内容顺序与正式块顺序一致，屏幕阅读器不因视觉双栏改变事实顺序。
- 对照在读屏顺序中按“概念A—内容A—概念B—内容B—差异”组织。
- 展开/折叠控件声明当前状态和控制对象。
- 图标按钮必须有文字名称，不能只读作“按钮”。
- 纠错输入、范围选择和搜索筛选具有可见标签，不只使用 placeholder。
- 错误提示靠近字段并提供恢复操作。
- 揭晓答案不会自动跳到下一项，用户能控制读屏顺序。

## 13. 浅色、深色和模块主题

当前应用只有浅色全局主题。首轮政治 V2继续浅色，避免只为一个模块建立不完整暗色并影响常识/笔记。

同时必须做到：

- 新组件只使用主题/知识语义变量，不硬编码页面颜色。
- 阴影不是层级唯一手段，暗色未来可替换为边框和表面层。
- 图片、图标和关系线支持主题替换。
- 将暗色作为未来全应用迁移，不把“系统深色下仍显示浅色”误标为已支持暗色。

## 14. 性能预算

### 14.1 数据与渲染

- 页面只接收当前 `TerrainViewModel`、`FocusWorkbenchViewModel`、路线/搜索/回忆视图，不把整个 KnowledgePackage重复写入页面 `data`。
- 非当前活动使用懒加载或不渲染；切换后保留03语义快照。
- 地形遵守 L0≤8、L1≤12、L2≤16；关系图不超过6邻居。
- 长文先渲染可用首屏，超长块按稳定 blockId分批追加；分批不能改变顺序和锚点。
- 动画只使用轻量属性，避免同时更新大量节点。

### 14.2 可测目标

在约定的微信开发者工具中档设备配置上：

- 用户操作100ms内获得反馈。
- 纯投影函数正常样本单次执行目标≤50ms；超出必须记录诊断。
- 模块首页冷启动目标2.5s内出现可操作 L0主体，暖启动目标1.5s。
- 动效期间避免超过50ms的主线程长任务。
- 切换活动不重复解析正式 Markdown或重新构建全包。

性能目标通过开发工具数据和自动化计时获取，不使用 Computer Use代替测量。

## 15. 通用组件边界

首轮通用组件建议：

```text
KnowledgeHomeShell
KnowledgeTerrain / KnowledgeDirectory
ContextBar / GoalStrip / ActivityDock
RelationOrientation / RelationExplorer / RelationPreviewSheet
SemanticBlockRenderer / EvidencePanel
RecallSurface / RemedyTrail
SearchPreview / ScopePicker
DisplaySettings
```

组件输入只能是通用 ViewModel、语义 token 和事件回调。模块 profile可以提供标题、文案、能力和品牌轻量变量；页面不能把“政治篇章”“法律表格”“笔记题型”写入通用组件分支。

## 16. 手工 UI 验收清单

用户负责以下手测，Codex不使用 Computer Use：

1. 首页第一眼是否先理解知识领域，而不是先看到功能大厅。
2. L0→L3是否感到进入同一空间，并知道如何返回。
3. 目录/地形切换后焦点与位置是否连续。
4. 关系A→B后是否理解切换依据及返回方向。
5. 完整阅读是否不像纯文字堆积，也没有变成卡片海。
6. 条件、例外、易混和来源是否容易识别且不依赖颜色。
7. 回忆失败到原文再返回是否保持同一项。
8. 320px宽度、长标题和四活动控制器是否无横向溢出。
9. 130%字号下正文、按钮、弹层和底栏是否不裁切。
10. 低动画模式下是否仍能理解层级、方向和来源。
11. 地形/关系切到列表后是否完整等价。
12. 政治启用新 UI时常识和笔记既有行为是否未改变。

开发工具与自动测试负责尺寸、状态、性能、数据数量和路由证据；人工只判断认知、连续性和视觉可用性。

## 17. 验收场景

### VIS-AC-001：首页层级

政治首页第一屏以 L0地形为最大信息主体；目标和搜索可达但不以四张功能卡压过体系。

### VIS-AC-002：活动控制器

工作台底部控制器不遮挡最后一块内容，安全区正确；无关系/回忆时不出现空壳入口。

### VIS-AC-003：语义非颜色唯一

将页面转为灰阶后，体系、定义、易混、回忆和来源仍可通过文字、形状和位置区分。

### VIS-AC-004：空间往返

从 L2节点进入 L3和阅读后返回，源节点、焦点标题、路径和视窗一致；关闭动画后语义不变。

### VIS-AC-005：关系换焦点

A→B时新焦点方向与关系一致，并显示“来自A”；低动画模式使用文字和焦点环表达相同信息。

### VIS-AC-006：完整阅读

普通段落保持连续文章流，显式语义块得到增强；关闭增强后内容完整且顺序不变。

### VIS-AC-007：窄屏与放大

320px和130%字号下无页面级横向滚动，长标题完整可读，主要操作≥44px且可触达。

### VIS-AC-008：地图等价

不用双指、Canvas和动画，只用按钮与列表仍能访问所有节点、关系理由和返回目标。

### VIS-AC-009：主题隔离

政治模块品牌样式不改变绿色体系、蓝色阅读、橙色边界、紫色回忆的含义，也不覆盖常识/笔记主题变量。

### VIS-AC-010：性能

## 18. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 首页用四张大功能卡作为主体 | 再次把认知链路做成功能大厅 |
| 所有正文段落卡片化 | 形成卡片海，阅读节奏破碎，视觉层级失真 |
| 用动画制造实际不存在的连续性 | 动画关闭后产品逻辑消失 |
| 大幅视差、弹跳和长过渡 | 干扰阅读、增加眩晕和性能风险 |
| 只靠颜色区分活动和关系 | 色觉、灰阶和低对比环境下不可用 |
| 为政治写独立颜色和组件 | 无法迁移，且容易破坏现有模块主题 |
| 首轮只为政治增加暗色 | 形成不完整全局体验和两套维护成本 |
| 字号、行距、密度、重点绑定为一个模式 | 用户无法解决真实阅读需求 |
| 地图只在 Canvas中可读可点 | 屏幕阅读器、无地图和自动测试无法使用 |
| 用固定高度容器承载可变文字 | 字号放大、长标题和翻译后裁切 |
| 在页面 data放全量知识包 | setData和渲染成本随内容无限增长 |
| 用 Computer Use代替用户UI判断 | 不能代表用户认知验收，也违背既定测试协作 |
