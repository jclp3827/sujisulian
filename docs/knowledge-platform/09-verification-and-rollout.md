## 0. R0–R6恢复治理修订

本节优先于本文后续仍保留的S0至S6历史实施记录。恢复阶段不删除已有代码和门禁，只撤回它们尚未证明的产品结论。

### 0.1 两类证据不得互相冒充

- **工程基线**：字段、投影、路由、静态结构或CLI能够连接，最多证明`implemented`。
- **产品结果**：用户能在一条完整旅程中识别位置、理解当前任务、完成唯一下一步、返回且能从失败中恢复；只有用户验收能够达到`UX-passed`。
- A、B、C、D是动作、展现、语言和目标四个横向镜头，不再作为依次通过便可推出产品完成的纵向阶段。
- 禁止使用`follow-up optimization`掩盖未达到目标的CORE问题。未通过必须写成`UX-failed`并回到对应结果行。

### 0.2 产品结果状态

```text
specified → prototype-confirmed → implemented → UX-passed
                                  ↘ UX-failed
                                  ↘ waived-debt（仅非CORE）
```

- `specified`：问题、失败条件和Given/When/Then齐全。
- `prototype-confirmed`：关键空间或交互形式已经用户确认，尚未进入产品代码。
- `implemented`：代码和自动证据满足契约，尚未证明用户结果。
- `UX-passed`：用户按黄金旅程完成手测并确认结果。
- `UX-failed`：真实展现未达到预期；必须保留失败事实和唯一下一动作。
- `waived-debt`：只有非CORE缺陷可由明确所有者、理由和恢复条件暂缓；CORE结果不得豁免。

### 0.3 恢复实施顺序

1. `R0`统一真实状态、缺陷账本和候选指纹。
2. `R1`将仍有争议的设计思想改成可证伪假设，并提交P0裁决建议。
3. `R2`冻结J1至J5黄金旅程、允许/禁止形态与结果验收。

5. `R4`先建立能失败的纵向旅程门禁，再允许页面实现。

## 1. 本文要解决什么

本文把已冻结的产品规格转换为可执行、可验证、可回退的实施路径，回答：

1. 展现实现与内容校对如何互不冒充、也互不错误阻塞。
2. 政治首轮按什么顺序落地，每一阶段改什么、不改什么。
3. 自动验证与用户 UI 手测各负责什么。
4. 如何保证常识、笔记和后续新模块不被政治改造破坏。
5. 内容、状态、渲染或规格出现错误时回到哪一层纠正。
6. 政治验证后，通用能力如何逐模块推广而不一次性重写。

本文不重新决定00至08的产品规则，不批准任何待审内容发布，也不以实施便利为由降低数据或可访问性契约。

## 2. 两条状态轴必须分离

“页面能运行”和“内容可正式发布”是两个独立事实，禁止合并成一个 `done`。

### 2.1 展现实现状态

```text
Specified → Implementing → Implemented → Verified
```

- `Specified`：00至09均 Ready，可以开始对应切片。
- `Implementing`：正在编码，仍保留上一可运行阶段。
- `Implemented`：代码和自动门禁通过，尚待用户 UI 手测。
- `Verified`：用户完成规定手测，缺陷已闭环。

### 2.2 内容发布状态

```text
staging → review → approved → release
```

- 内容可在 `review` 状态完成解析、结构化、建图、搜索、回忆和隔离 UI 联调。
- 内容事实、来源、风险页或固定表述未完成校对时，不得进入 `approved/release`。
- 页面通过 `Verified` 不会自动改变内容发布状态。
- 内容批准也不会自动证明页面达到 V2 验收。

政治当前基线为37篇 `review`、11个风险页、`release=0`。因此可以完成 P3 V2 隔离展现验证，但不能以“UI完成”替代最终校对。

## 3. 每模块只使用一个有序实施阶段

为避免大量功能开关组合出无法验证的状态，每个模块只保存一个 `rolloutStage`：

```text
legacy
→ foundation
→ terrain
→ workbench
→ learning
→ candidate
→ verified
```

| 阶段 | 对用户可见的含义 | 回退目标 |
|---|---|---|
| `legacy` | 保持当前页面与行为 | 无 |
| `foundation` | 通用适配、状态和投影已接入，页面行为仍等同当前版 | `legacy` |
| `terrain` | 新首页、L0–L3地形和目录等价入口可用 | `foundation` |
| `workbench` | 焦点工作台、关系定向、语义阅读和返回恢复闭环 | `terrain` |
| `learning` | 四类路线、上下文搜索和主动回忆闭环 | `workbench` |
| `candidate` | 自动门禁全部通过，交由用户完整手测 | `learning` |
| `verified` | 用户手测通过，可作为该模块的 V2 验证实现 | `candidate` |

规则：

- `rolloutStage` 属于应用实施配置，不写进正式 Markdown 知识事实。
- 阶段按模块独立保存；政治推进时常识与笔记继续为 `legacy`。
- 回退只切回上一已验证阶段，不删除知识源、不修改发布状态、不迁移其他模块。
- 阶段只解决代码选择；深链、缓存和持久状态仍按03的版本与失效规则处理。

## 5. 推荐代码边界

首轮以现有页面为壳，新增通用纯逻辑和小粒度通用组件，不先重写常识与笔记。

```text
正式 Markdown / 模块现有事实源
  → 独立 builder 与 validator
    → 模块运行包 / review 包
      → ModuleAdapter
        → 通用状态、投影和路线纯逻辑
          → 通用 ViewModel 组件
            → 现有模块页面壳
```

推荐职责落点：

| 位置 | 只负责 | 禁止负责 |
|---|---|---|
| `scripts/` | 构建、审计、校验、确定性输出 | 页面展示状态 |
| `miniprogram/services/knowledge-platform/` | adapter、焦点状态、地形/工作台/路线/搜索/回忆投影 | 政治固定文案和页面样式 |
| `miniprogram/components/knowledge-*/` | 只消费 ViewModel、语义 token并发出标准事件 | 读取整库、决定关系、修改知识事实 |
| 现有政治 pages/subpackages | 路由、模块 profile、页面组合和阶段切换 | 复制通用规则 |
| 现有常识/笔记页面 | 在各自迁移前保持原行为 | 被政治切片隐式接管 |

精确文件清单在每个编码切片开始前依据当时工作区生成；本文冻结职责，不假定目录本身就是实现完成。

## 6. 政治首轮实施切片

每个切片必须形成独立可回归点：先通过自动门禁，再交给用户手测；失败只修改该切片涉及层，不能顺手扩大范围。

### S1 平台基础：`legacy → foundation`

**落实决策**：CORE、STATE、DATA、MAP投影边界、VIS-014、SHIP实施约束。

**实现**：

- 建立通用 `ModuleAdapter` 读取政治现有运行包，输出04规定的统一读取契约。
- 建立以 `moduleId` 分桶的焦点、轨迹、活动、层级、路线和显示偏好状态。
- 建立纯函数 ViewModel 投影与版本/失效恢复，不改变当前页面视觉。
- 建立 `rolloutStage` 选择和回退入口；政治初始仍显示现有实现。

**明确不做**：新首页、地图视觉、路线 UI、常识/笔记接入、内容发布。

**自动门禁**：adapter数量与ID一致；相同输入产生相同投影；跨模块状态不串桶；无效深链安全降级；`legacy/foundation` 页面输出与当前基线等价。

**用户手测**：无需完整视觉验收，仅确认政治、常识、笔记原入口均无行为变化。

**回退**：政治阶段退回 `legacy`；新增命名空间状态可保留但不得被旧页面读取。

### S2 首页与知识地形：`foundation → terrain`

**落实决策**：IA、MAP-001至MAP-012、VIS-001/003/005/006/009/010/012/013。

**实现**：

- 政治首页采用搜索熟悉入口、单一状态主任务、紧凑四目标及可见L0全景预览；首次默认推荐快速了解。
- 落实同一知识空间的L0–L3语义缩放、稳定底图、分支原地展开及目录等价访问。
- 地形与正式目录使用同一投影、同一焦点和同一返回位置。
- 图形地形提供等价列表；节点数量过多、窄屏或低性能时可主动降级。
- 无焦点时不显示任意知识卡或默认第一条知识。

**明确不做**：完整工作台、四类路线生成、掌握度、全库自由力图。

**自动门禁**：42个目录节点均可达；L0至L3往返焦点不丢；图形/列表选中结果一致；320px不横向裁切；空焦点不创建伪焦点；政治以外页面快照/结构基线不变。

**用户手测**：第一眼能否找到熟悉入口和唯一下一步，同时看见知识全景；缩放是否改变知识粒度；目录与地形是否可逆；返回是否回到原位置；无地图模式能否完成同一任务。

**回退**：阶段退回 `foundation`，仍可从旧政治首页访问全部37篇内容。

### S3A 焦点工作台与关系：`terrain → workbench` 的第一半

**落实决策**：STATE、WORK-001至WORK-007、MAP-008/010、VIS-002/003/005/006/010/013。

**实现**：

- 建立 `ContextBar + KnowledgeSurface + 可选GoalGuide` 稳定知识表面；ActivityStage保留内部状态，不默认显示四项ActivityDock。
- 聚焦知识后直接打开同一完整大知识卡；关系上下文通过按需入口进入，没有有效关系时只显示体系位置。
- 关系探索只呈现当前知识一跳邻居，首屏最多6个，完整列表始终可达。
- 关系节点显示类型和“为什么有关”，点击先预览再切换焦点。
- 切换焦点写入探索轨迹，返回恢复原焦点、活动和滚动锚点。

**明确不做**：全库关系网、算法推荐关系、自动改写关系理由、路线完成度。

**自动门禁**：0/1/3/超过6条关系均有确定输出；每类型上限、总量上限和排序稳定；反向关系不重复维护；深链与逆向返回恢复正确；空活动不会出现。

**用户手测**：卡内关系上下文是否帮助理解而不阻塞完整内容；换焦点与返回是否保持空间方向；列表等价是否完整；长标题和底部安全区是否可用。

**回退**：保留 `terrain` 页面和旧详情入口；关系数据与正式目录不回滚。

### S3B 语义阅读与锚点闭环：完成 `workbench`

**落实决策**：DATA-004至DATA-007/012、WORK-008至WORK-013、VIS-004/007/008/009/010/013。

**实现**：

- 完整阅读升级为连续文章流，按显式语义块增强定义、结论、条件、例外、边界、易混对照、步骤、表格和来源。
- 速览、结构理解和完整证据来自同一内容母体，不复制事实。
- 关系、搜索和回忆可以定位 `blockId`；关闭深入阅读后恢复原活动与锚点。
- 实现重点透镜、专注阅读和独立显示偏好；未知语义块按普通正文安全显示。
- 长文按稳定块分批渲染，最后内容始终可达。

**明确不做**：从正文猜测新关系、自动生成未审核摘要、每段卡片化、修改 Markdown 发布状态。

**自动门禁**：所有已声明块类型和未知类型可渲染；长文/表格/超长标题不丢内容；blockId定位和返回恢复稳定；字号130%不裁切；ViewModel不含无关全库数据。

**用户手测**：是否从“文字堆积”变为可理解结构；完整内容是否仍连续、可信；重点透镜是否准确；专注模式和字号调整是否保持当前位置。

**回退**：阶段退回 `terrain` 或S3A可运行点；正式 Markdown 与运行包保持不变。

### S4 路线、搜索与主动回忆：`workbench → learning`

**落实决策**：LEARN-001至LEARN-016、STATE路线事件、WORK-011/012、VIS活动语法。

**实现**：

- 快速了解、系统学习、易混突破、考前速记都先由系统生成有明确范围和依据的推荐路线并提供一键开始；调整范围、换组和随机为次级控制。
- 路线展示范围、依据、顺序、起点和结束条件；目录与前置关系冲突时透明说明。
- 搜索结果展示标题、体系路径、命中块和关系上下文，并可定位地形或原文。
- 问题入口只解析受支持意图，不拼接来源中不存在的新政治表述。
- 主动回忆从正式结构、卡片和内容锚点取材；失败后可回一句话、体系位置、易混对照或原文。
- 首轮只记录路线进度和回忆交互，不显示未经证实的掌握度预测。

**明确不做**：开放式生成答案、个性化掌握算法、随机全库背诵、P4间隔复习系统。

**自动门禁**：四类路线在空/单项/多项范围下输出稳定；前置依赖无环或可解释降级；搜索排序确定；同一回忆种子可重现；无卡片知识有诚实降级；失败补救回到正确焦点和锚点。

**用户手测**：四类目标是否分别形成主干导览、连续知识周期、左右对照和单卡回忆，而不是同一选择/确认流程；搜索是否保留体系感；回忆失败是否能立即补理解。

**回退**：阶段退回 `workbench`；路线进度使用独立命名空间，回退不污染焦点和内容。

### S5 视觉、可访问性和性能收口：`learning → candidate`

基础可访问性不能等到S5才开始；本切片负责对全部活动统一收口并建立候选包。

**落实决策**：VIS-001至VIS-015全部，特别是显示偏好、低动画、列表等价和性能预算。

**实现**：

- 统一体系绿、阅读蓝、易混橙、回忆紫、证据灰的语义别名与非颜色信号。
- 完成120–240ms空间转换、低动画等价、触控尺寸、读屏名称、焦点顺序和安全区。
- 完成320px、130%字号、长标题、长表格、低密度/专注模式回归。
- 页面只持有当前 ViewModel；活动懒加载；记录启动、投影、反馈和长文分批指标。
- 生成带提交、构建版本、数据版本、自动证据和已知限制的 candidate 说明。

**自动门禁**：第9节全部通过；无Obsidian/插件/`.base`运行依赖；无硬编码政治语义进入通用组件；常识与笔记回归通过；性能未越过08预算或有明确降级证据。

**用户手测**：执行第10节完整矩阵，Codex不使用Computer Use替代用户判断。

**回退**：退回 `learning`；视觉 token变更若影响其他模块，先退回共享修改而非在旧模块叠加补丁。

### S5.5 产品表层统一升级：保持 `candidate`

S5.5不新增rolloutStage，也不把上一轮技术candidate视为产品通过。统一实施必须同时消费已归并的A至D：

- 首页、空间、知识卡、关系、搜索、路线和回忆只使用一套焦点、活动、轨迹、路线、显示偏好和viewport状态。
- 一个决策状态最多一个推荐主动作；选择组、回答组、系统操作和情境工具按各自语法呈现。
- 全景、分支、完整卡和回忆是同一知识空间/知识表面的连续状态；知识入口不得恢复预览卡、层层过门页或四项ActivityDock。
- 四类目标分别实现系统推荐、进行中主体、完成反馈及失效恢复；不能只换标题、颜色、步骤名或数据筛选。
- 政治当前卡片能力按构建产物消费：643个稳定块、313个KnowledgeAtomRef、37张KnowledgeUnitCardProjection、37个RecallProjection、39/39关系双端锚点和5组ContrastPair；页面不得另建卡片事实或把未确认相似项升级为易混。

**自动门禁**：执行A至D全部验收、现有S1至S5门禁、内容/关系/卡片构建门禁、常识与笔记隔离回归、微信开发者工具CLI编译与preview；旧技术candidate结果不能替代本轮证据。

**用户手测**：按第10节及S5.5 candidate矩阵验证首页触达、同一空间深入、完整大卡、关系/回忆原文返回、四目标真实分化、320px、最大字号和低动画。

**回退**：按A至D文件级切片回到上一可运行candidate，不改变正式Markdown、目录、关系、回忆、发布状态或其他模块。

### S6 用户验收与缺陷闭环：`candidate → verified`

- 用户记录每个场景的通过、失败和感知问题。
- Codex将问题归类到规格、内容、构建/adapter、状态、投影、渲染或视觉层。
- 每个修复引用原决策和失败场景，执行受影响自动门禁及相邻回归。
- 用户只复测受影响场景和必要相邻链路，不重复无关全量手测。
- 所有P0/P1问题关闭后，政治展现状态可记为 `verified`；内容仍保持其独立发布状态。

### S7 内容发布提升：不属于展现验收

只有37篇内容及11个风险页完成规定校对、来源与关系复核并满足发布门禁后，独立执行：

```text
review → approved → release
```

该动作必须重新构建正式运行包、执行内容差异和全套数据校验，再做受影响页面抽检。不得通过调整 `rolloutStage`、复制 review 包或修改页面状态绕过发布门禁。

## 7. 单个编码切片的固定任务单

每次开始编码前必须形成以下最小任务单，缺项则不实施：

```text
切片 ID / 目标 rolloutStage
引用规格决策 ID / 设计思想 ID
当前基线与已知脏改动
精确修改范围 / 明确不修改范围
数据、状态、ViewModel 或路由变化
自动验收及期望结果
用户手测及期望感知
常识/笔记回归范围
回滚点与回滚方法
实施证据与遗留问题
```

一个切片只解决一个可演示纵向闭环。若编码中发现未定义产品行为，立即停止该行为的实现，先更新负责分规格和决策表；不得在事件处理函数或样式中临时决定产品规则。

## 8. 实时纠错闭环

### 8.1 唯一正确修改方向

```text
正式 Markdown / 正式模块事实源
  → builder
    → review 或 release 运行包
      → validator
        → adapter / ViewModel
          → UI
```

纠错必须逆向定位到错误所属的最上游可控层，再顺向重建。禁止直接手改生成 JSON、页面 data 或 UI 文案来掩盖源错误。

### 8.2 问题归属

| 现象 | 归属层 | 正确动作 |
|---|---|---|
| 事实、目录、来源或固定表述错误 | 内容源/审计 | 修订源、复核、重建和重验 |
| 关系缺失、类型或理由错误 | 关系源/审计 | 修订正式关系，不在UI猜测 |
| 数量、ID、blockId或版本不一致 | builder/adapter | 修复映射并做确定性差异 |
| 返回位置、焦点或路线丢失 | 状态控制器 | 增加状态事件与恢复测试 |
| 节点密度或路线顺序错误 | 投影器 | 修复纯函数和固定夹具 |
| 内容裁切、控件不可达 | 渲染/视觉 | 修复通用组件并跨模块回归 |
| 用户无法理解链路 | 产品规格 | 回到负责决策，不用装饰性补丁掩盖 |
| 待审内容被显示为已发布 | 发布门禁 | 立即阻断并审计包选择和状态文案 |

### 8.3 纠错记录最低字段

`moduleId`、`knowledgeId`、`contentVersion`、`blockId/routeId`、入口、预期、实际、归属层、修复决策、自动证据、用户复测结果。无法定位到块时至少记录体系路径与来源页。

## 9. 自动验证矩阵

| 层 | 每切片必验 | 候选包加验 |
|---|---|---|
| 数据与构建 | ID唯一、引用可解、构建可重复、review/release隔离 | 全量内容差异、来源/风险统计、无Obsidian运行依赖 |
| Adapter | 数量、路径、块、关系、卡片、能力与profile一致 | 政治/常识/笔记同契约夹具 |
| 状态 | 焦点、层级、活动、轨迹、返回、深链、失效、分桶 | 更新版本恢复、异常缓存和跨模块跳转 |
| 地形投影 | L0–L3、目录等价、密度上限、稳定排序 | 大目录、无地图、320px结构 |
| 工作台 | 0/1/3/>6关系、预览换焦点、锚点返回 | 长轨迹、无关系、失效关系和反向派生 |
| 阅读渲染 | 全部语义块、未知块、长文、表格、最后一块可达 | 130%字号、专注/重点偏好组合 |
| 路线/搜索/回忆 | 范围、顺序、搜索排序、种子、失败补救 | 四路线端到端、无卡片/空结果降级 |

| 模块隔离 | 常识/笔记入口和核心校验不变 | 主导航、共享主题、持久状态全回归 |

### 代表性固定夹具

- 无焦点、失效焦点、深链焦点和更新后焦点。
- 0、1、3、6及超过6条关系；正向、反向、易混和跨分支关系。
- 0、1和多张回忆卡；无内容锚点和失效锚点。
- 超长标题、超长段落、列表、表格、来源块和未知语义块。
- 两层、小于16节点、大于16节点和极不均衡目录。
- 空搜索、标题命中、正文命中、关系理由命中和同分排序。
- review内容、release内容及错误混用运行包。

自动测试只证明规则和技术行为，不替代“是否看懂体系、是否感觉连续”的用户判断。

## 10. 用户 UI 手测矩阵

用户负责真实设备或微信开发工具中的感知验收；Codex提供入口、场景和预期，不使用Computer Use代测。

| 场景 | 用户要判断的核心问题 | 最低通过条件 |
|---|---|---|
| 首页第一屏 | 是否一眼找到自己要去的地方，同时知道这里有完整知识体系 | 能找到搜索、唯一状态主任务、四目标和全景入口，且不理解为功能大厅 |
| L0→L3 | 缩放是否改变知识粒度 | 每层信息角色不同且可逆 |
| 地形/目录 | 图形与列表是否指向同一知识 | 切换不丢焦点和位置 |
| 建立焦点 | 是否清楚“我正在看什么、位于哪里” | ContextBar和路径始终可信 |
| 卡内关系上下文 | 是否获得必要方向而不过载且不被强制转页 | 关系少而有理由，完整内容直接可达 |
| 关系探索 | 换知识后能否理解来源并返回 | 预览、换焦点、轨迹和返回连续 |
| 完整阅读 | 是否结构化但不碎成卡片海 | 条件、边界、证据完整可读 |
| 阅读深入/返回 | 从关系或回忆进入原文后是否回到原处 | blockId和原活动恢复 |
| 四类路线 | 是否分别呈现内容先行连续导读、连续知识周期、左右辨析和单卡速记 | 均由系统先推荐并持续引导；快速了解不打开详情也能获得完整导读并感知整体结构，其他三类主体、动作与完成反馈保持既有定义 |
| 搜索/问题 | 是否在找到答案时仍知道体系位置 | 可回地形、关系或原文 |
| 主动回忆 | 失败是否转化为理解补救 | 可选一句话、位置、对比或原文 |
| 320px/长标题 | 是否无裁切、重叠和不可达控件 | 主任务完整可完成 |
| 130%字号 | 是否保持内容、锚点和控制可用 | 不靠缩回字号才能操作 |
| 低动画/无地图 | 是否仍保留方向和完整任务 | 不依赖缩放动画或Canvas |
| 常识/笔记 | 政治改造是否影响旧模块 | 原入口和核心行为不变 |

手测记录至少包含：切片/提交、构建版本、设备或开发工具、基础库、日期、场景、通过/失败、现象、截图或复现步骤、修复后复测。

## 12. 回滚策略

1. 每个切片开始前记录基线，结束后建立独立提交或等价可回归点。
2. 页面选择通过模块 `rolloutStage` 回到上一已验证阶段。
3. V2状态使用按模块、版本命名的独立存储；旧状态不覆盖，新状态失效可丢弃重建。
4. UI回滚不删除正式 Markdown、关系源、review包或审计结果。
5. 内容回滚按内容版本和发布流程处理，不能借UI阶段开关完成。
6. 共享主题或路由变更若引发跨模块回归，先回滚共享变更，再重新切小实施。
7. 回滚后必须运行目标阶段的自动门禁，证明不是“页面能打开但状态已损坏”。

禁止以大批文件覆盖、重置工作区或直接修改生成包作为回滚手段。

## 13. 跨模块推广路径

### 13.1 政治

作为首个真实全链路样本，依次完成S0至S6。其目录、理论固定表述和PDF页码仍留在政治 profile/adapter，不进入通用层。

### 13.2 常识

政治 `verified` 后才开始：

1. 盘点其事实源、层级、类型、表格和现有入口基线。
2. 编写/更新常识 profile与adapter契约，不复制政治“篇章”结构。
3. 先到 `foundation` 并证明旧页面等价，再逐阶段启用。
4. 用大规模节点、法律规则、表格和多类型内容反压通用骨架。

### 13.3 笔记

常识至少完成 `foundation` 且通用契约稳定后：

1. 盘点笔记与题型、模块分类、搜索和既有状态的联系。
2. 只迁移适合的体系、阅读和轻关系能力，不强制复制政治地图密度。
3. 保持既有训练/题型行为，任何联动均通过显式profile能力启用。

### 13.4 后续新模块

接入前必须具备：稳定 `moduleId`、正式事实源、导航或诚实的无层级声明、可追溯来源、独立builder/adapter、能力profile、自动夹具和发布门禁。新模块不得通过页面硬编码绕过平台契约。

## 14. 明确不采用

| 方案 | 放弃理由 |
|---|---|
| 一次重写政治、常识和笔记 | 无法定位回归，用户已有行为风险过高 |
| 大量独立功能开关自由组合 | 状态组合不可穷举，回滚和证据失真 |
| 等37篇最终校对完成后才加工和联调 | 错误耦合内容发布与展现实现，延误结构纠错 |
| UI通过后自动发布内容 | 混淆两条状态轴并绕过风险页审核 |
| 手改dist或页面文案实时修错 | 下一次构建丢失且破坏单向来源 |
| 先抽象全平台再做政治纵向闭环 | 缺少真实使用证据，容易形成空泛通用层 |
| 用政治页面复制出“通用组件” | 只是换目录名，仍无法维护和推广 |
| 用Computer Use替代用户手测 | 不能判断认知效果，也违反已确认协作方式 |
| 自动截图通过即视为Verified | 只能验证表面结构，不能证明体系理解和空间连续性 |
