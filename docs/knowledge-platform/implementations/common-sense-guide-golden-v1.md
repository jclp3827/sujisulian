## 4. 黄金样例卡片准入合同

候选卡必须同时满足：

1. 只有一个明确学习目标；
2. 标题可独立理解，不带正文目录编号；
3. 首次阅读可以说明对象、核心关系和必要条件；
4. 不包含「先记、抓住、挂回、配对、按……记忆、收束」等元学习指令；
5. 每张卡都有显式稳定 `card.id`，不使用标题、数组序号或来源编号作为身份；
6. 每张卡可以唯一定位到正文页签；
7. 直接复用、轻度整理和综合总结均保留正文证据；
8. 事实风险卡进入 HOLD，不通过润色强行准入。

## 5. 扩库产品规则 v1（已冻结）

2026-10-24 根据黄金样例冷读结果确认：该样例已经覆盖直接复用、轻度整理、综合总结和 HOLD 四种典型处置，能够作为后续扩库的内容生产合同。规则冻结只解决「如何生产候选知识卡」，不替代事实审核、正式迁移、设备 UX 验收或发布审批。

### 5.1 产品单位

1. **知识组**：以一篇常识正文 `point` 为边界，承载一个可以连续学习的主题。
2. **知识卡**：知识组内最小学习单位，只承担一个明确学习目标，每次只展示一张。
3. **正文定位**：每张卡必须唯一指向正文页签或来源单元，供核对原文和追溯证据。
4. **学习轮次**：从当前环境可用的知识卡中按范围和数量组成本轮，不改变知识组、知识卡及正文定位的身份。

### 5.2 内容生产方式

| 方式 | 使用条件 | 允许处理 | 不允许处理 |
|---|---|---|---|
| `reuse` 直接复用 | 正文单元已经是可独立理解的知识点 | 只做标点、空格和展示格式整理 | 改变事实、条件或结论 |
| `light-edit` 轻度整理 | 正文事实与结构正确，但带目录语气、主语缺失或条件表达不完整 | 补足对象与必要条件，删除元学习话术，调整为独立卡片 | 引入正文没有支持的新事实 |
| `synthesized` 综合总结 | 同一知识组内多个来源单元需要合并，才能说明一个完整学习目标 | 在保留逐项来源映射的前提下重组表述 | 把多个可独立考查的目标堆成一张卡 |
| `HOLD` 暂缓 | 当前内容不能安全满足准入规则 | 登记问题、来源和恢复条件 | 通过润色掩盖事实或边界缺口后强行准入 |

### 5.3 单卡准入规则

候选卡必须同时满足以下十项：

1. 标题脱离正文目录后仍能独立说明概念或知识对象；
2. 一张卡只有一个明确且可验证的学习目标；学习目标应直接说明用户学完后能说清、区分、说明、识别、概括、判断或比较什么具体内容，不使用“理解、掌握、建立、对应、将……对应、从……理解”等编写者加工指令代替学习结果；
3. 正文说明「对象是什么、核心事实或关系是什么、哪些条件不可省略」；
4. 不预设用户已经读过正文或掌握上位概念，首次阅读可以理解；
5. 内容服务于公考中的概念回忆、事实判断、条件辨析或方法运用；
6. 不包含「先记、抓住、挂回、配对、按……记忆、收束」等元学习指令；
7. 不堆叠彼此无关的事实，不以压缩篇幅牺牲因果和条件；
8. 可以唯一定位正文证据；
9. 法律、政策、经济条件链及存在争议或时效风险的事实，须有权威来源复核，否则进入 HOLD；
10. 不与同一知识组或正式候选库中的既有卡片语义重复。

### 5.4 拆分与合并

- 当一段内容包含多个可独立考查的目标、不同适用条件或不同正文来源时，拆成多张卡。
- 当若干短句只有合在一起才能解释同一个概念或关系，拆开后会丢失对象、条件或结论时，合成一张卡。
- 不按字数机械拆分；判断标准是用户能否在单张卡内完成一次完整的理解与回忆。
- 一个知识组可以包含多张卡，多张卡也可以定位到同一正文页签，但每张卡必须保留自己的稳定身份和证据映射。

### 5.5 身份、修订与进度

- 新候选卡使用 `pointId::card.id` 作为稳定身份；标题、数组顺序和来源编号不得承担身份职责。
- 每张卡记录 `semanticRevision`。学习目标、核心事实、必要条件或来源绑定发生语义变化时递增；仅标点和展示格式变化不递增。
- 拆分、合并和退役必须单独登记旧身份去向；不得根据标题或数组位置自动继承用户进度。
- 正式进度迁移在内容批次之外单独验证，扩库规则冻结不改变当前正式存储。

### 5.6 分批路线与停止门

- 每批以完整知识组为边界，目标产出 20—40 张候选卡；为保持知识组完整，可在批次登记中说明小幅偏离原因。
- 每批候选建设依次完成：选组与来源盘点 → 生产方式分类 → 卡片编写 → 准入自检 → 自动合同检查 → 批次登记；申请正式准入时，再完成未参与编写者逐卡事实审核。
- 每批必须登记知识组数、候选卡数、三种生产方式数量、HOLD 数量、来源定位、稳定身份、审核状态和未完成项。
- 出现以下任一情况即停止继续扩写：规则本身需要改变且尚未获得授权；来源无法唯一定位且无法在原合同内排除或修复；稳定身份或进度迁移边界不清；需要修改公共 UI、业务接口或正式存储合同。已授权且能在现有合同内处理的内容质量问题，按下列修复规则完成后继续，不等待逐次确认。
- 未参与编写者的逐卡事实审核仍是正式准入门。自动检查、同一编写者复核或用户样例冷读均不能替代该审核。
