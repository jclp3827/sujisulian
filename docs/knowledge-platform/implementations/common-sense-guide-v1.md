# 常识「知识导读」实施登记

版本：1.0；登记日期：2026-10-23。

状态：已接入开发工作树，静态检查、页面契约测试和微信开发者工具本地运行态检查通过；尚未进行真机/人工 UX 验收，也不代表正式内容准入、提交、上传或发布。

## 1. 产品决定

常识首页原「常识口诀」入口改为「知识导读」。公开学习链路不再生成、展示或训练口诀，也不要求用户先理解口诀的记忆目的、记法和覆盖范围。

旧口诀内容、题目映射和存储仅作为历史兼容数据保留，不再作为公开产品入口；旧的 `mode=mnemonic` 路由进入知识导读，且不复用旧口诀会话身份。

## 2. 内容编排

- 一个常识正文 `point` 对应一个知识组。
- `readingMeta.takeaway` 对应知识组的学习导读。
- `readingMeta.focus` 中每一项对应一张知识卡，标题取 `label`，正文取 `note`。
- 每次只展示一张知识卡，并提供定位到对应正文页签的「查看原文」入口。
- `readingMeta.review`（30 秒回顾）不是知识卡的必需来源，也不参与卡片身份、内容签名和准入判断。

当前正文自动投影为 170 个知识组、653 张知识卡：文史 204 张、科技 174 张、经济 112 张、法律 163 张。

## 3. 学习链路

入口 → 选择范围和每轮数量（5 / 10 / 15）→ 查看知识组导读和当前知识卡 → 查看原文（可选）→ 选择「记住了 / 有点模糊 / 没想起 / 跳过」→ 下一张 → 本轮完成。

设置保存后立即按新范围和数量重建本轮。页面不展示「继续上次」横幅；未完成会话在再次进入时可直接恢复。

## 4. 状态与边界

- 使用独立存储键 `common-sense-guide-v1`，不读写原答题学习状态。
- 稳定卡片身份由 `pointId + sourceUnitIds` 构成；卡片正文变化后旧标记自动失效。
- 「记住了 / 有点模糊 / 没想起」保存为当前知识卡的记忆标记。
- 浏览进度与长期记忆标记分开保存；「跳过」会推进知识组进度，但不覆盖这张卡已有的长期标记，也不会让下一轮反复卡在同一知识组。
- 来源不能唯一定位到正文页签时拒绝生成，避免链接到错误原文。
- 580 张卡由来源单元直接定位到正文页签；73 张卡因知识组只有一个页签而安全回退到该页签，不声称精确定位到页签内段落。

## 5. 验收口径

自动检查覆盖知识组与卡片数量、稳定身份、来源定位、设置刷新、会话恢复、四种标记、内容变更失效和旧状态隔离。微信开发者工具已确认首页入口、单卡展示、原文返回、设置刷新、恢复态以及固定底部四按钮；测试后本地存储已恢复。真机/人工 UX 验收仍单独进行。

## 6. 扩库规则决策

2026-10-24，用户确认[常识知识导读黄金样例 v1](common-sense-guide-golden-v1.md)的内容测试通过，并足以冻结「知识导读扩库产品规则 v1」。后续候选内容按该文档登记的直接复用、轻度整理、综合总结和 HOLD 四种方式生产，以完整知识组为批次边界；页面布局优化暂不执行。

当前 170 个知识组、653 张自动投影卡仍是既有知识导读基线，未因规则冻结而迁移或替换。既有基线继续使用 `pointId + sourceUnitIds` 内容身份；新增候选卡使用显式 `pointId::card.id` 与 `semanticRevision`。两套身份之间的正式迁移和用户进度继承必须另批验证，不得按标题或数组位置推断。

[扩库第 1 批](common-sense-guide-expansion-batch-1.md)已按上述规则完成古代史 4 个完整知识组、39 张候选卡和 3 项 HOLD。该批没有改变公开入口、正式存储或既有进度；候选卡在未参与编写者逐卡事实审核完成前，不得视为正式准入内容。
