## 1. 本轮目标与权威边界

## 3. 内容对象与颗粒度

CS-010：一个原子学习目标必须能用一项明确判断或简短回忆检验。一个小节可以产生多个目标；一张卡可以引用多个相关知识点，但不得隐式覆盖整章。

问答卡至少有：

- 稳定 id、revision、领域、主题组、学习目标。
- 题干、选项、唯一正确选项、解释、易混边界；生成题明确标为自编学习题，不冒充真题。
- 每条来源的 pointId、tabId、sourceUnitIds、源 tab 内容哈希。
- 内容状态、核验依据、对应口诀 ID（可选）。

口诀卡至少有：

- 标题、口诀正文、记忆方法（押韵/首字/对照/顺序等）。
- 范围说明、明确覆盖的目标 ID、明确不覆盖的内容。
- 逐句释义，每句分别映射正文来源；共同前提、例外和容易误用处。
- 对应问答卡，能从提示回忆口诀，也能由口诀恢复实际含义。
- 来源哈希、revision、状态；外部参考单独记录 URL、访问日期和使用范围。

主题组只持有卡片 ID 和编排说明。进度、错误、稍后再看属于用户状态；不回写内容包。

## 4. 口诀怎样形成，覆盖怎样证明

CS-020：先确认学习目标和覆盖范围，再写口诀。禁止“每小节自动生成一句”作为覆盖指标。

固定流程：

1. 从正文抽出可核对的事实目标：如人物—称号、概念—判别条件、顺序、分类。
2. 选择 2–5 个具有真实共同点的目标；超过时拆组。法律条件和例外不可为押韵省略。
3. 先写直白的正确解释，再尝试对照、首字、节奏等记忆表达。没有自然记法时保留对照表，并标记 `not-suitable`，不硬凑口诀。
4. 给口诀每一分句建立释义和来源映射，注明只覆盖哪些目标、不覆盖哪些内容。
5. 做双向检查：口诀能否恢复全部声明目标；每个字是否有明确含义；是否会误记相反概念。
6. 编写至少一道回忆或辨析题。涉及数字、期限、否定、例外时，增加边界样例。
7. 内容复核后进入候选包；人工审核通过才能进入正式发布包。

范围示例：

- “李白诗仙，杜甫诗圣；诗史评诗，称号记人”：只覆盖李白/杜甫称号和杜甫诗歌评价，不宣称覆盖人物生平、全部作品或整个“诗赋”。
- 汇率标价口诀：只覆盖固定哪种货币作为基准及另一种货币的计价方向。贸易影响、资本流动不在覆盖范围中。
- 声音特性口诀：区分音调、响度、音色；不宣称覆盖传播速度、超声或听力范围。

覆盖报告分开计算：可用正文小节数、已映射学习目标数、问答覆盖目标数、口诀适用目标数、已审核口诀覆盖数、待处理/不适用数。分母必须显示，不能以“有 3 条口诀”声称覆盖三个领域。

## 5. 缺失项处置

| 缺失项 | 处理方法 | 未完成时的产品行为 |
|---|---|---|
| 没有问答 | 从明确正文事实编写；逐项核对答案与干扰项 | 该主题不进入问答/每日组 |
| 没有适合的口诀 | 尝试对照或顺序记法；仍不适合则记录不适用 | 不造假填充，不影响正文 |
| 只有口诀没有释义/范围 | 补齐逐句映射、条件与排除项 | 不准入 |
| 正文有争议或信息不足 | 创建内容问题，回到来源核验；不靠推测补全 | 对应学习卡停用 |
| 来源变更 | tab 哈希不匹配即排除派生卡，旧会话失效 | 提示重新开始，保留未受影响记录 |
| 题频/地域考情缺失 | 后续建立有年份、地区、题型、去重规则的真题索引 | 只称编辑精选，不称必考/高频 |
| 法律卡缺效力信息 | 补充现行法版本、核验日期、官方依据，复用已有法律审计 | 不进入正式包 |
| 某领域没有候选材料 | 如实显示覆盖数和空态 | 提供主题汇总，不跨领域偷偷补足 |
| 今日范围内容不足 5 张 | 按实际数量成组 | 不重复卡片凑数 |
| 本地存储失败 | 提示本次记录暂未保存，仍可阅读 | 不显示“已保存” |
| 通知模板/服务端缺失 | 列为站外推送依赖 | 不出现假提醒开关 |

## 6. 网络补充机制

CS-030：网络只提供候选记法与事实核验来源。先检索已有正文，再按具体缺口搜索，禁止全网口诀直接导入运行时。

1. 先写检索问题与目标 ID，例如“直接/间接标价法如何区分”，不泛搜“常识必背大全”后批量收录。
2. 事实优先使用政府、法律原文、科研/教育机构等可核查来源；社交平台可记录表达创意，但不能独立证明事实。
3. 保留 URL、标题、访问日期、来源类型、支持的具体事实及与正文差异。
4. 外部资料补出正文没有的新事实时，先走正文增补/纠错流程，再生成学习卡。外部记法只改变表达时仍需逐句覆盖核验。
5. 原创改写记忆表达，不搬运整份商业资料。来源不可访问、互相矛盾时进入待处理队列。
6. 可使用 AI 生成候选，不允许 AI 自行把自己的候选升级为人工审核通过。

## 7. 站内推送与复习编排

CS-040：第一版离线本地执行，不需要登录或云端推荐服务。仅存本模块最少状态，显示实际覆盖。默认选择“全部已开放领域”，用户可收窄。

排序：

1. 同一模式、同一范围未完成会话优先恢复，冻结卡片顺序。
2. 每日组先取到期待回顾项（最多 2 张），再选一个编辑主题组的新内容，补足到最多 5 张。选择“全部”时，新主题按文史、科技、经济、法律轮换；已没有新主题的领域跳过。指定一个领域时只在该领域选择。
3. 没有新内容时，仅从到期旧内容中选择较久未看的项，回顾仍最多 2 张；没有到期内容则显示今日暂无新内容或到期回顾，不提前重复凑数。
4. 一问一答优先当前范围未看内容，再按最近学习时间排列；也可直接选择一个 3–5 题的主题组，单独保存和恢复进度。
5. 考前急救的待回顾模式只取用户答错或标记再看的项；精选模式使用编辑顺序。
6. 每日组以北京时间日期和范围冻结；同一天返回不能刷新成无限新组。跨日未完成优先继续旧组并显示所属日期，完成后才建立当天组。

首版回顾规则是产品试验参数：答错/“再看”次日优先，答对且选择“继续”三日后允许回顾。直接揭晓不算答对，跳过不算掌握。首次无历史时只按编辑组顺序。不得把这些时间描述为科学最优遗忘曲线。

内容版本变化使会话失效；单张卡源文/revision 变化使其旧学习记录失效，不挪用旧答案。退出、查看原文、返回、应用重开均恢复当前卡及揭晓状态。

## 8. 站外提醒方案（后续切片）

CS-050：站内安排内容与微信发送通知分开。第一版只实现站内安排，不申请通知、不部署云函数、不发送任何消息。

接入前缺失项：实际账号可用服务类目和模板、templateId/字段、服务端环境、用户身份绑定、订阅授权与可发送次数、时区和静默时段、隐私与记录清理策略。

后续链路：

用户点击订阅 → 客户端取得授权结果 → 服务端验证身份并记录有效授权 →
用户配置时段 → 定时任务筛选“有待学组且有可用授权” →
创建幂等发送任务 → 发送 → 记录结果/消耗授权 → 消息点击恢复对应组。

- 不假定教育类小程序具有长期订阅资格；按账号实际模板能力处理。
- 拒绝授权不影响站内学习；撤销后不继续安排发送。
- 去重键：用户 + 范围 + 北京日期 + 提醒类型；重试复用任务 ID。
- 不确定是否发送成功时先对账，不直接盲重试；区分永久拒绝、授权耗尽、临时故障。
- 服务端保管凭证；客户端不得持有 access_token 或伪造已授权次数。
- 消息失效或内容版本变化时进入学习首页并解释，不打开错误卡片。
- 完成一组后不继续催促；提醒频率由用户选择，不使用无限营销推送。
- 开通、部署、真实发送各自记录验证结果；没有服务端证据不得宣称提醒完成。
