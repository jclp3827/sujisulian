# 常识口诀“概念先导”边界审计

审计日期：2026-10-23  
状态：proposal / implementation-not-started  
范围：129 条口诀的数据模型、生成链路和学习页呈现；本审计不改正文、题目、口诀或公共 UI。

## 一、结论

用户反馈成立，而且属于全库系统性问题。当前产品已经建立“口诀句子—知识目标—题目—原文”的后台映射，但缺少面向学习者的“概念身份—概念结构—口诀解码”链路。口诀被直接作为学习对象呈现，默认用户已经理解上位概念、分类依据和子概念含义，因此新用户看到的是压缩结果，无法知道它在压缩什么。

正确方向不是给现有口诀统一补一个长标题，也不是继续扩写“记忆目的、记法、覆盖”。学习链路应调整为：

> 概念定位 → 一句话定义或任务 → 概念关系骨架 → 子概念与区分点 → 口诀压缩 → 逐句反解 → 条件与边界 → 自测

“大概念 → 小概念 → 口诀”的设想方向正确；中间必须增加关系骨架。不同知识使用不同关系：分类、顺序、对照、因果、条件判断或组成关系。不能把所有内容机械处理成同一棵分类树。

## 二、现状证据

- 129 条口诀均有 `purpose`、`method`、`coverage` 和逐句 `phrases`。
- 129 条口诀均能通过题目 ID 反查到一个主题组，说明现有稳定 ID 和映射可以复用。
- 0 条口诀有显式上位概念字段，0 条有显式概念层级或关系骨架字段。
- 仅 42 条口诀标题直接包含或等同主题概念；其余标题多数是口诀本身、缩略语或记忆动作。
- 67 条 `purpose` 仍采用“帮助回忆……”等作者视角写法。
- 页面依次展示类型、口诀标题、口诀正文、记忆目的、记法和覆盖，没有展示主题概念、概念定义、组成关系及考试中要解决的判断任务。

三个截图主题都能证明问题：

| 当前口诀标题 | 实际大概念 | 当前缺失的信息 |
|---|---|---|
| 多同、多异、少互、独无 | 市场结构 | 什么是市场结构；包含哪四类；按哪些维度区分 |
| 一逐二量三人群 | 价格歧视 | 什么是价格歧视；为何分三级；三级的区分维度 |
| 两非—搭车—政府供 | 公共物品 | 什么是公共物品；属性、分类、供给问题和供给方式之间的因果关系 |

生成历史也暴露了字段冲突：早期资源使用“四类市场结构”“三级价格歧视”等概念标题；Q2 为强化记忆锚点，将同一个 `title` 改成口诀短句。概念标题与口诀标题没有独立字段，导致“我在学什么”被“我怎么记”覆盖。

## 三、问题边界

### P0：概念身份没有进入学习界面

用户首先看到压缩词，无法确定学科位置、概念名称和学习任务。这影响全部口诀卡，而非少数文案。

### P0：作者元数据被当作学习说明

`purpose`、`method`、`coverage` 主要用于作者和审核者说明编写方式。它们即使事实正确，也不能替代学习者需要的“这是什么、包含什么、如何区分、考试怎么问”。

### P1：有目标映射，没有概念结构

现有 `targetIds` 能说明一句口诀对应哪些目标，却不能表达目标之间属于分类、因果、顺序还是对照，也不能回答哪个是上位概念。

### P1：口诀标题承担了两个职责

概念名和记忆锚点共用 `title`。继续批量改标题只能在“概念清楚”和“口诀醒目”之间来回牺牲。

### P1：逐句释义出现得太晚

逐句映射需要用户主动展开，展开前没有概念骨架；用户只能先接受一段陌生压缩语，再尝试理解。

### P2：当前质量门没有检查新手可理解性

现有质量契约能检查锚点、解码、目标和试用证据，但没有要求：概念身份先出现、术语先解释、关系骨架完整、用户在没读过正文时仍能说出学习对象。

## 四、产品边界判断

1. 口诀是检索线索，不是完整教学单元。它只能压缩已经在同一学习卡上建立过的知识结构。
2. 概念说明不能复制一份平行正文。概念框架应引用现有知识目标和原文来源，成为题目、口诀、易混辨析可共同使用的结构层。
3. 不是每个主题都适合口诀。规则长、条件多、无法稳定反解的主题，应降级为速记提纲、对照表或简明解释。
4. “大概念—小概念”不是唯一关系。生成时必须先登记关系类型，再选择页面结构和记忆方法。
5. 快餐式学习不等于跳过理解。概念先导应短而完整，目标是让用户在 20 至 40 秒内知道学什么和怎么分，再进入口诀。
6. 本轮不应改变题目 ID、口诀 ID、学习记录和判分协议。新结构通过引用现有目标实现兼容。

## 五、建议的学习链路

### 1. 概念定位

显示领域路径和主题，例如“经济常识 / 市场理论 / 市场结构”。标题固定使用概念名，不再使用口诀短句。

### 2. 大概念

用一至两句话回答：这是什么、考试通常要判断什么。避免作者语言和“帮助回忆”等空泛表述。

### 3. 关系骨架

按主题选择一种主要结构：

- 分类：上位概念包含哪些类别，用什么维度区分；
- 因果：条件、机制、结果和治理方向；
- 顺序：节点、先后和转折；
- 对照：共同维度下的差异；
- 条件判断：先检查什么，再根据什么分流；
- 组成：整体由哪些部分构成，各部分承担什么作用。

### 4. 子概念

每个子概念只给名称、一句话含义和一个关键区分点。完整细节仍可回到正文。

### 5. 辅助口诀

单独显示“口诀标题”和“口诀正文”，明确它是对前述结构的压缩。口诀不能再承担主题标题职责。

### 6. 口诀解码

默认展示或紧邻展示“口诀片段 → 子概念/关系 → 完整结论”。每个缩略词和数字都必须有对应解释。

### 7. 边界与自测

先检查能否识别概念结构，再检查口诀回忆，最后用条件或情境题判断是否会运用。不能只考口诀原句补全。

## 六、建议的数据结构

新增可复用的 `conceptFrames`，不在口诀内复制事实：

```text
conceptFrame
  id / revision / sourceRefs
  conceptTitle
  parentPath
  definition
  examTask
  relationType
  nodes[]
    targetId
    label
    plainMeaning
    distinction
  edges[]
    fromTargetId / toTargetId / relation
```

口诀资源改为引用结构：

```text
mnemonic
  conceptFrameId
  mnemonicTitle
  text
  phrases[]
    anchor
    targetIds
    decodedMeaning
    conditionRefs
```

`purpose`、`method`、`coverage` 保留给审核和生成链路；用户界面改为由 `conceptFrame` 生成“学什么、怎么分、口诀如何对应、哪里不能用”。

## 七、三个试点的建议重组

### 市场结构

- 概念：市场结构；描述同一市场中厂商竞争与控制力的基本格局。
- 包含：完全竞争、垄断竞争、寡头、完全垄断。
- 关系骨架：厂商数量 → 产品差别 → 进入门槛 → 相互依存。
- 口诀：多同、多异、少互、独无。
- 解码：逐项映射四类结构及其关键条件。

### 价格歧视

- 概念：价格歧视；对同等级同质量商品或服务向不同接受者收取不同价格。
- 包含：一级、二级、三级。
- 关系骨架：逐单位最高支付意愿 / 数量段 / 市场或人群。
- 口诀：一逐二量三人群。
- 解码：一、二、三分别映射区分维度。

### 公共物品

- 概念：公共物品；重点从竞争性和排他性识别。
- 关系骨架：两项属性 → 纯/准分类 → 搭便车 → 市场供给不足 → 主要供给方向。
- 口诀：两非—搭车—政府供。
- 解码：明确“两非”指什么，并说明因果链不是四个并列名词。

## 八、建议的生成链路

1. 选定一个稳定主题和原文范围。
2. 建立概念框架：概念名、定义、考试任务、关系类型、子概念和边界。
3. 审核概念框架是否能脱离口诀被新用户理解。
4. 判断是否需要口诀、速记提纲、对照或无记忆资源。
5. 编写记忆锚点，建立逐片段解码映射。
6. 检查每个锚点是否能反向恢复概念节点与关系。
7. 建设三层检测：概念识别、关系理解、条件/情境运用。
8. 进行新手理解测试和延迟记忆测试；失败则改写、降级或撤回。

## 九、分批方向

### Q0-C0：概念框架契约

建立 `conceptFrames` schema、关系类型、负例和红基线，不改页面。

### Q0-C1：三个主题试点

用市场结构、价格歧视、公共物品完成概念框架、口诀解码和三层题目映射。

### Q0-C2：学习页链路

页面按“概念—结构—口诀—解码—边界—自测”呈现；保留现有蓝白样式、底部按钮和进度协议。

### Q0-C3：质量门

新增概念身份、关系完整性、术语预解释、锚点可解码、新手复述和自测不越界检查。

### Q0-Cn：存量迁移

按关系类型和领域分批迁移，每批少量主题；允许保留、改写、降级为速记提纲或撤回。未完成概念框架的口诀不进入正式准入。

## 十、当前决策建议

暂停为 129 条口诀批量补现有 Q0-A 质量规格。应先完成 Q0-C0 与三个主题试点，否则会给缺少概念先导的旧产品形态建立大量即将失效的质量证据。题库、正文和普通问答可保持现状；口诀仍维持候选状态和正式准入为 0。
