## 2. 实际实现中需要先收敛的部分

当前已共享基础阅读角色和`reading-controls`字号/行距组件，但仍有以下临时实现：

- 共用角色仍位于名为`politics-article-visual.wxss`的文件，已被三类页面使用；样板ID判断分布在多个模板、页面和组件中。
- `readingUiEnabled`同时涉及样式、字号入口以及部分正文工具栏条件。直接扩充旧白名单可能连带改变返回入口或段落投影。
- 正文样板为4个一级短脉络、模块说明和普通关联链接；尚未覆盖所有正文结构。
- 当前系统学习新增样板只补显示字段，保留原有分段投影。后续不能因启用视觉样式，顺带对73节重新执行新的切段规则。

先统一入口和角色，再推广；不逐页继续复制新的条件判断和样式补丁。

## 3. 复用结构

### 3.1 共用基础

将已验收的角色声明无损整理到中性命名的阅读token文件，旧文件保留兼容导入。第一步保留已有变量别名与数值，避免同时进行大规模改名。默认正文沿用34rpx，而不是误用当前基础库中32rpx的另一个正文角色；大/特大沿用36/40rpx。

共用：标题/正文/辅助信息字号、1.7默认行高与2倍舒展行高、自然字距、白色阅读面、阅读边距、分级间距、圆角、线条、蓝色配色与按钮触摸尺寸。rpx按设计基准校准，验收以实际运行的逻辑像素和几何为准。

行内重点继续使用蓝色底部42%→36%→24%→透明渐变；易混边界使用主题蓝色下划线。摘要/导读使用浅蓝底与侧线，模块说明和系统学习结论使用更浅的蓝底。普通讲解保持连续白底。只改变已有强调的显示方式，不重新决定哪些字需要强调。

### 3.2 复用已有组件和轻量模板

| 复用单元 | 复用方式 | 保持的边界 |
| --- | --- | --- |
| 字号与行距 | 继续使用现有`reading-controls`和偏好键 | 不迁移进度，不复制偏好保存逻辑 |
| 标题、导读、讲解、结论等区域 | 共用视觉角色，按现有数据类型选用 | 不为凑布局新增标题、摘要或结论 |
| 行内重点与边界 | 共用显示规则 | 文本、角色和标注范围不变 |
| 自测区 | 系统学习复用现有模板 | 小号快速自测、题目、按钮；展开后保留答案 |
| 原文及相关知识入口 | 复用现有跳转事件和关联ID | 保留依据定位、关系方向、来源与返回上下文 |
| 进度与底栏 | 共用尺寸、颜色和安全区规则 | 各模式保留自身信息与按钮职责 |

优先复用样式和现有组件。只有确实消除重复且不改变定位边界时，才抽取共享模板；不为形式统一增加大量嵌套组件。既有DOM定位ID、语义块ID和原文定位范围保持稳定，避免字号恢复、目录跳转、来源核对因组件边界变化而失效。

### 3.3 三类页面分别适配

| 类型 | 主要职责与布局 | 必须保留的区别 |
| --- | --- | --- |
| 快速了解 | 建立全貌：标题、核心判断、主线讲解、选读信息 | 保留5步节奏和前后步，不新增系统学习式自测/结论 |
| 独立正文 | 深入阅读与核对：摘要、按需脉络、分层正文、依据及相关知识 | 无脉络不造脉络；多级目录保持层级；返回任务优先级按入口处理 |
| 系统学习 | 理解一个小节：目标说明、讲解、一个本节结论、精简自测、原文 | 正常阅读、回看与补读同样式，学习完成与跳过事实各自保留 |

自测精简规则推广至所有系统学习小节：省略题数、计分说明、作答提示和重复答案标签。重要状态信息另行保留，例如定位失败、未保存、跳过事实、浏览不等于掌握等，不能当作普通辅助说明全部隐藏。

## 4. 正文差异处理：推广前必须补齐

当前37篇的实际结构盘点：5篇无脉络、17篇只有一级脉络、15篇含多级脉络；14篇有多列阅读配置；1篇有概念对照；3篇含4个来源校正提示；20篇的相关知识携带易混边界说明。当前没有实际表格块，不为本轮额外开发未使用的表格系统。

### 4.1 脉络

- 默认单列完整标签，保持父子层级及原有展开行为。
- 短标签、少量一级入口可使用已验收的两列紧凑布局；科学体系当前4个短入口继续沿用。
- 长标签、多级脉络或较多入口使用单列；大/特大字号优先单列，避免缩字或截断。
- 具体布局由展示能力清单及实际可用宽度决定，不能只根据篇名，也不能把所有脉络统一改成两列。

### 4.2 蓝底区域

`displayRole: reading-heading`目前代表含标题的展示块，不足以证明它是模块导读。比如高质量发展正文的许多二级标题也使用该角色；全部改成蓝底会产生连续大卡片。

建立独立的展示角色映射，复用已有语义、标题层级和明确区域ID。只有已确认的导读/模块说明区域使用浅蓝底；普通标题与连续讲解使用字号、字重和留白区分。无法明确判断的区域保持普通阅读排版，进入差异清单，不用标题关键词猜测内容职责。

### 4.3 清单、概念对照和来源

移动端长清单以单列连续阅读为默认；原有多列阅读按既有顺序展开，不改条目内容。概念对照保留维度与对应对象，可按维度上下排列，不能简单拆平后丢失对应关系。

来源补充、校正和失效定位属于不同信息类型。补充来源可降为辅助层级；影响理解或定位有效性的提示保留可读与可操作性。不删除、不重排补充摘述，不借UI推广修复知识内容或重新标重点。

### 4.4 相关知识

标题点击直接跳转，沿用现有关系跳转处理，保留目标依据和返回位置。对于带易混边界的20篇，直接跳转与说明展开分别处理：标题仍直接进入目标正文，区别说明使用独立的次级入口按需查看，保留已有内容，避免点标题必须先展开，也避免原有区别信息消失。该变体需在补样阶段确认后复用。

## 5. 实施入口与控制方式

建议增加统一的阅读展示策略文件，例如`services/knowledge-platform/reading-surface-policy.js`，集中管理：模式、已启用页面ID、批次、脉络布局及特殊展示能力。清单只存ID和展示配置，不复制正文、题目或知识事实。

三个页面/组件从同一策略取得显示标记，替换分散的样板ID判断。正文页面外壳与`knowledge-card-surface`必须同步启用，防止只换其中一层。组件继续只展示和触发事件，学习、回忆、跳过及关系状态由原有业务层处理。

保留`reading-ui.js`原有偏好保存、定位恢复以及原样板分段行为。视觉推广独立于内容分段投影；标题拆分后必须能逐字拼回原标题，无法确认序号结构时保留完整标题。

每批用明确ID清单启用，可按批撤回视觉标记。只撤回该批展示文件/配置，不清理学习记录，不重置工作树，不改内容版本。新增未知结构先保持可读的默认排版，作为后续差异项处理。

## 7. 验证与验收

1. **内容与记录冻结**：检查标题拼接、正文、已存在的分段、重点片段、题目答案、来源ID和顺序与批前一致；只允许明确的展示字段和辅助文字显示变更。完成、跳过、参考答案及返回逻辑不被样式推广改变。
2. **模拟器逐页检查**：本批所有新增阅读实例检查标准/特大字号、横向溢出、目录标签、定位目标、底栏重叠、末段遮挡及来源/相关知识入口；中间字号通过角色配置和代表页复核。记录全量排版结果，不以少量样板截图代替覆盖。
3. **流程检查**：快速了解前后步、跳过与恢复；系统学习自测、正常完成、回看/补读、原文往返；正文目录、关系方向、来源、普通入口与任务返回入口；字体设置不推进学习。
4. **人工视觉验收**：检查信息层级、模块职责、阅读节奏、强调和操作主次。代码通过、模拟器通过、用户验收、集成与发布分别登记；320px与真机继续沿用用户豁免。

R0必须先处理已有旧内容封存校验差异：追溯到已登记的改动，补足当前工作树的内容复验与清单。不能简单刷新旧摘要让它变绿；旧封存记录保持原样。若无法归因或当前内容复验失败，只停止受影响批次，不把该项宣称为通过。

方案获准后，常规间距、颜色和换行等问题按已验收规则自行处理，逐批交付验收路径。遇到未覆盖的新结构、必须改变知识语义/重点范围、学习记录风险或已验收样板明显回归时，先限制影响范围；需要用户作实质决策时才停止询问。没有这些问题时，不重复要求用户逐页批准相同实现方式。
