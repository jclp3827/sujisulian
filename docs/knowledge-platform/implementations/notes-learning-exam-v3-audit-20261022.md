## 产品定义与规则适用范围

本轮用户补充的产品定义作为审计前提：笔记是多年网友及机构积累的行测知识的系统精炼、整理与关联，帮助用户面对庞杂知识建立框架、整理思路、复习易混易忘点并加以应用；它不是用户的个人记录工具。

因此应区分两层价值：

| 对象 | 应保留或审查的价值 |
|---|---|
| 笔记本体 | 精炼完整的概念／方法框架、必要解释、前提条件、知识之间的联系与适用边界。整理性、解释性内容即使不适合单独出题，也可以长期保留。 |
| 笔记练习 | 帮助调取具体知识与方法，辨清差异并应用；需要明确考试用途、检测目标和真实干扰。 |

**V3应作为练习内容准入标准，不能成为删除正文、目录或知识关系的标准。** 当前规则允许正文点没有快练，并保护原目录正文，未发现实际越界删减。此前评审中的“教学价值准入”“新内容规则”用语稍宽，后续建议限定为“练习内容准入”。这属于范围澄清，未单列P1/P2。

按这个定位，后续模块验收除题目质量，还应单列：知识框架是否清楚、精炼是否保留必要条件、概念／方法关系是否准确、练习能否返回相关知识与应用。采编总结的来源和原例题的考试出处应分别记录，网友或机构整理不自动等于官方考纲、真题出处或普遍有效规则。

1. **生成起点已纠正。** 从“正文可以提问”转向“考试中需要调用什么”，并要求具体用途、记忆内容、误用后果与目标一致性。
2. **没有过拟合八张截图。** 定义不是一律禁用；图8只是方向样板，不是批准全部符号题；其余56题的状态没有被外推。
3. **三类有可用边界。** 基础检测规则／方法的直接调取，方法检测区别、识别或一步决策，应用完成完整原任务。允许目标相关，但按实际主要动作归类，不靠题干关键词硬分。
4. **干扰项标准有效。** 同域真实错误能排除图4的跨领域送分选项；来源口吻与字面复述也被明确列入反例。词面检查只报疑点，不能假冒语义合格。
5. **图形方向符合产品定位。** 口诀需展开成考点和观察路径，避免只考字形或脱离方法的几何定义，同时保留“提示／考虑”与必然规律的区别。
6. **模块方案与来源登记相符。** 原JSON为5科、40专题、162点；主归属登记覆盖162个唯一来源身份，无遗漏、重复或额外项。拟归属判断27、图形39、言语19、数量44、资料33，其中图形39包含原判断目录里的3条图形来源，不是新增来源点或新增覆盖。

## 发现的问题

### AUD-01 · P2 · 语义审核决定未绑定被审内容和依赖版本

位置：[评审字段](/Users/jmac/.codex/worktrees/notes-learning-exploration/miniprogram-1/docs/knowledge-platform/implementations/notes-learning-exam-rubric-v3.json:81)、[现有正式批准摘要校验](/Users/jmac/.codex/worktrees/notes-learning-exploration/miniprogram-1/scripts/lib/notes-learning-compiler.js:28)。

评审字段只列判断值、决定、理由和`reviewerIdentityOrScope`，未定义独立评审记录的身份、日期、规则版本、题目ID／revision／内容摘要，以及目标和来源的依赖版本，也未明确`accept-candidate`与现有`review / blocked / approved`的关系及失效条件。

如果EV0只实现字段非空检查，旧的“接受候选”决定可以被复制给修改后的题目或目标，“不能自报true即通过”就缺少可复核凭据。当前V3语义门尚未部署，本项是落地契约不足，不是已部署门被绕过。现有正式批准digest也不能直接替代独立的语义评审账。

最小补充：评审记录绑定评审者身份、角色／范围、时间、规则版本、题目有效内容版本及目标／来源依赖摘要，记录决定和理由。实质变化后重新评审；`accept-candidate`仅表示可选入新标准候选，不自动变为正式批准；`rewrite / drop / hold`不进入新标准活动入口。历史评审保留，不覆盖成“通过”。

验收反例：题干不变但条件／目标已变，或者题目修改后沿用旧评审，必须拒绝旧决定继续准入。只写`targetAndActualTestMatch: true`不能通过该门。

### AUD-02 · P2 · 现有会话签名没有覆盖目标内容修订

位置：[沿用既有会话规则的批次约定](/Users/jmac/.codex/worktrees/notes-learning-exploration/miniprogram-1/docs/knowledge-platform/implementations/notes-learning-exam-v3-batches.md:24)、[目标ID检查与资源签名](/Users/jmac/.codex/worktrees/notes-learning-exploration/miniprogram-1/miniprogram/subpackages/note/services/learning-content.js:66)、[会话有效性](/Users/jmac/.codex/worktrees/notes-learning-exploration/miniprogram-1/miniprogram/subpackages/note/services/practice-session.js:14)。

V3要求修改版本与受影响会话按既有规则处理。现实现会将知识原子和辨析关系纳入资源指纹，但对目标仅检查ID存在，签名未包含解析后的目标版本与必要条件。

独立内存复现使用图8对应题，仅把其目标revision从1改2并增加条件，未修改题目正文：

| 观察项 | 结果 |
|---|---|
| 目标内容与构建包版本 | 已变化 |
| 题目批准摘要 | 未变化 |
| 可用资源签名 | 未变化 |
| 原活动会话 | 仍可恢复 |
| 保存的实例 | 没有解析后的目标快照 |

这说明“沿用既有规则”不足以覆盖新的考试目标审核口径。复现在review内存夹具中完成，不代表正式approved已绕过，原文件与用户记录没有被改写。

最小补充：把目标的实质内容版本／摘要纳入语义评审与会话依赖。目标用途或必要条件变更时重新核对相关语义决定，并让受影响的旧活动题组失效；无关题组与旧作答事实保留。展示性改名与实质目标修改需区分，避免整包无差别清空。

验收反例：只改目标必要条件，也应检测到依赖变化；另一个不依赖该目标的题组仍能恢复。

## EV0应明确的实施细则

下列是对现有方案的落实建议，不追加为已证实缺陷：

- **推进门矩阵。** 模块内容目标、旧题处置、候选语义复核和构建回归通过后，可继续独立模块。正式批准、真机、实际包体分别约束启用或最终交付；不能因一题缺图卡死全部内容，也不能跳过候选语义门。现规则已允许局部hold，这里只是把“完成验收／相关依赖”写成可执行表。
- **冻结清单与统计。** 每模块冻结来源范围与目标清单版本，逐项记录可练习、仅供整理／解释、不适合独立题、缺源待核等去向。题量、来源涉及点、有效考试目标、语义合格候选和正式批准分别计数；未决项不能靠排出分母变成“完成”。
- **按条件适用规则。** `EXAM-08`在涉及口诀时生效，不涉及口诀可记不适用及原因；不能将`allRequired: true`机械翻译为每道题都必须填写口诀映射。基础和方法最好用同目标、不同实际动作的成对样题校准。
- **共享来源贯通整条消费链。** 当前同科编译检查和运行范围筛选都需要适配，不能只放宽编译器一行。需验证主模块／专题选题、原来源点回练、精确回源、返回同一会话以及来源或关联版本变化。原logic中的图形来源身份保持，不能靠复制正文或伪造source subject绕过。
