## 原行为与待改差异

[页面处理逻辑基线](evidence/notes-learning-v1-n0-behavior.json)直接加载现有页面与组件，在内存中的微信接口替身下执行。覆盖首页五科入口、40 个分类和 162 个详情、五科搜索、错误引用、原例题交互、懒渲染、生成与判分，以及特殊训练跳转，共保存 16 组汇总记录。

该检查不操作真实用户缓存，不调用云函数或下载图像；它是页面处理逻辑证据，不代表微信渲染、触摸或设备体验验收。

| 已确认差异 | 本次证据 | 后续归属 |
|---|---|---|
| 四处关联训练走错入口 | `base-period`、`abrx-system` 应进拆分估算，`share-415` 应进比例感，`assumption-allocation` 应进分配树；笔记侧当前都进通用会话，通用生成器返回空组 | N3 统一笔记侧启动解析 |
| 搜索结果未携带页签 | 五科搜索均能命中本科学习点，但跳转只带科目和知识点 | N2 搜索落点 |
| 无效页签静默回首签 | 以不存在的页签打开基期量，实际显示首个页签 | N2 明确失效和降级 |
| 数量关系合并例题页签 | 已记录 14 处源页签到显示页签的合并映射 | N2 来源定位，N3 往返复核 |
| 块锚点是渲染下标 | 详情先渲染 8 块，后续块尚需加载；`note-anchor-N` 会随展示变化 | N2 加载后定位，N1 建可靠来源引用 |
| 例题作答只在组件内部 | 提交改变本地组件状态，例题键变化会重置；未形成持久答题事实 | N3 独立会话与查阅记录 |
| 随机题 ID 可跨组复用 | 现有生成器使用 `trainingId-index`；原判分与容差可用 | N1 实例快照和身份，N3 消费 |

30 处训练连接全部在资料分析。清单逐项记录声明连接、实际笔记入口、训练目录入口、通用生成器结果、容差、结果归属和知识检测范围。直接练某项计算技能也不等于检测整个知识点；“图表查找→年平均量”“比重趋势→基期比重”等映射列为需复核项。

原训练默认题量为 10，新笔记方案默认 5。N3 应在适配层显式使用笔记配置，不能通过改变全局默认值影响原训练。
