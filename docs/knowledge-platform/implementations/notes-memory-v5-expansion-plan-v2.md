## 一、目标与内容边界

笔记承载系统精炼的行测知识，目标是理清结构、关联、快速回忆、易混易忘复习，再以原题应用。基础快记主要记具体关系／公式／概念和必要条件，不要求数值解题；方法判断识别信号、适用范围和具体方法差异，允许公式／概念的对照。分类按目标，资料／数量不是只能基础，出现公式也不自动归基础。图推统一方法判断，保留理解所依赖的原图。

考前速记只是同一批卡片的弱项路线，不另造内容。完整题应用作为首页独立入口保留，使用笔记已有完整题目，判分／解析／历史及原题曝光沿原链路。原文只保留原知识与既有技能训练；卡片只有查看原文，通过顶部原生返回；所有换卡由按钮操作，滚动不换卡。

原JSON与原轻量公式组件仍为权威，保留nodes／content／cellNodes、表头、父主题、对照和必要前提。卡片只存精确原引用与编写字段；新增说明和提示单列核验。不以原样引用替代正确性核查，不静默更正原源。

## 二、来源处置与0..N目标模型

来源工作单元是盘点／核源单位，卡片目标是记忆单位，两者分开：一个来源可零卡、多卡、复用已有目标或合并；一原块也可承担不同目标。没有固定卡片配额，来源和行数不作为卡片数。当前首批仍采用单来源组合，多来源导航与跨科绑定没有证据时只暂缓对应组合。

- 编写范围先冻结batchId、主模块及来源workUnitIds，不能由草稿自己声明越界来源。
- 来源处置台账必须覆盖该范围每个来源，状态为目标已提出／仅正文／复用／合并／暂缓；需要理由、关联目标或去向及必要恢复条件。
- 每个目标有稳定targetId，卡片有稳定id／revision、workUnitIds、kind、目标、归类理由、原引用及作者身份。来源任务反查subject／point／category，实际refs必须指向对应原源和允许原块。
- 来源台账的targetIds与实际目标关系必须一致；允许一源多目标，不以重复workUnit本身判错；遗漏来源处置或伪造来源匹配会失败。
- 旧来源级分类保留为historicalSourceKindHint，不是准入依据；targetClassifications记录当前目标的类型与理由，同一来源可有不同类型目标。
- 标题不同不等于目标不同；设计需登记重复、复用或不同目标的实质理由，独立审阅继续核实目标及组合，而非只检查ID或摘要。

“无既有来源观察”不等于内容通过。已知问题按具体块／目标暂缓；不依赖问题片段的其他组合可继续核源，不将整个模块冻结。

## 五、学习版本稳定性工程（EXP-A05，G0已实施）
