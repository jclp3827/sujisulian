# 政治知识正文页｜产品编排优化实施文档

**版本：** v1.0  
**日期：** 2026-10-04  
**用途：** 交付 Codex，作为本次正文页面产品优化的需求、实施边界与验收依据。  
**实施状态：** 本文档已形成；本会话未修改项目代码，未执行项目测试，未代替用户完成体验验收。  
**建议仓库位置：** `docs/knowledge-platform/implementations/politics-knowledge-body-product-orchestration-v1.md`

> 本次不是重建知识系统，也不是再做一次功能堆叠或整体换肤，而是围绕用户进入、阅读、理解、回忆和返回的过程，重新编排已有内容与能力。
>
> **核心合同：正式正文不变，既有知识身份和关系不变，已有功能机制不扩大；调整信息层级、出场位置、默认展开、上下文提示与已有操作之间的衔接。**

## 0. 执行摘要

本轮只解决三个产品问题：

| 目标 | 要让用户获得的体验 | 本轮实现方式 |
|---|---|---|
| G1：进入即理解 | 进入后约 3 秒内知道“这篇讲什么、为什么现在看它” | 正式标题、现有一句话理解、入口任务提示、轻量本篇脉络 |
| G2：长文不迷路 | 同时看清文章展开和正文中的知识节点，又能连续阅读 | 正式标题层级、原位知识卡、现有文内导航、按需出现的关联信息 |
| G3：阅读与回忆闭环 | 尝试回忆，自己发现不确定之处，回到对应原文，再继续原任务 | 前移已有回忆入口，编排已有揭晓、自评、答案锚点和返回行为 |

**补充决定：**保留“显示”；“来源／反馈”不再作为普通学习界面的功能入口展示，保留底层来源与调试追溯能力；关联线索、易混、相关知识、知识延伸保留并优化展示；正文过长先通过编排减轻使用负担，不在本轮拆分、压缩或重写。

**执行顺序：**B0 核对基线与改动归属 → B1 三篇样板的页面编排 → B2 入口、关联和回忆流转 → B3 全量回归与同构建体验验收包。满足每批门禁后继续；发生数据、合同或并发边界冲突时停止受影响范围，不自行扩项。

## 1. 产品定义与依据边界

### 1.1 正文页不是一张知识卡

**知识正文页／知识学习页**是承载一篇正式内容的阅读与学习页面。它包含原文、文章结构、若干知识卡以及学习辅助和操作。

**知识卡**是正文内部已经正式识别的知识单元。它保留在原文上下文中，供理解、定位、引用，以及在现有回忆映射支持的范围内回看。它不等于整页，也不意味着每一张卡都有一题独立回忆题。

**文章结构**回答“这一篇按什么顺序展开，我现在读到哪里”；**知识结构**回答“这部分是什么定义、结论、理由、条件或正式易混边界”。二者协作，不互相替代。

代码中的 `KnowledgeUnit`、`KnowledgeAtomRef`、`SemanticBlock`、`knowledge-card-surface` 等既有名称，不能直接当作用户概念的一一对应关系。**本轮不为纠正产品名称而重命名数据模型、迁移 ID 或拆组件体系。**Codex 应先核对现有映射；不得把每段、每个语义块或每个 Atom 机械渲染成一张独立视觉卡。

### 1.2 本文据什么制定

产品决定来自本次用户明确确认的讨论；实现基线来自用户提供的 Codex 审计及修复报告。报告描述的正文底座包括 37 篇、643 个稳定块、313 个 Atom、39 条关系双端锚点和 5 组正式易混，以及已接通的若干定位、来源、回忆和返回能力。

**以上是交接基线，不是本文作者重新读取工作树后得到的当前事实。**本文件未直接核验这些本地代码和权威文档的当前版本。Codex 必须在 B0 对目标工作树复核，不能用这些历史数量和“曾通过”记录替代本轮证据。

本文件在**本次页面体验范围内**取代前面讨论中以下表述：整页等于知识卡；来源／反馈应作为普通学习工具保留；回忆一次即可证明整篇掌握。其余既有内容真实性、同源正文、稳定锚点、发布与路线合同继续有效。

## 2. 范围：允许改变什么，必须保持什么

### 2.1 允许的产品编排

允许调整页面和共享组件的布局、视觉权重、段落节奏、标签表达、现有辅助内容的展开方式；允许增加为此必需的轻量展示状态和事件接线；允许把现有入口上下文、正式标题、语义、关系理由、回忆映射投影到合适位置。

“不增加功能”不等于不能增加一个展开状态或返回提示；它意味着**不增加新的知识生产、学习算法、数据服务和独立业务流程**。任何展示字段都必须能回指已有正式内容或明确的 UI 状态。

### 2.2 保护边界

| 必须保持 | 明确禁止 |
|---|---|
| 正文原字句、正式顺序、稳定块 ID、来源绑定、知识身份 | 改写论证、自动生成导读知识、抽取另一条摘要正文、重新拆知识卡 |
| 现有知识关系、正式易混边界及两侧原文锚点 | 根据关键词相似度新造关联、把普通关系升级成易混、编造扩展知识 |
| 现有题目、答案依据、自评语义与学习路线规则 | 一卡一题、自动出题、自动判断具体遗漏、掌握度算法、间隔复习系统 |
| 各入口正文同源、已有导航和返回能力 | 新建一套正文引擎、重做四条路线、重新定义知识空间 |
| 内容校对／终审状态与发布权限的区别 | 因 UI 优化而修改 `publishable`、批准发布或推进 S6 |
| 其他工作树及当前分支的既有改动 | reset、clean、跨检出覆盖、混合无关暂存或提交 |

**长文专项延期：**本轮不分页、不按知识卡拆屏、不折叠普通正文、不做仅剩要点的精简模式、不加入虚拟阅读器；也不通过减小字体或压缩行距让长文“看起来变短”。

## 3. 页面总体编排

### 3.1 正常进入时的页面顺序

```text
页级操作：返回                         显示

正式路径／标题
已有的一句话理解
已有学习上下文（确有数据时显示）

本篇脉络：正式结构的轻量预览＋原文内导航入口

完整正文
  正式小节标题
  连续普通段落
  原位知识卡
  对应的关联线索／正式易混提示（按需展开）
  ……

回忆一下
  已有回忆操作
  合法的继续／返回操作

相关与延伸（可选探索，不要求阅读）
  已有相关知识
  已有知识延伸
```

此结构是**信息顺序合同，不是要求所有区块都套一张卡**。无对应数据时不显示空模块，不为完整凑齐版式生成内容。

“显示”留在页级次要操作位置，阅读中容易找到；已有收藏等非调试功能保留原能力，不新增独立工具广场。“来源／反馈”不进入上述普通阅读结构。

### 3.2 任务型进入时，不强迫先读首屏

从搜索、关系、易混或回忆进入且有合法块锚点时，直接到相应原文。用户不必先看导读、展开目录或完成阅读。

定位处保留现有轻量任务栏，用真实入口说明“正在核对什么”，同时提供最近一层的返回操作。任务栏不能重复堆叠完整标题、长路径和整段关联说明。滚动后返回仍可发现；定位必须计入栏高，不能把目标文字压在吸顶栏下。

正常进入优先展示身份与概览；任务型进入优先展示目标原文与返回。**同一份内容，不同进入状态；不是两套页面。**

### 3.3 操作层级

阅读时正文最重要，导航和显示为辅助；正文结束后“回忆一下”为主要动作，合法继续／返回为次要动作；核对原文时“返回刚才的任务”为主要动作。相关与延伸保持可发现，但不占用回忆之前的必经位置。

不得通过自动跳转、必读提示或禁用返回，强迫用户走完整学习链。

## 4. G1：进入后快速理解主题与来意

### 4.1 首屏信息从哪里来

| 信息 | 数据依据与展示规则 |
|---|---|
| 正式路径和标题 | 使用既有正式身份；长路径允许弱化或适配展示，标题不能被工具挤成难以辨认的碎片 |
| 一句话理解 | 使用已存在、已审核或已正式采用的内容；没有就省略，不现场生成摘要 |
| 为什么现在看 | 有学习路线说明时显示原说明；任务入口显示实际任务；普通目录进入不编造学习动机 |
| 本篇怎么展开 | 使用现有正式结构和合法锚点，提供轻量预览与原文内导航 |

不展示没有依据的“高频必考”“预计 4 分钟”“你尚未掌握”等说明。章节数量等确需展示的统计只能从当前实际投影得出。

“3 秒”是**页面方向感的体验目标**，不是新增计时功能、强制过门或工程加载时限。不能为挤进一屏而截去重要条件、硬限摘要高度或缩小字号。320px 与大字号允许自然增高，但应保持标题、理解线索和正文的优先顺序。

### 4.2 入口行为矩阵

| 入口 | 初始落点 | 可以显示的来意 | 读完／核对后的去向 |
|---|---|---|---|
| 目录、知识空间、收藏 | 篇首；有合法既有恢复状态时按原规则恢复 | 正式主题与一句话理解，无须反复强调“来自目录” | 返回原入口；仅有正式后继时提供继续 |
| 系统学习／导读路线 | 既有路线指定位置 | 当前路线已有的学习目的、阶段信息 | 回原路线；推进遵守既有完成条件 |
| 搜索 | 合法命中块 | 有查询词时说明查询词及命中；无查询词只说“来自搜索” | 恢复原查询、结果列表和滚动位置 |
| 关联线索／相关知识／延伸 | 有正式目标锚点则定位，否则篇首 | 真实来源与已有关系理由；没有块锚点不能声称已定位某句 | 回来源正文，恢复原位置与展开状态 |
| 易混 | 正式对应边界／证据块 | 本次核对的正式概念对与两侧角色 | 回同一对照及原阅读状态 |
| 回忆核对 | 现有答案依据块 | “核对这道回忆题的原文”等中性说明 | 回同一道题、原揭晓／自评状态 |

关系入口的返回目标为来源正文及原展开状态；由来源正文继续返回其外层活动。不能为简化流程，统一返回首页或目标卡顶部。

**禁止臆测用户状态：**仅凭 `origin=recall` 不能显示“你没有记住”；只有实际自评支持时才能说明“刚才选择了不确定”。搜索词、目标 ID、块 ID 和返回目标应按既有有效性规则验证，不直接信任任意深链参数。

### 4.3 “本篇脉络”的限定实现

复用现有文内导航。篇首默认给出轻量的正式小节预览，建议初值不超过 3 项，并能打开完整现有导航；这只是首屏容量，不限制正文或完整导航的可达性。窄屏／大字号可收成清楚的导航入口。

预览和导航优先用正式标题及明确层级；不得把文章目录自动改写成“先学什么、再学什么”的新教学论断。只有既有数据已提供该学习说明时才可采用。

已存在正式名称和锚点的知识卡，可以在同一个导航中归到对应小节下，作为轻量定位项；**不另建一套知识目录，不复制卡片正文，不将所有 Atom 强塞到导航。**缺少可靠标题或归属时，保留原有导航，不从段首句擅自制造卡名。

## 5. G2：文章脉络与知识脉络协作

### 5.1 三层阅读表达

| 层级 | 负责什么 | 实现约束 |
|---|---|---|
| 文章骨架 | 小节边界、论证顺序和阅读位置 | 使用正式层级；标题与段落在字重、间距上有清晰差别；不将所有小标题都做成彩色卡 |
| 原位知识卡 | 显示值得理解的既有知识单元及其正式语义 | 原字句、原位置、原依赖；用适度标签或局部强调识别，不造成连续大色块墙 |
| 按需辅助 | 关系、对照、延伸和操作 | 在需要处被发现，用户主动展开；不把工具和正文做成同等权重 |

“文章是主体”不意味着知识卡文字更小，也不意味着条件、例外不重要。**结论与使其成立的条件、例外和限定必须保持连续可见的逻辑关系，不能只突出结论而把限定降成可忽略的小字。**

普通段落仍是完整论证的一部分，不能灰化到难读、默认折叠或标记为不必读。不是所有内容都需要卡框；同一知识单元跨多个正式块时保留原序和已有归属，不新生成卡片对象。

### 5.2 阅读位置与导航

使用既有文内导航帮助回找；页面显示稳定的小节层级，任务型落点有短暂、非闪烁的定位强调。已有当前小节状态可以复用到导航；如果项目没有该能力，本轮不另建滚动跟踪引擎或学习进度条。

点击导航到块、调整字号、展开关系、返回原文后，应仍能看到目标知识及其上下文。不能依赖初次计算的固定高度，让字号变化后持续错位。

不为本轮新增“只看重点”开关。已有知识卡的原位表达和现有导航承担快速扫描、回找能力；现有 `keyPoints` 类定义不应被擅自实现为隐藏全文。

### 5.3 视觉落实顺序

先确定信息顺序和展开状态，再处理正式标题、段落、知识卡、辅助提示的层级；最后调整间距、字号、颜色和触控范围。复用现有设计令牌及政治模块风格，不建立新设计系统。

本轮完成的判断不能是“多了几种标签和底色”，而应是：用户能看出一个小节在哪里结束，一个知识卡为何值得注意，一条辅助关系如何使用，以及如何继续读正文。

## 6. 关联线索、易混、相关知识与知识延伸的展示合同

四类能力都有价值。**不全部移到页尾，也不全部展开在正文。**下面规定展示职责，不创建新的关系分类或改变既有业务类型。

### 6.1 位置、默认状态和点击结果

| 现有能力 | 合理位置 | 默认呈现 | 用户主动操作后 |
|---|---|---|---|
| 关联线索 | 对应知识卡或论述段落组之后 | 紧凑的目标标题＋已有关系提示；没有短理由时只提供明确入口 | 原位展示已有关系理由与原文入口，再由用户选择是否跳转 |
| 正式易混 | 正式边界涉及的原文位置 | 清楚展示概念对，以及已有简短正式边界；比普通关联更醒目，但不压过正文 | 展开现有对照，看到两侧正式差异和各自原文入口 |
| 相关知识 | 正文收口和回忆操作之后的探索区 | 简明目录式入口，保留已有关系表达 | 使用现有目标页／原文定位能力打开，返回恢复原状态 |
| 知识延伸 | 同一探索区中的已有延伸分组 | 明确是可选延伸，不暗示本篇必学 | 使用已有内容及跳转方式打开，保留返回 |

若某类信息**已经是正式正文的一部分**，不得为满足上述位置表而移走原文；表格调整的是辅助投影和操作，不是正文顺序。

### 6.2 正文旁的信息容量

关联提示不默认展开整段关系理由、目标全文和多组操作。优先复用现有展开／收起控件；需要补充时只新增局部展示状态，不造新的关系浏览业务流程。用户展开某一条关系后，不应导致其他段落整体重排或丢失阅读位置。

易混边界不能因为“收起辅助信息”而被隐去其关键条件；短边界可直接展示，长对照保持完整可展开。没有正式简短说明时使用概念对标题和“查看区别”，**不自动压缩出一句新结论**。

同一位置多条关系可在一个紧凑的既有关系容器中列出。折叠可以减少初始占位，但全部既有内容必须可达。无既有排序规则时保持正式顺序，不增加相关性评分、推荐排序或任意筛掉所谓次要关系。

### 6.3 去重与事实保留

先核对“关联线索、易混、相关知识、知识延伸”是否部分来自同一事实对象的不同投影。展示去重应依据稳定关系／对照 ID、证据锚点及既有身份，不以相同标题粗暴合并；同一目标但理由不同，不能误删。

正文内可展开事实，页尾可有对应索引入口，但不要再次默认展开同一整段内容。所有现有有效关系和两侧原文入口保持可达。没有正式类型支持的分组不强行生成；没有内容的分组不占位。

### 6.4 本轮交互示例（只示意模板，不生成知识）

```text
正文中：
  [既有知识卡正文]
  关联：[正式目标标题]  查看联系

展开后：
  [现有正式关系理由]
  查看对应原文   收起

正式易混处：
  易混：[正式概念 A] / [正式概念 B]
  [已有可直接展示的正式边界；缺少短文本时不造摘要]
  查看区别与原文

正文结束：
  回忆一下 →
  [合法的继续／返回]

  相关与延伸
  [已有相关知识入口]
  [已有知识延伸入口]
```

## 7. G3：回忆、发现不确定、回原文、再继续

### 7.1 回忆入口的位置与措辞

已有回忆入口应位于**最后一个正式正文块之后、普通相关与延伸探索之前**。这不要求用户必须滚到底才允许回忆；已有快捷回忆入口可以保留，但不新增满屏固定按钮。

推荐中性表达“回忆一下／试着回忆”，不使用“整篇已经掌握”“本篇全部考点已通过”。交接报告中曾提到每篇只有一条回忆题，应在 B0 复核覆盖范围；**不把一题自评当作所有知识卡的掌握证明**。

### 7.2 闭环的行为合同

```text
阅读正文
  → 用户主动进入已有回忆
  → 使用现有题目、揭晓与自评
  → 用户发现不确定，主动查看答案依据
  → 定位既有对应块；多处依据按现有能力切换
  → 返回同一道回忆题，保留先前状态
  → 按已有能力再次尝试、继续原路线或返回原活动
```

“暴露薄弱点”在本轮的含义是**用户通过回忆、答案比对和自评发现自己不确定**，不是系统自动诊断。若没有逐知识点的现成判定依据，不能声称“你遗漏了第二条”“你的薄弱点是某概念”。

### 7.3 自评后的动作

| 现有状态 | 合理下一步 | 约束 |
|---|---|---|
| 未揭晓 | 继续回忆／揭晓 | 不因提示信息提前泄露答案 |
| 已揭晓，尚未自评 | 按现有选项自评，也可查看依据 | 不新增必填评分或学习锁 |
| 实际自评为模糊／不会 | 突出“查看对应原文”，保留继续／退出 | 复用原选项语义，不修改评分算法 |
| 实际自评为记住／会 | 突出合法的继续／返回 | 不宣称全篇掌握或自动解锁新路线 |
| 从原文回到回忆 | 同一道题、原揭晓与自评状态 | 不自动换题、不静默覆盖先前回答 |

“再回忆”只复用已有重试或重新呈现同题的机制。没有该机制时，不新增复习队列或调度系统；先保证能回同题继续现有操作，并在证据中说明能力边界。

### 7.4 两层返回不能混淆

须区分**最近一步**和**外层活动**：例如“搜索结果 → 正文 A → 回忆 → 答案原文”，在答案原文点返回应先回同一道回忆题，而不是直接回搜索；退出本篇后再恢复外层搜索。

正文 A → 相关正文 B → 返回 A，应恢复 A 的关系展开、阅读位置与入口上下文。以上优先复用现有页面栈、状态和恢复机制，不新建通用导航框架或第二套全局状态树。

建议至少保留并测试：来源活动及其状态、当前正文 ID、目标块／依据选择、阅读位置、关系展开状态、同题回忆身份及揭晓／自评状态。字段名与存储方式以当前工程为准，本文不要求照此新建数据结构。

### 7.5 锚点或返回失效的降级

合法 ID 存在但块失效时，回到该篇可读正文并说明“未能定位到指定段落”，不得显示“已定位”。关系没有块级依据时，以篇级进入，不伪造精确落点。

来源活动已不存在时，保留当前可阅读内容，提供已有合法的上一级／目录返回；不要伪造已恢复原任务。不能为修复恢复边界，擅自新增跨设备进度服务或新的持久化协议。
