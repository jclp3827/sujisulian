## 本切片交付

1. 新增纯 `FocusWorkbenchViewModel`，输出 ContextBar、活动控制器、阅读前关系定向、一层关系探索、预览和返回模型。
2. 政治从 L3 进入工作台；有关系时默认 `relations/orientation`，无关系时显示体系位置并保留完整阅读主操作。
3. 定向最多3条、每关系类型最多1条；深度关系图形最多6个邻居，完整列表不截断。
4. 点击关系只打开预览，不改变焦点；确认“切换焦点”或“阅读全文”后才执行 `FOLLOW_RELATION` 并写探索轨迹。
5. A→B→C 可用知识级返回逐步恢复 B→A；关系预览关闭不入轨迹。
6. ActivityDock 固定“体系—关系—阅读—回忆”语义顺序，只显示当前焦点真实可用活动；切换活动不更换焦点。
7. 阅读和回忆继续复用现有政治内容承载，S3B/S4 再分别升级语义阅读和范围化主动回忆。

## 状态、ViewModel 与路由变化

- `KnowledgeContext` 继续作为唯一焦点、活动、轨迹和快照来源；页面不维护第二套知识历史。
- `FocusWorkbenchViewModel` 只携带当前焦点、当前一层关系、当前活动所需内容引用和返回模型，不把整库交给页面。
- 工作台深链仅使用 `pointId + activity + origin`；关系预览为页面瞬态，不持久化。
- “在体系中定位”只传稳定导航 ID 和临时高亮，不改变正式焦点。

## 自动验收

1. 相同包和上下文连续投影完全一致。
2. 0/1/3/>6关系夹具均有确定输出；定向≤3且每类型≤1，邻居≤6，完整列表覆盖全部有效关系。
3. 预览不改焦点和轨迹；确认切换后轨迹+1；A→B→C连续返回为B→A。
4. 反向前置只派生展示，不新增或写回正式关系；重复目标不会制造重复邻居。
5. 无关系隐藏深度探索，无回忆隐藏回忆活动；无焦点不生成工作台。
6. 深链、内容版本失效和跨模块 ID 安全降级。
7. S1/S2、政治内容与关系、常识和笔记既有门禁保持基线。

## 用户手测

1. 从任一 L2知识建立焦点，进入工作台，确认标题、完整路径和关系定向清晰且不超过3条。
2. 点击关系只出现预览；关闭后焦点不变；确认换焦点后中心变化并出现“返回上一个知识”。
3. 连续切换两个关系节点，再逐次返回，确认方向与标题恢复正确。
4. 在体系、关系、阅读、回忆之间切换，确认始终是同一知识焦点。
5. 确认完整关系列表可达、长理由可读、底部控制器不被安全区遮挡。
