## 0. 本轮结论

旧J2已经取得“四站可推进、六锚点可解析、详情可往返”的工程证据，但用户手测得到两个独立失败：

1. 页面可见，但真实交互无法完成，现有自动门禁没有覆盖真实selector tap；
2. 即使修复点击，主体仍是“沿目录结构走四站”，不能让一个没有系统学过政治理论、只有零星印象的新用户获得经过加工的初步理解。

因此OUT-J2必须回到`UX-failed`。旧实现和旧绿灯冻结为`J2 v1 engineering-passed / UX-failed`历史证据，不删除、不改写，也不再授权J3。

J2 v2冻结为：

> 一份目标时长8–12分钟、内容先行、连续纵向阅读的政治理论新手导读。用户先看到经过审核的解释、代表例和两条主线的关系，再看到这些内容在整体中的位置；完整目录与知识卡只作为可选深入入口。

保留旧J2中仍然正确的原则：

- 系统给出默认起点，不让新手先选篇章或范围；
- 所有政治结论有正式unit/block/atom来源；
- 沿用现有LearningRoutePlan、RouteSession、KnowledgeContext、DisplayPreferences和viewport；
- 可选详情继续进入同源KnowledgeCard，原生返回恢复原位置；
- 完成只陈述可观察动作，不声称理解、掌握或正确率。

废止：

- 以`overview → n002 → n024 → closure`四站构成快速了解；
- 以六个锚点入口代替导读正文；
- 逐站点击`COMPLETE_TOUR_STOP`才能继续；
- 缺少导读内容时退回目录游并仍称“快速了解”；
- 用标题、summary列表、结构数量或按钮点击证明学习结果。

## 1. 用户、结果与范围

### 1.1 目标用户

首版服务三类首次用户：

- 从未系统学习政治理论，只熟悉少量公共表达；
- 在其他渠道零星看过概念，但不知道它们怎样组成整体；
- 学过其他政治或哲学理论，需要先建立当前政治模块的边界与坐标。

用户无需先懂“知识地形”“篇章”“锚点”“关系投影”等产品内部概念。

### 1.2 结束时允许期待的结果

用户应有机会做到：

1. 用自己的话说出当前政治理论模块主要由哪两条主线构成；
2. 说明两条主线不是互不相关的目录，并能指出“两个结合”这一正式连接点；
3. 区分“基本原理中的方法镜头”和“新时代思想中的当代回答与实践展开”；
4. 看懂至少两个带边界的代表例，并知道它们位于整体哪里；
5. 知道下一步可以进入完整知识、知识全景或系统学习。

这只是产品提供的学习机会，不等于自动证明用户已经做到。候选阶段仍需真实用户关屏复述验证。

### 1.3 明确不承诺

- 不覆盖全部考公政治、时政、党史或政策更新；
- 不等于完整讲完37个KnowledgeUnit；
- 不承诺记忆、掌握、正确率或个性化诊断；
- 不把8–12分钟写成对每个人的精确时长预测；
- 不以完整目录、37个summary轮播或六个必点KnowledgeCard作为正文；
- 不实现J3系统学习、J4易混突破或J5考前速记。

首版只能诚实说明：当前review内容覆盖两篇正式主线；马原的具体内容主要覆盖概述、哲学和政治经济学选定内容，尚未独立展开科学社会主义；时政、党史和完整考试范围也未覆盖。权威缺口账本见[政治profile](../profiles/politics.md#当前内容覆盖缺口与后续补充)；J2 v2不在教学过渡文案中补写这些正式内容。

## 4. 每段的固定展现语法

`J2V2-SEC-02`至`J2V2-SEC-07`采用同一连续语法：

1. **用户问题**：以用户会问的话开场，不以目录名或内部状态名开场；
2. **一句回答**：1–2句可以独立理解的核心判断；
3. **解释展开**：2–3个连续短段，不把每一句切成独立卡片；
4. **代表表述或边界**：直接消费经审核的source block/atom，说明“看什么、为什么、放在哪里”；
5. **整体位置**：用完整命题说明当前内容与两条主线的关系；
6. **自然过渡**：引到下一段，不使用“已看清，下一站”作为通行门。

`J2V2-SEC-01`使用“用户场景—已有印象—本次结果”；`J2V2-SEC-08`使用“自我解释—参考表达—总图—诚实完成”。

每段最多提供一个`查看完整知识`次级入口。用户不打开任何详情仍能获得完整导读；打开详情不推进路线、不自动完成该段。

## 5. 结构定位层

结构定位不再是第二份目录，而是同一语义模型的三种密度：

1. 顶部`StructureMiniBar`：只显示“政治理论 › 当前主题”和细进度，高度目标40–56px；不常驻完整图；
2. `J2V2-SEC-02/J2V2-SEC-08`宏观总图：固定为`n001 → n002/n024`三个宏观节点，每条连线都必须有可读关系命题；
3. `J2V2-SEC-03`至`J2V2-SEC-07`局部定位：当前主干加最多4个与本段直接相关的节点，纵向排列，不拖拽、不缩放、不横向平移。

六个v1锚点可作为取材候选，但不再作为六个强制入口。总图不得用“19项/18项”代替两条主线的意义；第二篇必须保留政治经济学`n038`作为“仍可继续深入”的可见分支，避免首版方法内容让用户误以为第二篇只有哲学。

## 6. 内容制品与同源契约

J2 v2需要一份人工策展、可构建、可失效的`QuickPrimerDefinition`。它属于内容加工层的审核制品，不是profile文案、WXML常量、第二张知识卡或新的GraphRelation。

```text
QuickPrimerDefinition
├─ id
├─ moduleId
├─ version
├─ status: review | approved | retired
├─ scopeNodeId
├─ targetMinutes { min, max }
├─ scopeBoundary
├─ sections[]
│  ├─ id
│  ├─ order
│  ├─ kind
│  ├─ title
│  ├─ guidingQuestion
│  ├─ narrativeSegments[]
│  │  ├─ type: source | bridge | scenario | label
│  │  ├─ sourceBlockIds[]
│  │  ├─ sourceAtomRefIds[]
│  │  ├─ editorialText?
│  │  └─ reviewState
│  ├─ structureFocusNodeIds[]
│  └─ detailTargets[]
├─ structure
│  ├─ macroNodeIds[]
│  └─ propositions[]
├─ reflection
├─ completionCopy
└─ sourcePackageVersion
```

约束：

- `source`段直接读取正式SemanticBlock/KnowledgeAtomRef，不复制正文；
- `bridge/scenario`是经审核的教学编排，不成为搜索答案、关系事实或KnowledgeUnit正文；其中任何事实性命题都必须列出支持它的block/atom引用；
- 所有编辑性表达绑定`sourcePackageVersion`；引用内容变化后整体重新审核，不能继续显示旧解释；
- profile只保存`primerId/scopeId/reason`，不得保存完整脚本或逐段事实；
- builder验证段落数量、顺序、全部引用、审核状态、两例、宏观结构命题和完成文案；不得用标题、summary或相似度自动补缺；
- 运行时只生成纯`QuickPrimerProjection`，仍以正式blocks为事实母体；
- 这一对象确认后再归并进04契约。首轮只为政治实现，第二个模块出现同类需求后再判断是否抽象通用作者工具。

现有summary不能单独作为逐项证据。多个政治summary综合了多个块，却只带一个代表性`summaryBlockId`；v2必须直接消费脚本列出的显式block/atom，不能重演“一句话看似有来源、实际只锚定半句”的问题。

## 7. 状态、恢复与动作

不建立`QuickPrimerSession`或第二套viewport。继续使用：

- `LearningRoutePlan`保存`primerId/version/scopeId/sourcePackageVersion`；
- `RouteSession`保存最后可见段、已见段、自我解释状态与最终状态；
- 既有viewport保存滚动锚点；
- 既有DisplayPreferences保存字号、行距和减少动画；
- 既有KnowledgeContext保存入口、原生返回和可选详情来源；滚动段落不伪造KnowledgeFocus。

最小事件：

```text
START_QUICK_PRIMER
VIEW_QUICK_SECTION          # 观察事实，不自动完成
OPEN_QUICK_DETAIL           # 不推进段落
SUBMIT_QUICK_REFLECTION
SKIP_QUICK_REFLECTION
COMPLETE_QUICK_PRIMER
EXIT_QUICK_PRIMER
```

旧`COMPLETE_TOUR_STOP`不再用于v2。滚动、展开来源、查看知识卡或触发intersection observer都不能自动完成。

进入完整KnowledgeCard时保存`primerId/sectionId/scrollAnchorId/viewportToken`；微信原生返回恢复原段原位置。package或primer版本不匹配时说明“导读内容已更新，需要从开头重新了解”，不按标题猜旧段对应关系。

## 8. 一次轻量自我解释

冻结问题：

> 如果只用一句话向第一次接触的人解释：《马克思主义基本原理》和《习近平新时代中国特色社会主义思想》为什么不是两份互不相关的目录，你会怎么说？

交互约束：

- 使用微信原生多行输入，建议6–80个汉字；
- 主动作是“看参考表达”；明确次级动作是“暂时说不清，先看参考表达”；
- 不接AI、不判分、不显示正确/错误、正确率或mastery；
- 提交或暂缓后显示经审核且有来源的参考表达，并重新点亮两条主线的连接；
- 返回/重载仍由同一RouteSession恢复`submitted|skipped`及输入；
- 存储失败显示“本次表达未保存”，允许重试或暂缓继续，不能吞错。

## 9. 失败与诚实降级

| 失败 | v2行为 | 禁止行为 |
|---|---|---|
| primer缺失、状态不合格或段落不全 | 显示“快速导读内容正在完善”，提供知识空间和其他已可用目标 | 回退四站目录游并称快速了解 |
| 任一必需block/atom失效 | 整份primer不可用，给出内容已更新说明 | 删除该句后静默完成部分导读 |
| 可选详情目标失效 | 隐藏该详情入口，正文仍须完整 | 用相似标题猜另一个知识 |
| package/primer版本变化 | 会话expired，显式从头重建 | 沿用旧完成状态或按段标题迁移 |
| 本地保存失败 | 阅读可继续，显示未保存、重试和暂缓 | 当成首次使用或假装保存成功 |
| 后续目标暂不可用 | 结束页主动作改为“回到知识空间” | 展示死按钮或提前实现J3 |

政治仍为`candidate`，37篇仍为`review`，发布数0。页面和导读内容通过不改变发布资格。

## 10. 完成语义

完成条件只有：

1. 用户到达`J2V2-SEC-08`；
2. 自我解释状态为`submitted`或`skipped`；
3. 用户显式点击“结束本次导读”。

快速滚到底只证明到达，不能证明阅读。完成页标题为“本次快速导读已结束”。报告只允许显示：

- 到达过哪些导读段；
- 两个代表例是否进入视口；
- 一句话解释为“已留下”或“暂缓”；
- 进度是否保存；
- 可选详情实际打开数量。

允许写“现在可以尝试说清两条主线及其连接”，不得写“你已理解”“已经掌握”“正确率”或根据停留时长推断学习效果。

## 11. 320px、触控与无障碍

- 首屏必须出现实质政治内容和本次结果，不先出现目录数量、范围选择或大面积结构图；
- 正文为单列连续流，不使用横向滚动、双列窄卡、拖拽或缩放作为理解前提；
- 结构条不能遮住正文，最大字号下允许换行和页面增长；
- 所有次级详情入口、输入框和最终动作必须满足微信真实触控，不依赖hover；
- 自动化必须执行真实selector tap/输入/原生返回，不得直接调用page handler代替用户操作；
- 130%字号、减少动画和320px宽度下，正文、输入、参考表达、返回与最终动作均可达；
- 常识、笔记和主导航行为保持不变。
