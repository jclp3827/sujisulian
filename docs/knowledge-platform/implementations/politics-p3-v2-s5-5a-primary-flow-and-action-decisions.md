## 1. 本文要解决什么

现有实现已经能从首页进入地形、搜索、路线、详情、关系、阅读和回忆，但“功能能到达”不等于“用户知道下一步”。同一状态中仍可能出现多个看似同权的去向；相反，真正需要用户决定的地方又可能只有一组样式相近的卡片，无法判断选择后会发生什么。

本文把 S5.5A 从“删几个重复按钮”提升为完整的主流程与动作合同，逐页回答五个问题：

1. 用户来到这里时正在完成什么任务。
2. 当前界面要求用户做哪一个决定。
3. 哪个动作是唯一推荐动作，哪些只是对象选择、上下文工具或退出操作。
4. 执行动作是否建立或改变知识焦点、活动、路线及探索轨迹。
5. 用户返回时应回到哪个认知位置，而不是只回到哪个微信页面。

本文不定义 L0–L3 的最终视觉布局，不完成四类目标各自的任务体验，不逐字冻结学习者文案，也不修改正式知识、目录、关系、回忆或发布状态。这三部分分别由 S5.5B、S5.5D、S5.5C 继续细化。

### 1.1 用户已纠正的路线前提

路线的主流程不是让用户先选择篇章、范围、易混对或回忆卡组，再由用户自行组织学习。路线必须承担“替用户安排一条可信路径并持续告诉他下一步”的责任：

- 系统根据目标、正式知识结构、当前有效上下文和07允许的范围来源，生成一条默认推荐路线。
- 用户进入目标后首先看到系统建议怎样开始、为什么这样安排和完成后能得到什么；主动作是开始引导，不是配置路线。
- 调整范围、换一组、查看完整计划可以保留，但属于次级控制，不成为进入路线的必经步骤。
- 引导必须贯穿体系、关系、阅读和回忆活动；用户不需要在路线总览和工作台之间往返编排步骤。
- 07要求“范围明确、计划冻结、依据可解释”，并不等于“范围必须由用户手动选择”。系统推荐的范围同样必须显式展示、可追溯、可调整。

## 2. 当前问题不是“按钮太多”，而是决策层级不清

### 2.1 已出现的根因

- 首页、目标路线、搜索和目录都能成为“开始”，却没有明确默认起点与情境起点的差别。
- 地形节点、列表项、推荐动作、活动切换和返回操作都被画成相近的可点击卡片，用户无法区分“选择对象”和“推进任务”。
- 搜索结果同时提供体系、关系和阅读方向，相当于要求用户在理解命中前先理解平台结构。
- 关系预览同时提供切换焦点、阅读全文和体系定位，平台把导航决策转嫁给用户。
- 路线页和焦点工作台都在告诉用户“下一步”，形成两个任务控制中心。
- “一个状态一个主动作”只停留在按钮数量，未说明主动作由什么意图产生、何时改变状态、返回到哪里。

### 2.2 必须避免的错误修复

- 只把三个按钮折叠进“更多”，但仍不说明哪个动作最符合当前意图。
- 只把一个按钮涂成主色，其余按钮仍同样突出且去向相近。
- 为每个页面分别维护 `selectedPoint`、`currentItem`、`fromPage` 等局部事实，形成第二套焦点和返回状态。
- 把所有入口强制串成“首页 → 选择篇章 → 进入知识”，导致快速了解、易混突破和考前速记再次与系统学习同构。
- 让路线页复制关系、正文或回忆内容，以便看起来更完整，最终形成第二个工作台。

## 3. 主流程重新定义

### 3.1 不是一条包含所有能力的固定漏斗

政治模块有两类顶层意图，它们共享 `KnowledgeFocus`、`ActivityStage`、`Trail`、`RouteSession`、显示偏好和 viewport 状态，但入口决策不同：

```text
自由探索
首页
→ 知识全景
→ 选择区域 / 主题 / 知识
→ 聚合节点改变视窗；具体知识直接建立焦点
→ 完整知识详情（同源关键筛选 / 下部关系与回忆）
→ 按需打开关系抽屉并决定是否进入关联知识
→ 有正式回忆时主动回忆
→ 返回原地形、搜索或探索轨迹

目标任务
首页选择目标
→ 系统按目标生成一条有依据的默认推荐路线
→ 用户一键开始；调整范围只是次级动作
→ 持续引导条说明“现在做什么、为什么、下一步是什么”
→ 在同一焦点工作台依次完成体系 / 关系 / 阅读 / 回忆
→ 当前活动的明确完成事件直接推进 RouteSession
→ 给出该目标特有的完成反馈
```

自由探索不要求先选学习目标；目标任务不要求用户先选篇章或自行编排。二者在“建立焦点后”复用同一工作台，但目标任务始终带着系统生成的引导上下文。

### 3.2 空间地形、快速了解与系统学习不是同一件事

| 能力 | 谁决定下一步 | 主要回答 | 结束条件 |
|---|---|---|---|
| 空间地形 | 用户自由选择 | “这个领域有什么、我现在在哪里” | 没有路线完成概念；用户可随时建立焦点或离开 |
| 快速了解 | 系统按L0/L1与显式核心锚点引导 | “为了形成总体认识，我现在应该看哪一部分” | 走完有限的主干总览和核心锚点 |
| 系统学习 | 系统按正式范围、前置约束和学习活动编排 | “为了深入理解，我接下来应学习哪个知识、做什么活动” | 完成范围内规定的关系、阅读、回忆步骤，并诚实记录跳过 |

快速了解可以借用地形作为讲解材料，但它不是让用户自由浏览地形；系统学习可以显示体系位置，但它不是从L0逐层点进每篇知识。地形负责空间认知，路线负责有目的的时间顺序。

### 3.3 首页的默认主流程

首页首先解决“我怎样最快到达想去的地方”，其次才承担“让我认识这套产品的新空间模型”。推荐采用四层意图分发，而不是让知识地形独占第一认知：

```text
模块身份
→ 熟悉入口：完整宽度搜索/提问框
→ 状态主任务：继续当前引导 / 继续上次知识 / 首次推荐快速了解（三选一）
→ 四类目标：紧凑、直白、可一键进入系统推荐路线
→ 知识全景：可见的结构预览 + 打开全景 + 目录等价入口
```

#### 第一层：搜索是熟悉入口，不是主任务卡

- 搜索框始终在模块标题之后立即可见，使用用户熟悉的输入框形态，不做成第三张“功能卡”。
- 占位说明同时覆盖关键词和问题，例如“搜索知识，或问‘二者有什么区别’”。
- 搜索只负责表达明确需求，结果仍按第5.7节先预览再建立焦点。
- 搜索可以视觉显著，但不使用与状态主任务相同的填充按钮样式，因此不形成两个主动作。

#### 第二层：系统只推荐一个当前最合适的任务

| 用户状态 | 唯一状态主任务 | 为什么 |
|---|---|---|
| 存在有效活动路线 | 继续 `{目标名称}` · `{当前步骤说明}` | 已开始的明确任务优先，减少中断 |
| 无活动路线、有最近焦点 | 继续了解 `{知识短标题}` | 回到已形成的认知上下文 |
| 首次进入或无有效状态 | 先快速了解政治理论 | 用系统导览建立最低成本的整体认识，不要求先理解地形操作 |
| 恢复状态失效 | 重新快速了解整体 | 给出一次失效说明，不猜替代知识 |

首次进入的推荐是“快速了解”，而不是“查看知识全景”。快速了解会借用地形内容，但由系统带领；知识全景仍保留为自由探索入口。

#### 第三层：四类目标是紧凑意图，不是四张功能大卡

- 四类目标在首屏可扫描区域内同时可见，320px下使用2×2紧凑入口或等价列表。
- 每项只表达“我现在想达到什么”，例如了解整体、系统学一遍、解决易混、考前过一遍；不在首页解释内部步骤。
- 点击后立即看到该目标的系统推荐方案和一键开始，不先进入选择器。
- 当前系统推荐目标可以有轻量“适合你现在”标识，但不能伪装成个性化预测。

#### 第四层：知识全景是差异化入口，不是理解产品的前置考试

- 首页展示一块紧凑、真实的 L0 结构预览，让用户知道这里不只是搜索和卡片集合。
- 预览只表达主要区域和整体规模，不要求用户在首页完成层级操作。
- 主入口命名为“浏览知识全景”，旁边提供“按目录查找”；二者进入同一 system 状态与范围。
- 用户通过快速了解获得第一次成功后，可自然理解全景的价值；不要求首次进入就学习空间地形语法。

#### 为什么这不是功能大厅

| 传统功能大厅 | 本方案 |
|---|---|
| 搜索、目录、背卡、阅读都是并列工具 | 搜索是明确需求入口，状态区只有一个推荐任务，四类目标进入系统引导 |
| 用户自己选择工具并组织顺序 | 系统负责给出路线和下一步 |
| 每张卡进入孤立功能页 | 所有入口最终共享焦点、活动、路线和返回状态 |
| 首页不表达知识结构 | L0结构预览持续可见，但不强迫用户先理解它 |

该方案保留CORE-004规定的首页四项职责，但改变原IA-002、08第3.1节和VIS-001“L0地形必须是第一视觉主体”的固定优先级。用户已于2026-08-28确认，02与08已同步修订；没有让低层实现静默覆盖上游规格。

### 3.4 “一个状态一个主动作”的准确含义

一个状态最多有一个视觉主动作，但允许以下三种非竞争性交互：

1. **对象选择组**：例如选择一个区域、一个搜索结果或一个易混对。每一项只是选择对象，不同时承诺多个不同去向。
2. **回答选择组**：例如回忆揭晓后的“记得 / 模糊 / 没记住 / 跳过”。这些是同一问题的互斥回答，不是四个导航主动作。
3. **系统操作**：返回、关闭、展开、显示设置等不参与主动作竞争。

“主动作唯一”约束的是同一决策状态中的推荐去向，不是把所有可点击对象压成一个按钮。

## 4. 动作分层与视觉责任

| 层级 | 用户含义 | 数量与位置 | 是否改变认知状态 | 例子 |
|---|---|---|---|---|
| 主动作 `primary` | 按当前意图继续完成任务 | 每个决策状态最多1个；处于当前内容之后或固定任务区 | 可以，但必须在动作结果中明确 | 查看这个知识、阅读完整内容、开始当前任务 |
| 次级动作 `secondary` | 可逆地选择另一条合理路径 | 默认最多2个；低于主动作，不使用同等填充样式 | 可能改变活动，不得静默换焦点 | 深入关系、查看知识全景 |
| 对象选择 `selection` | 选择“对谁/在哪个范围”执行后续动作 | 可以有多个同构项；选中后才出现或更新主动作 | 只更新临时选择，不提交焦点或路线 | 区域、搜索结果、易混对 |
| 上下文工具 `context` | 调整阅读、查看来源或提交反馈 | 收进命名明确的单一入口或上下文区域 | 不改变焦点、路线、正文位置 | 显示、来源与反馈 |
| 系统操作 `system` | 返回、关闭、取消、展开 | 使用平台标准位置 | 只恢复或关闭临时界面 | 返回、关闭预览 |
| 回答选择 `response` | 回答同一个回忆问题 | 作为一组呈现，不使用多个导航式主按钮 | 只写本次 RouteSession / recall snapshot | 记得、模糊、没记住、跳过 |

### 4.1 主动作必须同时说明三件事

主动作的展示词和无障碍名称必须能共同回答：

- **对象**：查看哪个知识、进入哪个范围或完成哪个任务。
- **结果**：定位、建立焦点、阅读、回忆还是推进当前引导。
- **成本**：立即进入，还是先预览/确认。

“开始”“进入”“查看详情”不能脱离上下文单独作为关键主动作。

### 4.2 主动作不是全局固定按钮

主动作由当前 `origin + intent + selection + activity + goalContext` 确定。页面不得硬编码“只要有知识就显示阅读全文”或“只要有路线就显示继续”。相同知识从搜索、关系和路线进入时，推荐动作可以不同，但事实内容和焦点状态仍相同。

## 5. 页面级动作合同

### 5.1 政治首页

| 当前状态 | 用户要回答的问题 | 主动作 | 次级入口 | 状态结果 |
|---|---|---|---|---|
| 首次进入/无最近焦点 | 我怎样低成本开始 | 先快速了解政治理论 | 四类目标、知识全景、目录；搜索框始终可见 | 生成快速了解推荐计划，先说明再一键开始 |
| 有有效最近焦点 | 我是否继续上次的知识 | 搜索框下方单行悬浮卡：`上次学习：{知识短标题} · 继续 · 关闭` | 四类目标、知识全景、目录；搜索框始终可见 | 点击继续恢复原焦点、活动和有效语义锚点；关闭只隐藏本次页面入口 |
| 最近焦点已失效 | 从哪里重新开始 | 重新快速了解整体 | 四类目标、知识全景、目录；搜索框始终可见 | 显示一次恢复失败原因，不猜替代知识 |
| 有活动路线 | 我是否继续本次任务 | 继续 `{目标名称}`：`{当前步骤}` | 调整/退出任务、知识全景；搜索框始终可见 | 恢复 RouteSession 当前步骤；不把普通最近焦点当成更高优先级 |

首页“继续路线”和“继续知识”同时存在时，最近仍有效的活动路线优先；普通最近焦点作为次级恢复入口。首页不同时出现两个填充式“继续”。搜索框、四类目标和全景预览始终可达，但不复制主任务动作。

### 5.2 知识全景、目录与 L0–L2 选择

地形和目录中的聚合节点用于改变视窗，具体KnowledgeUnit则是明确的阅读对象。点击具体知识直接建立焦点并进入详情，不再插入知识预览抽屉。

| 选择对象 | 选择后必须出现的信息 | 唯一主动作 | 是否建立焦点 |
|---|---|---|---|
| L0区域 | 区域说明、主分支数量、当前路径 | 查看这个区域 | 否，只更新 system viewport |
| L1篇章 | 篇章位置、下级主题概览 | 进入这个篇章 | 否，只更新 system viewport |
| L2主题 | 主题范围、核心知识与溢出说明 | 查看这个主题 | 否，只更新 system viewport |
| KnowledgeUnit | 完整标题、路径、一句话理解或诚实缺省 | 点击卡片直接打开详情 | 是，执行 `SELECT_POINT` |

目录与地形对同一对象使用相同的提交动作与返回合同；投影切换不新增主动作，不改变选中对象、焦点或 viewport。

### 5.3 建立焦点后的关系定向

焦点建立后直接打开同一KnowledgeSurface的完整详情。关系不再阻断阅读，而是在详情下部作为情境入口；用户打开关系抽屉后先理解“为什么相关”，再决定是否进入目标知识。

- 正文是默认内容，不再需要一次“阅读完整内容”确认。
- 存在正式关系时，下部显示`相关知识`入口并按需打开关系抽屉；默认不提供四项ActivityDock要求用户自行切换。
- 没有正式关系时不显示空关系入口。
- 若当前 RouteStep 明确要求关系活动，持续引导条给出该步骤的具体动作；通用“阅读完整内容”降为次级，不与路线争夺主动作。
- 页面标题只说明知识身份；GoalGuide除说明当前任务外只提供当前一步的唯一推进动作，不做成第二套活动切换器。

### 5.4 深度关系探索与关系预览

关系节点点击只打开预览，不改变当前焦点，也不写探索轨迹。预览必须先显示关系方向、完整理由、目标路径和可用来源，再给动作。

| 来源意图 | 关系预览主动作 | 主动作结果 | 折叠的其他去向 |
|---|---|---|---|
| 自由探索 | 继续了解 `{目标知识}` | `FOLLOW_RELATION`，目标成为新焦点，留在关系活动 | 阅读目标完整内容、在体系中定位 |
| 路线当前步要求阅读全文 | 阅读 `{目标知识}` | `FOLLOW_RELATION` 后进入 reading，保留路线与来源关系 | 继续看关系、在体系中定位 |
| 路线当前步要求对照 | 开始这组对照 | 保持关系两端和 RouteSession，进入对照活动 | 阅读任一侧原文 |
| 仅需定位 | 在知识全景中查看 | 创建临时 system 快照，不改变原焦点 | 继续了解、阅读全文 |

“其他去向”展开后仍保持普通文本/列表权重，不能重新形成三个同权按钮。关闭预览必须回到原焦点、原 lens、原关系节点和原 viewport。

### 5.5 完整阅读

完整阅读是同一大知识卡的正文态，不是离开知识卡进入另一份文章。正文只渲染正式卡片的一份有序内容块，不再把`KnowledgeAtomRef`作为“关键内容”重复置于正文上方。`只看关键内容`仅使用既有`DisplayPreferences.emphasis=keyPoints`筛选同一组正式内容块；显示工具和来源不参与任务竞争。关系与回忆入口并置于详情下部的情境学习区。

| 阅读上下文 | 文末主动作 | 次级动作 | 返回 |
|---|---|---|---|
| 自由探索且有正式回忆项 | 回忆这个知识 | 返回相关知识 / 知识全景 | 回忆结束后回到原阅读锚点 |
| 自由探索且无回忆项 | 返回相关知识，或返回原体系（按来源二选一） | 另一有效返回方向 | 恢复来源快照，不默认跳下一篇 |
| 路线当前步 | 完成本步并继续：`{下一步结果}` | 查看来源、回看关系、调整计划 | 写入明确完成事件并直接进入下一 RouteStep，不返回总览二次确认 |
| 从回忆补救进入 | 返回这道回忆 | 查看完整来源 | 恢复同一 item、揭晓和 remedy 状态 |

`显示`是唯一阅读偏好入口；`来源与反馈`是唯一信任工具入口。二者不是文末主动作，切换或展开均不得改变正文滚动锚点。

### 5.6 主动回忆

主动回忆使用“题目状态机”，不能套用普通页面的多去向卡片：

```text
提示态
→ 主动作：查看答案
→ 揭晓态：回答选择组（记得 / 模糊 / 没记住 / 跳过）
→ 必要时：逐层补救
→ 主动作：下一项，或完成本次回忆
```

- 揭晓不会自动进入下一项。
- “模糊/没记住”只影响本次 RouteSession 和补救展示，不产生长期掌握度。
- 打开体系、易混或原文补救后，必须返回同一回忆项和揭晓状态。
- 只在正式 `RecallItem` 或 `terrain-hide` 可用时显示对应动作；无数据时跳过，不临时生成问题。
- 单知识自由回忆完成后回原阅读锚点；目标路线中完成一次规定作答后由同一引导继续下一卡或下一活动，不返回路线总览二次编排。

### 5.7 搜索结果与直接落点

搜索列表的唯一点击行为是按**显式问题类型或实际命中字段**直接进入对应落点，不再插入搜索预览抽屉。结果卡只展示标题、命中类型和一块高对比命中摘要；不显示面包屑、灰色重复summary、关系数量或“直接打开”提示。系统在点击时执行唯一推荐动作，不靠标题相似度猜用户意图。

| 可解释意图/命中 | 结果卡首先说明 | 点击后的唯一落点 | 状态效果 |
|---|---|---|---|
| 在哪里、属于什么、NavigationNode命中 | 它位于哪条正式路径 | 在知识全景中查看 | 使用 MAP-009定位，不建立焦点 |
| 是什么、definition/conclusion命中 | 命中了哪个定义或结论 | 阅读完整内容 | 用户确认后建立焦点并定位命中块；无blockId则到知识顶部 |
| 条件、范围、例外命中 | 适用边界是什么、来源在哪里 | 阅读上下文 | 建立焦点并定位来源块；不单独拼接成新答案 |
| 为什么、什么关系、Relation.reason命中 | 哪两个知识因何相关 | 打开知识详情及对应关系抽屉 | 建立焦点后显示正式关系理由；选择目标后才换焦点 |
| 有什么区别、contrast命中 | 对照对象和正式理由是什么 | 开始这组对照 | 有正式 contrast 时交给对应对照任务；无正式数据时不显示 |
| 怎么回忆、RecallItem.prompt命中 | 将回忆哪个知识/范围 | 回忆这个知识 | 以用户已选知识作为明确范围；无有效卡片则改为阅读完整内容 |
| 普通标题命中且无显式问题类型 | 这是什么知识、位于哪里 | 阅读完整内容 | 默认不猜关系或回忆意图 |

返回搜索必须恢复查询词、筛选、结果序号、选中结果和滚动锚点。只有点击结果执行唯一落点时才提交焦点；搜索列表本身不得覆盖最近焦点。

### 5.8 路线壳层

S5.5A冻结所有路线共用的“系统引导壳”；四类目标怎样生成推荐计划、每一步怎样讲解和怎样完成，由 S5.5D 分别冻结。路线不是一个让用户配置和管理步骤的页面，而是一层持续存在的教学引导。

```text
用户选择学习目标
→ 系统用正式规则生成默认推荐 RoutePlan
→ 说明本次会怎样进行、覆盖什么、为什么这样安排
→ 主动作：开始本次引导
→ GoalGuide持续显示当前步骤、目的、当前动作和下一步预告
→ 用户在体系 / 关系 / 阅读 / 回忆中执行明确动作
→ 动作完成事件推进RouteSession并直接展示下一步
→ 下一步或目标特有的完成反馈
```

- RoutePlanner负责根据正式规则编排默认推荐路线；用户不负责从空白状态自己拼装范围、对象和步骤。
- RouteSession拥有当前步骤、完成、跳过、结束和恢复；工作台只渲染该步骤所需的真实体系、关系、正文或回忆内容，不复制事实。
- GoalGuide是同一路线状态的投影，可随当前活动以内联引导、顶部任务条或底部单动作区呈现；它不是第二套焦点或第二套活动控制器。
- 每一步必须同时说明“为什么现在做”“具体做什么”“做完去哪里”，不能只显示步骤名和进度数字。
- 当前活动产生规定的显式完成事件后，主动作直接完成本步并进入下一步；不得要求用户先返回路线总览，再点击一次“完成当前步骤”。
- “看过页面”仍不自动算完成。阅读需显式“完成阅读并继续”，关系需完成规定的查看/对照动作，回忆需揭晓并作答或明确跳过。
- “跳过”保持次级且记录在本次报告；“调整范围/换一组/查看完整计划”也属于次级控制，不与“开始/继续引导”同权。
- 07的范围契约继续有效：推荐计划必须显示明确范围、数量、依据和失效处理；区别只在于系统先给推荐，用户不必先操作范围选择器。

### 5.9 四类目标的共同引导骨架

| 目标 | 系统默认安排什么 | 用户首先做什么 | 允许的次级调整 |
|---|---|---|---|
| 快速了解 | 模块L0/L1主干与显式核心锚点的有限导览 | 开始了解整体结构 | 缩小到某个区域、退出导览自由探索 |
| 系统学习 | profile推荐正式范围或当前上下文范围内，按前置约束与正式顺序形成学习序列 | 开始第一个知识的引导学习 | 调整正式范围、处理范围外前置 |
| 易混突破 | 当前焦点/最近范围优先的已确认contrast对；没有上下文时用profile策展顺序 | 开始系统推荐的第一组辨析 | 换一组、限定区域；不从普通篇章列表开始 |
| 考前速记 | 优先恢复有效会话；否则用profile默认正式范围生成可解释卡组 | 继续或开始第一张卡 | 调整范围、明确随机；不先浏览知识层级 |

这张表只冻结“系统先引导、用户后调整”的共同责任。四类路线的推荐规则、步骤内容、进行中结构和完成反馈必须在S5.5D中单独展开并再次确认。

## 6. 动作所有权：谁负责决定，谁只能展示

| 产品对象 | 唯一所有者 | 其他页面允许做什么 | 禁止 |
|---|---|---|---|
| 当前知识焦点 | `KnowledgeContext` / 03状态事件 | 预览并请求 `SELECT_POINT` / `FOLLOW_RELATION` | 页面维护另一份当前知识 |
| 当前活动 | 内部 `ActivityStage` + 路线步骤约束 | KnowledgeSurface与GoalGuide按上下文投影，不要求用户理解四活动 | 标题、顶部Tab、底栏暴露多套活动切换 |
| 路线当前步骤 | `RouteSession` + 纯派生 `GoalGuide` | 工作台渲染当前步骤并提交规定完成事件 | 用户手动编排、页面栈推测步骤、访问即完成 |
| 搜索决策 | `SurfaceDecision` | 结果行展示命中依据并执行唯一推荐落点 | 结果行直接给多个目的地或维护第二套选择状态 |
| 关系换焦点 | `RelationPreview` | 关系图只负责选中关系 | 点击邻点立即换焦点 |
| 阅读偏好 | `DisplayPreferences` | 单一“显示”入口投影当前值 | 页面散落字号、重点、密度开关 |
| 来源与反馈 | `EvidencePanel` | 正文块提供来源锚点 | 默认首屏展示内部审计信息 |
| 返回目标 | `ReturnModel` + semantic snapshots | 页面发出返回事件 | 仅依赖微信页面栈或像素位置 |

## 7. 状态提交与返回合同

### 7.1 瞬态工具与提交的边界

下列操作只改变界面瞬态，不改变焦点或最近学习：

- 选中地形/目录的L0–L2聚合节点并打开说明。
- 打开关系预览。
- 展开其他去向、来源、显示设置或内容反馈。
- 临时在体系中定位关系目标。

只有以下显式动作可以建立或改变焦点：

- 点击具体KnowledgeUnit或搜索结果的直接落点 → `SELECT_POINT`。
- `继续了解目标知识` → `FOLLOW_RELATION`。
- 搜索唯一推荐动作 → 验证后 `SELECT_POINT`；关系命中同时打开关系抽屉但不自动跟随目标。
- 目标入口中的 `开始本次引导` → 使用系统推荐并冻结的 RoutePlan 建立或恢复焦点。
- GoalGuide中的 `完成并继续` → 在当前活动满足规定条件后推进同一 RouteSession。

### 7.2 每次提交必须保留什么

| 提交来源 | 必须保留 |
|---|---|
| 地形/目录 | projection、expandedNodeIds、focusNodeId、scrollAnchorId、viewportToken |
| 搜索 | query、filters、resultId/index、scrollAnchorId、命中依据 |
| 关系 | fromPointId、toPointId、viaRelationId、lens、selectedRelationId、viewportToken |
| 路线 | planId、currentStepId、推荐依据、进入前活动和焦点、当前引导投影 |
| 回忆补救 | itemId、revealed、response、remedyStep、原活动和blockId |

这些字段沿用03已有状态与快照，不新增第二套持久状态。缺少精确 blockId 时只降级到知识顶部，并明确“查看完整内容”，不得伪造锚点。

### 7.3 页面返回使用微信标准左上角

用户可感知的页面级返回统一使用微信原生左上角按钮，按实际进入顺序返回，不再显示页面内“返回刚才的位置”或根据认知来源猜测另一个页面。地形/目录进入知识、知识进入回忆、关系进入目标知识、回忆进入补救内容均创建真实页面栈层级。弹层关闭仍只关闭当前弹层，不等同页面返回。

KnowledgeContext、Trail、RouteSession和语义快照继续用于恢复最近状态、路线进度和内容锚点，但不覆盖用户熟悉的页面栈返回行为。

## 8. 推荐动作派生合同

推荐动作是现有状态和数据的纯派生 ViewModel，不是新的用户状态：

```text
SurfaceDecision
├─ stateId
├─ userIntent
├─ goalGuide?
│  ├─ routeType
│  ├─ stepId
│  ├─ purpose
│  ├─ instruction
│  ├─ completionEvent
│  └─ nextStepPreview?
├─ selectedObject?
├─ recommendedAction?
│  ├─ id
│  ├─ labelKey
│  ├─ objectId?
│  ├─ event
│  ├─ targetActivity?
│  ├─ commitsFocus
│  ├─ returnPolicy
│  └─ disabledReason?
├─ secondaryActions[]
├─ selectionGroup?
├─ responseGroup?
└─ contextTools[]
```

派生顺序固定：

```text
验证模块与内容版本
→ 恢复有效 RouteSession（若有）
→ 无会话且已选目标时生成有依据的默认推荐RoutePlan
→ 读取明确 origin 与 userIntent
→ 验证已选对象和能力
→ 选择唯一 recommendedAction
→ 删除数据不支持的 secondaryActions
→ 附加 ReturnModel，不写新持久状态
```

- `labelKey` 由 S5.5C 冻结用户语言；状态逻辑不得依赖中文字符串。
- 同一输入必须产生同一推荐动作、次级动作顺序和禁用理由。
- 无合法主动作时显示明确空态及恢复操作，不保留灰色空壳主按钮。
- 页面只渲染 `SurfaceDecision`，不得再次依据数据数组顺序自行决定主动作。
- GoalGuide只投影现有RoutePlan和RouteSession，不保存另一套步骤；用户调整范围后必须重建并重新冻结计划，不能在原计划上局部拼接。

## 9. 空态、失效和降级

| 场景 | 展现 | 唯一恢复动作 | 禁止 |
|---|---|---|---|
| 最近焦点失效 | 说明内容已调整 | 返回知识全景 | 自动打开第一篇 |
| 搜索无结果 | 保留查询并给结构化建议 | 查看知识全景 | 展示全库卡片冒充结果 |
| 搜索命中块无精确锚点 | 显示知识级命中与路径 | 阅读完整内容 | 伪造段落定位 |
| 当前知识无关系 | 显示正式路径和同级位置 | 阅读完整内容 | 猜测“可能相关” |
| 当前知识无回忆项 | 说明本知识暂无回忆卡 | 返回阅读 | 从正文临时挖空 |
| 易混入口无 contrast | 不显示易混目标或说明暂无可用对照 | 返回目标选择 | 用相似标题生成一对 |
| 路线内容版本失效 | 说明本次计划需更新 | 重建本次路线 | 静默续用旧答案 |
| 返回快照部分失效 | 恢复仍有效的最近语义父级 | 返回有效范围 | 猜测同名知识或恢复像素位置 |

## 10. S5.5A 页面交付清单

规格达到 `Ready` 后，实施必须按以下独立切片完成，不允许一次大改后只看最终页面：

1. **A1 首页决策**：活动路线、最近焦点、全景默认入口的优先级和互斥主动作。
2. **A2 体系选择**：L0–L2聚合节点只改视窗，具体KnowledgeUnit直接 `SELECT_POINT` 并进入详情。
3. **A3 知识表面控制**：单一KnowledgeSurface、单份正式正文、同源关键筛选和下部关系/回忆入口；不实现默认四项ActivityDock。
4. **A4 关系决策**：关系预览推荐动作、其他去向和轨迹返回。
5. **A5 搜索决策**：结果直接落点、意图映射、焦点提交与搜索回返。
6. **A6 系统引导壳层**：默认推荐计划、一键开始、持续GoalGuide、活动完成事件、跳过/调整和 RouteSession 恢复。
7. **A7 回忆闭环**：提示、揭晓、回答、补救、下一项和原活动回返。
8. **A8 静态门禁**：同权动作、重复控制器、无依据默认项和非法状态写入检查。

每个切片完成后都要先验证状态事件和返回合同，再检查样式。不能用视觉上“看起来只有一个主按钮”代替状态正确。

## 11. 自动验收场景

### S55A-AC-001：首页主动作互斥

无恢复、有最近焦点、有活动路线、路线失效四种输入分别产生“快速了解、继续知识、继续路线、重新快速了解”之一；活动路线优先于普通最近焦点，失效状态不打开第一篇。搜索框始终可见但不被计算为第二个状态主动作。

### S55A-AC-002：聚合节点只改视窗、具体知识直接进入

在地形和目录选择 L0、L1、L2 时只改变system viewport；点击KnowledgeUnit立即触发 `SELECT_POINT` 并进入详情，不出现知识预览抽屉。切换投影不改变焦点和 viewport。

### S55A-AC-003：详情只有一个活动控制器

默认、路线、专注阅读及无关系/无回忆降级状态均不显示四个并列活动标签；详情只渲染一份正式正文，`只看关键内容`筛选同一组正式块，关系与回忆在下部按需可达，内部ActivityStage及快照仍正确。

### S55A-AC-004：关系预览不提交

打开、浏览、关闭关系抽屉均不改变焦点和轨迹；只有用户选择关系目标才触发 `FOLLOW_RELATION`，A→B→返回恢复 A 的 lens、选中关系和 viewport。

### S55A-AC-005：搜索结果直接进入唯一落点

每条结果只有一个点击行为并直接执行唯一推荐落点；结果卡展示命中依据，不出现预览抽屉或体系/关系/阅读三个并列按钮。

### S55A-AC-006：搜索意图决定主动作

位置、定义、边界、关系、对照、回忆和普通标题七类可解释输入分别命中第5.7节稳定规则；能力或数据不存在时使用明确降级，不猜测。

### S55A-AC-007：搜索完整回返

从第 N 条结果进入阅读或关系后返回，查询、筛选、结果序号、选中结果和滚动锚点一致；命中blockId时详情滚动到真实正文块。

### S55A-AC-008：路线持续引导且不要求用户编排

选择任一目标后，系统直接生成有范围、有依据、有步骤的推荐计划并提供“一键开始”；进入活动后GoalGuide持续说明目的、当前动作和下一步。完成规定动作后直接推进，不要求用户返回路线总览再确认；调整范围、换一组和跳过保持次级。

### S55A-AC-009：回忆回答组例外

提示态只有“查看答案”；揭晓后出现一个回答选择组；作答后只有“下一项/完成本次回忆”主动作，不把四个回答画成四个导航入口。

### S55A-AC-010：补救保持原题

从同一回忆项依次查看体系、易混和原文后返回，itemId、revealed、response和remedyStep保持；回看被记录为回看，不折算独立正确。

### S55A-AC-011：阅读工具不夺主流程

显示、来源与反馈展开/关闭不改变焦点、活动、路线步骤和正文语义锚点；默认首屏不与阅读主动作同权。

### S55A-AC-012：标准左上角返回

搜索、地形/目录、路线、关系目标、回忆和回忆补救均通过真实页面层级进入，页面内不再渲染重复返回按钮；微信左上角按用户实际进入顺序返回。冷启动无上级页面时只使用明确的模块兜底，不猜测历史页面。

### S55A-AC-013：无第二套状态

代码审计确认页面没有新增持久 `currentPoint/currentActivity/currentRoute/fromPage` 替代既有 Context、Stage、Trail、RouteSession 和 snapshots。

### S55A-AC-014：模块与内容隔离

政治仍为 `candidate`、内容仍为 `review`、发布数仍为0；常识、笔记、主导航和正式 Markdown/目录/关系/回忆指纹不变。

### S55A-AC-015：窄屏与可访问名称

320px和130%字号下主动作、选择组、回答组及系统返回仍可区分、可达且不横向溢出；动作层级不只依靠颜色。

### S55A-AC-016：地形、快速了解与系统学习可区分

知识地形允许用户自由选择下一处；快速了解由系统引导有限主干导览；系统学习由系统引导正式知识与关系—阅读—回忆序列。三者即使复用同一地形和工作台，也不能呈现为相同的逐层点选流程。

## 12. 用户确认后的最小手测

自动门禁通过后，用户只判断以下认知结果：

1. 首页第一眼是否只有一个明确的默认开始方式，同时仍能找到四类目标和搜索。
2. 首次进入时，是否无需理解“知识地形”就能找到搜索、快速了解、系统学习和考前速记。
3. 点击区域、主题和搜索结果时，是否先知道“选中了什么”，不会莫名换掉当前知识。
4. 进入知识后是否始终只有一个当前任务和一套活动切换。
5. 关系预览是否先解释“为什么相关”，再清楚推荐下一步，同时仍能找到其他去向。
6. 搜索“是什么 / 在哪里 / 有什么区别 / 怎么回忆”时，推荐动作是否符合问题而不是平台结构。
7. 从搜索、关系、路线和回忆原文返回时，是否回到刚才正在思考的位置。
8. 回忆是否像一条“想—揭晓—判断—补救—下一项”的连续任务，而不是按钮集合。
9. 选择任一学习目标后，是否立即得到清晰可开始的系统引导，而不是先被要求选择篇章、范围、对照对象或卡组。
10. 快速了解、系统学习和自由知识地形是否能明显感觉到“系统带着走 / 深入学习 / 自己探索”的不同。

以上感知只验证 S5.5A；四类目标是否真正成为不同体验，由 S5.5D 单独确认。

## 13. 放弃的方案

| 方案 | 放弃理由 |
|---|---|
| 把全部能力串成唯一固定漏斗 | 自由探索和四类目标的首要对象不同，会再次把目标压成篇章浏览 |
| 坚持让L0地形独占首页第一视觉 | 首次用户必须先学习新空间心智，熟悉入口触达过低 |
| 退回搜索、目录、背卡、阅读四张大功能卡 | 虽熟悉但再次要求用户自己组织学习链路 |
| 每页保留多个并列快捷按钮 | 平台把内部信息架构决策转嫁给用户 |
| 所有可点击项都算主动作 | 对象选择、回答和系统操作被错误混为导航竞争 |
| 搜索统一推荐阅读全文 | 位置、关系、对照和回忆意图没有得到回应 |
| 用关键词黑箱猜搜索意图 | 不稳定、不可解释，可能把普通命中错误引向高成本任务 |
| 点击地形或关系节点立即换焦点 | 用户没有预览与撤销空间，返回来源难以理解 |
| 路线页复制工作台内容 | 形成第二套焦点、活动和事实展示 |
| 看过工作台就自动完成路线步骤 | 访问不等于完成，且无法解释跳过和补救 |
| 先让用户选择范围、对象和卡组，再称为路线 | 把系统应承担的教学编排转嫁给用户，四类目标重新变成配置页 |
| 每一步返回路线总览再点完成 | 打断认知连续性，使用户变成流程管理员 |
| 只依赖微信页面栈返回 | 深链、弹层和多步探索后无法恢复认知来源 |
| 用样式门禁代替状态门禁 | 可以做到视觉单按钮，但焦点、路线和返回仍然错误 |
