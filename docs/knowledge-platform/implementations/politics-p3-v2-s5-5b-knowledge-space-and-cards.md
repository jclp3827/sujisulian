## 0. 本轮确认边界

用户已确认以下产品方向：

1. L0–L3继续作为内部语义尺度，但不再成为用户必须依次经过的四层页面。
2. 小屏使用“一个知识空间 + 一个当前分支 + 一个当前知识对象”的渐进承载，不要求在一屏同时铺开全部节点与正文。
3. 体系、关系、阅读、回忆继续作为内部状态和投影能力，但不默认暴露为四个并列标签。
4. 正文是知识卡的事实来源；小知识卡来自显式语义结构，大知识卡由小知识卡按正式顺序组合。
5. 回忆卡是知识卡的提问/揭晓投影，易混突破消费正式确认的卡片对照，不另造事实。
6. 可以吸收Obsidian的块引用、嵌入、反向链接和大纲思想，但小程序运行时不得依赖Obsidian、插件、`.base`或`.canvas`。

本轮新增确认：

- 整体采用稳定分区底图，优先表达正式体系位置；路线和知识关系只是按场景出现的叠加层。
- 当前分支原地展开；顶层整体改用紧凑区域栏持续在场，只有当前层真正相关的同级分支继续显示，避免底图、路径和分支重复罗列。
- 产品采用“同一知识空间页面、四种连续状态”，不把全览、分支、完整卡和翻卡回忆拆成四个用户过门页面；所有知识入口直接进入完整卡。
- 全局上下文按完整底图、缩略图和ContextBar逐级压缩，320px按可读预算聚合，正式层级、目标路线和知识关系分层显示。
- 完整目录直接消费正式导航树并以“篇—章—知识”呈现；正式数据没有章级时显示“本篇知识”，不得虚构层级。

P01至P07现已全部确认并完成页面实施。2026-08-30用户复测后，预览态、重复空间层和扁平目录已被最新决定替代：知识卡采用同一大卡的完整与回忆两种连续形态；基础大卡、小卡、回忆和易混分别以四项可验证能力标记诚实增强；政治37篇已由独立构建器任务完成卡片化。本切片只消费其同源投影，不修改正式内容。

## 1. 本文要解决什么

上一轮虽然实现了L0、L1、L2、L3不同投影，也建立了体系、关系、阅读、回忆四种活动，但真实体验仍存在三个结构问题：

1. 地形和目录都只是不同外观的层层入口；每层主要作用是进入下一层，没有持续提供全局理解。
2. 从领域到完整内容需要经过区域、篇章、主题、焦点和关系定向等多个决策层，关系成为阅读前的额外门槛。
3. 正文、关系和回忆被分成不同活动，用户无法感到它们属于同一个知识对象；阅读仍接近非结构化长文，回忆卡像另一套内容。

本文重新冻结知识空间、分支展开、知识卡片、完整内容、回忆和易混之间的产品关系。它先冻结对象、责任、状态和移动承载边界，再讨论整体及分支的具体视觉形态。

## 2. 当前基线证据

- 当前政治地形页面通过层级按钮、面包屑和节点列表在L0–L3间切换；每一层仍以卡片列表为主。
- 目录投影也按当前范围列出条目，和地形共享“选择一层再进入下一层”的漏斗。
- 建立焦点后默认进入独立关系定向，再由按钮进入完整阅读。
- 详情页默认暴露`体系 / 关系 / 阅读 / 回忆`四项ActivityDock，内部模型成为用户必须理解的导航术语。
- 政治review运行包有37个KnowledgeUnit、643个稳定内容块、313个显式KnowledgeAtomRef和37张KnowledgeUnitCardProjection。
- 37个知识均有可追溯summary与RecallProjection；39条关系已具备39/39双端精确块锚点，5组正式ContrastPair具备卡片级来源与边界。

因此，知识空间问题不能只改节点样式，知识卡问题也不能只给正文增加圆角。必须同时处理空间投影、活动暴露、内容引用和回忆来源。

## 3. 已确认的统一产品模型

```text
KnowledgeSpace：领域整体、分支、位置与直接访问
        ↓ 选择具体知识，不经过强制关系页
KnowledgeSurface：同一知识对象的完整内容与上下文
        ↓ 合上或由路线触发
RecallProjection：同一知识卡的提问、揭晓和补救状态

GoalGuide：在上述表面之上持续告诉用户现在做什么和下一步是什么
```

三个对象各自只承担一种责任：

| 对象 | 负责 | 不负责 |
|---|---|---|
| KnowledgeSpace | 整体结构、当前分支、位置、关系概况和直接选点 | 展开完整正文、要求用户逐层通过 |
| KnowledgeSurface | 一个知识的身份、卡片结构、完整内容、相关与易混上下文 | 复制正式正文、成为第二个知识空间 |
| GoalGuide | 根据目标组织顺序和当前动作 | 保存知识事实、让用户手动编排 |

## 4. 内容对象层次

### 4.1 正式源仍是事实母体

正式Markdown及其经04构建的SemanticBlock继续是事实来源。知识卡只保存引用、角色、顺序和可验证的展示元数据，不复制另一份正文。

```text
Canonical Markdown
→ SemanticBlock[]
→ KnowledgeAtomRef[]
→ KnowledgeUnitCardProjection
→ Reading / Recall / Contrast投影
```

### 4.2 小知识卡：KnowledgeAtomRef

小知识卡不是任意段落，而是能够独立理解、独立回忆且有明确来源的最小语义单元。允许的首轮角色包括：

- definition：定义或“是什么”。
- conclusion：核心结论。
- reason：原因、依据或作用机制。
- hierarchy：组成和层级。
- sequence：步骤、阶段或演进顺序。
- condition：条件与适用范围。
- exception：例外或不适用边界。
- contrast：区别、易错和判断边界。
- evidence：来源与证据。

一个KnowledgeAtomRef至少引用一个有效`sourceBlockId`，并记录其在正式知识中的顺序。普通段落、过渡句、修辞性小标题不能因长度适中就自动升级成卡。

### 4.3 大知识卡：KnowledgeUnitCardProjection

一个正式KnowledgeUnit对应一张大知识卡。它由以下内容组成：

```text
KnowledgeUnitCardProjection
├─ pointId / title / path
├─ summary及其来源
├─ orderedAtomRefs[]
├─ relationRefs[]
├─ recallRefs[]
├─ sourceRefs[]
└─ completeness / fallback
```

- 大卡按正式正文顺序组合小卡，不由页面临时排序。
- 一个主题或篇章可以组织多张大卡，但首轮不继续递归生成“超级大卡”。
- 没有足够显式语义时仍可显示标题、路径、summary和完整原文，但必须标记为卡片结构不完整，不能从plain段落猜角色。
- 大卡展开后的完整正文仍保持连续阅读；不能把每个段落都做成独立阴影卡片。

### 4.4 回忆卡不是第三份内容

RecallItem继续保存经过审核的prompt、answer和pitfall，但必须逐步增加对KnowledgeAtomRef或`sourceBlockIds`的引用：

```text
RecallProjection
├─ recallItemId
├─ pointId
├─ prompt
├─ answerAtomRefs[] / sourceBlockIds[]
├─ pitfallAtomRefs[] / sourceBlockIds[]
└─ returnTarget
```

阅读态、合卡态、揭晓态只是同一知识对象的不同投影。揭晓答案可以使用正式RecallItem文本，但必须能返回对应小卡或原文，不再长期保留无来源答案。

## 5. 小屏完整承载合同

“完整承载”不等于一屏同时显示全库。移动端在任一时刻最多承担：

```text
一个全局结构提示
+ 一个展开分支
+ 一个选中的知识对象
```

### 5.1 四个状态，不是四个页面

| 状态 | 用户看到 | 状态变化 |
|---|---|---|
| 全览 | L0主区域、整体规模和少量主干 | 选择分支只更新同一KnowledgeSpace |
| 分支展开 | 紧凑全局区域栏、当前分支及其主题/知识 | 顶层区域持续在场，相关同级分支可直接切换 |
| 完整知识卡 | 同一身份下按顺序组合的小卡和完整正文 | 保留返回空间的语义快照 |
| 翻卡回忆 | 同一卡的提问、揭晓、自评和原文返回 | 保持pointId、atom/block引用及揭晓状态 |

四种状态由同一KnowledgeSpace产品页面和同一状态容器承载：分支原地展开，具体知识直接切换为完整卡，完整卡和翻卡回忆继续使用同一知识对象。实现可以对组件懒加载，但不得把四种状态实现为用户必须依次经过的四条页面路由；旧`state=preview`深链必须兼容并直接恢复为`full`，不得重新显示预览卡。

### 5.2 目标路径预算

```text
首页 → 知识空间 → 完整知识卡
搜索 → 完整知识卡/正式命中位置
目标路线 → GoalGuide指定的知识卡/小卡 → 下一步
```

- 从知识空间或完整目录看见一个具体知识后，一次点击直接进入完整内容。
- 关系定向不得作为所有知识进入阅读的强制独立页面。
- 搜索、易混和回忆可以直接定位到对应大卡或小卡，但返回时恢复来源。

## 6. 知识空间的已确认行为

以下行为已确认，不依赖最终采用树形、泳道、放射或其他具体形态：

1. 用户深入当前分支时，整体结构或其可信缩略表示继续可见。
2. L0–L3表示认知粒度和展开状态，不表示四个必须依次访问的页面。
3. 聚合节点负责展开/收起当前分支，不建立知识焦点。
4. 具体KnowledgeUnit节点直接打开完整知识卡；进入前保存空间viewport。
5. 完整知识卡可以在有正式数据时开始回忆或查看易混，不再增加预览过渡层。
6. 返回恢复原整体结构、展开分支、选中节点和语义viewport。
7. 关系理由可以作为知识卡内上下文或空间镜头出现；深度关系网络按需打开，不成为阅读前门槛。
8. 路线可在同一空间高亮顺序和当前位置，但不改变正式导航事实。

## 7. 整体结构与分支形态：已确认原则

### 7.1 稳定分区底图

- 整体底图由正式导航树确定稳定区域、主要分支和相对位置，不使用自由力图或访问热度重新排布。
- 全览只承担“由哪些区域和主分支构成”，不试图同时显示全部知识标题。
- 体系层级是底图；目标路线和知识关系只能作为可关闭的场景叠加，不能改写正式位置。
- 政治的两大区域只是首轮样本，通用规则仍必须覆盖常识多分类与笔记弱关系结构。

### 7.2 去重后的原地展开

- 点击聚合分支只改变同一KnowledgeSpace的展开状态，不进入下一层页面。
- 当前分支获得主要显示空间；只有当前层相关的同级兄弟保留为可直接切换入口。
- 其他顶层区域使用单条紧凑区域栏持续在场，不再重复渲染完整区域卡。
- 当前区域不在区域栏、面包屑和分支标题中重复三次；路径只补充区域栏没有表达的祖先。
- 点击具体KnowledgeUnit直接进入完整内容，不再显示只承担过渡作用的预览卡。
- 从完整内容返回时恢复原底图、展开分支、选择对象和语义viewport。

P01至P05已经关闭；具体预算与连接分工见第16节。形态必须持续通过政治37知识、常识170知识和笔记弱关系三个样本验证，不能只为政治两大区域选择一种看起来漂亮的布局。

## 8. 目录不再是另一种层层深入

目录承担“完整扫描和精确直达”，与知识空间分工：

| 知识空间 | 目录 |
|---|---|
| 理解整体、分支和空间关系 | 查看完整、稳定、正式顺序 |
| 当前分支原地展开 | 单页分组索引、锚点跳转或等价直接访问 |
| 节点直接打开完整知识卡 | 条目直接打开同一完整知识卡 |
| 受节点预算约束 | 不丢任何正式项 |

目录使用正式导航树的篇、章、知识层级分组，但不能要求用户先打开区域页、再篇章页、再主题页才能看到知识。没有正式章级的篇只标为“本篇知识”，不虚构结构。地形和目录共享同一选择、焦点与返回状态，但不应成为两套相同漏斗的皮肤。

## 9. 四活动改为内部模型

体系、关系、阅读、回忆仍保留，因为它们分别拥有不同状态、深链、恢复和数据能力。但默认用户表面改为连续KnowledgeSurface：

```text
知识身份与体系位置
→ summary / 核心小卡
→ 前置、相关、易混上下文
→ 完整大知识卡与连续原文
→ 合上知识卡进行回忆
```

| 内部活动 | 默认用户呈现 |
|---|---|
| system | 始终可见的路径、全局缩略位置和返回空间 |
| relations | 卡内前置/相关/易混说明；完整关系网络是次级深入 |
| reading | KnowledgeSurface主体和完整原文 |
| recall | 合卡、路线引导或文末触发的回忆状态 |

- 默认不展示四个并列ActivityDock标签。
- ActivityStage仍可用于深链、快照、性能懒加载和无障碍状态，但由页面和GoalGuide自动投影。
- 关系不再是阅读前必经页面；有价值的关系上下文在完整知识卡中按需打开。
- 用户主动深入关系时可以打开一层关系视图，返回仍是同一知识卡。
- 路线存在时，GoalGuide直接指示当前卡片或活动动作，用户不必理解内部活动名称。

## 10. 结构化正文与卡片感

知识卡片感来自稳定对象和结构，而不是每段增加背景：

1. 卡片头部始终保持标题、路径和summary。
2. 显式definition、conclusion、condition、exception、contrast等块可形成小知识卡。
3. plain内容继续按正式顺序连续阅读，不强制切碎。
4. 小卡之间通过正式顺序、层级、原因和对照语义串联，不由视觉位置暗示不存在的关系。
5. 回忆卡显示“来自哪些小知识卡”，揭晓后可回原卡。
6. 来源与反馈继续作为低干扰上下文工具，不成为小卡。

当前政治直接使用已构建的title、path、summary、313个显式atom、关系理由、RecallProjection和ContrastPair形成同源大卡；未来模块缺少显式语义或锚点时仍按能力标记降级，页面不得自行猜测。

## 11. Obsidian能力的中立实现

| 需要的思想能力 | 平台正式实现 | 运行时边界 |
|---|---|---|
| 块引用 | `sourceBlockIds` / atom引用 | 小程序只读构建结果 |
| 嵌入组合 | 大卡按ID和顺序引用小卡 | 不复制正文文本 |
| 反向链接 | block反查relation、recall、contrast | 由builder生成索引 |
| Outline | 正文块顺序和卡片组合顺序 | 普通Markdown也能构建 |
| Page Embed | 同源完整知识卡投影 | 不依赖Obsidian窗口 |
| Canvas/Mindmap | KnowledgeSpace受控投影 | 不读取`.canvas` |

Obsidian可以作为作者编辑和检查工具，但不是事实源格式、构建依赖或小程序运行环境。社区插件不可成为必要步骤。

## 12. 回忆与易混来源

### 12.1 回忆

- RecallItem必须引用一个或多个小知识卡/原文块。
- prompt可以针对单卡，也可以要求组合多张小卡。
- answer和pitfall揭晓后标明来源卡，并可定位原文。
- 速记路线只是批量组织RecallProjection，不复制卡片内容。

### 12.2 易混

正式易混对象推荐为：

```text
ContrastPair
├─ leftPointId / leftAtomRefs[]
├─ rightPointId / rightAtomRefs[]
├─ reason
├─ dimensions[]
├─ boundaries[]
├─ sourceBlockIds[]
└─ recallItemIds[]
```

- 语义相似只可用于生成校订候选，不直接进入用户界面。
- 用户可见易混必须有人确认“为什么混、按什么区分、边界是什么”。
- 易混突破由GoalGuide组织正式ContrastPair的理解、原文和辨析回忆。
- 标题相似、向量相似或共同关键词都不能自动晋级为正式contrast。

## 13. 状态与ViewModel边界

继续沿用现有KnowledgeFocus、ActivityStage、Trail、RouteSession、DisplayPreferences和viewport状态，不建立第二套状态。

建议在现有投影层增加两个纯派生对象，最终字段由04修订确认：

```text
KnowledgeSpaceViewModel
├─ overviewContext
├─ expandedBranchState
├─ nodes / links
├─ selectedPointId?
├─ activeCard?
```

### 16.1 S55B-P03推导稿：全局上下文逐级压缩，不消失

同一页面四种状态使用同一份`KnowledgeSpaceViewModel`，但不要求把完整底图永久占据正文空间：

| 状态 | 持续可见的整体信息 | 当前主体 | 返回合同 |
|---|---|---|---|
| 全览 | 完整稳定分区底图 | 区域与主要分支 | 无需恢复 |
| 分支展开 | 顶部紧凑区域栏 + 不重复的祖先路径 | 当前分支及其直接对象 | 返回完整底图或切换兄弟分支 |
| 完整知识卡 | 压缩ContextBar显示区域、分支、知识与“返回知识空间” | 连续正文与显式小卡 | 直接返回原分支，不重算位置 |
| 翻卡回忆 | 压缩ContextBar显示同一知识/卡组来源 | 提问、揭晓、自评、补救 | 返回同一大卡、小卡或原分支 |

推荐规则：完整底图只在全览显示；分支使用紧凑区域栏；完整阅读和回忆使用一行ContextBar保持方位，不让小地图长期挤占正文。进入完整卡前保存语义viewport：`expandedBranchId + selectedPointId + scrollAnchor + scale`，返回按语义锚点恢复，不只保存易失效的像素值。

### 16.2 S55B-P04推导稿：同屏限量，范围不丢失

- 320px全览首屏最多显示6个可读区域单元；超过6个按正式上级分组纵向延续，不缩小文字塞入一屏。
- 每个区域在全览只显示区域名、规模和2–4条主分支结构刻度，不列出全部知识标题。
- 当前分支首屏最多显示6个直接对象；全部对象可在同一分支纵向继续访问，超过预算时按正式导航节点聚合，不按算法相似度临时分组。
- 同级兄弟优先保留最多3个可直接识别入口；更多兄弟收敛为带正式父级名称的“其他N个分支”，展开后仍在同一页面。
- 普通节点标题最多两行；被选中节点、知识卡标题和无障碍名称必须可读完整标题，不能只靠省略号区分。
- 数量是同屏上限，不是数据截断；目录等价视图始终可以完整访问全部正式对象。

### 16.3 S55B-P05推导稿：底图只画体系，路线与关系按需叠加

| 连接类型 | 显示时机 | 视觉责任 | 禁止 |
|---|---|---|---|
| 正式层级 | 全览与分支默认显示 | 中性实线/缩进表达父子与稳定归属 | 用关系热度改变位置或粗细 |
| 目标路线 | 仅存在活动RouteSession时显示 | 在既有节点上用编号、方向和单条高亮路径表达先后 | 把路线画成新的知识体系或移动节点 |
| 知识关系 | 选中具体KnowledgeUnit后显示 | 卡内列出1–3条带类型和理由的关系；主动深入时最多展开6个一层邻居 | 在全览铺开关系网、仅靠颜色区分类型 |

同一时刻只允许一种连接成为空间主叙事：自由探索以正式层级为主；目标任务以层级底图上的路线高亮为主；关系探索以当前知识的一层邻域为主。路线进行中遇到关系步骤时，关系先在卡内表达，不同时把路线线和关系网铺满底图。所有连接同时使用文字/方向/形状，不能只依赖颜色。

### 16.4 S55B-P06推导稿：一张大卡的两个连续形态

完整知识卡和翻卡回忆不是两张不同来源的卡，也不是两个用户页面；它们是同一`KnowledgeCardViewModel`的两个呈现状态。知识入口不再经过预览态。

#### 完整卡态

- 从地形或目录一次点击进入完整页面状态，保留压缩ContextBar和“返回知识空间”；不新建第二张详情卡或重新加载另一个知识对象。
- 外层只有一张大知识卡身份。definition、conclusion、condition、exception、contrast等显式语义可形成轻量小卡；plain段落、标题、列表和表格继续组成连续正文。
- 小卡不得互相嵌套成多层卡片，也不得给每个段落增加独立阴影、边框和来源副本。
- 关系理由、来源、反馈和显示设置作为上下文工具出现；不进入正文的主要层级。
- 文末动作由自由探索或GoalGuide决定；访问完整卡本身不自动完成路线步骤。

#### 回忆态

- 合上同一大卡进入RecallProjection，显示prompt、提示、揭晓、自评和补救；保持相同pointId、atom/block引用和返回模型。
- 揭晓后可回到对应小卡；缺少精确blockId时诚实回到完整知识卡，不伪造位置。
- 回忆结束后按RouteSession或原分支继续，不跳到无依据的下一知识。

#### 无障碍与降级

- 打开完整卡时焦点进入卡片标题；返回后焦点和viewport恢复到触发节点。
- 返回键按回忆→完整卡→原分支逐级退回同一状态容器，不依赖微信页面栈猜测。
- 标题、主动作和关闭/返回触控目标不小于44逻辑像素；长标题完整换行。
- 低动画直接切换状态并更新标题、路径和展开状态；动画不是理解连续性的必要条件。
- 无小卡数据时仍显示summary与完整连续正文；不展示空小卡壳或声称已经结构化。

### 16.5 S55B-P07推导稿：先建立可追溯性，再逐篇完成卡片化

#### 首轮最低完整度

卡片完整度不使用一个含混百分比，而使用四个可独立验证的能力标记：

| 标记 | 达成条件 | 用户侧能力 |
|---|---|---|
| `sourceComplete` | 标题、路径、summary、完整正文与来源均可追溯 | 可以显示基础大知识卡 |
| `atomStructured` | 至少1个有明确语义角色的KnowledgeAtomRef，所有可见小卡均绑定有效sourceBlockId并保持正式顺序 | 可以显示结构化小卡；没有则诚实退回连续正文 |
| `recallLinked` | RecallItem的答案/易错点绑定小卡或sourceBlockIds | 可以从揭晓准确回看小卡/原文 |
| `contrastLinked` | 正式ContrastPair两侧、区分维度和边界均有来源引用 | 可以进入易混突破；语义相似候选不计入 |

基础大卡只要求`sourceComplete`；声称“已完成知识卡片化”至少要求`sourceComplete + atomStructured`。回忆和易混是否精确，分别由`recallLinked`、`contrastLinked`单独决定，不能用大卡存在替代。

#### 政治37篇加工顺序

1. **全量锚点基线**：先为37篇、643个现有内容块建立稳定blockId、正文顺序和构建校验；不修改正式表述，不改变`review`或发布数。
2. **三类代表样本**：各选择一篇“定义/结论为主”“层级/顺序为主”“条件/易混为主”的正式知识，验证小卡角色、长标题、列表、连续正文、回忆回看和对照引用。样本只验证契约，不自动标记核心知识。
3. **按正式目录逐篇闭环**：沿现有正式目录顺序处理剩余知识；每篇一次完成显式atom标注、summary来源、RecallItem锚定、关系理由锚定和构建报告，再进入下一篇，避免37篇只完成一种横切字段。
4. **跨知识对照闭环**：当ContrastPair两侧均完成atom结构后，再确认区分维度、边界和双方来源；单侧未完成时保持待审核候选，不进入用户界面。
5. **全量覆盖复核**：输出四项能力标记、缺失锚点、plain降级和风险页清单；页面只按能力标记渐进增强，不自行猜小卡。

11个风险页可以进行结构和锚点加工，但仍保持`review`并走独立内容复核；卡片化完成不等于事实批准。P07只冻结后续内容加工任务的方法和顺序，本轮不修改正式Markdown、目录、关系、RecallItem文本或发布状态，也不要求Obsidian/插件作为必需步骤。

### 16.6 三模块覆盖验证

| 代表模块 | 数据特征 | 同一空间如何成立 | 卡片与关系如何降级 |
|---|---|---|---|
| 政治 | 37个知识、两个主要区域、643个稳定块、313个显式atom、39/39关系锚点、37/37回忆锚点、5组ContrastPair | 两个区域形成稳定底图；分支使用紧凑区域栏和相关同级入口；任一KnowledgeUnit可直接打开同一大卡 | 当前政治直接消费精确卡片投影；未来数据缺口仍按能力标记回完整知识，不伪造锚点 |
