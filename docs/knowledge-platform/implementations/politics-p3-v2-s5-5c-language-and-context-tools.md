## 0. 本轮冻结的产品方向

用户已经接受以下六项方向，细节由本规格直接完成，不再逐条返回讨论：

1. 产品以“学习引导者”而不是“知识工具箱”的方式说话：先告诉用户在哪里、为何从这里开始、下一步做什么。
2. 信任信息渐进披露：默认克制，来源、校订和反馈在用户需要时展开；诚实不等于把内部处理过程铺在首屏。
3. 工具情境化：工具只在当前对象、当前意图和有效数据同时成立时出现，不常驻为工具面板。
4. 语言密度随认知深度增加：首页最轻，知识空间解释位置，完整卡承载核心判断、条件与边界，回忆态只保留提问、揭晓和补救。
5. 正式知识声音、系统引导声音与信任来源声音严格分离，不能互相代写。
6. 跨模块共享动作动词与状态语法，模块保留自己的知识名词，不用一套抽象术语抹平政治、常识和笔记。

本规格冻结产品表达、工具出现规则、降级语义和自动门禁，不修改正式Markdown、目录、关系、RecallItem文本或发布状态，不重新讨论A/B，不提前设计D的四条完整路线。

## 1. 当前问题不是“文案不好看”

现有界面已经出现一批可理解但仍偏系统视角的表达，例如“体系 / 关系 / 阅读 / 回忆”“上下文工具”“显示”“来源与反馈”以及校订状态。单看每个词都不一定错误，但它们共同产生三个问题：

1. 用户先看到系统有哪些能力，再自行判断该用哪个，主流程重新退化为工具选择。
2. 正式正文、引导提示、来源状态和工程诊断混在同一注意层，用户难以判断哪部分是知识事实。
3. 相同动作在首页、空间、完整卡、关系和路线中使用不同词，或不同动作使用相同词，用户需要不断重新学习界面。

因此C不是逐页润色，而是建立一套能跨状态、跨模块执行和校验的表层语言系统。

## 2. 四种声音及所有权

### 2.1 正式知识声音 CanonicalVoice

只负责回答“知识本身是什么”。来源只能是正式KnowledgeUnit、SemanticBlock、RecallItem和经审核关系理由：

- 标题、定义、结论、条件、原因、边界、例外和来源原文不得由UI文案改写。
- 页面不能为了更口语化而补充源内容没有支持的解释、结论或易混关系。
- summary可以作为完整卡导读，但不能替代完整正文或伪装成系统生成的权威结论。

### 2.2 学习引导声音 GuideVoice

只负责回答“我在哪里、为什么从这里开始、下一步做什么、失败后怎么回来”：

- 允许说明当前位置、推荐依据、当前任务、预计范围和恢复去向。
- 一次只给一个推荐主动作；解释必须短于所引导的知识内容。
- 不复述或改写正式结论，不声称用户已经掌握，不把内部状态名当作学习建议。

### 2.3 信任来源声音 TrustVoice

只负责回答“内容从哪里来、目前核对到什么程度、怎样反馈”：

- 默认只显示一次克制状态；详细来源与反馈由明确入口展开。
- 允许显示可读来源名、页码或位置、有效修订日期、人类可理解的校订状态。
- 不用工程字段解释可信度，不让用户理解构建链路后才能判断内容身份。

### 2.4 诊断声音 DiagnosticVoice

只供构建、校订和开发诊断：路径、schema、blockId、package/build/hash、内部风险编号、review/release枚举、适配器与联调信息。它可以存在于数据、日志和显式开发诊断中，但不得进入生产默认可见文本或无障碍名称。

### 2.5 声音冲突裁决

同一位置需要多种声音时，优先级不是把文字堆在一起，而是分层：

```text
正式知识内容
→ 当前学习引导
→ 按需展开的来源与反馈
→ 生产界面之外的诊断信息
```

GuideVoice不得改写CanonicalVoice；TrustVoice不得抢占正文标题；DiagnosticVoice不得通过模板插值泄漏到前三层。

## 3. 四类表面的语言预算

语言密度跟随S5.5B同一KnowledgeSpace的四种连续状态，而不是跟随四个页面。

| 状态 | 首要问题 | 默认可见语言 | 不应出现 |
|---|---|---|---|
| 首页 | 我想做什么、现在从哪开始 | 熟悉的搜索表达、一个状态主任务、四个目标的短说明 | 平台模型、知识层级说明、完整工具清单、来源细节 |
| 知识全览/分支 | 整体怎么组成、我在哪个分支 | 区域/篇章/主题名、规模、当前分支、返回整体 | L0–L3、语义层、viewport、聚合算法、长段解释 |
| 完整知识卡 | 条件、边界和完整论证是什么 | 正式连续正文、显式小卡、必要关系理由、压缩位置提示 | 工程状态、常驻路线选择器、每段重复操作 |
| 回忆 | 我能否想起、忘了去哪里补 | 一个问题、揭晓、自评、精确或诚实降级的回看动作 | 体系工具栏、来源审计说明、无依据的下一题推荐 |

用户向下深入时增加的是知识语义密度，不是系统术语密度；返回上层时恢复位置和任务，不把深层说明带回首页。

## 4. 跨模块统一动词与模块名词

### 4.1 共享动作词

平台层只维护少量稳定动词，并按同一行为使用：

| 动词 | 唯一行为含义 | 典型使用 |
|---|---|---|
| 查看 | 打开明确对象或其按需信息；知识入口可直接提交焦点 | 查看这个知识、查看来源 |
| 展开 / 收起 | 在同一对象内增加或减少信息密度 | 展开完整内容、收起卡片 |
| 开始 | 建立明确任务或路线会话 | 开始了解、开始学习、开始速记 |
| 继续 | 恢复已有且仍有效的任务状态 | 继续上次学习 |
| 返回 | 回到明确保存的来源位置 | 返回原位置、返回这张卡 |
| 对照 | 同时查看正式确认的两侧知识及边界 | 对照这组知识 |
| 回忆 | 合上当前卡进入提问状态 | 回忆一下 |
| 揭晓 | 显示已有正式答案 | 揭晓答案 |
| 回看 | 从回忆或关系回到有来源的卡片/原文 | 回看原文 |
| 调整 | 修改系统推荐的次级范围或偏好 | 调整范围 |
| 提交 | 明确发送用户输入 | 提交内容反馈 |

“进入、前往、定位、聚焦、建立焦点、切换活动”等不能在同一行为上随机替换。页面主动作使用上表中的用户动词，内部事件名可继续保持技术命名。

### 4.2 模块自己的名词

- 政治使用“政治理论、篇章、主题、知识、易混知识、回忆卡”。
- 常识使用其正式分类与知识名称，不强制改称政治的“篇章”。
- 笔记使用“笔记、主题、内容、练习”等profile确认名词，不为统一代码改成“知识单元”。
- 平台抽象名`KnowledgeUnit`、`NavigationNode`、`ActivityStage`只存在于契约、代码和诊断中。

动作语法统一是为了减少学习成本；名词保留差异是为了符合用户已有心智。

## 5. 默认学习者词典

### 5.1 必须替换或隐藏

| 内部表达 | 默认学习者表达 |
|---|---|
| L0 / L1 / L2 / L3、语义层级 | 知识全景 / 篇章 / 主题 / 当前知识，能省则省 |
| NavigationNode、KnowledgeUnit、节点、对象、单元 | 对应模块的区域、篇章、主题、知识或笔记 |
| 建立/切换知识焦点 | 查看这个知识；真正换焦点时按上下文用“查看…” |
| Activity / ActivityStage / 活动控制器 | 不显示；用当前任务或主动作表达 |
| 体系 / 关系 / 阅读 / 回忆四项并列 | 位置提示、卡内相关知识、完整内容、情境回忆 |
| 一跳/一层关系、关系定向 | 直接相关、为什么相关、学前提示 |
| 范围聚合、正式目录范围 | 主题组、本次学习范围 |
| 内容块、blockId、anchor | 正文、对应内容；通常不显示 |
| canonical、schema、package、build、hash | 不显示 |
| review / approved / release | 内容校订中 / 已核对；发布流程不显示 |
| 风险页、风险编号、联调、适配器 | 不显示 |
| 正式Markdown修订并重新构建 | 提交内容反馈 |

### 5.2 可见状态不得冒充结果

- “已完成”只表示当前明确步骤完成，不能替代“已掌握”。
- “已看完主干”“已核对本组边界”“本轮速记结束”按目标报告事实，不统一写成“路线完成”。
- “内容校订中”描述内容状态，不暗示内容错误，也不随用户学习完成而变化。
- 缺少精确来源锚点时说“查看这条知识的完整内容”，不能说“定位到原文”后跳到不确定位置。

## 6. 渐进信任披露

### 6.1 默认层

同一知识表面最多显示一次：

> 内容校订中，部分内容可能调整

它不与每个小卡、段落或回忆项重复绑定；用户继续阅读无需先确认该提示。

### 6.2 展开层：“来源与反馈”

用户主动展开后，按存在性显示：

1. 来源名称。
2. 可读页码、章节或位置；没有可靠页码就不显示占位。
3. 有效修订日期；不能用构建时间冒充内容修订时间。
4. “内容校订中”或“已核对”等人类状态。
5. “查看来源”和“提交内容反馈”。

路径、哈希、schemaVersion、blockId、包ID、构建目标、内部审核人状态和风险编号始终不进入该区域。精确blockId可以支持跳转，但不能成为用户看到的可信依据。

### 6.3 状态隔离

政治继续保持`rolloutStage=candidate`、内容保持`review`。用户完成学习、回忆或反馈不会改变内容审核状态；卡片化完成也不等于事实批准或正式发布。

## 7. 工具情境化规则

### 7.1 出现条件

一个工具只有同时满足以下条件才出现：

```text
当前对象支持
∩ profile声明能力
∩ 有效数据存在
∩ 当前意图需要
```

任一条件不成立就移除入口，不显示灰色空工具，也不进入空页面。

### 7.2 工具不常驻

- 不保留“上下文工具”常驻面板或工具抽屉作为学习主导航。
- ContextBar只承担位置、任务和返回，不变成所有能力的快捷栏。
- “显示”只在完整内容需要阅读偏好时出现；知识空间和回忆不常驻字号/行距设置。
- “来源与反馈”是次级折叠入口，不与正文主动作同权。
- “深入关系”只在有正式关系且用户当前需要扩展关系时出现；卡内1–3条关系上下文本身不要求打开工具。
- “回忆一下”只在有有效RecallProjection且当前任务允许时出现。

### 7.3 动作预算

每个状态最多：

```text
1个推荐主动作
+ 最多2个与当前对象直接相关的次级动作
+ 1个低干扰的来源与反馈入口
```

返回、关闭和无障碍导航不计入业务动作预算。更多能力进入内容内部的自然位置或被移除，不能用“更多工具”重新拼成工具箱。

### 7.4 状态副作用

展开来源、提交反馈、改变显示偏好不得改变KnowledgeFocus、ActivityStage、Trail、RouteSession或正文滚动位置。工具只读或修改其已有专属状态，不建立第二套焦点、活动、路线或viewport状态。

## 8. 各表面的表达合同

| 表面 | GuideVoice职责 | CanonicalVoice职责 | 可用工具 |
|---|---|---|---|
| 政治首页 | 说明当前可继续的任务、默认推荐和四目标差异；每项一个开始/继续动作 | 只显示必要的模块与知识标题 | 搜索；次级目标入口；不显示来源工具 |
| 知识全览/分支 | 说明整体位置、当前分支和深入方向 | 正式区域、篇章、主题与知识名 | 目录等价入口、活动路线叠加；无常驻工具栏 |
| 完整知识卡 | 当前路线存在时只提示当前一步和完成事件 | 完整连续正文、显式小卡、正式关系理由 | 显示、来源与反馈、按条件出现回忆/关系 |
| 回忆 | 提问、揭晓、自评、精确补救和返回 | 正式RecallItem及引用内容 | 提示、揭晓、回看；无关系/显示工具箱 |
| 搜索 | 解释命中位置和推荐下一步，不自动改焦点 | 命中标题、路径及安全片段 | 清空/修改搜索、打开正式命中；结果卡无三去向按钮 |
| 路线 | 解释推荐依据、当前一步和唯一继续动作 | 只引用知识标题与已有内容 | 调整、跳过按目标规则次级出现；不复制知识工具 |

S5.5D负责四类目标的具体推荐依据、进行中引导与完成反馈；C只冻结其共同声音、动作和信任规则。

## 9. 空状态、异常与诚实降级

所有异常文案必须包含“发生了什么 + 现在能做什么”，不得暴露实现原因。

| 情况 | 用户表达 | 恢复动作 |
|---|---|---|
| 当前知识无正式关系 | 暂无需要展开的相关知识 | 继续查看完整内容或返回原位置 |
| 当前知识无有效回忆 | 这条知识暂未提供回忆卡 | 回看完整内容 |
| 无结构化小卡 | 不显示任何空提示或空壳 | 直接呈现summary与连续正文 |
| 无精确原文锚点 | 可查看这条知识的完整内容 | 打开完整知识卡顶部 |
| 路线版本失效 | 内容已更新，本次安排需要重新生成 | 重新生成本次安排；不静默续用 |
| 恢复的焦点无效 | 上次查看的内容已调整 | 回到最近有效分支或模块全览 |
| 搜索无结果 | 没有找到相关知识 | 修改关键词或返回知识全景 |
| 数据暂不可用 | 这部分内容暂时无法打开 | 重试或返回上一位置 |
| 关系只有候选无正式确认 | 不显示候选存在 | 继续当前知识，不推荐伪对照 |

不使用“加载失败：schema不兼容”“route invalid”“anchor missing”等诊断语言；详细原因只进入日志和自动证据。

## 10. 无障碍表达等价

1. 可见标题、读屏标题与当前状态使用相同模块名词，不得在aria中泄漏内部枚举。
2. 节点读屏名称包含完整名称、对象类型、展开/选中状态和可执行动作，例如“实践与认识，当前知识，双击查看”。
3. 卡片sheet打开时焦点进入完整标题，背景临时不可交互；关闭后回到触发节点。
4. 展开、收起、揭晓、返回必须报告状态变化和明确目的地，不能只读“按钮”。
5. 关系同时说明方向、类型和已有理由；不能只报颜色或连线。
6. 长标题、130%字号和320px宽度下不得用截断后的可见词与完整读屏词指向不同对象。
7. 低动画与读屏模式直接切换状态，但位置、任务和返回语义与动画模式完全一致。

## 11. 文案所有权与纯投影

### 11.1 共享层

在现有知识平台展示层维护一个最小`platformSurfaceCopy`或等价纯字典，只包含：

- 共享动词与动作模板。
- 通用恢复、空状态和网络/数据异常表达。
- 通用信任入口与校订状态的人类表达。
- 无障碍状态模板。

不建立通用国际化框架，不引入组件库或第三方依赖。

### 11.2 模块profile

政治profile只维护模块名词、首页短说明、模块专有目标名及必要领域短语。常识和笔记不读取政治文案，也不因政治改版改变入口、模型、主题语义或持久状态。

### 11.3 正式内容

CanonicalVoice永远来自KnowledgePackage正式事实对象，不进入`surfaceCopy`。页面不得把正文、RecallItem答案或关系理由复制成展示常量。

### 11.4 投影边界

`SurfaceLanguageProjection`或等价ViewModel字段只由以下输入纯派生：

```text
现有KnowledgeFocus / ActivityStage / Trail / RouteSession
+ DisplayPreferences / viewport
+ 当前KnowledgeSpace或KnowledgeCard投影
+ ModuleProfile / platformSurfaceCopy
```

它不持久化新的语言状态，不拥有路由，不改变事实数据；同一输入必须产生同一默认文案和动作优先级。

## 12. 自动门禁

### 12.1 扫描范围

candidate静态校验至少扫描：

- 政治首页、知识空间、详情、搜索、路线的默认可见WXML文本。
- navigation bar标题、aria-label、空状态和错误文案。
- ViewModel默认展示字符串、政治profile的`surfaceCopy`及共享表层词典。
- 能把内部字段直接插值到可见文本的模板表达式。

JS变量名、正式运行数据、构建报告、日志和显式开发诊断可以使用内部术语，但不能被宽泛正则误判为用户界面。

### 12.2 默认禁止词

生产默认学习者层不得出现：

```text
L0 / L1 / L2 / L3
schema / blockId / canonical
review / approved / release
package / build / hash
ActivityStage / KnowledgeUnit / NavigationNode
联调 / 构建包 / 风险页 / 适配器
```

“节点、对象、单元、焦点、语义、聚合、活动”需按白名单检查：只有正式知识本身确需该汉语词义时允许，平台导航语境默认禁止。

### 12.3 结构门禁

自动校验还必须证明：

1. 同一状态只有一个标记为主动作的业务按钮。
2. 搜索结果不直接并列体系、关系、阅读三个去向。
3. 详情默认不出现四项ActivityDock和“上下文工具”常驻标题。
4. 没有能力或数据的工具不产生可见入口或空面板。
5. 来源与反馈默认折叠，内部字段不在展开内容中出现。
6. 共享动作词只由平台展示层拥有，政治profile不复制同名通用常量。
7. CanonicalVoice内容来自正式投影，页面常量不包含知识答案副本。
8. 常识170条、笔记入口/训练、主导航和三模块持久状态门禁不变。

静态门禁只证明违规结构没有进入代码，不能证明用户理解目标已经达到；最终仍需用户UI手测。

## 13. 验收场景

### S55C-AC-001：首页先给去向

首次进入政治首页，用户先看到搜索、一个系统推荐主任务和紧凑四目标；不需要理解知识平台模型或工具清单即可开始。

### S55C-AC-002：深入时语言递增

从全览进入分支再打开完整卡，新增文字依次是位置、核心判断、完整条件与边界；工程术语和来源审计不会随深度增加。

### S55C-AC-003：三种声音可区分

完整卡中的正式正文保持原文；当前路线提示位于引导层；“来源与反馈”按需展开。任一层隐藏后，其他层的含义仍完整。

### S55C-AC-004：工具只在需要时出现

无关系、无回忆或不在完整阅读场景时，相应工具不存在；有数据且当前意图需要时，入口出现在对象附近而非全局工具箱。

### S55C-AC-005：来源诚实且克制

默认只见一次校订提示；展开后能看到有效来源和反馈动作，看不到文件路径、blockId、包版本、风险编号或内部审核枚举。

### S55C-AC-006：降级可以恢复

关系、回忆、锚点、路线或数据任一缺失时，用户看到人类可理解原因和一个安全恢复动作，不进入空页面、不丢焦点和返回位置。

### S55C-AC-007：读屏与可见语言一致

读屏能够知道完整对象名、状态、动作和返回目的地，且不读出内部枚举；卡片开合后焦点恢复正确。

### S55C-AC-008：跨模块一致但不失真

政治、常识和笔记对相同行为使用相同动词，对领域对象使用各自名词；政治表层改动不改变常识/笔记行为或主导航。

### S55C-AC-009：状态无副作用

展开来源、提交反馈或改变显示偏好后，KnowledgeFocus、Trail、RouteSession、viewport和正文位置保持；未产生第二套状态。
