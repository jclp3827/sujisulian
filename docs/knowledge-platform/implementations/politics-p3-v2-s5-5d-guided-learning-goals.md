## 1. 现在为什么仍然同构

现有`RoutePlanner`已经生成四种不同步骤，但真实页面仍共享同一产品语法：

```text
进入目标
→ 自己选择范围或对照对象
→ 查看计划/确认
→ 打开当前步骤
→ 手动标记完成
→ 统一完成页
```

四种目标因此只在标题、卡片数据和局部样式上不同，决定下一步的责任仍交给用户。具体证据：

- 系统学习与考前速记先列出全部范围，易混突破先列出全部对照对象。
- 当前`planLearningRoute`把推荐依据写成“用户选择的本次学习范围”。
- 系统学习对每个有关系的知识强制生成独立`relations`步骤，与B确认的“关系不阻塞完整阅读”冲突。
- 易混突破一组关系只有一个`relations`步骤，没有先判断、边界核对、来源回看和再辨。
- 完成页虽然文案有所区别，但仍由同一个“路线完成”壳承载，完成后的下一步主要是重新选择。

卡片化后的真实能力基线为：37个KnowledgeUnit、643个稳定正文块、313个显式KnowledgeAtomRef、37张KnowledgeUnitCardProjection、37个精确RecallProjection、20条前置关系、14条普通关系和5组正式ContrastPair；summary与Recall均37/37精确锚定，39/39关系具备双端块锚点。D仍必须按能力标记诚实降级，但政治不能再沿用“锚点为0、易混只能知识级”的旧基线。

## 2. 四类目标不是四种筛选器

四类目标共享底层状态，但分别改变五个核心问题：

| 目标 | 用户想得到什么 | 系统组织单位 | 进行中主体 | 完成证据 | 完成后去向 |
|---|---|---|---|---|---|
| 快速了解 | 形成整体认识 | 主分支和显式锚点组成的导览站 | 带当前位置的知识全景 | 主干/锚点已看或跳过 | 回到全景自由深入 |
| 系统学习 | 完整学完一个正式范围 | 按依赖和正式顺序排列的知识周期 | 同一大知识卡的定位、理解、回忆 | 阅读/回忆等显式动作及跳过 | 继续下个范围或回到本范围 |
| 易混突破 | 建立两者判断边界 | 正式ContrastPair | 左右稳定在场的对照表面 | 先后判断、边界核对、来源回看 | 下一组推荐或返回当前知识 |
| 考前速记 | 快速检索记忆 | 冻结的RecallItem卡组 | 单张提问卡 | 揭晓、自评、回看与跳过 | 优先补看没记住的卡 |

“系统引导”不是隐藏所有信息替用户决定，而是系统先给一套有依据、可解释、可恢复的默认安排；用户可以调整，但不负责从空白页面编排任务。

## 3. 统一推荐与进入合同

### 3.1 推荐优先级

进入任一目标时，按确定顺序只生成一个推荐：

```text
同目标有效RouteSession
→ 同目标未完成且仍兼容的冻结计划
→ 当前焦点/最近范围可以命中显式推荐规则
→ politics profile的默认目标范围或策展顺序
→ 无能力时诚实不可用
```

- 有有效RouteSession时主动作是“继续”，不重算路线。
- 当前焦点只能在profile允许的规则中影响推荐，不能按浏览热度、关系度数或相似度猜。
- 没有上下文时必须使用profile显式默认，不得让页面临时选择“第一个范围/第一组关系”。
- 推荐无法成立时隐藏目标入口或说明当前缺什么及安全去向，不能退回普通范围选择器冒充系统引导。

### 3.2 推荐方案页不是配置页

开始前只回答四件事：

1. 系统推荐了什么。
2. 为什么这样安排。
3. 本次会怎样进行。
4. 完成后会得到什么可验证结果。

每类目标只有一个主动作“开始/继续”；`调整范围`、`换一组`、`改为随机顺序`和`退出任务`按目标成本作为次级控制。调整页进入时已有当前推荐，不从空状态开始；调整完成后回到同一推荐方案，不建立第二个计划状态。

### 3.3 推荐字段归属

通用`LearningRouteDefinition`引用07已冻结并由politics profile落位的`routeDefaults`：

```text
routeDefaults.quick.scopeId
routeDefaults.quick.anchorNodeIds[]
routeDefaults.systematic.scopeId
routeDefaults.systematic.allowedScopeIds[] / allowedScopeTypes[]
routeDefaults.confusion.priorityRelationIds[]
routeDefaults.exam.scopeId
routeDefaults.exam.order
```

这些字段只保存稳定ID、优先顺序和用户可解释的推荐理由，不复制正文、关系理由或回忆答案。没有显式策展时使用正式目录顺序诚实降级，并明确“不标记核心/不做个性化预测”。

## 4. 快速了解：被带着看懂全景（J2 v1历史冻结，用户证伪 / UX-failed）

> **本节完整保留旧J2 v1方向和工程语法，只用于追溯当时的设计与实现，不再授权当前页面。** 用户手测证明真实交互无法继续；即使修复点击，以结构站和锚点入口为主体也无法为首次用户提供经过加工的政治理论初步理解。
>
> 当前恢复必须使用[J2 v2快速导读规格](./politics-p3-v2-s5-5-r5-j2-v2-quick-guide.md)和[J2 v2首版完整内容脚本](./politics-p3-v2-s5-5-r5-j2-v2-content-script.md)：8段连续内容、最小语义定位、2个带批注代表例、1次轻量自我解释和诚实完成。缺少合格内容时显示不可用，不回退为本节的目录导览。

### 4.1 目标边界

快速了解回答“这套政治理论主要由什么组成、两条主干怎样放在整体中”。它不是自由地形、目录浏览、篇章选择或37篇摘要轮播，也不以读完长文为结束条件。

### 4.2 开始态

系统默认推荐政治根范围，展示：

- 一张可识别两篇主分支的真实缩略全景。
- 本次导览包含多少条主干和多少个显式锚点。
- 推荐依据：正式主分支；有profile策展锚点时再说明锚点来源。
- 导览只看结构和核心位置，不进入长篇学习。
- 主动作：`开始了解整体`。
- 次级：`只看某个区域`、`退出并自由浏览全景`。

没有显式核心锚点时只说“沿正式主分支导览”，不得把关系度数最高或目录第一篇标成核心。

### 4.3 计划结构

```text
整体定位
→ 主分支A导览
→ A的显式锚点预览（若有）
→ 主分支B导览
→ B的显式锚点导览（若有）
→ 回到完整全景收束
```

- “整体定位”和“回到全景”是RouteStep，不要求用户自己找到返回入口。
- 分支站只展示正式名称、覆盖范围、直接下级和有来源的导览信息。
- 锚点站可在全景中显示summary和关键提示，但不得伪装成知识卡预览；用户主动打开该知识时直接进入完整正文。
- 当前政治没有显式锚点时，首轮计划可以只有整体、两条主分支和收束四站；不能用37篇列表补足“丰富度”。

### 4.4 进行中形态

知识全景始终是视觉主体：已看主干、中间当前位置和随后主干同时可见；底部或内联GoalGuide一次只讲当前站“它在整体中的作用”和一个`看下一站`主动作。

- 用户不需要点击分支选择下一站。
- 点击非当前节点只打开轻量预览，不改变路线；`退出导览，自由探索`才解除GoalGuide。
- 进入锚点预览后，合上卡片返回同一站；主动作仍由路线决定。
- 低动画模式直接改变高亮和位置说明，不使用自动飞行作为理解前提。

### 4.5 完成与恢复

完成页叠加在完整全景上，报告：已看主分支、已看锚点、跳过站点；不说“已经掌握政治理论”。主动作是`回到全景继续探索`，次级可以是`开始系统学习`，但不能两个同权。

恢复时回到原站和viewport；packageVersion失效时重建导览并说明“知识结构已更新，本次导览已重新安排”，不猜对应旧站。

## 5. 系统学习：连续完成一个正式范围

### 5.1 目标边界

系统学习回答“为了完整理解这个范围，我现在应该学哪个知识、先注意什么、读到什么程度、怎样检验是否记起”。它不是按目录逐层点入，也不是把关系、阅读、回忆做成三个需要用户管理的功能页。

### 5.2 开始态

系统先给profile默认范围或当前焦点命中的显式推荐范围，并展示：

- 正式范围名称、知识数量和路径。
- 依赖规则、正式顺序及范围外前置数量。
- 第一个知识、最后一个知识和每个知识的学习周期。
- 有效回忆覆盖；无回忆的知识如何结束本周期。
- 主动作：`开始第一个知识`或`继续当前知识`。
- 次级：`调整学习范围`、`查看完整安排`。

推荐范围不能默认整库37篇后只给一个巨大步骤数。politics profile必须提供一个有明确边界的默认正式范围；较大范围按正式上级分成连续阶段，但仍是一份可恢复计划，不要求用户先自行选章。

### 5.3 每个知识的连续周期

```text
定位与学前提示
→ 完整理解
→ 主动回忆（有正式RecallItem时）
→ 下一个知识
```

#### 定位与学前提示

- 在完整知识卡顶部显示体系位置、为什么现在学它和必要前置；关系通过按需入口提供。
- 关系是提示内容，不生成每篇必经的独立关系页。
- 只有RouteDefinition明确要求进行对照或回看前置时，才生成独立关系/来源步骤。
- 主动作是当前完整知识中的学习动作，不再先经过`完整学习这个知识`过门按钮。

#### 完整理解

- 展开同一大知识卡的连续正文，显式小卡与plain内容保持正式顺序。
- 文末主动作是`完成阅读并回忆`；没有RecallItem时为`完成这个知识并继续`。
- “访问过页面”不算完成，必须提交明确阅读完成事件。

#### 主动回忆

- 合上同一卡片进入RecallProjection，揭晓并选择记得/模糊/没记住/跳过。
- 模糊或没记住时，按C的情境工具提供回看当前小卡或完整知识；返回后仍在同一题。
- 一次有效回答或显式跳过完成该周期，系统直接展示下一个知识，不返回计划总览。

### 5.4 进行中形态

用户持续看到“第几个知识 / 共多少个”和当前知识周期，但不看到可点击的体系/关系/阅读/回忆ActivityDock。周期阶段是GoalGuide中的进度说明，当前只有一个动作。

退出知识卡回到路线时仍显示同一知识和阶段；进入来源、关系或显示工具不改变RouteSession。调整范围会结束当前计划并生成一份有新ID的新计划，旧计划保留为已退出记录，不静默改步骤。

### 5.5 完成与恢复

完成报告分别列出：完整学习的知识数、完成阅读数、完成回忆数、回看数、跳过知识/阶段和范围外前置处理；只报告行为，不输出掌握度。

- 主动作：存在profile定义的连续下一范围时`继续下一范围`；否则`回到本范围知识全景`。
- 次级：查看跳过项、重新学习本范围。
- 恢复直接回到当前知识和阶段；版本失效时说明变化并重新生成，不把旧完成索引套到新顺序。

## 6. 易混突破：先判断，再用依据修正边界

### 6.1 目标边界与能力等级

易混突破不是关系列表，也不是让用户先从5组contrast中选择。系统按以下顺序推荐一组：

```text
有效未完成易混会话
→ 当前焦点直接相连的正式contrast
→ 最近正式范围内的未完成contrast
→ profile.priorityRelationIds
→ 正式目录顺序下第一组可用contrast
```

每次都必须显示“为什么推荐这组”，只能引用当前焦点、最近范围、profile策展或正式顺序，不能说“系统发现你容易混淆”。

能力分两级：

| 能力 | 必需数据 | 可以完成 | 不能声称 |
|---|---|---|---|
| `contrastBasic` | 正式contrast关系、两侧KnowledgeUnit和正式reason | 先想、核对关系理由、分别回看两侧完整知识 | 辨析通过、精确定位边界 |
| `contrastRecallReady` | ContrastPair维度/边界、双方atom/block引用及两侧正式单元Recall引用 | 完成先判断、证据核对、再辨和结果记录 | 长期掌握或以后不会混淆 |

当前政治5组正式ContrastPair均已具备维度、边界、双方atom/block引用和两条正式单元回忆引用，达到当前内部能力标记`contrastRecallReady`。这些单元回忆题并非成对辨析题；页面应围绕正式ContrastPair维度给出中性自我解释提示，完成先判断、证据核对和再辨，不展示无关的单侧回忆题；其他没有正式ContrastPair的知识不生成易混任务，也不以标题相似或普通关系降级冒充对照。

### 6.2 开始态

开始页固定显示左右两个知识、各自路径、系统推荐理由及本次四段节奏。主动作是`开始这组辨析`；`换一组`和`限定范围`为次级。不能先展示5组可选择卡片。

### 6.3 进行中四段

#### 第一段：先判断

左右知识标题稳定在场，GuideVoice只问一个不含新事实的通用问题，例如“先想一想：二者判断的对象或适用边界有什么不同？”主动作是`查看判断关键`。当前没有独立的成对辨析题；只用正式ContrastPair维度和双方标题提示自我解释，不收集正确/错误。

#### 第二段：核对边界

显示正式ContrastPair维度与边界；只有`contrastBasic`时显示正式relation.reason并明确是“已确认的相关判断”。主动作是`查看两边依据`。

#### 第三段：回看依据

左右大知识卡保持同屏身份，依次打开有来源的小卡；缺精确锚点时分别打开完整知识，并保持A/B和返回位置。主动作按能力为`再辨一次`或`完成本组核对`。

#### 第四段：再辨一次

只在`contrastRecallReady`时再次呈现与初判相同的正式对照维度，记录“能分清/仍模糊/未分清”的本次自我判断；不把任一侧普通Recall题冒充成对辨析题，也不生成新的知识事实或正确率。

每一段只有一个主动作，左右卡片不能退化为“分别阅读全文”两个同权按钮；切换两侧证据属于同一对照状态。

### 6.4 完成与恢复

- `contrastBasic`只报告“本组判断边界已完成一次核对”。
- `contrastRecallReady`报告首次判断、是否回看、再次判断和跳过；仍不报告掌握度。
- 有下一组时主动作`继续下一组推荐`；单组入口或无下一组时`返回原知识`。
- 恢复必须保留relationId、当前四段、两侧来源位置和揭晓状态；任一侧版本变化则整组失效并重新建立，不能只替换一侧。

## 7. 考前速记：最短路径进入冻结卡组

### 7.1 目标边界

考前速记回答“在一个明确范围内，我现在还能不能主动想起这些内容”。它保留用户熟悉的翻卡心智，但卡片仍来自B定义的同一知识卡，不建立独立答案库，也不自动推断掌握度或安排长期复习。

### 7.2 开始态

进入优先恢复有效卡组；无会话时按profile默认范围生成冻结卡组，展示范围、卡片数量、正式/固定随机顺序和推荐依据。主动作是`开始第一张`或`继续第N张`；`调整范围`和`更改顺序`为次级。

- 默认不显示知识层级列表。
- 随机必须由用户显式开启且seed和item列表在本次会话冻结。
- RecallItem是否在提示前显示知识标题由正式卡片元数据决定；当前没有该字段时保持现有标题，不能用页面猜测“标题是否泄题”。

### 7.3 单卡状态机

```text
提示
→ 揭晓
→ 记得 / 模糊 / 没记住 / 跳过
→ 情境补救
→ 下一张
```

- 提示态只显示范围、进度、prompt和一个`揭晓答案`主动作。
- 揭晓态显示正式answer、pitfall和同一回答选择组。
- `记得`：主动作直接进入下一张。
- `模糊`：先显示pitfall或最小来源提示，主动作进入下一张，次级为回看知识卡。
- `没记住`：系统推荐主动作改为`回看这张知识卡`；回看后返回同一揭晓态，再由用户进入下一张。`先继续`为次级并记录未回看。
- `跳过`：记录跳过并进入下一张，不计入没记住。

RouteSession需要保存每个stepId的结果和是否回看，以便完成页生成即时补救队列；这是现有RouteSession的字段扩展，不建立掌握度或第二套学习状态。

### 7.4 完成与恢复

完成报告显示记得、模糊、没记住、跳过和实际回看数量，并列出本会话中模糊/没记住的卡片标题。

- 存在未回看“没记住”卡时，主动作是`回看没记住的N张`，复用同一冻结item列表形成即时补救段。
- 没有未回看项时，主动作是`返回本次范围`；`再来一轮`作为次级并生成新RouteSession。
- 即时补救只处理本次明确结果，不建立间隔重复、错题本、掌握度或P4个性化。
- 恢复保持卡序、当前卡、是否揭晓、逐卡结果和补救返回位置；packageVersion变化使整组过期并要求重建。

## 11. 失效、退出与并发会话

- 四类目标各自保存和恢复`RouteSession`；首页只突出一个最近任务作为视觉主动作，其余目标可直接进入或恢复，互不暂停、清除或阻挡。
- 用户进入自由探索不会自动结束路线；GoalGuide可以最小化，返回后仍在原step。显式`退出本次任务`才改变session状态。
- 调整范围生成新planId并结束旧计划；不能在原planId下替换steps。
- packageVersion、scopeId、relationId、RecallItem或必需能力失效时session标记`expired`，说明原因并提供一个重建动作。
- 回忆补救、关系证据和完整阅读使用returnTarget回到同一step；微信页面栈只负责物理返回，不能推测路线状态。
- 不实现跨设备同步、长期掌握度或自动复习调度；同一时刻只显示一条路线，但四目标会话进度可以分别保留。

## 12. 自动验收场景

### S55D-AC-001：四目标不先选择

四个目标从首页进入后都先得到一个有依据的系统推荐和一个开始/继续主动作；范围、对照和随机只是次级调整。

### S55D-AC-002：快速了解不退化为目录

政治默认导览在同一全景依次投影整体、两条主分支和收束；没有显式锚点时不列37篇知识、不伪造核心节点。

### S55D-AC-003：系统学习关系不阻塞

有关系知识的默认周期直接进入完整理解；关系作为学前提示，只有显式RouteStep才打开独立关系证据。

### S55D-AC-004：系统学习连续推进

完成阅读或回忆事件后直接进入同一计划的下一阶段/知识，不返回总览点击“完成当前步骤”。

### S55D-AC-005：易混推荐可解释

当前焦点存在contrast时优先推荐对应组；无上下文时按profile/正式顺序推荐。任何推荐理由都不声称预测用户弱点。

### S55D-AC-006：易混能力诚实

具备`contrastRecallReady`时完成页报告本次先判断、回看与再辨结果；只有`contrastBasic`时只报告边界核对。同一代码按能力标记渐进增强，当前政治5组应走前者。

### S55D-AC-007：速记响应式补救

记得进入下一张，模糊显示最小提示并允许回看，没记住优先引导回看；所有路径返回同一卡组和当前进度。

### S55D-AC-008：四种完成页不同

快速了解报告主干、系统学习报告学习动作、易混报告核对/再辨、速记报告逐卡自评；默认不出现统一“路线完成N步”文案。

### S55D-AC-009：恢复与失效

四种路线分别恢复站点、知识阶段、对照阶段和卡片揭晓；版本变化后诚实过期并重建，不把旧索引套到新计划。

### S55D-AC-010：独立目标进度与单一视觉主任务

同时存在其他目标的有效会话时，启动新目标不得暂停、覆盖或阻挡旧目标；返回首页可分别继续四种目标，但只突出一个最近任务。旧单一活动路线规则由2026-10-03用户决策替代。

### S55D-AC-011：无第二套状态

路线页面重建后只凭Plan、Session、KnowledgeContext和现有视图状态恢复相同位置；删除页面瞬时data不会丢失正式进度。

### S55D-AC-012：模块和内容隔离

政治profile增加的默认范围/策展不进入常识和笔记；37篇继续`review`、发布数0，S6保持暂停。

## 13. 用户确认后的最小手测

| 场景 | 用户只需判断 |
|---|---|
| 首次快速了解 | 是否像有人带着看全景，而不是自己点两篇列表 |
| 系统学习 | 是否始终知道为什么学当前知识、当前处于理解还是回忆、下一步是什么 |
| 易混突破 | 是否真实经历先判断、核对和回看，而不是看到两张并排卡后自己研究 |
| 考前速记 | 是否进入后很快开始翻卡，没记住时系统给出合适补救 |
| 四种完成 | 是否分别回答了四个不同目标，而不是同一完成页换标题 |
| 中断恢复 | 是否回到准确站点/阶段/卡片，且不会丢失原知识位置 |

## 14. 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 四个目标都先选择篇章或范围 | 把路线编排责任交给用户，真实体验继续同构 |
| 快速了解逐篇播放37个summary | 变成浅阅读列表，无法形成整体结构 |
| 系统学习每篇强制独立关系页 | 关系重新阻塞阅读，并与B的单一卡片表面冲突 |
| 易混入口先列出全部contrast | 用户仍需自己诊断和编排 |
| 只把两篇知识左右排版就叫易混突破 | 缺少判断、边界、证据和再辨过程 |
| 速记先浏览目录再选卡组 | 破坏翻卡心智和低成本进入 |
| 模糊/没记住自动记入长期错题或复习 | P4学习状态未定义，当前结果只属于本次会话 |
| 用浏览次数、关系度数或相似度猜推荐 | 缺乏知识与用户证据，且不可解释 |
| 用同一个完成页只替换标题和统计数字 | 四种目标的结果仍然无法区分 |
