# 快速了解：重点简读与阅读节奏优化

日期：2026-10-20。状态：已实现，待用户体验反馈；发布、上传暂停。

## 问题与目标

用户反馈集中在“阅读太长，重点和节奏不明显”。原导读虽已逐步呈现，但定义、解释、例子、边界仍堆在同级长段里；相关篇章标签挤占阅读空间，最后还必须打开一段完整参考表达才能结束。用户看到了步骤，却不容易判断每一步应该先抓住什么。

本轮让默认路径先建立两条主线的初步框架，保留随时深入的解释。仍不把点击、浏览或完成视为理解／掌握的证明。

## 本轮决策

1. 保留八个稳定 section ID、原生前后步、暂停与详情返回。按“搭框架 → 认主线 → 串起来”显示当前阶段；按钮明确提示下一步的内容。
2. 每步默认显示一句主旨、2–4 条带语义标签的短解释和必要边界。摘句正文总计 855 字，原导读正文 1,909 字，减少约 55%；单步默认摘句不超过 200 字。标题、标签和展开区不计入这两个正文数字。
3. 原有完整段落放入明确的“展开完整解释”，没有从内容制品中删除。原来占据正文头部的篇章标签改为展开区末尾的“这一节涉及”；完整知识入口继续作为可选深入入口。
4. 最后一步直接呈现简短回看，“完整参考表达”可展开和收起，不再作为完成门槛。只有到达最后一步且明确点完成，路线才结束；未打开参考时，记录仍如实保留 `referenceOpened=false`。
5. 首页入口改为“先看重点，按需深入”，界面不再对简读路径沿用完整脚本的 8–12 分钟设计时长。原导读制品的时长、正式事实、来源与覆盖缺口保持原样。

## 同源加工与边界

- 已批准的 `quick-primer-v2.json` 和 37 篇正式 Markdown 均未改动。
- 新增 `quick-primer-reading-v3.json` 仅存段落编号、逐字摘句和阅读标签。它绑定原导读文件的 SHA-256，每个摘句必须在指定段落唯一匹配；构建器拒绝失配或超出单步预算的配置。
- 运行包版本同时计算原导读与简读配置；生成包与页面从同一个定义消费。未引入新的知识实体、事实、关系或路线状态机。
- 新包版本会沿既有规则使旧版本路线进入恢复流程，不能把旧路线静默改成本版进度。原始访问、参考展开与详情打开记录的含义不变。
- 这份实施记录不把新的呈现策略记作用户验收通过，不把内容晋级为 `published`，也不把模块晋级为 `verified`。

## 验证与后续

新增简读专项校验检查八步实际投影、摘句来源、默认字数、完整段落保留、无参考也可显式结束及恢复。J2 回归补充展开不改进度、切步收起、参考可收起并保留访问事实等检查。相邻路线和共享展示回归继续运行。

本轮先做本地编译与模拟器检查，再由用户评估阅读体验。用户已要求暂停发布与上传；上一候选的微信包体数据只属于上一构建，本轮代码变化后需要重新验包才可继续发布。
