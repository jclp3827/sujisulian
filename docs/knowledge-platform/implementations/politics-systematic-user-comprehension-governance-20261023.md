# 政治系统学习用户理解审核与纠偏方案

日期：2026-10-23。

状态：**P19独立AI专家与首次学习者内容终审通过。首轮17项问题涉及15节，修订后两角色均77节pass；当前版本units-8553e42cacb8。新增修订的人工抽样、320px、真机及发布分别待办，历史证据保留。**

适用范围：政治理论系统学习当前2条路线、21个主题、77节候选教学稿，以及后续新增或改写的小节。快速了解、考前速记、易混突破、每日练习和一问一答只在发生任务迁移或共用内容时进入影响检查。

本方案解决的不是若干截图文案，而是同一类业务问题：内容虽然具备来源和抽象结构，用户却无法快速判断“正在讲什么、为什么放在一起、读完应理解什么、题目究竟要回答什么”。整改目标是让用户以较低上下文成本获取知识并形成可复述的最小理解。

## 1. 当前裁决

1. 既有路线、主题、小节粒度和来源绑定可以继续作为候选底座，不因本轮审计直接推翻。
2. B4“逐节终审通过”仅证明当时范围内的来源、目标、边界、衔接和跨模块职责成立，不再作为用户可理解性的通过证据。
3. 当前72节全部重新进入“用户理解待审”状态。已展示的15个问题作为首批种子问题，不代表问题全集。
4. 本轮优先修复派生教学内容和自测，不改写正式知识事实。发现正式来源自身存在缺口时，继续使用来源限缩或阻断，不由教学稿补造。
5. 用户理解审核必须覆盖实际可见的标题、问题、段落、边界、结论、自测与答案，不能只审核lesson级目标或来源引用。

## 2. 用户视角内容合同 UC-1

以下规则是系统学习所有用户可见内容的强制合同；执行中可以补充，但不得以局部实现静默削弱。

1. **标题表达知识对象或结论。** 不以“先看、再读、保留、补上、放回、读完整、材料怎样用”等编辑动作充当知识标题。
2. **标题脱离作者上下文仍可理解。** 用户只看到当前标题，也能判断它在讲什么；做不到时取消该小标题，使用连续正文。
3. **正式编号只作辅助定位。** 来源确有枚举时采用“知识名称（所属组·第N条）”；来源没有枚举时不得自行生成序号。
4. **抽象聚合必须给出明确映射。** 使用“角度、职责、结构、层次”时，必须紧接“A回答什么、B回答什么”；三项以上优先使用简洁关系结构。
5. **一次自测只检验本节一个小目标。** 题干独立可读、一个作答任务、读完默认内容即可回答；允许重复本节核心问题，不为制造题干差异牺牲清晰度。
6. **虚构纠错和材料情境不作为系统学习默认自测。** 经来源和评分点审核后，可迁移到理解应用题；系统学习保留直接理解与轻量自我解释。
7. **教学正文不使用无对象的“原文、正文、材料”。** 直接说出知识对象；来源由明确的查阅入口承担。必须提到来源时写出具体名称。
8. **参考答案先直接回答。** 明确写出对象与含义，不以无前置指代的“它们、这里、正文”开头，不先解释出题或编排理由。
9. **小标题允许为空。** 只有形成独立知识块时才显示标题；不得为满足结构数量制造空洞标题。
10. **可理解性是独立门禁。** 来源正确、覆盖完整、字数合适、题干不重复都不能替代用户理解审核。
11. **来源绑定必须落到当前可见对象。** 每段解释、边界、结论和答案使用自己的最小充分来源集；同主题来源并集不能替代直接支持。无关来源进入对象绑定记为风险，缺少直接支持当前主张的来源记为hold。
12. **总标题使用知识名称。** 标题优先采用概念、制度、关系或正式表述名称，不用“怎样放在一起、怎样放回整体、各管什么、先读、再读”等提问或阅读动作代替名称。
13. **核心设问使用直接句式。** 优先使用“是什么、包括哪些内容、有什么区别、是什么关系、为什么、如何理解”；不用“分别看什么、怎样放在一起、为什么还要保留、不要混成一层”等要求用户猜测编排意图的口语表达。
14. **段落标题只承担知识定位。** 段落标题写概念、关系、判断标准或正式项目，不写“日常争吵、先看完整结构、材料怎样用、回看这一组”等类比、操作和编辑提示。
15. **自测与核心设问使用同一语言标准。** 自测只提出一个清楚任务，答案首句直接回应；不得为了显得像题目而加入额外的编排理由、纠错前提或口语化动作。
16. **正式枚举采用父级对象加序号。** 同一正式表述被拆为多节时，显示标题使用“十个明确·七”“十四个坚持·一至七”等格式；中文序号仅在来源确有枚举且归属明确时使用，正文再展开知识内容。
17. **每页形成“对象—关系—结论”闭环。** 先明确本页涉及哪些对象及其含义，再直接说明对象之间的关系，最后用结论回答核心设问。页面不能依赖用户从纠偏提示、应试判断或上下文中反推基础概念。
18. **关系表达必须写出关系双方和关系类型。** 不使用无对象的“相互联系、不能割裂、放在一起、没有结束”；应写成“A依赖B”“A发展为B”“从A到B是第一次飞跃”等可直接复述的完整关系。
19. **否定式提醒不得代替默认知识标题。** “不只是、不取消、不要、不能只”等表达只在基础对象和正向关系已经建立后用于必要边界；正文主标题优先直接陈述定义、阶段、关系或结论。
20. **运行接入不等于用户理解通过。** 自动构建、来源校验、页面加载和AI抽样通过，只证明内容按预期进入候选运行版。真实用户无法复述对象、关系或结论时，当前节判为失败；同类反馈跨多个抽样页面时，重新打开全量残余语义审计。
21. **编排过程不进入知识表达。** “保留正式名称、没有改写、重新命名、为了控制单次学习量、分成两节、仍按正式定位理解”等作者或审核动作只进入元数据和审计证据；用户页只说明知识对象、正式归属、关系和必要边界。
22. **集合词必须带父对象或成员。** “前七项、后七项、三项、几个、其余、各自、这一组”等词不能单独承担标题；标题至少写明所属正式集合，正文首次出现时写明成员或可追溯范围。
23. **标题、正文与答案履行同一承诺。** 标题写“区别、关系、正式名称、N项内容”时，正文必须解释同一对象的区别或关系、给出相应名称或覆盖N项；自测和答案不得改换对象、数量或任务。
24. **正式枚举使用唯一序号真值。** 标题、正文、“本节结论”和参考答案中的第N项必须与正式来源及彼此一致；同页出现冲突直接判为L1并阻断接入，不能通过上下文猜测放行。
25. **教学分组不得生成正式类别。** 分页、前三项／后三项和复习分组只用于阅读组织，不得改写为来源中不存在的“三项方法、两个层次、固定步骤”等类别；跨体系相近概念必须同时写明各自所属正式体系。
26. **关系题先正向建立双方对象。** 核心问题比较A与B时，正文必须在关系结论前分别说明A是什么、B是什么或各自承担什么；不能让B首次出现在否定式边界或参考答案中。
27. **边界只补充真实误解条件。** 边界不得复述上一段、结论或答案，也不得用“不能互换、不能省略、各有作用”代替正向知识。没有新增误解条件时删除边界；需要保留时写明对象双方和具体误解。
28. **概念承担知识，序号只负责定位。** 正式序号必须准确，但不得反复占据标题和正文的主要位置。跨节范围可在总标题和核心设问中保留一次；段落标题先写概念，再以括号补充序号；正文只在说明顺序时使用序号；结论以“依次是”统一收束。理解任务以概念、含义和关系为主，序号只作为检索与顺序记忆的辅助信息。
29. **边界与结论不得重复。** 边界只在提供结论之外的真实防误解信息时保留；与标题、正文或结论重复时删除。删除边界后，由“本节结论”承接左侧强调线和视觉重点。不得为了保留视觉样式制造边界，也不得把结论改写成审稿提醒。
30. **页首学习任务只保留一个结果句。** 页首统一显示“读完能理解：<知识结果>”，不再同时显示“这次要回答”和“读完能理解”。知识结果使用陈述式对象、含义、区别或关系，去掉“理解、认识、分清、说清”等动作词；核心设问继续作为内容合同和页末快速自测存在，不在页首重复。
31. **结论的视觉语义必须固定。** “本节结论”始终使用左侧强调线，左侧线只表示本页结论，不得在结论与辨析块之间切换。必要辨析作为次级信息单独显示，只有在提供结论之外、来源支持的具体误解条件时保留；与正文或结论重复时删除。
32. **视觉主结论必须回应核心设问。** 定义题和关系题的结论直接给出核心定义或关系；枚举题的结论提供分类结构、对应关系或记忆框架，完整正式成员保留在正文和参考答案中，不再逐项抄写正文。正文、结论与参考答案共同形成完整主答案，不能把作答所需的核心关系只放在次级辨析中。必要辨析只补充具体误解，不承担主答案缺失部分。
33. **小节结论使用唯一名称。** 72节末尾的结论组件统一显示“本节结论”，不因其处于主题末尾而改名为“本主题小结”。主题层级的汇总只能出现在主题或篇章收束结构中，不能复用小节结论组件改变其名称。作者源、运行模型、页面投影和验证规则必须使用同一名称。
34. **整页按语义去重。** 同一知识关系或误解在正文、辨析、结论和自测中以正向、否定、近义改写重复出现，仍视为重复，不能只按字面相似度判断。基础关系由正文正向建立，结论负责收束，自测负责提取；具体误解如需提示，只在最贴近概念的位置出现一次。辨析块必须增加正文和结论无法直接推出的条件、场景或易错边界，否则删除。
35. **定义任务使用完整对象和“是什么”。** 当学习目标是取得一个或多个概念的含义时，核心设问与自测直接问“A是什么”或“A和B分别是什么”，不用“分别说明什么、分别看什么”让用户先判断回答层级。段落标题写“完整对象＋含义／关系／要求”，不用裸“阶段、质量”等简称承担对象。属于概念定义的稳定限定直接写入对应定义段，不另设辨析；辨析只保留定义之外的具体误解条件。
36. **并列概念标题补全共同主语。** 当多个概念同属一个上位对象时，标题必须明确写出共同主语，不能依赖总标题或上一段补足。例如写“货币的价值尺度与流通手段”，不用裸“价值尺度与流通手段”；标题单独截取后仍应能判断是谁的属性、职能或关系。
37. **辨析必须直接服务本节核心作答任务。** 某条信息即使事实正确，只要不参与回答当前核心设问，也不应作为系统学习默认辨析；属于核心关系的条件或机制应进入对应正文。只有缺少该提示会直接误读本节主答案，且正文和结论无法自然容纳时，才保留独立辨析。
38. **辨析必须先做融合反事实。** 审核每个独立辨析时，先假设删除该组件：如果主答案缺失，就把必要内容并入最接近的定义、关系或判断正文；如果主答案仍完整，且误解可从正文或结论直接推出，就删除。只有具体误解会直接导致本节主答案误判、正文无法自然容纳、具有直接来源且结论脱离辨析仍能完整答题时，才保留独立辨析，并登记具体误解、触发场景、不能融合的理由和直接来源。
39. **同页同层标题必须平行。** 兄弟段落标题使用同一共同主语、语法模板、解释粒度和序号位置。一个标题按阅读动作或序号命名、另一个按完整知识名称命名，直接判为风险；成对或并列对象应采用可并排比较的标题结构。
40. **同知识组采用唯一命名策略。** 同一正式集合的所有展示标题、核心设问和段落序号必须在组级矩阵中并排审核。展示标题统一以知识内容为主、范围序号为辅助，采用“知识内容·序号范围”；不得让作者源、前端投影和兄弟章节形成两套命名真值。修改组内任一标题时，必须同时回归其余兄弟章节。
41. **评分点必须映射到正文视觉重点。** 先把参考答案拆成核心对象、关系、条件或成员，再为每个评分点登记正文落点和视觉锚点。定义题突出完整定义，关系题突出关系谓词，枚举题突出正式成员，判断题突出成立条件；不得只突出概念名、错误命题或序号。结论的左侧强调线不能替代正文重点。
42. **审查必须绑定最终用户视图并保留分歧。** 审查包至少绑定作者源、运行模型、展示投影、页面模板、样式、规则和实际页面证据的版本或哈希。AI首次用户只看最终可见文本或页面，学科专家核对来源，测评专家核对题答，视觉审核检查扫读层级；任何角色的风险都不能用多数通过抵消。修订不得覆盖旧失败，必须保留原意见、修订动作和定向复测结果。
43. **验收清单必须提供可导航路径。** 每个待验收小节同时给出“篇章-主题-小节”三级路径，三级名称分别取当前运行版的路线标题、主题标题和最终展示标题。不能只给`lessonId`、作者源标题或孤立小节名；正式枚举小节必须保留最终展示标题中的父对象和序号范围。验收证据与用户报告使用同一份路径真值。
44. **正文、辨析、结论和答案各自承担唯一职责。** 正文完整解释知识对象与关系；辨析只处理会直接造成误答的具体误解或成立条件；结论提炼结构、关系或判断框架；参考答案保留可评分的完整回答。同一限定不得在正文、辨析和结论中重复出现，题干与参考答案为完成作答闭环所需的对应不计为区域重复。
45. **结论必须产生压缩或组织增量。** 结论不能逐句拼接正文，也不能把正文中的正式清单换一个标点后重新展示。定义题和关系题允许复述必要核心判断，但须删除正文已有的解释过程；枚举题改用分类结构、对象映射或记忆框架，逐项正式表述留在正文和参考答案。机器相似度只用于召回，最终由语义审核判断是否存在增量。
46. **辨析采用单点归属。** 删除辨析后主答案缺失的内容并入正文；会直接导致误答、且不属于定义本身的具体误解保留为次级辨析；可以由正文或结论直接推出的辨析删除。内容一旦归入辨析，就不得在正文和结论再次完整复述；内容一旦并入正文，也不得继续保留同义辨析。
47. **分号枚举必须形成视觉分段。** 结论包含中文分号时，前端按分号生成独立段落并保留原有顺序和语义，不依赖屏幕自动折行制造层次。分段只解决阅读节奏，不能替代第44、45条的语义去重；新增内容优先使用结构化段落，旧文本允许由投影层兼容拆分。

合同增补规则：新增规则必须登记触发问题、正反例、影响字段、现有内容命中范围和验证方法；不能只添加禁止词，也不能让自动检查代替语义判断。

第11条为UC1增补。触发问题是`CULTUREECO-02`、`PARTY-02`答案混入无关块以及`COGNITION-01`答案缺少直接支持块，而既有“来源块都存在”的结构检查仍能通过。正例为当前句子的每个主张均由本对象绑定块直接支持；反例为用同主题、下一课或其他领域的块组成大并集。影响字段为正文、边界、结论、自测答案及其`sourceBlockIds`；UC1学科审核还点名一组同类风险，UC2起以对象级最小来源复核和专家语义判断共同验证。

第12至16条为真实页面抽样后的UC3增补。触发文本包括“怎样放在一起”“矛盾不只是日常争吵”“不同问题不要混成一层”“判断时分别看什么”以及带编辑目的的复合自测。正例为“矛盾的同一性和斗争性、普遍性和特殊性分别是什么？”；反例为“这些内容怎样放在一起？”影响字段为`title`、`question`、`sections.label`、`boundary.label`和`reflection.prompt/answer`。机器检查负责召回口语化和编辑化短语，最终仍由用户视角与学科语义共同裁决。

## 3. 审核对象与问题切片

每节按用户真实阅读顺序拆成以下对象，逐个登记，不再以“整节已审核”覆盖内部问题。

| 对象 | 必审问题 |
|---|---|
| 单元显示标题 | 不看路线说明能否知道本节讲什么 |
| “这次要回答” | 是否只有一个核心问题，名词与关系是否明确 |
| “读完能理解” | 是否给出可验证结果，而非作者目标或泛泛动作 |
| 正文小标题 | 是否增加知识定位；是否只是编辑动作、序号或空泛过渡 |
| 解释段落 | 是否先给对象和含义，再解释关系；抽象词是否有映射 |
| 边界 | 是否防止真实误解；是否只是暴露审稿规则或反向假设用户犯错 |
| 本节结论 | 是否直接回答开头问题；是否能用自己的话复述 |
| 自测题 | 是否单目标、独立可读、可由本节作答，是否属于系统学习职责 |
| 参考答案 | 是否直接、完整、有明确主语，与题干逐项对应 |
| 来源入口 | 是否能准确回到知识对象，不在正文中用“原文/正文”代替对象 |

问题按十一个切片归类，同一对象可以同时命中多个切片：

| 切片 | 定义 | 典型信号 |
|---|---|---|
| S1 语境锚点 | 用户不知道当前对象属于什么 | 裸“第4条”“前七项”“另外两个” |
| S2 标题语义 | 标题没有独立知识含义 | “先保留完整结构”“材料怎样用” |
| S3 来源层泄漏 | 编辑、构建或来源术语进入用户表达 | “原文”“正文”“保留正式名称” |
| S4 抽象未翻译 | 给出角度、职责、结构，却没有具体映射 | “补上两个角度”“分层理解” |
| S5 问题任务 | 一题多问、预设错误、编排理由冒充知识题 | 两个问号、为什么还要保留序号 |
| S6 答案可用性 | 答案无主语、只给占位解释、不能与题干对应 | “它们分别回答……” |
| S7 模块职责 | 系统学习混入速记、易混或材料应用任务 | 虚构提纲纠错、材料题 |
| S8 事实与边界 | 派生解释超出来源或把教学分组写成正式分类 | 无来源分类、关系过推、限定条件缺失 |
| S9 枚举与承诺 | 标题、正文、结论或答案的对象、数量、序号不一致 | 标题写九项但本段只列七项；第3、4项写成第4、5项 |
| S10 体系归属 | 相近概念跨正式体系出现，但没有写明各自归属或被合并成新类别 | 把六个必须坚持的分段统称为“三项方法” |
| S11 对象覆盖与顺序 | 问题要求比较多个对象，正文未在关系或边界前逐一正向说明 | 国家机关职能首次出现在否定式边界 |

严重度按用户结果判定：

- **L1 不可理解/可能误导**：用户无法识别对象、问题不可作答、派生分类冒充正式事实、答案无法对应题目。进入候选前必须修复。
- **L2 明显增加理解负担**：需要回翻、猜指代、拆解复合题或理解编辑语言。纳入当前专项修复。
- **L3 表达优化**：含义基本明确，但标题、节奏或答案仍可更直接。可随同主题批次处理，不阻塞其他切片。

## 4. 问题台账

建立逐对象台账，而不是只记录lesson ID。每条至少包含：

| 字段 | 含义 |
|---|---|
| issueId | 稳定问题ID |
| lessonId / objectId | 所属小节与具体标题、段落、自测或答案 |
| visibleText | 用户实际看到的文字 |
| slice / severity | 问题切片与L1—L3严重度 |
| userFailure | 用户具体会不知道什么或会怎样误解 |
| sourceStatus | 正式来源充分、来源限缩或来源阻断 |
| proposedAction | 改写、合并、删除标题、拆题、迁移题型或保持 |
| before / after | 修改前后文字 |
| affectedModes | 系统学习及可能受影响的题库/正文入口 |
| reviewStates | AI用户、AI专家、编辑复核、用户抽样状态 |
| validation | 静态检查、运行时版本、页面验证与未完成项 |

台账状态使用`identified → proposed → source-reviewed → user-view-reviewed → implemented → verified → accepted/hold`。截图只能创建`identified`项，不能据此直接标记全量完成。

## 5. AI用户与AI专家补充审核

AI审核用于扩大覆盖和暴露盲点，不作为事实来源，也不替代真实用户验收。

### 5.1 AI首次使用者

只提供用户当前屏幕能看到的内容，不提供作者说明、来源块、目标矩阵或预期答案。至少回答：

1. 这段正在讲什么对象？
2. 每个标题分别意味着什么？
3. 为什么这些内容放在一起？
4. 自测题要求完成什么任务？
5. 哪些词必须依赖页面外信息才能理解？
6. 读完后能否用一至两句话说出结论？

AI首次使用者不能替内容补上下文。若必须猜测“第几条、原文、正文、它们”所指对象，应直接登记S1/S3/S6问题。

### 5.2 AI公考学习者

从公考学习目标检查：本节是否帮助理解、快速恢复或应用知识；是否把考试价值较低的编排理由当成知识；题目是否能帮助形成可迁移的判断，而不是只适配当前页面措辞。

### 5.3 AI学科专家

查看正式来源与派生教学稿，检查术语、范围、限定条件、枚举归属、关系强度和教学分组是否越界。专家不得用模型常识补齐当前来源缺口，所有事实修订都要指向稳定来源块。

### 5.4 AI测评与内容设计专家

检查核心问题、自测和答案是否一一对应，是否单任务、可评分、无虚构前提；检查标题层级、段落节奏与抽象映射是否支持快速理解。

### 5.5 AI审核的约束

- 用户角色与专家角色独立执行，前者不得提前看到来源和标准答案。
- 每条意见必须引用具体可见文字、指出失败类型并给出可验证修订，不接受只有分数的结论。
- AI不能直接写入正式来源或把建议自动标记为通过；修订须经过来源复核和编辑决定。
- AI用户失败时，即使学科专家认为事实正确，也不能标记用户理解通过。
- AI专家发现事实或边界问题时立即进入L1/hold，不能靠语言润色放行。
- 角色意见冲突进入台账，由产品合同和正式来源裁决；保留不同意见，不用多数票代替判断。
- 高风险内容在修改前后各跑一次相同角色与量表，记录提示版本和输入版本，避免只保留修改后的正面意见。
- 最终状态分别记录`ai-user`、`ai-exam-learner`、`ai-subject-expert`、`ai-assessment`、`editor`和`real-user-sample`，不得合并为单一“AI通过”。

## 6. 纠偏机制

每条问题依次执行：

1. **定位用户失败**：先写清用户不知道什么，不先改句子。
2. **确认来源身份**：区分正式知识、产品教学分组、编辑说明和虚构情境。
3. **选择最小动作**：优先改写；无知识价值的标题删除；多目标题拆分；错模块内容迁移；来源不足则限缩或hold。
4. **重建用户表达**：先对象、再含义、再关系、最后必要边界；不从审稿规则开始。
5. **AI双侧复核**：AI用户检查可懂性，AI专家检查事实、题目和模块职责。
6. **编辑复核**：确认修改没有制造新分类、丢失正式限定或扩大本节目标。
7. **运行验证**：重建候选、执行来源/覆盖/进度兼容检查，再检查实际页面顺序和自测展开。
8. **抽样验收**：真实用户不看作者说明即可说出对象、关系和结论；未覆盖项保持待审。

只改措辞、标题或自测但不改变目标和顺序时，保留lesson ID并登记课程版本兼容；若拆分/合并小节、改变核心目标或来源责任，必须建立新ID或明确迁移，不能把旧“已读”静默当作新内容已读。
