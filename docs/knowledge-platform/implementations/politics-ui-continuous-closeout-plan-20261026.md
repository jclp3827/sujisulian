# 政治模块 UI 连续收口计划

用户明确授权：登记后持续完成三项工作，中间不设人工停止门。目标工作树codex/politics-quick-reading；未授权提交、合并或发布。已通过的路线列表与主题回看页作为基线保留。

| 顺序 | 批次 | 实施范围 | 完成依据 |
|---|---|---|---|
| 1 | U1 状态页收口 | 两篇全篇完成、旧版记录入口/续接、读取失败、保存失败与恢复 | 状态可理解，已有记录保留，重试与返回可用 |
| 2 | U2 跨模式回归 | 路线—正文—回看—补读—下一主题、原文往返、快速了解转系统学习 | 真实交互与事实记录检查，不只检查静态结构 |
| 3 | U3a 特殊结构与来源 | 全37篇结构复核、角色区分、补充来源与4处来源校正提示 | 普通标题不强制套卡，来源内容与定位保留 |
| 3 | U3b 重点选择与范围 | 5步＋37篇＋77节现有重点全量审计；按明确文本来源修正缺少完整概念/限定词的范围 | 不为凑比例新增重点；原文、题目及来源不改；每项变更可追溯 |
| 3 | U3c 题库练习 UI | 一问一答/每日练习、考前速记、易混练习的题目、答案、边界、来源、自评、底栏与结果页 | 178张回忆卡、24道应用题、14组易混内容保持不变，交互与统计语义不变 |
| 收口 | U4 最终验证 | 受影响页面全量数据检查、代表性渲染/操作与状态故障注入，接入目标前端 | 分开记录技术检查、人工抽样和发布状态 |

通用规则：蓝主绿辅；绿色用于辅助标签与实际结果，不用颜色单独代表正确/完成。非正文固定字号且无字号设置。标题/题干/按钮为主要信息；不新增编者说明和重复总结。重点调整采用可追溯展示层标注，保持源文字、标点、顺序、知识绑定不变。专题内容已有合理形式可评审后保留，不因“待评估”就批量改成同一种蓝卡。

320px和真机沿用用户豁免。所有合成记录与故障注入仅在隔离微信项目，测试后恢复。旧版/失败记录不得清理、丢弃或被“成功”样式掩盖。即使中间页面已完成，也继续本计划后续工作，不再次请求小批次批准。后续影响前一步时，补跑受影响的回归。
