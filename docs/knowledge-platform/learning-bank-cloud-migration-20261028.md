# 学习题库云端分批加载实施与交接（2026-10-28）

## 当前状态

笔记练习、笔记快记、常识问答和常识导读的正式内容已接入 `learningBank` 云函数。云函数已通过微信开发者工具当前登录的云开发环境部署到 `cloud1-d8gw5r2il0c0f198a`；不依赖本机 CloudBase 命令行登录。小程序代码已在开发者工具编译成功，**尚未上传、审核或发布**。政治理论保持原入口。

本次构建复用现有公开审核规则，没有把未通过筛选的条目提升为正式内容。结果：笔记练习 142 条（公考真题 121 条）、笔记快记 133 张（基础 41、方法 92）、常识问答 603 道、常识记忆材料 128 条、常识导读 1681 张；导读 1 条 HOLD 未进入正式产物。

## 存储与取题

源内容继续保存在仓库原始文件中。运行 `node scripts/build-learning-bank-function.js` 后，生成 `cloudfunctions/learningBank/data/manifest.json` 和每五条一个的 JSON 文件，再通过微信开发者工具部署云函数。这里用的是**云函数代码包内的只读数据**，不是云存储桶或云数据库。增加内容需要重新构建并部署函数；在云控制台新建空文件夹不会自动加入题目。

`start` 按公开模式和范围确定一组最多 15 条，返回首批最多 5 条及总量；`batch` 返回下一批最多 5 条；`catalog` 返回最多 100 条的轻量目录；`hydrate` 按 ID 恢复最多 5 条；笔记练习的 `resume` 一次返回当前版本与续学首批。常识问答 `bootstrap` 返回不含题目正文的索引及学习编排，导读 `bootstrap` 返回压缩索引与最多 5 张预取卡。单次独立正文批次上限 64 KiB。图片继续使用已有云存储路径，只在当前卡片需要时请求。

笔记练习新组由云端先按本机提交的练习次数、上次作答时间排序，再对并列候选随机排序；常识一问一答在原有最少练习优先规则的并列项中随机。公考真题默认只取 5 条；选择 10 或 15 条时分批取完本组，不加载整库。笔记快记每次恢复当前卡及相邻卡的最多五条正文；常识按当前学习组取最多五条正文。客户端学习记录仍在小程序本地，卸载重装后的跨设备进度同步不在本次实现内。

## 扩库和版本切换

新增题目先在原内容源完成审核、ID 与来源校验，再运行构建和 `node scripts/validate-learning-bank-function.js`、`node scripts/validate-learning-bank-clients.js`，核对准入数、版本、ID、分批内容及续学。部署新云函数后，先用开发者工具和体验版调用新版本，再上传对应小程序代码。

当前函数只保留**一个活跃题库版本**。接口拒绝跨版本拼接批次；旧学习记录仍保留在本地，但原条目变化后相关轮次可能提示重新开始。纯扩库也可能改变整个题库版本，因此**尚未实现旧轮次始终锁定旧版本**。正式扩库前要补版本并存或兼容策略，必要时冻结内容并安排小程序与云函数同批切换。紧急撤回内容时应阻断旧内容访问。

函数包文件数量和大小会随题库增长。当前云函数上传为 546 个文件、约 1.5 MB；若后续碰到包体或冷启动限制，可保持接口不变，把五条正文文件移入私有云存储，由函数读取。

## 2026-10-28 加载优化

开发者工具测得旧导读 `bootstrap` 的 JSON 文本长度约 21.8 万字符，后续卡片另一次请求约 0.3 秒；旧公考真题续学先查目录、再取正文。新版本把导读 1681 张卡片的重复 ID 从目录响应移除，以组内 ID 顺序和签名数组重建轻量卡；新目录连同预取卡的响应约 12.3 万字符，减少约 44%。公考真题续学改为一次 `resume` 调用，不再先请求目录。新导读 `bootstrap` 的一次开发者工具观测为 854 毫秒，公考真题 `resume` 为 345 毫秒；这些是单次模拟器观测，不代表真机冷启动或弱网耗时。云函数与小程序候选已同步更新，之前生成的预览二维码不再对应最新候选。
