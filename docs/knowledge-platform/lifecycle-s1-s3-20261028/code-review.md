# 收尾代码审查

按 code-review-expert 流程分组审查：权威内容/生成产物、授权与撤回、受控生成替换、四类引擎及页面恢复、旧客户端合同。当前无未处理的P0/P1问题。未顺手拆引擎、迁数据库、改加载策略或清理历史。

修复了审查中发现的：导读来源依赖绑定缺口；辅助对照/专题/概念关系的未授权泄漏与撤回；未授权候选造成公众版本漂移；候选输出目录误用；并发生成替换；回退清单及当前来源重验；畸形旧队列；对照审核元数据身份耦合。相应正反例纳入lifecycle-s2/s3回归。

生成JSON按源构建一致性、文件摘要与ID集合核对，没有声称人工逐条阅读全库。独立AI内容审核仅覆盖S1五项，不扩大为全库事实复核。FNV继续用于已有客户端漂移协议，公开授权/生成清单用SHA-256，不把客户端签名当审批或安全凭证。

现有过期历史不再作为新版有效掌握证明，受影响历史单独保留；没有新增批量历史清理。既有会话数量规则没有另立新政策。有限旧版本桥接以精确语义投影为条件，不凭ID猜测。

未覆盖层次：人工抽样、法律人工定向复核、微信实际整包与真机、进程强杀/断电和正式部署。现有两份老验证脚本的历史断言不适用当前B5规则，已在分批回执明确登记，未改旧脚本以伪造通过。
