## 已知现状

- 入口包含常识首页、层级页、分类页、搜索和详情。
- 知识规模明显大于政治模块。
- 内容覆盖法律、经济、人文、科技等异质主题。
- 已有大量来源审计和现行法律校对记录。
- 现有页面使用层级/分类/知识点组织，并复用部分笔记组件。

## 初步导航模型

```text
常识模块
→ 层级或学科
→ 分类
→ 知识点
```

正式迁移前必须核对当前模型实际字段，不能只根据页面文案推断。

## 能力初步判断

| 能力 | 初步建议 | 待验证问题 |
|---|---|---|
| 体系 | 必须 | L0 如何聚合大量学科而不过载 |
| 关系 | 按数据启用 | 当前是否存在正式关系和理由 |
| 完整阅读 | 必须 | 法律、表格、规则和例外如何语义化 |
| 主动回忆 | 按卡片数据启用 | 卡片是否都可追溯来源 |
| 快速了解 | 启用 | 学科/分类摘要是否存在 |
| 系统学习 | 启用 | 顺序来自目录还是运营配置 |
| 易混突破 | 优先验证 | 法律概念、机构职权和规则对照价值高 |
| 考前速记 | 启用 | 需要选择学科、分类或收藏范围 |
| 时间/人物/文件镜头 | 按领域启用 | 人文、法律、科技需不同实体数据 |

## 迁移前必须完成

1. 现有模块、层级、分类、知识点数量及稳定 ID 清点。
2. 当前内容类型、表格、图片、公式、例题和来源字段清点。
3. 搜索、路由、本地状态和组件依赖清点。
4. 正式关系、易混、卡片和现行法版本能力清点。
5. 建立现有行为自动回归和用户手测基线。
6. 判断哪些通用能力可以只通过配置启用，哪些需要数据升级。

## 常识用于验证的通用问题

- 大量节点如何在知识地形中聚合。
- 不同学科怎样共享语义块但保留差异。
- 缺少关系的知识怎样降级。
- 法律现行版本和来源可信度怎样成为通用能力。
- 表格、规则、例外和实体卡是否具备普适价值。

## 03/04 契约映射

| 通用契约 | 当前建议 | 迁移前证据 |
|---|---|---|
| 每模块独立焦点状态 | 使用 `moduleId=common-sense` 独立恢复 | 现有首页、层级、分类、搜索和详情返回行为 |
| 无关系能力降级 | 默认路径、同级和完整阅读；不先造关系 | 正式关系及理由数量清点 |
| SourceAdapter | 先只读映射当前稳定模型，不改页面行为 | 当前字段、数量、稳定 ID 和来源审计 |
| SemanticBlock | 法律规则、条件、例外、表格优先验证 | 每类真实内容样本与普通文本降级 |
| 能力诚实性 | 按学科/分类实际数据启用关系、回忆和镜头 | 构建包数据与 profile 声明对照 |
| 版本与纠错 | 现行法律版本和来源审计映射到统一引用 | 当前法审计、修订记录和知识定位 |

在适配器与现有行为回归建立前，本表只是迁移约束，不授权修改常识模块。

## 05/06 决策验证

| 场景 | 常识验证重点 |
|---|---|
| L0/L1大规模 | 学科和分类超出节点预算时使用正式层级或确定性聚合，不制造新分类 |
| L2长标题 | 法律规则、机构职权和复合标题在窄屏仍可辨识并完整查看 |
| L3能力差异 | 逐知识判断关系和回忆能力，不能因少数分类有数据就全模块启用 |
| 语义阅读 | 条件、例外、对照、表格与现行版本在同一完整内容流中呈现 |
| 无关系降级 | 保留路径、同级、正文和来源，不从标签自动生成关系 |

MAP/WORK决策只作为未来迁移门禁，不等于常识模块立即启用新 UI。

## 07/08 决策验证

| 场景 | 常识验证重点 |
|---|---|
| 系统学习 | 无前置关系分类按正式顺序，有关系分类才使用约束 |
| 易混突破 | 法律概念/职权对照必须来自正式contrast和现行来源 |
| 搜索/问题 | 条件、例外和版本命中显示上下文，不合成法律结论 |
| 考前速记 | 先选学科/分类范围，只使用版本有效卡片 |
| 视觉 | 长标题、表格、条件/例外在320px和130%字号完整可读 |
| 迁移 | 新路线和UI开关不影响未迁移分类与既有搜索 |

常识用于证明通用路线和视觉能处理异质、大规模、高版本风险内容。
