## 配置合同

省份通过 `profiles/index.js` 注册；正式入口仅列有依据的省份，测试配置不加入地区菜单。`profiles/jpeg-q40.js` 是现有国考、四川的兼容模板；不是以后所有省份的默认规则。配置由 `core/encoding.js` 校验，处理器复制并冻结当前配置。

| 字段 | 规则 |
| --- | --- |
| width、height | 正整数；输出像素数最多100万（工程预算，不是考试规则），裁剪、画布、预览、JPG校验同步使用 |
| quality | 1—100的整数；quality模式采用标准质量映射，explicit模式仅作质量标签，实际量化以两张表为准 |
| dpi | 1—65535的整数，同时写入横纵密度；densityUnits为1时表示DPI，为0时只表示像素纵横比 |
| densityUnits | 可选0、1或2，分别表示无物理单位、英寸或厘米；缺省1，保持国考与四川旧输出 |
| sampling | 字符串420、422或444，实际变更MCU采样与文件头，不能只改头部 |
| quantizationMode | quality或explicit；缺失或未知值拒绝 |
| qLumaHex、qChromaHex | JPEG之字形顺序各64个字节；explicit模式必填、各值1—255；quality模式若声明表，则必须与质量映射相符 |
| separateTableSegments | 可选布尔值；false合并DQT/DHT，true分别输出两段DQT和四段DHT；均使用现有标准Huffman表 |
| jpegSegmentLayout | 可选精确段序列；未设置时按上述分段设置严格检查现有基线JPEG布局 |
| tailHex | 偶数长度十六进制，可为空；仅在JPEG结束后追加，导出重新检查 |
| sourceMinBytes、sourceMaxBytes、sourceMaxPixels | 原图输入限制，须合理且不互相矛盾；转正工作图重新编码后可能变小，原图大小下限只针对用户选择的原图 |
| sourceMinWidth、sourceMinHeight、allowSourceUpscale | 按省份规则设置；原图方向修正后仍需符合尺寸及裁剪边界，不把方向恢复当成低清放大许可 |
| outputMinBytes、outputMaxBytes | 可选最终文件字节边界；不满足时停止导出，不自动降低质量或填充字节 |
| allowAiBackground | 新增考试显式声明，正常接入默认复用既有AI换背景流程；若官方规则要求限制，记录依据并向用户明确确认，不因新增profile漏掉入口 |

工具哈希、背景说明、输入要求、确认文案及文件名继续由省份配置持有。未知或矛盾配置拒绝生成，不静默回退国考。渐进式JPEG、非标准Huffman表、专有加密等不在本次能力范围内。

## 共用加工及方向恢复

流程为：地区配置 → 选择原图 → 输入检查 → 必要的设备内工作图准备 → 裁剪及可选AI背景 → 用户确认 → 按配置编码 → 追加标记 → 结构及解码检查 → JPG或ZIP文件交付。

合法EXIF方向1—8不是非法照片。正常正向照片沿用原路径；旋转、镜像照片先确定方向，将EXIF仅从内部临时副本移除以避免平台自动旋转，再由画布对原始像素明确执行一次变换。临时副本不能直接交付；必须完成绘制、编码和正向/尺寸校验。照片内容及像素来源SHA仍记录原图。

EXIF结构异常不再直接终止所有导入：仅导入预检查可记录方向未知，随后使用微信明确返回的已知方向恢复；微信未返回可识别方向时停止并提示在相册转正另存。严格的工作图和最终文件校验没有放宽。HEIC/PNG压缩产生带方向的JPEG时复用上述转正路径；平台未能提供可确认方向或尺寸时仍拒绝猜测。镜像变换以文件方向记录为依据，不自动改变用户自拍的意图。

方向恢复为设备内加工，可能重新编码内部工作图，不消耗AI次数、不创建订单，也不改写相册原文件。普通照片字节兼容测试与此前被拒绝照片的新增恢复测试分开验收。

## 新增省份步骤

1. 确定工具版本、适用考试与文件哈希，阅读说明并分析实际保存路径。
2. 用同一原图取得官方EXE输出，检查输入边界、输出尺寸、量化表、采样、DPI、JPEG分段、元数据和尾部；质量标签相同不代表不同编码器一致。
3. 判断现有编码能力是否覆盖；能覆盖则新增独立配置、入口和该省校验；超出范围则先适配编码能力，不伪装为支持。
4. 将原背景免费处理与可选AI换背景一并接入共用流程，复用既有服务可用性、云端处理告知、明确确认、付费权益、同结果背景／裁剪调整不重复调用及异常恢复。新增profile显式声明AI能力，检查入口显示和地区切换；不得只完成免费链路却遗漏已确认的AI入口，不为各考试复制AI服务或擅改收费方案。官方限制美化修饰时须记录具体要求并明确适用边界，不能把提供AI功能解释为考试允许使用。
5. 回归国考、四川固定像素输入的完整输出SHA-256，并验证原有裁剪、画布和AI前景映射不变；用模拟服务检查AI模式切换不发请求、取消不调用、重复使用当前结果不重复扣费，真实AI和支付仍分别按授权验收。
6. 生成候选图片，验证本地格式和ZIP解压字节；真实小程序导出、手机方向、官方平台接收分别确认。与EXE比较编码规则，不要求不同裁剪或解码器产生的整图字节相同。
7. 用户确认后按授权集成、上传与送审；后续工具变更保留版本和旧依据，不覆盖历史验收。

## 验证入口及证据边界

- `node scripts/validate-photo-profile-compat.js`：基线32c4d6de，国考、四川各4种固定像素输入，完整JPG SHA-256必须逐字节一致。基准由旧实现首次生成；禁止为了新实现通过而重录。
- `node scripts/validate-photo-configurable.js`：13组独立Pillow解码/量化/采样检查，覆盖横竖、奇数尺寸、质量端点、DPI、分段、自定义表和动态画布；错误配置拒绝。
- `node scripts/validate-photo-orientation.js`：8种变换对照Pillow，实际画布适配器调用检查，两地区14种旋转/镜像模拟导入，损坏记录可恢复/方向未知拒绝、失败清理检查；另覆盖四川合法原图生成小于30KB工作图、HEIC压缩后仍带方向的JPEG转正。
- 既有photo-core、sichuan、picker、adjust-interaction、zip-export、export-guide、preview-export、virtual-payment、order-state检查保留；外部服务均为注入模拟，不产生真实交易、照片上传或BDA调用。

以上是本地和模拟平台证据。真机需覆盖iPhone及Android的正向、横拍、镜像、相册旋转后照片，核对预览和导出方向一致、头肩和裁剪范围、切换地区、ZIP/JPG交付。暂无反馈用户的报错原图，不能断言已复现其全部实际来源。新省份仍需官方平台单独接收验证。正常照片基准一致不等于手机图像解码差异已全部验收。
